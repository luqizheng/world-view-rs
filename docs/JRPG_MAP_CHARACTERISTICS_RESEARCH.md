# JRPG 风格地图特征研究报告

> **性质**：外部取证研究，**不是**规格、不是 ADR、不是基线。供 worldview-rs 判断「JRPG 风格」这一目标是否成立、以及现有设计是否需要补强。
> **方法**：四路并行取证（地图类型学 / 视觉语言 / 编辑器功能基线 / 中文实践视角）+ 关键断言交叉复核。
> **日期**：2026-10-17
> **读法**：§1 是结论，§2–§5 是分维度证据，§6 是对 worldview-rs 的映射与缺口，§7 是建议动作。
> **证据纪律**：全文区分三档 —— ✅ 有一手来源（附 URL）／⚠️ 行业通识或推导（无一手来源）／⛔ 已证伪或不可引用。**未经取证的内容一律标注，不混入结论。**

## 1. 结论先行

**七条结论，按对本项目的相关度排序。**

| # | 结论 | 证据档 |
|---|---|---|
| **C1** | **JRPG 地图不是「一张大地图」，而是「一个分层容器」。** 世界地图是顶层容器，向下嵌套城镇 / 野外 / 地牢 / 室内四类子图，每类承担不同玩家契约。 | ✅ |
| **C2** | **「地图类型」是行为契约，不是视觉风格。** FF6 的 Zozo 官方标注为 Town，实际是满随机战斗的地牢；Narshe 在 World of Ruin 阶段本身变成地牢。→ **类型字段必须与「可否遇敌 / 可否存档」解耦，且允许按剧情状态改写。** | ✅ |
| **C3** | **门是数据对象，不是瓦片。** 钥匙、剧情旗标、隐藏、一次性——四种门禁语义全部挂在门上；墙才是瓦片。这是 JRPG 编辑器与通用编辑器最核心的一等公民差异。 | ✅ |
| **C4** | **区域（Area / Zone）是难度与遭遇的分组键，且必须对玩家可见。** FF7 的遭遇表按区域分组，区域名显示在菜单里；大量区域被显式标为「无遭遇」。 | ✅ |
| **C5** | **世界地图的必备信息是「状态」而非「细节」**：已探索 / 未探索二态、当前位置、区域连接拓扑、分类图标、载具航线。FF12 的三态（已探索浅灰 / 当前橙黄 / 未探索灰）已在本次复核中由独立来源印证。 | ✅ + 复核✅ |
| **C6** | **视觉上存在两代 JRPG 语言，必须做成两套预设而非一套参数。** 1986–2000 是「正俯视或斜 3/4 + 16px 手绘瓦片」；2018 至今 HD-2D 是「2D 精灵 + 全 3D 场景 + 动态光照」。两代的网格、描边、光照模型完全不同。 | ✅ |
| **C7** | **本项目现有设计已覆盖 C1/C4/C6；缺 C2/C3/C5 三项，且这三项恰好是 JRPG 辨识度最高的部分。** 详见 §6。 | ✅（对照本仓代码） |

> **一句话总结**：worldview-rs 已把「地图是什么」想清楚了（分层容器 + 区域 + 时间轴），但**缺「玩家怎么走」这一层**——门、类型契约、已探索状态。这三项不是加功能，是补上 JRPG 的交互语义。

## 2. 类型学：JRPG 地图分几类，各自的契约是什么

### 2.1 五分类与它们的必备信息元素

RPG Maker 官方教程直接给出五分类：Exterior Safe / Interior Safe / Man-made Dungeon / Natural Dungeon / World Maps【✅ RPG Maker VX Ace Tutorial V, `dl.komodo.jp/rpgmakerweb/tutorials/RPGMakerVXAceTutorial5.pdf`】，其中 World Map 的官方定义是：*"This is the main map that you will travel on to link together maps that are distant from one another."*（连接远端地图的主地图）

| 类型 | 玩家契约（职能） | 与上级地图的关系 | 必备信息元素 |
|---|---|---|---|
| **世界地图**<br>World / Overworld / _FIELD | 空间决策：「我在哪、还有哪、去不去」；低成本位移（陆行鸟 / 飞空艇 / 船）；低密度遭遇 | **顶层容器**，向下切换进所有其他类 | ★可前往地点图标及分类（城市 / 道路 / 地标）<br>★地名<br>★玩家实时坐标标记<br>★**已探索 / 未探索视觉区分**<br>★区域间连接拓扑（FF12 用蓝色虚线）<br>★道路 / 航线<br>★可通行性（载具不同则遭遇规则不同）<br>★传送 / 载具锚点 |
| **城镇 / 村庄**<br>Town / Village | 补给与结算：治疗、买卖、存档、任务接取、对话；**免战区** | 由世界地图或野外图进入；退出回上级 | ★固定功能建筑（商店 / 旅馆 / 教会 / 铁匠铺）<br>★建筑入口 / 门与可交互提示<br>★NPC<br>★存档 / 治疗锚点<br>★出口 gate<br>★传送点（锚定到「上次访问的某建筑」）<br>★剧情门禁（此镇是否可达） |
| **野外 / 道路**<br>Field / Route / Plains | 低压移动与遭遇刷取；连接城镇的「走廊」 | 夹在世界地图与城镇之间，或直接嵌在世界地图上 | ★地形类型（FF7 每区域分 grass / dirt-snow / beach / misc 四套遭遇表）<br>★通行性（道路 vs 门 vs 水路需特殊道具）<br>★遭遇点（草丛 / 水面）<br>★遭遇强度分档（FF6 分 Overworld 1–4 与 Dungeon 1–4）<br>★出口（连接两端关键目的地）<br>★固定 NPC（训练家）<br>★天气（Route 119 雷雨、Route 217 冰雹） |
| **室内 / 建筑**<br>Interior | 密闭叙事与私密服务；把「商店 / 剧情」放进可控盒子 | 由城镇图或野外图的门进入；退出回该建筑所在地 | ★门与楼层切换点<br>★楼梯 / 多层切换<br>★单一职能（商店 / 剧情）<br>★NPC 对话与事件旗标<br>★宝箱 / 隐藏道具<br>★默认无遭遇 |
| **迷宫 / 地牢**<br>Dungeon / Cave / Tower | 高强度挑战、boss 门、战利品；可反复重刷 | 从城镇 / 野外 / 世界地图进入；**退出通常回入口城镇并重置位置** | ★多层结构<br>★地形伤害<br>★陷阱<br>★宝箱<br>★钥匙 / 机关<br>★楼梯与秘密通道<br>★boss 位置<br>★存档点 / 撤退锚点<br>★重进时是否保持进度 |

★ = 有实证来源。FF6 Narshe 的四向连接实证了「入口 ↔ 出口双向配对」而非「返回上一层」：*"Narshe is a town connected to four dungeons: two in the mines' north and south passage, and two more… connected to its north passage mines."*【✅ finalfantasy.fandom.com/wiki/Narshe_(Final_Fantasy_VI_field)】

**区域（Region / Area / Zone）**是横跨上述五类的元数据层，不是一张地图：★显示名 ★所属地图 ★遭遇表组 ★等级带 ★区域锁定条件 ★未解锁时的显示状态。

### 2.2 C2 的决定性证据：类型是行为契约

这是本研究中最反直觉、也最容易被编辑器做错的一条。

| 案例 | 官方标注 | 实际行为 | 含义 |
|---|---|---|---|
| **FF6 Zozo** | Type: **Town** | *"Despite the fact that this is a town, its actually a dungeon… They're actually filled with random battles."* | 类型标签与遇敌规则**不一致** |
| **FF6 Narshe**（World of Ruin 阶段） | 城镇 | *"becomes a dungeon itself overrun with monsters"* | **类型随剧情状态改变** |
| **FF7 North Crater 森林 / 特定桥梁** | 野外 | 显式标为**无遭遇** | 「此区域安全」是一等数据 |
| **FF6 遭遇表** | — | `Overworld 1 = No encounters, 0` | 安全区域占一行表格 |
| **FF6 进出城镇 / 地牢** | — | 须走一段**安全距离**才能再遇敌 | 遭遇计时器须支持「进出即重置 + 安全距离」 |
| **FF7 世界地图计数器** | — | *"resets whenever the player leaves or enters the world map"* | 世界地图与野外是**两套独立计数器** |

【全部 ✅：finalfantasy.fandom.com/wiki/Walkthrough:Final_Fantasy_VI/BlueHighwind/Part_7 ；ff7speedruns.com/wiki/Field_map_encounter_mechanics】

> **对编辑器的直接结论**：若把「类型」做成 `enum MapType { Town, Dungeon, Field }` 并让它决定遇敌，则 Zozo 与 Narshe 两个案例立刻无法表达。**类型必须与 `encounter_rule` / `can_save` / `encounter_value` 解耦，且允许按剧情状态改写。**

### 2.3 C3 的决定性证据：门是数据对象

| 证据 | 原文 | 含义 |
|---|---|---|
| Pokémon Route 门禁 | *"Certain routes have a gate between it and a key destination."*【✅ pokemon.fandom.com/wiki/Route】 | 门是标准组件 |
| FF6 Narshe 隐藏矿口 | *"is concealed in a rockface, and opens with a secret switch."*【✅ 同 Narshe 页】 | 门可**隐藏**（地图上都看不见） |
| DQ 系列钥匙门 | DQ III 起区域被 key-based doors 门禁【✅ the-avocado.org Franchise Festival #95】 | 门可被**道具**开 |
| DQ III 隐藏区块 | 需特殊道具才显示 | 门禁可影响**可见性**本身 |

> **门禁的四种语义 = 钥匙 / 剧情旗标 / 隐藏 / 一次性**。全部挂在门上。墙是瓦片，门是对象。

### 2.4 上浮的三条路径（各有代价）

| 路径 | 机制 | 实证 |
|---|---|---|
| **原路返回** | 地牢退出回入口城镇 | 主流默认 |
| **一次性传送** | Etrian Odyssey：*"the only way to get out of the labyrinth is to return to the start"*，且**只有回城途中能存档**【✅ rpggamers.com/game/etrian-odyssey】 | 把「回城」做成显式动词与资源决策 |
| **锚点传送** | Pokémon Fly/Teleport 锚定「上次访问的 Pokémon Center」，战败也送回该处【✅ Bulbapedia Pokémon Center】 | 失败代价低，鼓励重试 |

## 3. 视觉语言：JRPG 地图应该长什么样

### 3.1 C6：两代语言必须做成两套预设

| 维度 | 传统 JRPG（1986–2000） | HD-2D（2018– ） |
|---|---|---|
| 代表 | DQ、FF I–VI、SaGa、Mother | Octopath Traveler、Live A Live、DQ III HD-2D、Triangle Strategy |
| 场景构成 | 2D 瓦片拼图 | **2D 像素精灵 + 全 3D 场景**（UE4）【✅ Square Enix 官方 HD-2D 站】 |
| 视角 | 正俯视 / 斜 3/4（three-quarters view）【✅ Tropedia】 | 俯视斜角；正交相机 **yaw 45° / pitch 30°**【✅ neta.art 推导】 |
| 网格 | 方形，8×8(FC) → 16×16 → 32×32 → **48×48(MV/MZ 默认)**【✅ RPG Maker Wiki】 | 32×32 环境 + 32×32 精灵 |
| 光照 | 烘焙进贴图，单层软阴影 | **动态点光源 + 实时投影** + tilt-shift 景深 + bloom + 体积雾 |
| 地形 | 逐块绘制 + autotile 拼接 | 真实 3D 高低差可探索 |
| 成本 | 低，可 UGC | 高，接近数字绘画 |

> **对 worldview-rs 的意义**：项目 ADR-0016 已定「古舆图」为默认观感——它属于**传统派的低饱和变体**（低饱和纸张感，而非高饱和手绘）。HD-2D 是另一条路线，不应作为本期目标，但**渲染预设的接口应为将来的 HD-2D 留位**（即 Theme Pack 的第二个实例）。

### 3.2 网格：只有两种合法解

| 解 | 参数 | 依据 |
|---|---|---|
| **正交方形网格** | tile 16 / 24 / 32 / 48 px，五档 | 【✅ RPG Maker MZ 官方；MZ 支持 16/24/32/48】 |
| **2:1 菱形（dimetric）** | 地边夹角 **26.57°**，tile 32×16 / 64×32；真等距为 35.264°、菱形比 1.732:1（**像素对不齐，勿用**） | 【✅ neta.art / the-pixel.art】 |

⛔ **常见错误**：把方形画布旋转 45° 当菱形——这是等距像素画最高频的错误。

### 3.3 描边与上色：规则要改，不是加细节

| 要素 | 规格 | 依据 |
|---|---|---|
| 描边线宽 | 16px 地块用 1px；32/48px 地块用 2px（≈ 边长 4–6%） | 【✅ neta.art】 |
| 描边颜色 | **禁用纯黑 #000**；取该材质色阶的最暗一档 | 【✅ the-pixel.art / Pedro Medeiros】 |
| 描边方式 | **选择性描边（selout）**：受光侧描中间调、背光侧描最暗色 | 【同上】 |
| 光源方向 | **左上为业界默认，项目内永不改变**；2D 转 3D 时主光须绑相机，否则旋转穿帮 | 【✅ neta.art】 |
| 软阴影 | 接触阴影 1–2px；建筑 autotile 相邻格自动向右下投影（即光源左上） | 【✅ RPG Maker MZ 素材规范】 |
| 三面明暗 | 立方体三可见面共享一条三档明度阶：顶面基值 → 一侧 −1 档 → 另一侧 −2 档；5–6 套色阶 ≈ 32 色 | 【✅ neta.art】 |
| 分辨率取舍 | **分辨率越低越应先丢描线**，改用高对比纯色块分离 | 【✅ Pedro Medeiros 明确建议】 |

⛔ **须纠正的流传规则**：业界常引的「描边色 = 基色明度 **−45%**」——**未找到任何一手来源**。可复现的等效规则是「暗一档」，在 5–6 档色阶下，中调色约等于 **HSL 明度 −20%~−35%**。

> ⚠️ **本项目现状提示**：`docs/ART_STYLE_SPEC_v0.1.md` §3.2 与 ADR-0016 采用了「基色明度 −45% 同色相」的表述（见 MAP_EDITOR_BASELINE §3.2）。按证据纪律，该数值应降级标注为「等效推导值」，或替换为「暗一档 + HSL −20%~−35%」的可复现口径。**这属文档追写范畴，需用户裁定后再动**（AGENTS §6.3）。

### 3.4 色彩：可区分性的硬阈值有据可查

| 要素 | 规格 | 依据 |
|---|---|---|
| 色差阈值 | **ΔE00：2.3 = JND**（几乎不可辨）；5 = 需并置才可见；**10 = 明确不同** | 【✅ darktable 手册 / Sharma / Witt & Green 2010】 |
| **结论** | **相邻地形必须按 ΔE00 ≥ 10 设计**，不能只满足 JND | 【推导】 |
| 地形区分硬约束 | 色相间隔 ≥30° **或** 明度差 ≥3:1（相对亮度），**之一** | 【3:1 来自 ✅ WCAG F73】 |
| 基色明度 | 中间调基色 **HSL V ≈ 40%–60%**，为高光 / 暗部留空间 | 【✅ spritory】 |
| 饱和度分布 | **基色处最高，向高光 / 暗部衰减**；全饱和色仅用于焦点，饱和色要「稀疏」 | 【✅ the-pixel.art】 |
| 色相偏移 | 暗部偏冷（蓝 / 紫）、亮部偏暖（黄 / 橙），**每档 10–25°** | 【✅ spritory / the-pixel.art】 |
| 可访问性 | WCAG **1.4.1 Use of Color（Level A）**：颜色不得为唯一信息载体；避免纯红 / 纯绿对立；仅明度不同亦满足，条件是**对比 ≥3:1**；约 **1/12 男性**有色觉缺陷 | 【✅ W3C WCAG 2.2 F73 / MDN】 |

> **落地形态**：地形 = 色块 **+ 纹理图案 / 描边 + 文字标签**，三重冗余；不可通行区加暗角或交叉线；目标 / 出口用**独立图标形状**而非仅换色。
> **本项目对照**：`ART_STYLE_SPEC` §3.3 已定「派系色两两 ΔE ≥ 25、相邻 ΔE ≥ 35」——**这比 ΔE ≥ 10 严得多，是正确的**（派系色需在低饱和古舆图上仍可辨，比地形色要求更高）。地形色之间则尚未见 ΔE 阈值约束。

### 3.5 可读性：规格从「视角」推导，不拍脑袋

| 要素 | 规格 | 依据 |
|---|---|---|
| 视觉角阈值 | **1 角分**为可察觉极限，制图实务取 **2 角分**（1/30°） | 【✅ Esri 最小尺寸指南】 |
| 像素↔视角换算 | 1080p / 24 寸屏 / 60cm 观看距离 ≈ **1.7 角分/px** | 【推导】 |
| 标签最小字高 | 网页地图 **≥10px 大写高度**；印刷 **≥5pt** | 【✅ Esri；UN Ormeling 地图注记规范】 |
| 图标最小尺寸 | 点符号最小直径 0.25mm（高对比）/ 0.45mm（低对比）≈ 推荐字号的 **2/3** | 【✅ Taylor & Francis 地图符号学最小尺寸】 |
| **推导建议** | **地图图标 ≥16px（临界）/ 24px（推荐）**，描边 1–2px 防同色背景吞噬 | 【由上述两项推导】 |
| 标签层级 | 字号类别**最多 3 种**；5–15pt 区间级差 ≥2pt，>15pt 级差 ≥15–20% | 【✅ Ormeling / Esri】 |
| 标签位置 | 点注记**右上为最优**，符号下方最差 | 【✅ Ormeling】 |
| 标签密度上限 | 同一视口非重叠标签 **≤12–15 条**、字号层级 ≤3 级 | 【⚠️ 推导，无直接实证】 |
| 必须常驻元素 | 当前位置、已探索边界、出口 / 传送点、当前目标朝向、可交互物高亮 | 【✅ GDC《Stop Getting Lost》】 |

### 3.6 手绘感 / 纸面感：已有可移植的 shader 实现

| 成分 | 可落地参数 | 参考实现 |
|---|---|---|
| 笔触抖动 wobble + 线 boil | 轮廓线随时间轻微位移，幅度 0.5–1px | 【✅ cannoli-cat/stylized-rendering（Unity URP, CC BY 4.0）】 |
| 程序化纸纹 | **零贴图占用**，参数：paper contrast / grain intensity | 【✅ 同上；Stylized Reality Toon (Fab)】 |
| 墨线不匀 | Sobel / 深度-法线边缘检测 + ink color influence（线条混入底色）；阴影区交叉排线（cross-hatching） | 【✅ OmniLine】 |
| 平涂分色 | Posterized banding；1-bit 设定：抖动 Spread ≈ **1/(调色板色数 −1)** | 【✅ Pterosoft Comic Shader】 |
| 色调偏移（纸感关键） | **暖阴影 / 冷高光**分离调色 | 【✅ Pterosoft】 |
| 缩放降饱和 | 像素图放大 >2× 时饱和度 **−10%~−15%** + 1–2% 亮度噪点消 banding | 【⚠️ 通识，未取证】 |
| 色边缘晕 bleed | 着色前对 UV 做 1–2px 低频扰动 + 边缘色扩散 | 【✅ Stylized Reality Toon 描述】 |

> **本项目对照**：ADR-0016 M2 已规划「纸面雾霭 / 纸张噪点 / 文字晕边」，方向与上表一致；**「暖阴影 / 冷高光」的色调分离是当前规格未见的一项**，可作为 M2 的候选项。

### 3.7 空间要素五件套与一个反直觉结论

GDC《Stop Getting Lost: Make Cognitive Maps, Not Levels》归纳的五个可设计空间要素：**通道 / 节点 / 地标 / 地区 / 边界**【✅ gameindustrylibrary.com】。中文译本见 indienova《不再迷路：建立认知地图》。

| 原则 | 内容 |
|---|---|
| 群组化 | 相似的元件归入同一群组（如「三座金字塔」）；随机分组会破坏记忆 |
| 边界必须干净 | 高墙或一扇门给出清晰边界 → 玩家形成清晰认知地图；模糊边界 → 模糊认知地图 |
| 心象地图的层级收缩 | 「我在森林场景 → 森林里的伐木场 → 伐木场的宿舍厨房」，主题逐级收窄；可用磨损 / 光线 / 主色调传达，不需额外美术资源 |
| 地标设计 | 需「多面可辨、非旋转对称」；地标大小 / 重要性差异会被玩家自动归类 |
| ⛔ **反直觉结论** | **小地图 / GPS 会让玩家以自我为中心看待环境**——*"玩家只是在探索地图而非探索环境"*；**不用小地图的玩家反而更记得路** |
| 学术补充 | 玩家在随机生成世界中**主要依赖「世界边缘」作为标记物**；仅靠物件图案不足以形成认知地图，需额外独特地标【✅ Biggs et al., Georgia Tech, PDF】 |

### 4.2 三条结构性发现

**发现 1：图层不是「美术分层」，而是「渲染序 + 独立数据源」的二元结构。**
LDtk 用 IntGrid 做碰撞、Tiles/AutoLayer 只做渲染；RPG Maker 用 A/B/C/E 图块页 + 通关判定标记分离。**JRPG 编辑器必须把这两类层做成不同类型，而非同一层的不同用途。**

**发现 2：autotile 只有两条技术路线，必须都支持。**

| 路线 | 机制 | 代表 |
|---|---|---|
| **位掩码 / peering bits** | 可配置规则集，2×2 或 3×3 邻接位；引擎按邻接选瓦片 | Tiled 三种 Terrain Set（Corner 16 张 / Edge 16 张 / Mixed 256 张，可只用 47-tile blob 子集）；Godot `Terrain Peering Bits`（`-1` 表示空格） |
| **固定模板位** | 47-tile / 16-tile 模板，零配置但素材受限 | RPG Maker A2 autotile：**固定 48 张图集**，每张拆 4 个 quarter-tile，红 / 绿 / 黄 / 蓝固定落在四象限 |

【✅ 全部官方实证：doc.mapeditor.org/en/stable/manual/terrain/ ；docs.godotengine.org/.../using_tilesets.html ；rpgmakerweb.com/blog/classic-tutorial-how-autotiles-work】

> ⚠️ **须纠正的预期**：本轮**未在任何一款工具的官方文档中找到「地形自动平滑 / 去锯齿」功能**。行业做法是美术侧用 47-tile 模板保证无缝，工具侧只做「连接一致性修复」。**不应把「去锯齿」写成任何现有工具的现成能力**——它是自研项。
> 📌 **本项目现状**：`MAP_EDITOR_BASELINE` §1.13 已把「自动自然化（去毛刺 + 样条平滑）」列为裁定，§2.4 建议 Chaikin + 噪声扰动。**这是自研且合理**，但需在文档中标明「业界无现成实现，成本为自研」。

**发现 3：大地图的正确形态是「关卡（Level/Room）+ chunk 存储」，不是一张无限画布。**
Tiled infinite map 用 `<chunk>` 稀疏存储（base64/zlib/zstd）；LDtk 用 Level + 外部关卡文件 + `__neighbours` 拼接。

### 4.3 实体模型的 JRPG 特征字段

LDtk 的实体定义包含一组**明显为 JRPG 预留**的字段【✅ LDtk JSON 文档】：

| 字段 | 值 | 为何是 JRPG 特征 |
|---|---|---|
| `maxCount` + `limitBehavior` | `DiscardOldOnes` / `PreventAdding` / `MoveLastOne` | **存档点必须「全世界唯一」** |
| `limitScope` | `PerLayer` / `PerLevel` / **`PerWorld`** | 同上，「每世界只一个出生点」 |
| `F_EntityRef` | 指向另一实体实例的强类型字段 | 门 → 目标传送点；钥匙 → 门 |
| `tags` | 字符串标签 | 地标 / 可破坏物 / 商人 |
| `renderMode` | Rectangle / Ellipse / Tile / **Cross** | Cross = 不可通行标记的经典表达 |

### 4.4 RPG Maker 的事件模型（JRPG 专用编辑器的典型形态）

| 机制 | 内容 |
|---|---|
| **五种 Trigger** | Action Button / Player Touch / Event Touch / **Autorun** / **Parallel**。前三者要求玩家相邻或同格；Autorun 冻结玩家且跑到结尾会重复；Parallel 允许移动但每帧重复执行 |

| **通关判定是图块属性** | 可从上方通行 / 从下方通行 / 方向修正；MZ 官方明确「passability tiles 在编辑器里始终以游戏中的样子显示」 |
| **内容即可视化指令列表** | ◆指令行 + : 分支块，支持右键复制粘贴、单条 Test |
| 内置生成器 | **Generate Dungeon**（官方博客以「生成地牢再人工升级」为题） |

### 4.5 若要做 JRPG 地图编辑器：功能优先级

| 档 | 项 | 依据 |
|---|---|---|
| **P0**<br>没有就做不成 | ① 三层固定语义 + 可扩展层：`Ground / Decor / Overlay / Collision / Region / Event`<br>② autotile 双引擎（47-tile + 16-tile 固定模板 ／ 可配置 peering bits）<br>③ **地形 / 图块级通关判定**（pass-above / pass-below / direction-fix / star 继承下层），编辑器内即显式可视化<br>④ 实体 Schema 系统（尺寸 / 图标 / pivot / 渲染模式 / 标签 / maxCount + limitScope + 强类型字段含 EntityRef）<br>⑤ **传送 / 邻接模型**：`port` 实体（目标 Level + 目标点 + 方向 + 淡入淡出）+ 自动推导邻接表<br>⑥ **存档点 / 出生点作为受限实体**（`limitScope: PerWorld`）<br>⑦ JSON 内部格式 + 规则预解算（autotile 结果落盘为瓦片，运行时不必解释规则） | RPG Maker A/B/C/E【✅】；LDtk IntGrid 分离【✅】；Tiled 三种 Terrain Set【✅】；LDtk `__neighbours`【✅】 |
| **P1**<br>决定好用 | ⑧ World / Level 两级模型（`worldLayout` GridVania + 网格对齐；Level 可拆独立文件；邻接自动提示）<br>⑨ **Region 系统**（矩形 / 多边形 + Region ID + Terrain Tag，可被运行时查询）<br>⑩ 无限地图 / 大地图分块存储（chunk 稀疏 + base64/zlib）<br>⑪ 对象层与自定义属性（9 类型 + 对象引用可视化箭头）<br>⑫ 模板系统（对象模板 + Stamp Brush 笔刷预设）<br>⑬ 内置 Playtest 预览窗口（含「仅测试当前事件」）<br>⑭ 内置迷宫 / 地牢生成器<br>⑮ 视差背景层 + 区域色调 Tint | 【✅ 各自官方文档】 |
| **P2** | ⑯ TMX 导入导出、CSV 导出<br>⑰ isodiamond / oblique / hex 朝向（JRPG 主视角用不上）<br>⑱ 规则 DSL 与种子复现<br>⑲ **对称绘制 / Y-sort 高度层 / LOD**——⛔ 全部工具均无官方支持，属纯自研<br>⑳ 插件 / 脚本系统（RPG Maker 用 JS 插件扩展是其生态护城河） | 【✅ / ⛔ 已逐项标注】 |

> **最关键的两条差异化结论**：
> 1. **Region 是 JRPG 编辑器相对通用编辑器的最大缺口**——RPG Maker 有 Terrain Tag + Region ID（可被 Get Location Info 读取），Tiled / LDtk / Ogmo 全都没有一等公民的 Region。**做 JRPG 编辑器，区域系统应进 P0 而非 P1。**
> 2. **遭遇表（Encounter Table）在全部五款工具中都没有一等公民实现。** RPG Maker 仅有敌组数据库 + 地图级开关 + terrain tag 影响遇敌率。**这是 P0 级自研差异化项。**

### 5.2 两条收敛的方法论主线

**主线一：认知地图 / 心象地图**（indienova 的 GDC 中文译本体系）
- 五要素：通道 / 节点 / **地标** / 地区 / **边界**
- 原文可引用句：*"认知地图是存在你脑中的地图，而迷路就是当认知地图与环境无法吻合的状态。"*
- **边界必须干净利落**：高墙或一扇门给出清晰边界 → 清晰认知地图；模糊边界 → 模糊认知地图
- **反直觉结论**：小地图 / GPS 让玩家以自我为中心看待环境，**不用小地图的玩家反而更记得路**
- **面包屑理论**：地标是链式关系的设计点，链状物体被潜意识当作一条线处理

**主线二：视觉引导 / 负空间**（网易互娱学习发展公众号，格式塔完形）
- **格式塔完形**：玩家第一印象来自「几个常见色块的拼接」；一棵树一栋楼若**破坏地图结构的简单性就必须删除**
- **负空间三要点**：① 色调明确（目标与背景有明确色调差距，且色调出现尽量平衡，忌多色杂乱堆叠）② 低认知复杂度（主流程外不加无关布景）③ 明确的游戏区间轮廓（潜意识可辨游戏区 / 非游戏区）
- **引导必须走在情景前**：引导服务游戏性，情景服务氛围与叙事
- **Weenie（地标建筑时隐时现）** 是中文语境补充的关键术语
- 引导手法清单：颜色、地标、吸引、入口、门和阀门、引导线、收紧构图、框架、面包屑、纹理、运动

## 6. 对 worldview-rs 的映射：已覆盖什么，缺什么

### 6.1 逐条对照

| # | 研究结论 | worldview-rs 现状 | 判定 |
|---|---|---|---|
| C1 | 地图是分层容器（World / Region / City / Interior） | `MapLevel` 四级已存在；P4 明确「子图内容不复制进父图，靠 ID 引用」 | ✅ **已覆盖** |
| C4 | 区域是难度 / 遭遇分组键 | `wv-core/src/model/region.rs` 已定义 `Region { id, name, map, polygon }` + `centroid()`；`ui/region_panel.rs` 有面板 | 🟡 **部分**——`Region` 只有几何与名称，**无遭遇表组 / 等级带 / 解锁条件 / 安全标记** |
| C6 | 两代视觉语言做成两套预设 | ADR-0016 定古舆图为默认；`ART_STYLE_SPEC` 的 Theme Pack 已预留接口；`colors_google` / `colors_dusk` 已是多实例 | ✅ **接口已预留** |
| — | 视觉可区分性阈值 | `ART_STYLE_SPEC` §3.3 定派系色 ΔE ≥ 25 / 相邻 ≥ 35（**比 ΔE ≥ 10 严，正确**）；**地形色之间无 ΔE 约束** | 🟡 **部分** |
| — | 标签 / 图标可读性阈值 | `ART_STYLE_SPEC` §3.4 定 TILE_BASE 32px、五档整数倍缩放；ADR-0017 有标签层 | 🟡 **部分**——无「标签最小字高 ≥10px」「图标 ≥16px」「密度上限 ≤12–15 条」的显式约束 |
| C2 | 类型是行为契约，与遇敌规则解耦 | ⛔ **无**——无地图类型枚举，也无 `encounter_rule` / `encounter_value` / `can_save` 字段 | 🔴 **缺失** |
| C3 | 门是一等数据对象 | ⛔ **无**——`Place` + `DistanceGraph` 承担可达性，但无「门 / 传送点 / 钥匙 / 旗标 / 隐藏 / 一次性」语义 | 🔴 **缺失** |
| C5 | 世界地图表达已探索 / 未探索二态 | ⛔ **无**——但**本项目定位为作者工具而非玩家工具**，此项需重新评估（见 §6.2） |
| — | 遭遇表 | 🟔 `wv-core/src/derived/encounter.rs` 是**「相遇检测」**（ADR-0005，两个 Unit 轨迹时空交叉但作者没写事件 → 提示），**与游戏内的「遭遇战表」是完全不同的概念**，不可混淆 | ⚠️ **命名需警惕** |
| — | 大地图 = Level + chunk 稀疏存储 | `TerrainGrid` 栅格 + `RasterRef` → `terrain.bin`；`MAP_EDITOR_BASELINE` §2.19 有 4096² 门禁与 8192²「必须分块」 | ✅ **已有等价设计** |

### 6.2 三项缺失的差异化裁决建议

> 以下为建议，**未经用户裁定，不得落盘为 ADR 或基线**。

| 建议 | 内容 | 依据 | 风险 |
|---|---|---|---|
| **甲 · 新增「门禁」概念（建议优先）** | 新增 `Portal { id, from_map, from_pos, to_map, to_pos, facing, gate: GateCondition }`；`GateCondition` 用**自由字符串 tag**（`key:xxx` / `flag:xxx` / `hidden` / `once`），**刻意不做枚举**（与 `Membership.kind` 的既有纪律一致）。P4 安全：只存 `Id` 引用，不复制子图。 | C3 + P4 + `Membership.kind: Option<String>` 先例 | 低。非破坏扩展，符合 `#[serde(default)]` 惯例 |
| **乙 · 区域补字段** | `Region` 增 `tags: Vec<String>` / `level_band` / `safe: bool`。**不做遭遇战表**——那属于游戏运行时，不属于作者的世界观整理工具。 | C4 + 工具定位（AGENTS §7.5「协助整理设定的助手」） | 低。但须先确认 Region 是否要承载游戏语义 |
| **丙 · 已探索状态需重新定位** | C5 的「已探索 / 未探索」是**玩家侧运行时状态**，作者工具里对应的概念应是「**作者已定义 / 待定义**」——即地图完备度，而非游戏内探索进度。 | C5 + 工具定位 | 🟡 **需用户裁定**：这个区分是否值得做，或属于过度设计 |

### 6.3 三处需纠正的既有表述（**待用户裁定，本次不动**）

| 位置 | 现表述 | 证据状况 | 建议 |
|---|---|---|---|
| `ART_STYLE_SPEC` §3.2 / ADR-0016 §2.6 | 描边色 =「基色明度 **−45%** 同色相」 | ⛔ **未找到一手来源**，判定为民间经验 | 按 AGENTS §6.3「追加不覆盖」，**新增一节**说明该值为等效推导，可复现口径为「暗一档 + HSL −20%~−35%」 |
| `MAP_EDITOR_BASELINE` §1.13 | 「自动自然化」作为既有能力 | ⚠️ **业界无现成实现**（Tiled / LDtk / Godot / RPG Maker 均无「去锯齿」功能） | 在该节追加注明「**自研项，业界无现成实现**」，避免后续误估成本 |
| `ART_STYLE_SPEC` §3.3 | 派系色 ΔE ≥ 25 | ✅ 阈值方向正确（远严于地形所需的 ΔE ≥ 10） | 可**追加**：地形色之间同样需要 ΔE ≥ 10 的显式约束（当前缺失） |
