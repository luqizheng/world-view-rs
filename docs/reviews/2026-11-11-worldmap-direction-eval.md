## 0. 先把话说在前面

我这一轮不谈 crate、不谈渲染管线、不谈 shader 分支，也不评价已落地代码的质量——**恰恰相反，代码做得比文档以为的多得多**，这才是问题所在。

我只问一件事：**我作为买这个工具的人，打开它，想拿它干成什么？**

用户这一轮补了一句原话，必须原样摆在最前面：

> **「地图画面非常地不好看，但是我不知道怎样做，主要是 browse 和 map」**（顶栏三段 `Browse / Map / CellMap`；旧 ADR / GLOSSARY 把中段记作 `Edit`）

这句话和上一轮「卡在世界地图上了，不知道怎样推进下去」其实是同一句话的两面：**一个说「不知道往哪走」，一个说「不知道怎么做」，两句里的主语都不是功能，是方向。** 我作为创作者，不会用「不知道」形容一个差某个按钮的工具；我用「不知道」，是因为没人告诉我「做到什么算完」，也没人在我正看着的那两个画面上给我一个能点头或摇头的答案。

而本轮全链复核给出一个更刺眼的答案：**§1 承诺的那件事，计算层早就算完了；它只是没锚点、没出现在我看的画面上、没被点过、也没在清单上销账。**

## 1. 用户真正要拿「世界地图」完成的任务

### 1.1 第一人称：我实际会怎么用它

> 我在写长篇，第 47 章卡住了。稿子里写「他三天前还在北境，今天已经站在南疆城下」。
> 我隐约觉得不对，但不确定——骑马能不能三天到？中间有没有河？那条河上有没有渡口？我翻笔记、翻脑图、翻上一卷的时间线，二十分钟过去，我已经忘了原本要改哪一句。
>
> 我打开 World View，不是想画南疆的海岸线。我是想**把时间轴拨到那一天，点一下这个角色，让工具直接告诉我：这句话是谎话，最少需要 11 天，除非你给他加一匹马或者把出发日提前**。然后我点一下跳到那个事件，把「三天前」改成「十二天前」，红字变绿，回去继续写。
>
> 带团的时候也一样。我准备让使节在 280 年出使，玩家需要一份能自洽的设定。我要的不是一张漂亮大陆图，是有人在我把国家建国年写成 300 年时，**当场举手说：那 280 年这位使节代表谁？**

### 1.2 一句话定义

**世界地图对创作者而言，不是一个「作画对象」，而是一块「盘问台」：在时间轴任意一刻、对任意地点或人物发起一次可信度盘问，当场拿到一条能直接用来改稿的结论。**

> 本文统一术语：**盘问** = 用户发起的一次「这合理吗」的提问；**校验结论** = 工具给出的红/绿判定 + 依据 + 可跳转的**冲突源**；**冲突源** = 引发该结论的那条事件 / 边 / 时间区间。不临时造词。

### 1.3 由这个定义推出的四条硬推论

1. **交付物是「一个判断」，不是「一份资产」。** 地形、等高线、街区、图钉都是资产；资产的价值在于它被谁消费。一张没人拿它算过「能不能三天到」的地图，对我等于零。
2. **空工程时这块台子必须是空的，但示例工程里它必须一开就有话说。** 校验只在「有内容且有矛盾」时才显形——这决定了它天生比像素难被看见，也决定了**必须有一个故意埋了矛盾的示例工程当门面**。
3. **结论必须可回跳、可改、可复验。** 只报「不合理」而不能一键定位到冲突源的校验，对我仍是负担。闭环是「盘问 → 定位 → 改一个值 → 复验转绿」，**30–60 秒内跑完**（依据：作者改稿时的注意力窗口，超过 1 分钟就会切回去凭记忆硬写，工具即被绕开）。
4. **结论必须出现在我正盯着的那两个画面（Browse / Map）上，且我得愿意点它。** 侧栏里一段灰字、要我先切面板再看，等于把「判断」和「改稿现场」分尸；而如果那两个画面本身粗糙到我不愿多看一眼，红标记再准也进不了我的视线。**这是「不好看」和「校验」真正的因果关系：不是二选一，是前者挡住了后者。**

### 1.4 反证：现有产物交付的是资产

`README.md:273-284` 阶段三 ✅ 的完成标志是「世界地图外框 + 地点标记、图层开关与顺序」，阶段五 ✅ 是「拖动滑块刷新视图」——**全部是「看得见」的完成标志，没有一条是「答得出」的完成标志**。近 25 条提交按标题归类，约 20 条落在晕渲色带、等高线、8× 缩放分档、街区生成、量测读数摆位、POI 图形；**0 条以校验 / 诊断的呈现与验收为主题**。

但必须补一句公平话：**这不代表校验没做**。`git log -S 'travel_feasibility'` → `d77f6fa wv-io: 事件间位移可行性提示（只提示不阻止）`（2026-10-12，距 HEAD 959 条）——这条 Hint 及其 5 条单测早就落地，只是**在此之后再无推进**。所以准确表述是：

> **能力早就算完了，但注意力全在表现层；而且算完的能力既没被摆到首屏，也没被文档标记完成。**

这不是做错了，是**做完了另一件事，且没给自己记上已经做完的那件**。

## 2. 「卡住」的性质诊断

### 2.1 结论（v3 精确化为三层病根）

**不是「功能不够」，也不是笼统的「没有终点」。三层病根，从上到下：**

| 层 | 病根 | 一句话 |
|---|---|---|
| ① 定义层 | **产品定义被三条裁定锁进「只编地形」，横跨边界的事没有 crate 认领** | 每一步推进都撞上「不归我管」——这是「不知道怎样推进」的直接原因（§2.5） |
| ② 呈现层 | **四段断裂：算得出 → 没锚点 → 没画面 → 没复验闭环** | 能力齐备，但没有任何一段把结论送到我眼前（§2.4） |
| ③ 验收层 | **走到了终点没插旗** | 代码完工了、关闭条件满足了，条目没关、首屏没摆、清单不减反增（§2.2 判据三） |

外加一条横切的**模式错配**（§2.6）：用户看的是 Browse / Map，表现投入落在 CellMap / Topographic——「继续加表现参数」与「用户觉得不好看」根本不矛盾，是**加错了模式 / 加错了层**。

公式：

> 三条裁定把边界钉死 → 谁都不认领「把诊断接出来」 → 能力停在侧栏 Hint、不进首屏 → 没有可验收场景 → 待办清单不减反增 → 只能拿「表现保真度」这种永远可以更精进的指标充当进度 → 每精进一层暴露新一层缺口 → 主观上「还差好多功能」 → 继续加功能，且加在用户不看的那个模式上。

### 2.2 三条判据（每条都能当场做，不靠感觉）

**判据一 · 删掉测试（验「方向偏了」）**
> 问：把整套地形渲染、缩放分档、街区、图钉删掉，只留地点标记和时间轴，`README.md` §1 的两句话能被回答吗？

能 → 方向没错；不能 → 方向偏了。
**实测：机制上「能」，体验上「不能」。** `detect_travel_feasibility_hints` 就是为第一句话写的（「预算时间不足：X→Y 需 ≥N 天，仅给 M 天」），`jump_to_anchor_now` 会把相机和时间轴拨到冲突现场。但**我第一次打开，看到的是一张地图，不是一个判断**：判断藏在侧栏 Hint 列表里，那条 Hint 连锚点都没有，示例工程也没为它埋矛盾。所以方向没错，呈现与验收错了。

**判据二 · 归因测试（验「功能不够」是不是错觉）**
> 问：让 §1 两句话可用，还缺哪些**可命名**的东西？

**实测：只缺四段断裂的接头，不缺系统**（逐项见 §2.4 / §2.8）。`shortest_journey`、`segment_days`、`effective_daily_speed`、`scale_hint`、结构化诊断骨架、位移判定、三跳转、面板可点、重算去重——**全在**。缺的是一个 `DiagAnchor`、一层首屏叠层、1 类诊断、1 个门面工程、1 次销账。**连「功能不够」都不成立。**

**判据三 · 净增测试（验「走到了终点没插旗」）**
> 问：待决问题数 / ADR 数收敛还是净增？每关闭一条，是少一条，还是生出下一条？

**实测：净增，且已找到机制。** §12 已累计 59 条（重号都在：`README.md:528-531` 自记「30–32 双双撞号」，`:519` 与 `:521` 又有两个「39.」），`docs/adr/` 已 105 份。`ADR-0105` 于 11-06 宣布「§12-55 五待裁点**全部关闭**」，同一批 `2f618e5` 立刻开「专家路线 #2」、`6c6ba8d` 补「补遗」、`cf0f93f` / `d46eff5` 继续扩缩放分档。

**最直接的一条证据是 §12-39 本身**：`README.md:521` 写着「（2026-10-17 裁定方向，**未实现**）……关闭条件：校验面板出现上述换算行，且天数 / 公里数值经手算期望值测试锚定」；而 `crates/wv-app/src/ui/validation_panel.rs:33-34, 40-71, 89-105, 197-209, 436-456` 的 `ref_vehicle` / `scale_hint_texts` 三行换算**已渲染并带单测「横穿行应含手算天数」**。**关闭条件满足了，条目却没关。**

> **「走到了终点没插旗」** —— 一条已完工的待办永久挂在清单上，本身就证明了：清单不是在记录工作，是在生产工作；而团队是在照着清单判断「还差什么」，于是永远判断成「还差好多」。

### 2.5 病根精确化之一：产品定义被锁进「只编地形」，横跨边界的事没有 crate 认领

这一条比「没有终点」准确得多，也是「不知道怎样推进」的直接原因。三条裁定把「世界地图」的产品定义物理化了：

| 裁定 | 原文 | 后果 |
|---|---|---|
| `ADR-0052:29-38`（§1.1 用户裁定） | 「**cell map 唯一目标就是编辑地形**」；「凡是与这条无关的能力（**势力、事件、标签、时间轴**），一律不进本 ADR」 | 「世界地图」在定位上被等同为一个地形工作台 |
| `ADR-0054:79` | 「**定位已锁死**——ADR-0052 §1.1 判据……crate 边界 = 定位的物理化：**依赖图替 review 者守门**」 | 定位不再是可讨论的产品判断，变成了**依赖图红线** |
| `ADR-0051:21, 26` | 「Browse 查阅+登记，Edit 关注势力/POI（**事件与区域因有时间性而隐藏**），**CellMap 只关注自然**」；「`EventDots=false`：事件有时间性，编辑态隐藏（用户裁定）」 | 事件在两个主要模式里被主动隐藏 |
| `GLOSSARY.md:404` | 「CellMap 工作区……**只编辑地形**（势力 / 事件 / 标签 / 时间轴不进本工作区）」 | 术语层固化，写进唯一权威源 |

于是「把已有诊断接出来」这件事的每一步都撞墙：
- 补诊断锚点 → 在 `wv-io`，但 `wv-io` 不管 UI；
- 画到画面 → 在 `wv-render`，但 `AGENTS.md §2.1` 的 `wv-render` 允许依赖表**没有 `wv-io`**（`crates/wv-render/Cargo.toml` 实读亦无），且「渲染层不做时间比较」；
- 面板与跳转 → 在 `wv-app`，但 `wv-app` 一直被当成「把 CellMap 工作台装进来的壳」；
- 事件在编辑态隐藏是**用户裁定**，谁都不敢动。

> **没有任何一个 crate 的产品定义里写着「我负责把一致性结论送到创作者眼前」。** 所以每一步推进都得到同一句回答：「不归我管」。这不是懒，也不是能力问题——**是三条裁定把边界钉死之后，一个横跨边界的任务在架构上失去了合法落点。** 这正解释了用户为什么说「不知道怎样推进」：不是没路，是每条路都通向别人的地界。

### 2.6 病根精确化之二：模式错配（用户新焦点）

用户原话：「**地图画面非常地不好看，但是我不知道怎样做，主要是 browse 和 map**」。

对照近 25 条提交：表现投入大量落在 **CellMap / Topographic**（晕渲色带、等高线、8× 缩放分档、街区生成、POI 图形、量测读数）。而制作人亲眼看帧确认，`docs/audit/2026-10-29/shot_browse2.png` / `shot_map.png` / `shot_cellmap.png` **三者共用同一套「纯饱和蓝海 + 硬边平涂色块」粗糙基底**——晕渲 / 等高线 / 纸纹**并未改善用户正在看的那两个模式**。

> **所以「继续加表现参数」与「用户觉得不好看」并不矛盾：是加错了模式 / 加错了层。** 在 CellMap 里把等高线做到第 8 档，对我每天盯着的 Browse / Map 一像素影响都没有。这也解释了为什么 25 条表现向提交之后，用户的评价仍是「非常地不好看」——**不是做得不够多，是做得不在场**。

### 2.7 一句最要紧的话

**「不知道怎样推进下去」不是因为没走到终点，是因为走到了终点没插旗、没把我叫过去看，然后继续在用户不看的那个模式上修路——所以每一步都既像进展、又像没动。**

**代价判断因此反转**：路线 A 从「保守」变成「**把已完成的校验接出来**」——几乎零新建基建；路线 B / C 的相对代价上升（等于放弃已到手的兑现）；「推倒重来」类路线不再有成本优势，因为没有东西需要推倒。tech-architect 亦确认：这条链完全不经过 `wv-world-cell-map` / `wv-render` 的地形管线，**冻结现有地形投入的反悔成本近零**。

## 3. 三条互斥的推进路线

**互斥性**：三条把「世界地图做完了」分别定义为 **① 给出结论并销账 / ② 导出一张图 / ③ 无损往返一个工程**。三者的首屏场景、冻结项、验收物互不重叠，只能选一条当主线，不能并行。

> ⚠ **「视觉重做」不是第四条路线**：本稿放行的一次视觉重做（见路线 A「明确不做什么」第 2 条）面向 `Browse / Map`、由可勾选验收点收口，它是让首屏结论「看得见、愿意被点」的**前置条件**；它与路线 B「以导出一张成品图为完成定义、并把校验正式推迟」不是同一件事。**互斥性由「完成的定义」决定，不由「这轮改不改画面」决定。**

| | 路线 A【推荐】 | 路线 B | 路线 C |
|---|---|---|---|
| 完成的定义 | 首屏地图上有红标记，改一个值转绿，且清单销账 | 导出一张能直接用的成品地图 | 两个工程开→改→存→重开完全一致 |
| 主线对象 | 校验结论的**呈现与验收** | 地形 / 地图表现 | 编辑器内核 |
| 首个可验收场景 | 30–60 秒「点标记 → 改值 → 转绿」 | 一张出图 | 一次无损往返 |
| 需新建基建 | **几乎为零**（补 1 处 anchor + 1 类诊断 + egui 叠层 + 示例工程） | 中（导出） | 大（快照 / 迁移 / 多根图） |
| 对 §1 承诺 | 直接兑现并宣布完成 | 正式推迟 / 放弃 | 继续后推 |
| 天然终点 | 有（红/绿是布尔值 + 关闭动作） | 弱（「好看」无上界） | 弱（内核稳定无上界） |

### 路线 A【推荐】· 世界地图 = 一致性盘问台（Verdict-first）

|---|---|---|---|
| **(A) 推荐** | 红标记由 **`wv-app` 的 egui 叠层**呈现：把 `anchor.at` 的真实坐标经新增的 `world_to_screen` 换算成屏幕坐标叠一层浮层；诊断数据**不进 `wv-render`** | **零新增依赖、零新 ADR**（但非零代码，见 §2.8） | ✅ **本稿选 A** |

### 路线 C · 世界地图 = 设定条的图层化画布（Editor-first，回到 P5/P6）

**一句话主张**：世界地图不是「世界」，只是「任意层级地图的一个实例」；真正该做的是把多地图层级 + 图层 + 非破坏编辑 + 撤销做成稳定、可迁移、可开多个工程的通用编辑器内核，世界地图只是第一份示例数据。

**首个可验收场景**：打开 → 新建第二张图（城市图 / 地城图）→ 图层开关与顺序、撤销重做、存盘 → 关闭重开，**两个工程内容逐字段完全一致**即完成。

**明确不做什么**：不做地形表现精修；不做校验；不做时间轴驱动视图；不追求视觉；不新增任何表现类 ADR。

**主要代价**
- 最「工程正确」，但第一次打开**没有任何一个与我稿子有关的答案**——对创作者是最难感知价值的一条，主观卡顿不会缓解。
- 「内核稳定」同样没有天然终点：快照、Schema 迁移、多根图导航正是 §9 阶段七 🟡 与 §12-41 那一批，极易变成又一轮 ADR 累积。**它把「卡住」从地图转移到了内核，没有解决它。**
- 在机制层已近乎完备的前提下，把资源转向内核是三条里对 §1 承诺推得最远的一条。

**推翻了什么 / 换来了什么**：推翻 ADR-0054 里「世界级」的特权，把世界图降格为普通一档地图；换来架构一致性与长期可维护性，代价是**继续把用户要的那个答案往后推**。

## 4. 专项回答：§1「互相校验」为什么至今没成为主线

### 4.1 五个结构性原因（不是疏忽，是机制）

**① 它最难被看见，而地形最容易被看见。**
校验的输出是「一个判断」，只在「已有内容且有矛盾」时显形；空工程里它是空白，`README` §12-54 自己就记着「示例工程入口缺失」。相反，等高线、晕渲、缩放分档在**任何空地图上立刻有像素反馈**。每一轮迭代里，「这周能看见进展」的那条会自然胜出。**表现吞掉验证，是激励结构，不是能力问题。**

**② §1 是营销主线，§9 是工程主线，两者从一开始就分叉了。**
`README.md:30-35` 把最痛的承诺放在第 1 节，却在 `:286-290` 把兑现它的工作排到**阶段六 ⬜ 待启动**，前面五个阶段全部以「可见的渲染/编辑成果」为完成标志。**写文档的人把承诺写在了开头，把兑现写在了最后；而代码其实在 2026-10-12 就把第一格做了，文档至今没认。**

**③ 每次想碰校验，都会先撞上一个更具体、更容易闭环的前置裁定。**
`README` §2 把「距离维度」定成「不存结论，只存参数」，参数的前提又牵着 §12-53 / §12-58 / §12-55。团队每次向校验伸手，先撞上「得先裁比例尺 / 先裁格网粒度」，于是转头去裁那个能当天关掉的表现问题。`git log` 标本：`0d9ae04` 宣布「§12-55 五待裁点关闭」，同一批 `2f618e5` 就开出「专家路线 #2」、`6c6ba8d` 补「补遗」、`d46eff5` 继续扩缩放分档。

**④（v3 改正）不是「词被提前花掉」，是「算出来了，但没有出口」。**
v1 说「现有校验检的是悬空引用」、附录说「全仓无位移校验实现」——**两处均不成立，本稿撤回**。实情是：`diagnostics.rs` 远不止悬空引用，`detect_travel_feasibility_hints`（`d77f6fa`，2026-10-12）**就是 §1 第一句的判定逻辑**，含 5 条单测，并已由 `derive_hints` → `diagnostics_bridge.rs:102` → `state::ProjectDiagnostics` → `validation_panel::panel_validation` 在 GUI 侧栏可视化。
**断点不在计算，在出口**：这条 Hint 由 `hint()` 构造、`:553 anchor: None`，`diagnostics_bridge.rs:102` 也没补——**它算出来了，却点不动、上不了首屏、没有锚点、没有复验闭环**（四段断裂见 §2.4）。加上 `README.md:521` §12-39 关闭条件已满足却未关，`README.md:286-290` 阶段六仍全 ⬜——**文档状态滞后于代码**。于是每次有人翻清单，看到的都是「校验还没做」；每次有人问「下一步做什么」，答案自然又回到还能看见进展的地形上。

**⑤（v3 新增，最根本）三条裁定把边界钉死，横跨边界的事没有 crate 认领。**
见 §2.5。`ADR-0052` 用户裁定「cell map 唯一目标就是编辑地形」→ `ADR-0054:79`「定位已锁死……crate 边界 = 定位的物理化」→ `ADR-0051` / `GLOSSARY.md:404` 把事件与人物排除在工作区外。结果：**「把已有诊断接出来」这件事在架构上没有合法落点**，每一步都撞上「不归我管」。这才是「不知道怎样推进」的直接原因——不是没路，是每条路都通向别人的地界。

### 4.2 地形绘制是在服务这个承诺，还是在替代它？

**结论：早期是服务；从地形表现成为独立迭代目标起（ADR-0077 / 0101 一线），已经变成替代。且可判，不靠感觉。**

| 判据 | 「服务」应看到 | 实测 | 结论 |
|---|---|---|---|
| **消费关系** | 高程 / 湖面 / 海岸 / 等高线 / 缩放档位的产出，被「两地通行耗时 / 换乘 / 可达性」计算引用 | `ADR-0101/0102/0103/0105`、`d46eff5`、`61f1a83` 落点全在 `wv-render` / `wv-default-theme` / `wv-terrain` 表现层；**没有一条输出接到边权或 `shortest_journey`** | ❌ 无消费关系 |
| **资源流向** | 地形与验证同步推进 | 近 25 条约 20 条表现向、0 条诊断呈现/验收向；`d77f6fa`（2026-10-12）落地 Hint 级侧栏诊断后**再无推进** | ❌ 做完即停摆 |
| **加错了模式** | 表现投入落在用户日常看的 `Browse / Map` | 投入大量落在 CellMap / Topographic；10-29 实拍三张共用同一套「纯饱和蓝海 + 硬边平涂色块」基底，晕渲 / 等高线 / 纸纹**未改善用户正在看的两个模式**（§2.6） | ❌ 加错模式 / 加错层 |
| **依赖必要性** | 兑现承诺必须先有更精细地形 | 时序矛盾（280 < 300）是**纯时间比较，零地形依赖**；位移矛盾需要「距离参数 + 交通边」，**不是「地形长什么样」**；`shortest_journey` 与 `detect_travel_feasibility_hints` 均已存在 | ❌ 不构成前置 |

**最刺眼的一条**：`README.md` §1 举的两个例子，**没有一个需要等高线**。最便宜、最早该兑现的那半个承诺（时序先后）不依赖任何地形工作；另一半（位移）**也已经在代码里算出来了**。地形却继续做了五个 ADR，而且加在用户不看的模式上。这不是「顺路打基础」，是**把通往承诺的路修到了别的方向，而且没回头看一眼已经修好的那截**。

另一个佐证：`ADR-0099《设计文档直通世界地图》`——连「把设定文档变成地图」这条最该接住人物/事件/因果的管线，落点也是「HTTP 工具面暴露既有**地形 / 势力**命令」。**连入口都在往地形上靠。**

### 4.3 替代的机制，一句话

> **可验收的像素，挤掉了已完工却未验收的结论；而那些像素大多还加在了用户不看的那个模式上。**
> 地形最初是「让地点有地方可放」的必要底座（服务）；一旦「让地形更好看 / 更可缩放 / 更可局部加密」成为完成标志与待裁点来源，它就自己生产完成感——**真正该被宣布完工的那条结论，因为既不上镜、也没人销账、更没人认领，被永久记成欠账。**

## 5. 停止条件（世界地图这条线何时收口）

### 5.1 主条件（一句话，可当场判真假）

> **`README.md` §1 的两句原话，在默认示例工程里以「`Browse / Map` 首屏上的红标记」自动现形 → 我点一下，相机 / 层级 / 时间轴三跳转定位到冲突源 → 改一个值 → 重算后标记转绿；这条 30–60 秒闭环跑通、写成回归用例、且清单上对应的待办被勾掉并宣布完工之后，世界地图这条线即告收口。**

> ⚠ **「代码跑通」不算收口**。收口 = **代码完工 + 首屏可见 + 文档/清单宣布完工**，三者缺一不可。§12-39 就是反例：代码完工了、面板也可见了，唯独没销账，于是它至今仍是一条待办。**走到了终点没插旗，等于没到。**

### 5.2 三条可勾选硬指标（缺一条就不算收口）

| # | 指标 | 判据 |
|---|---|---|
| 1 | **有答案，且长在 Browse / Map 首屏** | 默认示例工程在第 300 年打开，**画面上**出现 2 个由数据自动生成的冲突标记（非写死文案），覆盖 §1 两类矛盾：时序（280 使节 / 300 建国）与位移（3 日北境 → 南疆）；均为 Hint 级、不阻止保存；侧栏同步有「提示 2」计数 |
| 2 | **能改稿** | 点标记触发既有 `jump_to_anchor_now` 三跳转（钻到 `anchor.map` / 相机到 `anchor.at` / 时间轴到 `anchor.day`）并选中冲突源；改一个年份或一条边后，1 次重算内该 `fingerprint` 的提示与首屏标记一起消失。**回归用例只锁「红→绿 + 三跳转」，不锁新计算、不锁像素** |
| 3 | **净减，且销账** | 收口当次：§9 阶段六四项勾 ✅、§12-39 改「已实现」、§12-54 关闭；§12 待决项数与 ADR 数**不再净增**。此后每新增一条待裁点，必须同时关闭一条。做不到即说明尚未收口 |

**视觉重做的收口口径**：它不单独设终点，由 `art-model-director` 的 `docs/reviews/2026-11-11-worldmap-visual-direction.md` 中**可勾选验收点**定义；验收点全部勾掉即完成，**不得**以「更好看」「再调一版」延续。它服务于指标 1，不占用本线的终点定义。

### 5.3 收口后的冻结规则

- 不再新增以「表现保真度 / 缩放档位 / 局部加密 / 比例尺假设 / 图标对比度 / 方格平涂 / 导出排版」为题的待决项。
- 现存 §12 待裁项一律改标「**冻结 · 非本线**」，不是「待裁」——**冻结也是一种裁定**，比悬着便宜得多。
- 后续新增 ADR 只允许因「**校验结论算错了**」而开，不允许因「看起来不够好」而开。
- 快照 / Schema 迁移（§9 阶段七 🟡）**不并入本线收口**，单独立项，不占用世界地图的终点定义。
- **建立一条硬规矩：凡代码满足了某待决项的「关闭条件」，当次迭代必须同步关闭该条目。** 这条规矩直接针对 §12-39 这类「完工不销账」，是防止净增复发的最低限度机制。
- **依赖红线不动**：`AGENTS.md §2.1` 全表、`ADR-0054 D2/D4` 在收口前后均不因本线而改。

### 5.4 为什么这条能止住无限追加

因为它把「完成」的定义从「**图还可以更好**」（无上界，必然自产待裁点）换成「**这两句谎话被抓住了 + 清单上那几行被勾掉了**」（有真假、有动作）。**只有带真假的指标、加上一个必须执行的销账动作，才会停。**

### 5.5 收口后的守护口径（我的后续职责）

用户拍板选定路线后，该路线的「完成的定义」即成为阶段 1 确认过的玩法意图。此后阶段 2 灰盒 / 阶段 3 资产 / 阶段 4 完整实现的每一步出稿，我按「**这一步有没有让『盘问 → 定位 → 改稿 → 复验 → 销账』更近**」出「符合 / 偏离」结论；偏离即退回对应步骤，不带进下一步。判据不随迭代解释而放宽——**我在 `Browse / Map` 首屏看不到那两个红标记，就是没传达到，不是我打开方式不对。**
