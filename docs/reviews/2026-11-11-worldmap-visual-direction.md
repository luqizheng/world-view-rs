> **日间古舆图（Daylight Antique Chart）**：World View 地图画布的**唯一默认画面语言** = `docs/ART_STYLE_SPEC_v0.1.md` §1.4.4 的 28 枚低饱和纸基令牌 + §3.3 地貌笔触 + §3.4 的 11 类同一描线家族地物符号 + §3.6 程序化绘制；`Browse` / `Map` / `CellMap` 三模式共用，差异仅允许在 `MODE_TABLE` 内容层与信息密度；`docs/codex-assets/ref-map.jpg` 为其可视验收样本。

### 1.4 明确回答：「不好看」有多少是「规格没接进 Browse/Map」，多少是「规格本身定错了」？

按**改动项归因**（不是按主观感受打分）：

| 归因 | 占比 | 依据 |
|---|---|---|
| **规格没接进 Browse / Map（接线）** | **≈ 8 成** | §1.4.4 的 28 令牌、§3.3 笔触、§3.4 的 11 类符号、§3.6 程序化绘制、§四 LOCKED SHELL、ADR-0048 的水面纸纹 / 离岸墨线、`SeaRecipe::foam`、`decor.rs::WATERCOLOR`、`assets/symbols/` 七类 32/64/96 贴图——**全部已写完并落盘**，只是没接进默认路径或被 ADR-0066 关掉（`decor.rs::PROFESSIONAL` 把山 / 林符号设为 `SymbolStyle::None`；`recipe.rs::MODE_TABLE` 把 `Grain` / `MapFrame` 置 `false`；`sea.rs` 的 S3 字段已定义未接） |
| **「哪一套是默认」定错 / 只推翻一半（重定选择器）** | **≈ 2 成** | 两件事：① 把默认档从 §1.4.5 切回 §1.4.4（改选择器 + 同步 `:152` 锚点测试）；② 给规格书一个「唯一现行参考系」判据（`:117` / `:147` / `:149` 三处自称矛盾、`:14` 未回写 `:12`）。**两件都不产出新色值、新符号、新尺寸、新规格** |
| **规格本身定错（要重写规格）** | **0 成** | 没有任何一条色值、符号画法、尺寸档位、对比度阈值需要重新设计；§1.4.4 / §3.3 / §3.4 / §3.6 / §四 全部可直接使用 |

> **结论：这稿是「修订」，不是「补丁」**——因为它要动默认档的选择器与唯一名称，属裁定层变更；但**施工量 8 成是接线**，既不是补丁式继续加细节，也不是重定式重写规格。
> **主程序的动作 = 接线 + 一次选择器修订；用户 / 制作人的动作 = 一次拍板：默认档选哪套。** 这是「接线还是重定」的直接答案。

## 2. 画面诊断：六条可命名的缺陷（按严重度排序）

三类分法：**【基底/配色】** D2、D3；**【符号与信息密度】** D5；**【构图与 UI 壳】** D4、D6。**D1 是统摄三类的根因，单列并排在第 1 位（§1 已核实）。** 序号即全局严重度顺序。

| 序 | 类别 | 看到什么（帧证据 / 文件证据） | 违反了哪条视觉原则 | 为什么它让整张图显廉价 |
|---|---|---|---|---|
| **D1** | 参考系（统摄三类） | 10-29 三帧是硬边平涂 + 纯饱和蓝海：既无 `:14` 承诺的 Google 式路网分级 / POI 分类 / 注记层级，也无 §1.1 / §3.3 / §3.4 的手绘符号 / 纸感 / 笔触；只有 §1.4.5 的十色接了线。文档侧：`:14` 覆写 `:12` 未回写、`:117`/`:147`/`:149` 三处「现行值 / 历史记录」自称矛盾、ADR-0008 已废仍挂在开头、`ref-map.jpg` 从未被登记（逐条证据见 §1.1） | `ART_STYLE_SPEC_v0.1.md` §1.1 `:34`「每个维度都必须能落到规格，**不接受『有质感』这类表述**」；ADR-0016「默认观感唯一」；§2 单一 Theme Pack 契约 | **不是「配色不好」，是没有一张图知道自己该长什么样。** 两种定位各做一半，剩下的由渲染默认值填 → 读起来就是「不伦不类」。D2 / D3 / D5 全是它的下游症状：没有唯一判据，就没人能判定哪些令牌该生效、哪些规格该接线 |
| **D2** | 基底/配色 | 海是纯饱和蓝、陆是橄榄绿 / 土黄 / 棕的硬边平涂；**但**唯一的地名「东问城」是白描边无衬线字、POI 是砖赭点 + 纸白环、覆盖带是墨棕——后面这一组全是低饱和古舆图墨色令牌。§1.4.4（`:117–147`）与 §1.4.5（`:149–167`）**在同一帧同时生效** | 「一个 Theme Pack = 一套色板契约」（§1.4 / §2.B.1）。ADR-0035 只取代「日间地形十色 + 淡化强度」（`:151`），§1.4.4 其余槽位「沿用现行值」（`:145`），两套令牌被拼在一起 | 饱和地形读作「还没上色的矢量草图」，低饱和墨线与标签读作「从另一张图贴过来的」；两层的明度、纯度、线宽完全不咬合。**加任何细节都救不回契约分裂**——眼睛第一眼读到的不是「粗糙」，是「拼的」 |
| **D3** | 基底/配色 | 海面零纸纤维、零晕染、零离岸波纹、零白浪花；陆地色块边界是 1px 硬切，无软边无水彩过渡。对照 ref-map 的「岸线墨 → 白浪花 → 离岸波纹」三层水岸与手绘山 / 树 / 城笔触 | §1.6 材质语言、§3.3 地貌笔触（`:333`「让地图看起来是画的，不是看起来是格子拼的」）、ADR-0016 五条渲染规则。ADR-0048 已完成的水面纸纹 + 离岸墨线在这三帧里读不出来 | 大面积纯色平涂是「渲染默认值」的视觉签名。没有材质，就没有「这张图是被画出来的」证据；读者判定为「程序还没画完」，而不是「风格如此」 |
| **D4** | 构图与 UI 壳 | 地图是一个被笔直切断的矩形贴片，只占窗口中间约 60% 宽的竖幅，左右各约 20% 是空白米色；空白与图内蓝海之间无图廓、无纸边、无过渡 | 构图完整性；§4.6「画布为唯一弹性区」——留白应是**设计过的纸边**，不是未填满的窗口；参考图有完整画幅与收边 | 矩形贴片 + 硬切断 = 网页里嵌了一张图。留白没有被设计成「纸」，就只能被读成「没铺满」。这是第一眼**面积最大**的廉价来源 |
| **D5** | 符号与信息密度 | 全图仅 1 个地名；其余是十几个白色噪点状小斑点，无轮廓、无家族、大小随机；§3.4 `:353` 要求的 11 类符号（城 / 镇 / 村 / 关口 / 港口 / 桥 / 渡口 / 矿 / 神社·寺 / 战场遗迹 / 驿站）一类未见，无海域标签 / 罗盘 / 比例尺 / 图例。另有一条上下贯穿两陆、边缘绝对笔直的棕带与右陆一块精确等腰三角扇区，边界裸切无抖动无墨线 | §3.4 `:344–354`（地物是图标不是模型、尺寸档 32/64/96、同一描线宽 / 同一右下投影 / 同一底座留白）、§3.2.2 `:314–320`（1 秒可读）、§3.3 `:337`（海岸线允许 ±2px 抖动、不得跨格）、§3.6 `:370–383`（程序化绘制）。且 `decor.rs::PROFESSIONAL`（ADR-0066）把 `mountain_style / forest_style` 设为 `SymbolStyle::None`——**手绘符号是被主动关掉的**，而 `WATERCOLOR` 配方与 `assets/symbols/` 七类贴图（恰好 32/64/96 三档，与 §3.4 `:350` 完全对上）明明在位 | 低密度让大片纯色无处藏，空白被读成「没做」；白噪点在饱和底上既不可辨也不成族，读起来像渲染瑕疵而非符号；绝对直线与正三角是「矢量工具原样输出」的指纹，把可信度拉回 CAD 草稿。**这是「关掉了现成资产 + 没接 §3.3/§3.4」，不是「缺资产」** |

> **六条里没有一条是「细节不够」。** D2 / D3 / D5 都不是缺资产，而是既有规格与资产被关掉、或被两套契约打架抵消。这正是「不知道怎样做」的技术成因：问题不在「还差多少笔」，在「没有判定哪一版算对」（§1 第 1 号裁定）。

## 3. 参考系的可视样本与备选（先给推荐项及理由）

> 本节只回答「要不要往 `ref-map.jpg` 这个**画面**走」；「唯一参考系是谁」已在 §1 裁定，不在此重复。

### 3.1 推荐项

> **要往 `ref-map.jpg` 的方向走——准确说法是「恢复 §1.4.4 / ADR-0016 的可视表达」，不是引入新参考系，也不是新登记第五套。`ref-map.jpg` 是这套话的可视验收样本。**

**理由（按权重）**：

1. **用户自己已经选过一次。** ADR-0016（Accepted，2026-10-14 四问裁定）：默认观感 = 泛黄宣纸底 `#F2EAD8`、褐墨线条、灰蓝水、灰橄榄绿，用户原话「**优先用这套**」，并附五条渲染规则。ref-map.jpg 正是这五条的可视化。**采纳它不要求用户做一次新的审美选择，只要求承认一次已有裁定被局部推翻了。**
2. **推翻它的那一步是局部的，且只推翻了一半。** ADR-0035 / §1.4.5 `:151` 只取代「日间地形十色 + 淡化强度（0.35→0.85）」；§1.4.4 `:145` 明写其余槽位「沿用现行值」。结果就是 D2：一张画上跑着两套互斥令牌。**这不是审美分歧，是契约分裂。**
3. **资产几乎全在位，且「接回」不算新增表现工作**（逐项锚点见 §5.1）：§1.4.4 的 28 令牌、§3.4 的 11 类符号体系、§3.6 程序化绘制、`decor.rs::WATERCOLOR`、`assets/symbols/` 七类贴图、21 枚 POI SVG、指南针贴图、`SeaRecipe`（含 `foam`）、`paper_overlay.wgsl`、CJK 字体全部落盘。**与创意总监「冻结一切新增地形表现」、架构总监「不需要继续投入地形渲染」不冲突——本稿主张的是切换已有配方，不是新增。**
4. **与产品定位同向。** README §1 面向网文作者 / TRPG 主持人 / 世界观创作者：他们要的是一张能当设定集摊开的图，不是制图软件的输出。ref-map 的「手作 artifact」质感正是这个身份。

**不照抄的部分（明确边界）**：不照抄 ref-map 的具体画面、地名与地标（§1.2 `:43` 明定「参考方向只取画派，不给具体作品」）。只取 5 个可施工的装置：① 统一暖纸基底 ② 低饱和水彩海 + 三层水岸 ③ 同一描线家族的手绘地形符号 ④ 衬线字 + 字距 + 3 档标签层级 ⑤ 图廓 / 罗盘 / 比例尺收边。**不引入新图片 / 字体 / 音频文件**（继续零外部资源 + 程序化绘制，§3.6）。

**代价（必须说清）**：需要用户**重新裁定 ADR-0035 / §1.4.5 的中高饱和日间十色**（降为可选变体常量，不删），并回收 `soften.keep = 0.85`，同步 `:152` 锚点测试。这是一次明确、一次性的拍板动作，**不是新的待裁项**。§1.4.4 中标注「推导·待复核」的色值仍需实机校准，但那是既有账，不新增条目。

### 3.2 若用户拒绝恢复（明确表示中高饱和是他要的）

备选参考系 = `preview/professional_map_preview.html` 的「专业制图极简」，`colors_google.rs` 色值已在位（`#F4F5F6` 近白陆 / `#AADAFF` 淡水 / `#C9E7C7` 绿地 / `#3C4043` 墨字），与 `Map → ViewMode::GoogleMap` 的语义一致。**但不推荐**：① ADR-0008 的近白 Google 风已被 ADR-0016 显式取代过一次；② 该预览稿自己写明「道路分级 / 绿地平滑是当前引擎**尚缺**的两项」——真要做到反而要新增表现工作，与「冻结」冲突；③ 它解决不了 D2（两套令牌）与 D4（竖幅贴片）。

## 4. 三条互斥的视觉方向

**互斥性**：三条把「画面做完了」分别定义为 **① 三 tab 同纸（色彩契约统一） / ② 导出一张可贴进设定文档的制图成品 / ③ 首屏符号密度达标**。三个终点不可同时作为收口条件，只能选一条当主线。推荐项放第一条。

### 方向 A【推荐】· 归位：把已有古舆图令牌接回默认路径

- **一句话主张**：不画新东西，只把 §1.4.4 / ADR-0016 已接受、但被 ADR-0035 / ADR-0066 局部推翻的低饱和纸基色板、水彩海要件与手绘符号，接回 `Browse` / `Map` 的默认取色路径。
- **完成的定义**：三个 tab 的首帧看起来像**同一张纸画的**，且 §5 清单 8 项勾完、§7 的 V1/V2/V3 全真。
- **首屏目标态（具体描述）**：打开示例工程，首帧是暖纸底 `#F2EAD8` 一族；海为灰蓝 `#8FA2B3` / `#98A9B9` 水彩晕染，岸线有 1px 褐墨 + 一道**断续**白浪花 + ≥2 道离岸墨线；陆为灰橄榄 `#A8B898` / 暖沙 `#E3D5BC` 的软边分区，山 / 林 / 城用 §3.4 同一描线家族的小符号铺开；地名用深褐墨 `#4A3F35` 衬线 + 字距，按城 / 区 / 海域排 3 档；画布四边收进细褐墨图廓，罗盘与比例尺各一；左右空白变成**纸边**而非窗口底色；UI 壳保持浅色但顶栏 / 浮窗底色与 `soften.toward` 对齐。三个 tab 只有「画了哪些信息层」不同，颜色 / 线 / 字完全一致。
- **明确不做什么**：不新增任何表现类功能 / ADR / 待裁项；不做等高线、晕渲、LOD 分档、图内 AMR、街区、局部加密、量测读数改版；不改 `terrain.bin`、不动 `CellPalette` 固定色禁令；不生成新图片 / 字体；不重画演示数据里的笔直棕带与三角扇区（只把它们的**画法**改成 §3.3 / §3.4 同一描线 / 软边家族）；**不做画布内的诊断 / 校验标注、不采用架构稿 R1 的 (B) 路径、不新开 ADR**（见 §6.3）。
- **主要代价**：需用户重新裁定 ADR-0035 / §1.4.5 十色（一次拍板）；§1.4.4 的「推导·待复核」色值仍需实机校准（既有账，不新增条目）。

### 方向 B · 极简制图：以「可导出的成品图」为完成态

- **一句话主张**：承认高饱和地形不合适，但也不回到手绘；把 `colors_google.rs` + `professional_map_preview.html` 的近白底 / 分级道路 / POI 分类 / 白描边注记做成唯一画面语言。
- **完成的定义**：`Map` 模式能导出一张信息层级正确、可直接贴进设定文档的成品图。验收物是**一张出图**，不是「三 tab 同纸」。
- **首屏目标态**：近白 `#F4F5F6` 陆 + 淡水 `#AADAFF` 海、分级道路、绿地平滑边缘、白描边深灰字注记、无罗盘无图廓无手绘符号；Browse / Map / CellMap 全部按制图规范排布。
- **明确不做什么**：不做纸纹 / 水彩 / 罗盘 / 衬线字 / 手绘符号；不做 JRPG 资产；不追「地图能出版」。
- **主要代价**：放弃 ADR-0016 / §1.4.4 与项目「古舆图」身份，需再开一次方向 ADR；且预览稿自承「道路分级 / 绿地平滑是引擎尚缺的两项」→ 真做到是**新增表现工作**，与本轮「冻结」相冲。

### 方向 C · 只补信息层：不动配色，靠符号与密度把画面填满

- **一句话主张**：保留 ADR-0035 中高饱和色板，只把 §3.4 的 11 类符号体系、衬线标签、海域标签、罗盘 / 比例尺铺上去，用密度盖住平涂。
- **完成的定义**：首屏可见符号数与标签数达到阈值（配色原样）。
- **首屏目标态**：同样纯蓝海 + 橄榄绿陆，但每 100×100 px 有可辨山 / 林 / 城符号，地名 3 档层级，海域名弧排，图廓收边。
- **明确不做什么**：不调任何色值、不接纸纹 / 水彩、不改 UI 壳、不做新主题包。
- **主要代价 / 否决依据**：**不解决 D1（无唯一判据）、D2（两套色板契约分裂）与 D3（零材质）**。符号资产虽已在位（不是新增资产），但把低饱和墨绿手绘符号铺到高饱和草绿平涂底上，等于往同一帧再塞第二套契约，会**放大**拼贴感；且 D4 的竖幅贴片原样保留。列出这条，是为了让「只加图标」这个最容易被顺手选中的方案有一条明确的否决依据。

## 6. 明确回答（附：上游「模式错配」核实）

### 6.0 先核实：是否存在「投入落在 CellMap/Topographic，用户看的是 Browse/Map」的模式错配？

**判定：方向成立，但描述需修正。不是「CellMap 好看、Browse/Map 难看」，而是「投入落在 GPU 场管线的非默认分支，三个 tab 的主画布都没吃到」。**

### 6.1 (a) 三个模式该共用一套画面语言还是分开？

> **共用一套画面语言。** 差异只允许体现在「画哪些信息层」，不允许体现在「用什么颜色 / 线 / 字画」。

**理由**：① 三帧底图本就同构（ADR-0066 单一默认风格），用户是把它们当成「同一张图」在抱怨；分开会得到三张不像同一个软件的图。② `ART_STYLE_SPEC_v0.1.md` §〇 `:12` 已定分层：壳（LOCKED）与地图（Theme Pack）只有「色板令牌 + 位图契约」两个接头，三个 tab 属于**同一壳 + 同一 ThemePack**，必须同源。③ 一人开发优先复用，三套视觉等于三倍资产与三倍回归。

**允许差异，仅三处**：

1. **`MODE_TABLE` 的内容层**（ADR-0051 已定）：Browse 查阅 + 登记、Map 专业制图、CellMap 只关注自然；事件与区域因时间性而隐藏（`EventDots = false` 在编辑态）。差异是「画哪些层」，不是「怎么画」。
2. **信息密度档位**：同一符号系统的显示数量与 LOD 分档（复用 `zoom_level.rs`），不是符号造型。
3. **CellMap 的固定色数据视图**（ADR-0054 / ADR-0100）：唯一允许的颜色例外，且必须框在「编辑工作区」语义内，靠 tab 高亮给明确的进出反馈。

**明确不允许差异的**：纸基底色、海 / 陆色板、墨线色与线宽、字体与字距、POI 与地物符号造型、装饰件、UI 壳明暗基调。

> **口径澄清（避免被读成「统一色源」）**：「共用画面语言」指**同一套色板令牌 / 线宽 / 字体 / 符号造型在 Browse 与 Map 生效**，**不指三个 tab 从同一个色源取色**。CellMap 的 `CellPalette` 固定色数据视图（上列差异 3）原样保留、不接主题色板、不依赖任何 theme crate——这是 ADR-0054 的 crate 级硬约束，本稿**不动、不推翻、不新开 ADR**（逐项核对见 §5.2）。

### 6.2 (b) 这次视觉重做是否需要动地形数据模型 / `terrain.bin` / `wv-world-cell-map` 的固定色禁令？

> **都不需要。固定色禁令必须原样保留。** 证据：

1. 全部 8 项改动都是**颜色 / 配方 / 绘制指令**，落在 `wv-default-theme`（`colors.rs`、`sea.rs`、`decor.rs`）与 `wv-render` 的取色 / overlay 层——正是 ADR-0043「ThemePack 契约」与 ADR-0048「海的数值配方全进主题层」已划定的领地，不越界。
2. **ADR-0054 D4 明写**：`CellPalette` 是平面数据，`ThemePack → CellPalette` 换算在 **wv-render 侧**；GPU 场 uniform 吃平面色值，来源分「CellMap 冻结表」与「wv-render 主题换算」两支。→ 改主题色不必改 `wv-world-cell-map`，Browse / Map 走的正是「wv-render 主题换算」那一支，**天然合规**。
3. `terrain.bin` v2 存的是每格 `(height, surface, biome)` 域事实（README §12-55 / §12-47）。换配色不改任何格值，不触碰 `TerrainData` / `TerrainGrid` / 编辑命令族 / 256² 分块指纹。
4. **固定色禁令是「数据视图」语义**（逐格真色直出，ADR-0054 / 0100），Browse / Map 是「主题视图」。两者取色来源不同、互不侵犯——这恰恰是 6.1「共用语言但允许一处颜色例外」的技术依据，**动了它才会出事**。
5. README §12-59 已裁「CPU 回退路径不跟进 CellFlat」、`ShadeMode::Topographic` 为纸面占位：说明改动面不涉及任何存储格式升级。
6. `crates/wv-world-cell-map/src/terrain_view/field/material.rs:25–36`（架构总监实读）：三模式走 `Themed` 取色分支，原文「**分叉只发生在取色一步**」→ 本次改动全部落在「取色」这一层，地形数据零参与。
7. `crates/wv-world-cell-map/src/shading.rs:170`（架构总监实读）：原文「首版标定值，实机验收后可调（**改这里 = 改 Browse/Map 的海色**）」→ 海色有既有入口，不必新建取色路径，也不必碰 `TerrainData.cells` 的 `height / surface / biome`。

### 6.3 (c) 推荐方向是否需要「画布内的诊断 / 校验标注」？

- **规格依据**：`docs/ART_STYLE_SPEC_v0.1.md` §3.5 `:366` 明写「事件点 / 故事便签属**壳**（锁定），见 §4.6；**不进 pack** —— 因为它们是『工具的标记』，不是『世界的景物』」，`:368` 钉死「**世界的景物归 pack，工具的标记归壳**」。校验结论是典型的「工具的标记」。

#### 6.3.1 egui 叠层的视觉归属（与创意总监 v3 方案 A 对齐）

创意总监 v3 路线 A 选**方案 A**：首屏红色冲突标记由 `wv-app` 的 **egui 叠层**承载，诊断数据不进 `wv-render`；**标记位置由数据侧决定**（施工前提见下）。按制作人裁定的分工：

| 归谁 | 内容 |
|---|---|
| **本稿（美术总监）** | 叠层的**形状 / 颜色 / 气泡样式 / 控件状态视觉**，让它与世界地图共用同一套画面语言 |
| 创意总监 / 主程序 | 标记从哪来、**落在哪**、点它跳哪、数据链路与交互逻辑（含 `DiagAnchor.at` 的几何语义与世界→屏幕反向换算） |
| 动画总监 / 特效总监 | 出现时间轴与动效、粒子与辉光（本稿一律不涉及） |

> **施工前提 · 坐标可用性不由视觉层兜底**（架构总监实读转述，本稿未亲读这些源码）：叠层要按 `DiagAnchor.at` 定位，但现有 `at` 大量是**占位 `(0,0)`**——`derive_hints:133–137` 注释明写「没有几何意义」、`diagnostics.rs:536–540` 跨级尺度同理；且 `wv-app` 侧缺**世界→屏幕反向换算**（`wv-render/src/camera.rs:355` 只有 `screen_to_world`）。**「标记能落在正确位置」是创意侧第 1 / 2 件事与架构稿 §2.7 的施工前提，不是视觉层可假设的现成输入。**
>
> 因此：本画面语言规格只约束「标记长什么样」，**不假设坐标已就绪、不为坐标可用性兜底、不因此新增任何视觉侧验收项**；位置语义与反向换算归数据侧 / 主程序。§7 的 V1 / V2 / V3 与下方供引用的措辞**均不含位置判定**，不受此前提影响。

**叠层最小样式规格**（全部锚到既有规格，不新造）：

1. **形状**：三角警示标记，非圆点；1px 深褐墨描边，右下投影按 §3.4 `:352`（长度 = 符号高 ×0.5），底座留白 1/8。
2. **颜色**：底色 == `soften.toward #F2EAD8`（§1.4.4 `:135`）；文字 == `label.fill #4A3F35`（`:140`）；**语义红只出现在 1px 描边与图标，不铺底**；全屏语义色 ≤3 种（§四 P2 `:409`）。
3. **气泡**：纸色底 + 1px 褐墨描边 + 圆角 ≤2px（§四 工具型壳，禁大圆角）；系统衬线 / 无衬线栈 + 字距；正文对比度 ≥4.5:1、关键 ≥7:1（P1 `:408`）。
4. **无障碍**：按 §1.4 `:112–114`，冲突态必须**形状 + 文字 + 颜色**三重可区分，**颜色不得是唯一信息载体**。
5. **状态视觉**：默认 / 悬停 / 按下 / 禁用 / 选中只描述明暗与描边差异；**不定义点击后发生什么**（职责边界）。

> **是否列入收口验收点：不列入。** 叠层是「让首屏校验结论看得见、愿意被点」的**前置条件**（创意总监稿定位），不是本轮视觉重做的完成定义；把它绑进 V1/V2/V3 会让「三条全真即收口」被另一条主线阻塞。**本稿不新增第 4 条验收点。**
>
> **供创意总监停止条件 §5.2 直接引用的措辞（附条件、带真假、只判样式）**：
> 「叠层样式对齐：① 底色 == `#F2EAD8`（±2/通道） ② 文字色 == `#4A3F35` ③ 语义红只出现在 1px 描边与图标、不铺底 ④ 每个标记带三角形状差异而非仅靠颜色 ⑤ 正文对比度 ≥4.5:1。五项全 1 → 真。判定范围只覆盖样式，不覆盖数据来源、跳转与点击行为。」
