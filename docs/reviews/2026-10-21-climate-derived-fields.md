## 2. 必修项

### A1 热带雨林分支实测不可达（高）

**现象**：提交宣称低地分「冷带 → 雨林 → 干旱 → 森林 → 草原」五类，但雨林在生成结果里一次都没出现。

**证据（实测）**：256² / 256×128 / 512² 三种网格 × seed {1, 7, 42}，共 9 组，`BIOME_JUNGLE` 计数全为 0；再以 `forest_cover` × `desert_cover` 各取 {0, 0.30/0.15, 1.0} 三档共 9 组，仍全为 0。见附录 §5.2。

**根因（静态）**：`lowland_biome` 的雨林条件是 `temperature > 0.72 && moisture > 0.68`（`continent.rs:402`）。

- `temperature > 0.72` ⇒ `warmth > 0.682` ⇒ `|y_norm − 0.5| < 0.159`，只在**图幅中部 32% 纬度带**成立；
- 该带要 `moisture > 0.68`，而 `moisture = 0.10 + 0.75·m_noise + coast_wet`（`coast_wet ≤ 0.06`），即内陆需 `m_noise > 0.773`；
- 4 阶 Perlin fBm 归一化后实际取值几乎不越过 0.773 —— 雨林因此成为**结构性不可达**分支，不是「标定偏了」。

**为什么单测没拦住**：`hot_wet_lowland_becomes_jungle`（`continent.rs:880`）直接喂 `classify(0.85, 0.90)`，证明了「函数收到这对输入会返回丛林」，但没有证明**生成器能采到这对输入**。这是纯函数单测与端到端断言之间的典型空隙。

**附带问题：即使可达也看不出**。`biome.rs:144 display_kind` 把 `BIOME_JUNGLE` 与 `BIOME_FOREST` 同映射到色槽 4；`wv-render/src/terrain_decor.rs:101` 把两者同映射到 `DecorKind::Forest`。也就是雨林这一档当前**三重无效**：不可达、同色、同装饰。

**建议**：二选一 —— (a) 降雨林湿度阈值（如 `> 0.55`）并同步抬 `desert` 分支的下限，或 (b) 提高湿度动态范围（`0.10 + 0.95·m_noise`）。改完把端到端测试从「计数器 >0」升级为**逐类断言**（含雨林），否则同类问题会再次发生。若决定本期不做雨林，则从分支和文档里一起删掉，不要留一条永不命中的分类。

### A4 生成循环末尾的 NONE 重分类块不可达（中高）

**位置**：`continent.rs:669–686`，即提交说明里的「融合后 h<300 的 NONE 按气候重新分类，避免海岸带出现大片无群系」。

**静态证明**：该块的触发条件为 `surface == LAND && height < HILL_MIN_M && biome == BIOME_NONE`，而本函数内**没有任何分支产出这样的格**：

| 分支 | 产出 | 能否产出 LAND+NONE+<300 |
|---|---|---|
| `d >= 0` → `blended`，`h == new_height` | `new_biome`（`band_surface_biome` 结果） | 否——`lowland_biome` 只返回 SNOWFIELD/TUNDRA/JUNGLE/DESERT/FOREST/GRASSLAND |
| `d >= 0` → `blended`，`h < 300` 且 `h != new_height` | `(LAND, new_biome)`（`continent.rs:533` 新加的 else 分支） | 否，同上 |
| `d >= 0` → `blended`，`h >= 300` | `surface_biome_for_height` → NONE | 否——h 已 ≥300，与条件 `< HILL_MIN_M` 互斥 |
| 大陆架 `d ∈ [−shelf, 0)` | 水 / `continue` | 否 |
| 离岸小岛 | `(LAND, BIOME_HILLS)` | 否 |
| 其余 | `continue` | 否 |

**实测**：12 组配置下「低地（<300 m）且 biome==NONE」的格数恒为 0（附录 §5.2 `NONE_low(<300m)=0`）。

**结论**：真正修好海岸带「大片无群系」的是 `blended` 的 `else` 分支（`continent.rs:533`），那一条是对的、也是核心改动；末尾这块是多余的死代码，而且每次命中都要白算一次 `climate_at`（2 次 fBm）。

**建议**：删除该块，替换为 `debug_assert_ne!(new_cell.biome, BIOME_NONE, "低地必须已由气候分类给出群系")`，把「不可能发生」变成不变量而不是可执行代码。

## 3. 转裁定项

### A2 纬度轴挂在 `grid.height()` 上（高，但需你拍板）

**位置**：`continent.rs:623` `let y_norm = (gy as f32 + 0.5) / grid.height() as f32;`

**问题**：赤道被硬编码在**图幅垂直正中**，纬度与任何真实空间基准无关。两条后果：

1. **P4 多图层级失效**：子图（钻取后的北境/南境详图）各有自己的图幅高度，因此各有自己的赤道。同一片地理区域在父图与子图会得到不同气候带，且 `biome` 已落盘，不会自动纠正。
2. **真实底图浪费**：`wv-core/src/source/geographic_source.rs:68` 已有 `LatLonBbox`（EPSG:4326 经纬度 bbox），Overture 导入的工程本来知道真实南北纬，但生成器完全没用 —— 一张位于北纬 40–55° 的真实底图仍会在自己图幅中间长出热带。

**修法（需动 schema，故建议先裁后做）**：把纬度轴提成显式输入 —— 世界坐标 Y + 工程级 `equator_y` / `lat_span`；存在 `geographic_source` 时直接用 bbox 的南北界。`band_surface_biome` 的 `y_norm: f32` 参数可保持不变，只把「谁给定标系」从 `grid.height()` 换掉。

**关闭条件**：明确「气候纬度 = 图幅相对」还是「= 世界/真实纬度」，并把结论写进待裁条目或 ADR。**不影响本次合入**，但会决定下一次改这里要动多少。

### A10 同 crate 内已存在第二套气候规则（中）

`crates/wv-terrain/src/climate.rs:141 fn classify` 是 ADR-0037 模板生成器的分类规则：高度阈值 2400 / 1250 / 620、纬度切点 `lat >= 0.86 / 0.74`、外加一条「东陆中纬干旱带」的横向规则。本次新增的是另一套：高度阈值 2600 / 1200 / 300（经 `SNOW_LINE_M` 等共享常量）、纬度按 `warmth = 1 − |y−0.5|·2` 对称、干旱按「热 × 干」连续量。

两者都在 `wv-terrain` 内、都叫「气候」，但对同一张图会给出不同答案。本次提交的 `climate_at` 与 `lowland_biome` 是私有函数（`pub(crate)`），不构成 API 冲突，**但构成概念冲突**：后续接「世界模板重生成」时会出现「模板生成的世界」与「大陆生成的世界」两套气候不相容。

**待裁**：要么把 `climate.rs::classify` 逐步收敛到新的 `climate_at`（模板生成器降级为「v0 快照、不再演进」），要么明确两者服务于不同产物、并在文档里划清边界。

## 4. 建议改 / 挂账项

### A5 装饰层 y 轴语义与生成层相反（中）

`wv-render/src/terrain_decor.rs:254` 的 `DecorVariant` 派生：`fy < 0.30` → 针叶，`fy < 0.72` → 阔叶，`fy >= 0.72` → `Sparse`（稀树/绿洲）。这是 **ADR-0037 世界模板的「北寒南旱」不对称假设**。

新的生成器是 **南北对称寒带**（`warmth = 1 − |y−0.5|·2`，两端皆冷）。结果：南半球 `fy = 0.85` 的森林格在数据上是温带森林，装饰层却按「干旱稀树」画；`fy = 0.90` 已是苔原（`temperature ≈ 0.30`），装饰层仍会撒稀树点。

**建议**：把 `climate_cuts` 的语义从「北寒南旱」改成与生成器同源的对称判断（`|fy − 0.5|`），或由主题配方显式声明「对称 / 不对称」两种模式。属跨层契约，建议连 A10 一起裁。

### A6 荒漠判定不读湿度（中）

`continent.rs:402` 的荒漠条件是：

```rust
if aridity > desert_threshold || (hot > 0.35 && dry_patch < desert_patch)
```

第二项只读 `hot`（温度）与 `dry_patch`（一张独立 fBm），**完全不读 `moisture`**。后果：一个温度 0.75、湿度 0.60 的格子（够不着 `moisture > 0.68` 的雨林线）仍会因 `dry_patch` 的低尾被切成荒漠斑块。叠加雨林在 `moisture = 0.68` 处**硬切**，就出现「荒漠斑块与雨林贴脸」的分布：`m = 0.679` 可能荒漠、`m = 0.681` 直接雨林。

**建议**：第二项加合取 `moisture < 0.45`，并把雨林/荒漠两条边界错开（雨林 `> 0.62`、荒漠 `< 0.40`），避免阈值相邻。

### A7 `desert_cover` 档位失真（中）

实测（seed 7，256²，内缩 8% 包络，`forest_cover` 固定 0.30）：

| `desert_cover` | 0.00 | 0.15（缺省） | 1.00 |
|---|---|---|---|
| 低地中荒漠占比 | 5.0% | 11.7% | 28.5% |

`desert_cover = 0` 仍出 5% 荒漠（`aridity` 主判据不受旋钮控制），`= 1.0` 天花板也只到 28.5%。栈上 doc 已把语义改成「倾向，不是精确面积比」，算诚实；但面板若以 0–100% 展示，两端承诺与落点差得远。

**建议**：要么让 `desert_cover` 同时也缩放 `aridity` 主判据（让 0 真的等于 0），要么把面板文案从百分比改成「少 / 中 / 多」三档。

### A8 低地面积仍偏窄（中）

实测默认档（`ReliefLevel::Mountains`，峰值 2000 m）：三 seed 下「陆地中 ≥300 m」的面积占比 **55–56%**，低地只占 44%。提交 `3de8bb6` 的目标是「不再整块大陆都是山」，从数据看**只解决了一半** —— 气候场能落笔的面积仍不到一半。

**建议**：如目标确实是「低地为主」，需要继续压 `relief` 曲线（例如 t^2.5 或进一步放宽 `denom`），或把 `HILL_MIN_M` 当成可调参数而非硬常量。这属视觉验收项，请在预览图上定。

### A9 t² 剖面导数形态（中）

`land_height` 改为 `base = peak * t * t`（`continent.rs:311`）后，`dh/dd = 2·peak·t / denom`：

- 海岸处 `t = 0` ⇒ **导数为 0**，贴岸一圈「死平」，等值线极稀；
- 中段 `t → 1` 时导数最大，等值线最密；
- `t = 1` 处（`d = 0.8·inradius`）突然截平，**导数跳变**，等值线出现折角。

净效果是「平 → 陡 → 折」的三段式，比原线性（斜面 + 一处折角）更容易出视觉台阶。

**建议**：换 `smoothstep(0,1,t)`（两端导数为 0，无折角）或 `t^1.5`（折中）；两者都能保住「加宽低地」的目标，同时消掉贴岸死平与平台折角。

### A11 真 bug 修复应独立提交（低）

`fbm01` 的归一化修复（`v*0.5+1.0` → `(v+1)*0.5`）是**真 bug**：旧式把 `[-1,1]` 映射到 `[0.5,1.5]` 再钳制，落到 1.0，导致 `forest < forest_cover` 恒不命中（森林/荒漠掩码长期失效的根因）。这条修得对，且与 `climate.rs:345` 的既有实现对齐了。

但它同时改了两处：`land_height` 的调制项与 `coast_field_indexed` 的海岸扰动项（`continent.rs:265`）。后者会让**所有既有工程重生成时海岸线发生变化**。混在 feature 提交里，未来 `git bisect` 或做工程迁移时无法单独回溯。

**建议**：拆成独立提交（可保留在同分支），并在提交说明里显式写「既有工程重生成会改变海岸线」这一迁移影响。

### A13 测试方向偏（低）

6 个新测试的分布：

| 测试 | 覆盖对象 | 评价 |
|---|---|---|
| `temperature_drops_toward_poles_and_with_altitude`（:829） | `climate_at` 纯函数 | 海拔项用 3000 m，但生成路径从不在 `h > 300` 调 `climate_at`；该断言测的是「函数能算」，生成器用不到（300 m 处高度项仅 −0.041） |
| `moisture_is_higher_near_the_coast`（:845） | 同上 | 差值恒为 0.06，几乎同义反复 |
| `cold_lowland_becomes_tundra_then_snowfield`（:853） | `lowland_biome` | 雪原在常规包络下不可达（见下） |
| `moist_temperate_lowland_becomes_forest`（:860） | 同上 | 有效 |
| `hot_dry_lowland_becomes_desert`（:870） | 同上 | 有效 |
| `hot_wet_lowland_becomes_jungle`（:880） | 同上 | 输入不存在于生成结果中（A1） |
| `generated_continent_contains_climate_variety`（:888） | 端到端 | 只断言 4 个计数器 `> 0`；对 `blended` 改道与 NONE 清理**零覆盖** |

**补充实测**：`BIOME_SNOWFIELD` 在低地也几乎不可达 —— `temperature < 0.20` 要求 `|y − 0.5| > 0.4545`，即陆地必须伸进图幅上下 **4.5%** 以内。内缩 8% 的包络下实测雪原 **0.0%**，苔原 35.1%。所以「冷带」实际上只有苔原一档在常规图幅里出现。

**建议**：端到端测试改成逐类断言（含雨林、雪原的可达性前置），或显式声明「雪原只在图幅极边出现」并删掉相应单测的伪装。

### A12 参数膨胀（低，可留）

`band_surface_biome` 9 参并挂 `#[allow(clippy::too_many_arguments)]`（`continent.rs:461`），`climate_at` 7 参。注释说「拆结构体反而更难读」，有道理，但 9 参里有 5 个是同一份上下文（`p / d / diag / y_norm / shelf_wu`）。建议抽 `struct CellCtx { p, d, diag, y_norm, shelf_wu }`，`params` 与 `noise` 保持显式 —— 顺带把 A2 的纬度轴替换成本压到一处。

## 5. 可以确认的优点

1. **`fbm01` 归一化修复是对的**，且定位准确（旧式钳制导致掩码恒不命中），并与 `climate.rs` 既有实现对齐。
