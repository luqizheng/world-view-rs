## 一、风格定位与唯一色板

### 1.1 定位（一句话）

> **像「制图软件的一枚仪表」，不像「古舆图的一枚纹章」**：三件套是**屏幕空间 UI 控件**，不是画在地图上的景物；全件零彩度、零暖色、零手绘，只提供「方位 / 画幅 / 色义」三项结构信息。

沿用既定基调：陆面 `BIOME_RAW_COLORS[21]` 真色主导（`biome_tint = 0.82`）、8 阶中性冷灰绿 `#EEF1EF → #6E776F` 极淡起伏底、hillshade 常开、贴地符号 / 浪花 / 雪线 / 点点全无。三件套**不参与地形取色、不进 ThemePack、不进 `wv-render`**。

### 1.2 拍板色板（唯一出处 `crates/wv-default-theme/src/colors_google.rs`，不新造任何色值）

| 角色 | hex | 令牌 / 行号 | 用途 |
|---|---|---|---|
| **一级墨** | **`#3C4043`** | `GOOGLE_LABEL_FILL:150` / `GOOGLE_CONTROL_TEXT:228` | 罗盘北瓣实心、「N」字、图例族名、图廓强调（不用） |
| **二级墨** | **`#9AA0A6`** | `GOOGLE_ISOLINE_INK:160` / `GOOGLE_LINE_ON_MID:179` | 罗盘外环 / 刻度、图廓线、图例内分隔 |
| **三级墨** | **`#5F6368`** | `GOOGLE_LINE_ON_DARK:180` | 图例展开态群系项名（二级文字） |
| **极淡线 / 描边** | **`#DADCE0`** | `GOOGLE_CONTROL_BORDER:226` / `GOOGLE_LINE_ON_LIGHT:178` / `GOOGLE_ROAD_CASING:68` | 罗盘底板描边 / 内环 / 十字基线、图例面板描边、色块内描边 |
| **面板底 / 反白** | **`#FFFFFF`** | `GOOGLE_CONTROL_BG:224` / `GOOGLE_LABEL_STROKE:147` | 罗盘底板、图例面板、南瓣空心 |

**为什么全走这组、不走 `ShellPalette` 暗壳色**：`colors_google.rs:223-230` 明写「地图控件底色：白卡片。**它是地图体验的一部分，不跟随暗色软件壳**」——三件套贴在浅色地图画布上，跟 `bg_app @0.96` / `border_subtle #303B43`（`status.rs:40-41`）那套暗 chrome 会让画布上浮出一块黑卡片，直接打架。

**为什么不用任何暖色 / 不引入第四色相**：古舆图墨（`#5A4E42` / `#4A3F35` / `#6B5B49`）、纸色 `#F2EAD8`、金 `#D6B77B` 全部属用户已明确弃用的「古舆图 / Google 样式全部去除，全部改为专业色」语汇；且零彩度中性灰是唯一能同时压在群系绿 / 群系黄 / 水域蓝上都不漂色相的颜色（§五）。

**几何形状语言（全件只允许一族）**：规整几何图元 = { 1px 细直线、正圆、等腰三角、直角矩形 }。**禁止** 圆角 >2px、斜纹、手绘抖动、±2px 海岸抖动、右下投影（§3.4 古舆图符号语汇）、水彩 / 纸纹 / 噪点、衬线字、字距拉伸、装饰花纹、多环刻度盘。

## 二、资产清单与预算

| 件 | 形态 | 屏幕空间预算 | 图元数上限 |
|---|---|---|---|
| 罗盘 | 圆形底板 + 2 环 + 1 根双瓣针 + 2 条十字基线 + 4 刻度 + 1 个「N」 | 底板 64×64px（直径 56px 内容区），占 1080p 屏 ≈ 0.20% | **≤ 14** |
| 图廓边框 | 1 条矩形闭合线（4 段） | 距 `central_area` 四边 8px，线宽 1px，全幅占空比 < 0.1% | **4** |
| 图例 | 白面板 + 标题 + 8 族行（折叠态） | 折叠 168×188px ≈ 1.5%；展开上限 168×340px ≈ 2.8% | 折叠 ≤ 8 色块 + 8 行 |

- **色彩预算**：群系真色仍是主色 60% / 冷灰绿 + 水深为辅色 30% / 三件套全属点缀，**合计占屏 ≤ 5%、新增着色像素 ≤ 2%**，远低于点缀 15% 的「吵」阈值；主色占比一分不动。
- **零资产纪律**：不引入任何新图片 / 字体 / 音频 / 二进制。罗盘全部用 `ui.painter()` 现成图元（`status.rs:196-211` 已示范同类调用）；「N」与中文族名走既有 Inter / Noto Sans SC 系统栈（`docs/reviews/2026-11-11-worldmap-visual-direction.md:200`），不加载新字体；折叠钮用既有 `ICON_CHEVRON_*`。
- **不新增第 4 件装饰**：比例尺已有（状态栏）、不重做、不搬回画布；不加图名 / 制图者 / 年份 / 经纬度刻度 / 比例尺数字。
- **三测**：剪影测试——三件套不改变任何地物剪影，通过；灰度测试——去色后墨(L≈63) / 线(L≈159) / 白底(L=255) 三层明度单调，主次仍由群系真色与冷灰绿撑住，通过；形状语言检查——全件只有「规整几何」一族，无圆角 / 直角 / 尖刺三种语言并存，通过。

## 三、逐资产规格（逐项给值 + 一句理由）

### 3.0 三件共用规则

| 规格项 | 值 | 一句理由 |
|---|---|---|
| 锚点坐标系 | `central_area`（视口挖去顶栏 38 / 状态栏 28，`status.rs:29-30`），**不是全屏** | 装饰天然不跨入 chrome，不需要逐件算偏移 |
| 单位 | 屏幕 px，1080p 基准，**固定不随相机缩放 / 不随世界平移** | 屏幕空间 UI；随缩放会变成地图景物，回到插画 |
| 字重 | **一律 Regular (400)，不请求 bold** | `status.rs:234-235` 实读：egui 无合成粗体、`.strong()` 会退化成强调色；层级改靠字号 + 位置 + 缩进（我的 UI 硬规则 1） |
| 字号阶梯 | 12 / 11 / 10 px，对齐既有 `STATUS_FONT = 10.0`（`status.rs:10`）与 `MICRO(11)` | 本工程是 **PC 桌面编辑器**，不适用移动端 24px 正文下限；装饰字号**不得大于**既有 chrome 读数，否则工具比仪表还轻 |
| 安全区 | 折叠钮（唯一可交互元素）距屏幕边缘 ≥ 5%（1080p 基准 54px）：`central_area` 内缩 32px + 状态栏 28px = 60px ✓ | 移动端刘海 / 圆角吃边缘；非交互装饰（罗盘、图廓线）内缩 8–24px 即可 |
| 输入 | 三件套整体 `Sense::hover()` 或 `Sense::click()` 仅限面板矩形内；**不得吞掉地图点击 / 拖拽 / 笔刷** | `status.rs:191` 的比例尺段是现成先例；浮窗若吃全视口命中会重演 `status.rs:31-34` 记录的「根 Ui 提层导致全界面输入失灵」 |

### 3.1 罗盘 · 纯程序化几何（不引入图片 / 字体资产）

| 规格项 | 值 | 一句理由 |
|---|---|---|
| 位置锚点 | `central_area` **右上角**，距上 24px、距右 24px | 左下被时间轴 + 小地图浮窗常驻占据（`status.rs:160-162` 明证），右下留给图例；右上不与 `panel_inspector` 默认位冲突（须主程按 `ui-layout.yaml` 复核，见 §六） |
| 尺寸 | 底板 64×64px（圆心区直径 56px）；内容直径恒定，不随窗口缩放 | 56px 是「50% 缩略图仍能辨北向」与「不抢地图」的交点 |
| 底板 | `circle_filled` r=32px，`#FFFFFF` @ **0.92** + `circle_stroke` 1px `#DADCE0` @1.0 | 群系绿 / 水域蓝饱和度都不低，墨线直接压上去读不出；中性白载体是唯一解，且 0.92 保留一点底图透出、不成「贴了一张纸」 |
| 环（**2 个，封顶**） | 外环 r=28px，1px `#9AA0A6` @0.70；内环 r=20px，1px `#DADCE0` @1.0 | 双环是罗盘最小可辨结构；古舆图玫瑰盘是 3+ 环 + 星芒，这里用「≤2 环」把信息密度钉死 |
| 针（**1 根双瓣**） | 北瓣 = 等腰三角（底宽 8px、高 18px）`#3C4043` **实心**；南瓣 = 同形倒置 `#FFFFFF` **空心** + 1px `#9AA0A6` 描边 | 实心 / 空心 / 「N」字三重区分 → 颜色不是唯一信息载体（呼应 `ART_STYLE_SPEC_v0.1.md` §1.4 `:112-114`）；且零彩度、零暖墨、不做 8 向星芒（星芒是插画感第一来源） |
| 十字基线 | 2 条 1px `#DADCE0`，水平 / 垂直各长 36px，过圆心，不出底板 | 给「北」一个直角坐标参照，同时保持形状语言只有「细直线 + 圆」 |
| 刻度 | **4 个基点**（N/E/S/W），各 4px 长、1px `#9AA0A6`，只在外环内侧 | 明确**不做 8 / 16 / 32 分度盘**；分度盘是「地图能出版」和古舆图共有的语汇 |

| 图元总数 | **≤ 14**（1 底板 + 1 描边 + 2 环 + 2 针瓣 + 2 基线 + 4 刻度 + 1「N」+ 1 圆心） | 可数、可断言的信息密度上限 |

### 3.2 图廓边框 · 屏幕空间单线

| 规格项 | 值 | 一句理由 |
|---|---|---|
| 位置锚点 | `central_area` 四边，距边 **8px**；**不跨入**顶栏 38px / 状态栏 28px | 只框地图可视区；跨进 chrome 会把工具栏读成「图内元素」 |
| 线 | **单线 1px**，`#9AA0A6` @ **0.55** | 单线是专业制图的结构边；双线 / 内外框 / 刻度尺是「能出版」语汇，明确禁 |
| 留白边 | 线外到 `central_area` 边缘的 8px **保持透明，不填色、不铺纸纹**；线内无任何填充 | `2026-11-11` 稿 D4（`:101`）曾诊断「左右空白被读成没铺满」；若这里铺底色把空白「做成纸」，就是回到古舆图。本轮**明确不解决 D4**，只给一条极淡结构边，留白仍归窗口 chrome |

## 五、与「群系真色 + 冷灰绿起伏」基底的相容性论证

### 5.1 数值对照（sRGB，L = 0.299R + 0.587G + 0.114B）

| 色 | RGB | L | S=(max−min)/max | \|R−B\| |
|---|---|---|---|---|
| 一级墨 `#3C4043` | 60,64,67 | **63** | 0.104 | 7 |
| 三级墨 `#5F6368` | 95,99,104 | **98** | 0.087 | 9 |
| 二级墨 `#9AA0A6` | 154,160,166 | **159** | 0.072 | 12 |
| 极淡线 `#DADCE0` | 218,220,224 | **220** | 0.027 | 6 |
| 面板白 `#FFFFFF` | 255,255,255 | **255** | 0 | 0 |
| 咸水（冻结表 14）`#9DC3D8` | 157,195,216 | 186 | 0.273 | 59 |
| 淡水（15）`#7FB4CE` | 127,180,206 | 167 | 0.383 | 79 |
| 河流（16）`#6BA3C7` | 107,163,199 | 150 | 0.462 | 92 |
| 冷灰绿低阶 `#EEF1EF` | 238,241,239 | 240 | 0.012 | 1 |
| 冷灰绿高阶 `#6E776F` | 110,119,111 | 115 | 0.075 | 1 |
| 旧暖褐墨（古舆图，禁）`#5A4E42` | 90,78,66 | 80 | **0.267** | **24** |

### 5.2 三条不打架的理由

1. **明度分层完全不重叠**。一级墨 L≈63 **低于**冷灰绿最深阶 L≈115（差 52）与全部水域色 L 150–186，也低于绝大多数群系真色；面板白 L=255 **高于**冷灰绿最浅阶 L≈240（差 15，由 1px `#DADCE0` 描边补足，防近白群系上消失）。→ **灰度测试通过**：去色后「墨 → 线 → 白底」三层明度单调，主次关系仍由群系真色与冷灰绿起伏撑住，不靠颜色。
2. **零彩度 → 不引入第四种色相**。三件套任一色 `S ≤ 0.12 ∧ |R−B| ≤ 12`（上表逐行验算全部通过），而水域三色 `|R−B|` 为 59/79/92、群系绿黄带各自色相。中性灰压在任何彩色底上都读作「结构 / 控件」，不会被读成「另一块地形」或「一条行政边界」——正是 `colors_google.rs:159-160, 238-240` 已确立的制图口径（结构边用中性灰，水岸线才用水色加深一档）。**图廓线是中性结构边，不是水岸线，不与 `#9DC3D8` / `#7FB4CE` 争蓝相。**
3. **装饰不直接压在群系 / 水域上**。罗盘有 `#FFFFFF`@0.92 圆底板、图例有 `#FFFFFF`@0.94 面板，墨线只落在中性载体上；唯一直接叠底图的是 1px 图廓线（α≤0.55、全幅占空比 <0.1%），线本身无彩度，混合结果的色相仍由底色主导，只贡献一条 ≤45 L 的极淡边。且 `biome_tint = 0.82` 使冷灰绿只贡献约 18% 底色，三件套与它**根本不在同一层**。

## 六、「不回到古舆图」的边界判据（正面回答张力，全部可判，不写「克制」二字）

> **张力原文**：`docs/reviews/2026-11-11-worldmap-visual-direction.md:150-151` —— 首屏目标态「**无罗盘无图廓无手绘符号**」、明确不做「**纸纹 / 水彩 / 罗盘 / 衬线字 / 手绘符号；不追『地图能出版』**」。C 路线却要加回罗盘 / 边框 / 图例。

### 6.1 先回答「凭什么可以加回」——两句话并不矛盾，是按 ViewMode 分区共存

`:150-151` 属于 **§4「方向 B · 极简制图：以『可导出的成品图』为完成态」** 的首屏目标态，而方向 B 的语义位就是 **`ViewMode::GoogleMap`（Map 标签页 / 专业制图 / 普通地图）**（`bar.rs:216`；`state.rs:155-157` 明写 GoogleMap 是「主理人裁定走专业制图范式后该范式的唯一入口」）。**方向 B 从被采纳为唯一默认**（用户随后定了「干净专业制图 + 群系真色主导」基底），但用户这次选 C 路线加回装饰，等于给 **Browse 标签页**单独开了一个轻量装饰位。

> **裁定**：「无罗盘无图廓」约束的是 **Map / GoogleMap 那一屏**，不是全项目禁令。C 路线把三件套加回 **`ViewMode::VectorFlat`（Browse 标签页）**，而 **Map 标签页保持 `:150-151` 原样**。两个目标态各占一个 tab，靠 §四 白名单硬隔开。

### 6.2 七条可判边界（主程可直接写成断言 / 截图验收）

| # | 判据 | 可判方式 | 失败样例 |
|---|---|---|---|
| **B1 · 色值饱和度上限 + 零暖色** | 三件套任一色 `S = (max−min)/max ≤ 0.12` ∧ `\|R−B\| ≤ 12`（8-bit sRGB 直算）；**禁止任何 `R > G > B` 暖序色**；禁纸色 `#F2EAD8` / 金 `#D6B77B` / 褐墨 `#4A3F35` / `#6B5B49` / `#5A4E42`；配色只从 `colors_google.rs` 既有令牌取，不新造色值 | 取色器逐点算 S 与 \|R−B\|，枚举全部绘制色 | 旧暖褐墨 `S=0.267, \|R−B\|=24` → 直接判失败；这一步就把古舆图墨色挡在门外 |
