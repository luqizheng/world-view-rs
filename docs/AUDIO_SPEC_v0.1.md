# World View · 音效规格 v0.1

> **编制** 雷鸣远 · 音效总监
> **性质** 本文件是 World View 编辑器音频侧的**唯一权威规格**，与 `docs/MAP_EDITOR_BASELINE_v1.md` 冲突处以基线为准
> **范围** 编辑器（地图编辑器为核心 + 各管理面板）的**全部声音**
> **读者** 主程序（寇豆码）、主理人、后续验收
> **状态** Phase 2 补齐项；本文件同时给出「原型最小集」与「明确不做清单」

---

## 0. 一句话结论（先看这里）

> **World View 是长时间连续工作的单机创作工具，不是游戏。它的音频需求量极小。
> 本规格裁定的结果是：全项目只需要「3 个原型音效 + 2 个可选音效」，其余全部不做。**

| 类别 | 裁定 | 理由一句话 |
|---|---|---|
| UI 反馈音（点击/开关/面板开合） | ❌ **不做** | 一秒点 10 次 = 骚扰；工具类软件行业惯例是静默 |
| 编辑操作音（笔刷/选区/撤销） | ❌ **不做**（撤销/重做除外，见 §1.2） | 连续涂抹 + 音效 = 灾难；撤销是无视觉反馈的高频动作，值得一个轻音 |
| 连续操作音效（缩放/平移/拖时间轴） | ❌ **不做** | 连续音效在编辑器里 100% 是负收益，详见 §1.3 |
| 状态提示音（保存成功/校验失败/加载完成） | 🟡 **做其中 2 个**（保存成功 / 校验失败） | 破坏性、不可逆、结果离视线远 → 需要声音兜底 |
| 播放时的音效（事态播放） | 🟡 **可选**（默认关） | 播放本就有强视觉，声音是锦上添花，非必要 |
| 背景音 / 环境音 / BGM | ❌ **不做** | 无任何理由；这是编辑器 |
| 错误音去重 | ✅ **必须做**（硬要求） | 一次校验 20 条错误绝不能响 20 次 |

**给主程序的净工作量**：可程序化合成 3 个（零音频文件），1 个采样音效，1 个可选项。**总计 ≤ 4 秒的音频资产。**

## 一、声音基调

### 1.1 基调定义

> **「安静的实验室」——声音是仪器的指示灯，不是背景音乐。**

| 维度 | 规格化定义 |
|---|---|
| **整体存在感** | **极低**。默认音量偏小（见 §4.3），多数操作**无声** |
| **音色取向** | **干燥、短促、无混响、无音乐性**。避免任何旋律、和声、情绪暗示 |
| **材质方向** | 木质 / 电子提示音（Soft synth blip）。**禁止**：金属重击、爆裂、气声、人声 |
| **频率取向** | 中高频（800 Hz – 4 kHz）。此区间在小音量下仍可辨识，且不会产生低频压迫感 |
| **情绪基线** | **中性**。「保存成功」是「确认」不是「庆祝」；「校验失败」是「提示」不是「警报」 |
| **关键反差** | 全项目**唯一**需要「被听见」的声音是**校验失败**——它必须比其余所有声音更明确，但仍不刺耳 |

### 1.2 三层基调纪律（为什么这么克制）

| # | 纪律 | 说明 |
|---|---|---|
| **A1** | **声音只用于「视觉够不到的反馈」** | 保存成功（文件写盘，界面无变化）、校验失败（错误列表可能不在视线内）→ 需要声音。其余反馈**界面本身已经给了**（笔刷涂抹有像素变化、面板开合有动画） |
| **A2** | **任何声音都必须可单独关闭** | 作者可能听音乐工作时使用本工具。**BGM/环境音会与用户的音乐打架**——这是不做 BGM 的最硬理由 |
| **A3** | **默认值偏向「几乎听不见」而不是「刚好听见」** | 编辑器里「听不见」是可接受的失误，「太吵」是不可接受的失误。默认取「刚能辨识」的 70% |

> **设计哲学**：游戏音效追求「沉浸」，编辑器音效追求「确认」。前者错了叫「没氛围」，后者错了叫「用户关掉声音」。**代价不对称，所以规格必须不对称。**

## 二、声音清单

### 2.1 完整清单（全项目）

| 声音名 | 类别 | 触发条件 | 时长区间 | 优先级 |
|---|---|---|---|---|
| `SFX_UI_Save_Success` | 状态提示 | 工程写盘成功（`Project::save` 返回 `Ok`） | 120–160 ms | P2 |
| `SFX_UI_Validate_Fail` | 状态提示 | 校验完成且错误数 ≥ 1（§2.21 校验面板刷新） | 180–260 ms | **P1** |
| `SFX_UI_Undo` | 编辑反馈 | `History::undo()` 成功执行（栈非空） | 80–110 ms | P3 |
| `SFX_UI_Redo` | 编辑反馈 | `History::redo()` 成功执行（栈非空） | 80–110 ms | P3 |
| `SFX_UI_Playback_Tick` | 播放（可选） | 事态播放中，`current_day` 每跨 1 个「节拍单位」（见 §3.2） | 40–60 ms | P4 |

> **只有 5 个。其中 3 个是「做其中 2 个 + 撤销/重做」的延伸，1 个可选默认关。**

**变体要求**：`Undo` / `Redo` **必须各做 2 个变体**（音高 ±3% 随机），避免连续撤销（作者常连按 `Ctrl+Z` 5 次）产生机器感。其余 3 个**单变体即可**（低频次，不构成重复疲劳）。

### 2.2 关键裁定表：为什么其余都不做

| 候选声音 | 裁定 | 理由 |
|---|---|---|
| **UI 点击音**（按钮、菜单项、复选框） | ❌ **不做** | ① 作者一秒点 10 次（§3.2 场景）② 工具软件（Blender / VSCode / Figma）默认皆无声 ③ 点击有**即时视觉状态变化**，声音是冗余 |
| **面板开合音** | ❌ **不做** | 面板开合已有动画（动画总监规格负责）。加声音 = 把「工具感」变成「游戏感」 |
| **笔刷涂抹音** | ❌ **不做（重点）** | 涂抹是**连续、高频、无固定节拍**的操作。给声音 = 每秒 60 帧的循环噪音。**这是编辑器音频最经典的自杀式设计** |
| **选区/圈选音** | ❌ **不做** | 选区是「开始-拖拽-结束」三段，给音只在首尾 → 但首尾就是「点击」和「松开」，落回「点击音不做」的同一理由 |
| **海拔调整滑块音** | ❌ **不做** | 滑块拖动同样是连续操作 |
| **缩放音** | ❌ **不做** | 滚轮一秒可滚 20 格 → 见 §3.1 |
| **平移音** | ❌ **不做** | 同上，且平移是**纯视觉跟随**，声音只会干扰方向感 |
| **拖时间轴音** | ❌ **不做** | 见 §3.1；时间轴本身有日期数字实时变化（基线 §1.12），视觉反馈充足 |
| **加载完成音** | ❌ **不做** | 加载是**作者主动发起且已等待**的动作，他正在看进度条。加声音 = 提醒他「刚做了一件他刚做的事」 |
| **保存失败音** | 🟡 **复用 `Validate_Fail`** | 保存失败 = 错误，复用同一个错误音（不新增资产），但**优先级同 P1** |
| **报错弹窗音** | ❌ **不做** | 弹窗已抢占视线与焦点，声音冗余 |
| **BGM / 环境音 / 氛围音** | ❌ **明确不做** | ① 与作者的背景音乐冲突 ② 无任何信息传达价值 ③ 单机编辑器无「氛围」需求 |
| **角色语音 / 事件提示语** | ❌ **明确不做** | 这是编辑器，不是叙事播放器（播放功能本身也只做视觉） |
| **游戏化音效**（成就、连击、升级音） | ❌ **明确不做** | 本项目无游戏机制 |

## 三、分层与触发规则

### 3.1 必要音效详细规范

> 音量基准：**`0 dB` = 用户系统音量下的「刚好可辨识」**。本规格所有音量均为相对此基准的值。

#### ① `SFX_UI_Save_Success` — 保存成功

| 项 | 规格 |
|---|---|
| **用途** | 告知「数据已安全落盘」。**这是作者唯一无法从界面直接确认的状态**（脏标记 `●` 消失是唯一视觉线索，容易被忽略） |
| **时长** | 140 ms（单次，无尾音） |
| **音色描述** | 单音正弦 + 轻三角波泛音，音高 `C6`（≈1046 Hz）→ 上行 `E6`（≈1318 Hz）两音滑入，**10 ms 起音、无 ADSR 释放、直接切断**。听感像微波炉「叮」但更软、更短 |
| **音量** | **−12 dB**（本清单第 2 轻；保存是高频动作，不能响） |
| **触发时机** | `Project::save` 返回 `Ok` 后**立即**播放，不等待 UI 刷新 |
| **节流** | `Ctrl+S` 连按：**800 ms 内最多 1 次**（见 §3.3） |
| **优先级** | P2（可被 P1 打断） |
| **频次考虑** | 作者可能每分钟存 5–10 次（「写完一段就存」）。因此音量低 + 音色软 + 节流。**如果作者开启「自动保存」，此音效必须由自动保存分支静默**（只手动保存发声） |

#### ② `SFX_UI_Validate_Fail` — 校验失败

| 项 | 规格 |
|---|---|
| **用途** | 告知「校验产生了错误，且错误列表可能不在你当前视线内」。**本规格中唯一 P1 声音** |
| **时长** | 220 ms |
| **音色描述** | 双音下行：`A5`（880 Hz）→ `F5`（≈698 Hz），**方波轻混低通**（截止 2 kHz），起音 5 ms、释放 60 ms。听感明确但**不刺耳**——是「请注意」不是「警报」 |
| **音量** | **−6 dB**（本清单最响，但仍低于系统提示音） |
| **触发时机** | §2.21 校验流程完成、错误数 ≥ 1 时触发**一次**（**不按错误条数触发**，见 §3.3） |
| **节流** | 校验按钮连点：**1.5 s 内最多 1 次** |
| **优先级** | **P1**（最高，可打断 P2/P3/P4） |
| **频次考虑** | 校验是作者**主动发起**的动作，频次天然低。窗口 1.5 s 足够覆盖「连点校验」 |
| **硬约束** | 🔴 **一次校验无论 1 条还是 200 条错误，只响 1 次。** 错误严重度分级**不改变音效**（分级是视觉与面板的事，声音只负责「有事发生」） |

#### ③ `SFX_UI_Undo` / `SFX_UI_Redo` — 撤销 / 重做

| 项 | 规格 |
|---|---|
| **用途** | 撤销是**无视觉强反馈的高频动作**（`Ctrl+Z` 后画面可能只微小变化）。声音提供「操作已生效」的确认 |
| **时长** | 90 ms（`Undo`）/ 90 ms（`Redo`） |
| **音色描述** | **`Undo` 下行**：`D6`（1175 Hz）→ `A5`（880 Hz）；**`Redo` 上行**：`A5` → `D6`。**同一个音色的镜像**——作者可仅凭音高方向区分撤销/重做，无需看界面 |
| **音量** | **−15 dB**（本清单最轻。撤销常连按，必须极度克制） |
| **触发时机** | `History::undo()` / `redo()` 实际改动了世界时（栈为空、无操作时**不发声**） |
| **节流** | **不节流，但用变体**：连按 5 次 → 响 5 次，每次音高在 ±3% 内随机。理由：撤销是「离散动作」，连按 5 次 = 用户明确知道自己在撤 5 步，**每次给他确认是正确的**；节流反而会让他不确定第 5 次有没有生效 |
| **优先级** | P3 |
| **频次考虑** | 连按 `Ctrl+Z` 是本规格预估**最高频**的发声场景（作者试错式编辑）。因此：**音量最低 + 时长最短 + 变体随机化 + 无尾音**（不累积混响） |
| **变体要求** | 每个各 **2 个变体**（音高 ±3%） |

#### ④ `SFX_UI_Playback_Tick` — 播放节拍音（可选，**默认关闭**）

| 项 | 规格 |
|---|---|
| **用途** | 事态播放时，给「时间在推进」一个听觉锚点。**仅在有视觉盲区时有用**（作者盯着地图，不看顶栏日期） |
| **时长** | 50 ms |
| **音色描述** | 极轻的木鱼/Click：`E6`（1318 Hz）单音，5 ms 起音、30 ms 快速衰减。**无音高变化**（节拍音若变调会变成旋律，违反 A1 中性基调） |
| **音量** | **−18 dB**（最轻。仅在作者主动开启时播放） |
| **触发时机** | 播放中 `current_day` 每跨 1 个「节拍单位」触发一次。**节拍单位见 §3.2** |
| **节流** | 见 §3.2（按播放速率动态调整，高速播放时**自动静音**） |
| **优先级** | P4（最低，可被任何声音打断） |
| **默认状态** | 🔴 **关闭**。作者须在设置中主动开启 |

### 3.2 三处硬约束（关键裁定）

> 这三条是本规格**最重要的可执行裁定**，主程序须在实现中落地。

#### 约束 1：连续操作的音频节流 —— 裁定「干脆静音」

**场景**：缩放（滚轮一秒 20 格）、平移（持续拖拽）、拖时间轴（持续拖动）、笔刷涂抹（连续采样）。

**候选方案对比**：

| 方案 | 评价 | 裁定 |
|---|---|---|
| A. 每次事件播放（缩放每格一声） | 一秒 20 声 → 噪音 | ❌ 否 |
| B. 按位移量调制音高（滚得越快音越高） | **仍是连续噪音**，只是有音高变化。「调制」不会消除「连续」这个根本问题 | ❌ 否 |
| C. 节流（如 100 ms 一次） | 产生「突突突」的断续感，比连续更难受（像坏掉的扬声器） | ❌ 否 |
| D. **仅在操作开始/结束时播放** | 首尾两声——但首就是「鼠标按下」，末就是「鼠标松开」，等同于「点击音」；而我们已经裁定**点击音不做** | ❌ 否（连带回点击音） |
| **E. 干脆静音** | ✅ 彻底规避。**零实现、零资产、零风险** | ✅ **采纳** |

**结论（可执行条件）**：

```
if action ∈ { 缩放, 平移, 拖时间轴, 笔刷涂抹, 海拔滑块, 任何持续拖拽 } {
    play_nothing();   // 静音，不是节流，是根本不实现
}
```

> **为什么「干脆静音」是正确答案**：连续操作在编辑器里，**视觉反馈密度已经极高**（画面跟着动、数字实时变、地形实时刷）。声音在此处**没有任何信息增量**，只有风险。**任何「聪明」的调制方案，本质都是在为一个不该有声音的场景找补。**

#### 约束 2：事态播放的节拍音 —— 裁定「默认关 + 自适应 + 高速静音」

**基线依据**：§1.8「播放 = 时间轴以固定速率自动推进」，速率 `1 / 5 / 30 天/秒`，跨度自适应使任意链 ~20 秒播完。

**裁定**：

| 播放速率 | 节拍单位 | 节拍音间隔 | 裁定 |
|---|---|---|---|
| **1 天/秒** | 1 天 | 1000 ms | ✅ 播放（节拍音有效） |
| **5 天/秒** | 1 天 | 200 ms | ✅ 播放（5 次/秒，可接受） |
| **10 天/秒** | 5 天 | 500 ms | 🟡 切换到「每 5 天」 |
| **> 10 天/秒**（含 30 天/秒） | — | — | ❌ **自动静音** |

**可执行规则**：

```
tick_unit = max(1, floor(days_per_second / 5))   // 保证节拍音 ≤ 5 次/秒
if days_per_second > 10 { mute_tick(); }          // 高速播放直接静音
```

> **为什么高速必须静音**：30 天/秒时，若每单位响一声，一秒 30 声 = 噪音；若拉长间隔，节拍音就与「时间推进」脱钩，**变成无意义的 BGM**。**高速播放的视觉本身已足够强（轨迹飞速生长），声音在此处只会毁掉「播放」这件本该愉悦的事。**

**额外裁定**：跨地图播放（基线 §2.14）切换地图时**不播任何声音**（切图是视觉大事件，声音冗余）。

#### 约束 3：错误音去重 —— 裁定「聚合为单次」

**场景**：基线 §2.21 校验面板，一次校验可能产生 20 条错误（悬空引用、时间矛盾、轨迹不一致等）。

**候选方案**：

| 方案 | 评价 | 裁定 |
|---|---|---|
| A. 每条错误一声 | **20 声连响 = 恐怖**。绝对不能接受 | ❌ 否 |
| B. 每条错误一声 + 全局节流 200 ms | 20 条错误仍会响 4–5 声（持续 1 秒），且「响几声」还是不确定的 | ❌ 否 |
| C. 按严重度分级播放不同音（红/黄/绿） | 校验错误通常混合严重度，会产生音效鸡尾酒。且要求更多资产 | ❌ 否 |
| **D. 一次校验 = 一声** | ✅ 声音只承担「这次校验有错误」这一条信息；**有几条、什么级别，交给校验面板的视觉呈现** | ✅ **采纳** |

**可执行规则（伪代码）**：

```rust
// 校验流程：先聚合，再决定是否发声
let results = validate_project(&world);           // 可能返回 N 条
let error_count = results.iter().filter(|r| r.is_error()).count();

// 只在「整批校验完成」这一个时刻做判断
if error_count > 0 {
    play_sfx(SFX_UI_VALIDATE_FAIL);               // ← 恰好一次，无视 error_count
}

// 禁止在 validate_project 内部逐条错误调用 play_sfx —— 这是硬约束
```

**硬约束**：
- 🔴 **发声点在「校验完成」聚合层，不在「发现单条错误」的循环内。**
- 🔴 `error_count` **不参与音量/时长/音高计算**。1 条和 200 条，声音**完全一致**。
- 🔴 **校验结果无变化时（重新校验仍同样 20 条）是否重响**？裁定：**响**。理由：作者主动点了「校验」，他需要一个确认；若静音，他会怀疑按钮没生效。

---

### 3.3 全局节流规则汇总（可执行条件表）

| 声音 | 触发点 | 节流窗口 | 超窗行为 | 去重策略 |
|---|---|---|---|---|
| `Save_Success` | `Project::save` Ok | 800 ms | 丢弃 | 自动保存静默，仅手动保存发声 |
| `Validate_Fail` | 校验批次完成，error > 0 | 1500 ms | 丢弃 | **整批只响一次**（§3.2 约束 3） |
| `Undo` / `Redo` | `History` 实际改动 | **不节流** | 变体随机化代替 | 每次操作都发声（离散动作） |
| `Playback_Tick` | `current_day` 跨节拍单位 | 自适应（§3.2 约束 2） | 高速自动静音 | 默认关闭 |

**实现建议（给主程序）**：

```rust
// 一个通用节流资源，避免每个音效各写一份
#[derive(Resource, Default)]
pub struct SfxThrottle(HashMap<SfxId, f32>);   // SfxId -> 上次播放时刻

pub fn try_play(throttle: &mut SfxThrottle, id: SfxId, now: f32, window: f32) -> bool {
    if let Some(&last) = throttle.0.get(&id) {
        if now - last < window { return false; }   // 窗口内，丢弃
    }
    throttle.0.insert(id, now);
    true
}
```

## 四、混音与设置

### 4.1 音量总线分组

> **现实**：只有 5 个音效。但**分组必须保留**，因为它是「作者能分类关闭」的前提，且为未来扩展留位。

```
Master（总音量）
├── ui          —— UI 反馈（当前：Undo / Redo）
├── notice      —— 状态提示（当前：Save_Success / Validate_Fail）
└── playback    —— 播放（当前：Playback_Tick，默认关）
```

**总线分配表**：

| 总线 | 声音 | 默认音量 | 可单独关闭 |
|---|---|---|---|
| `Master` | — | **−6 dB** | ✅ |
| `ui` | `Undo` / `Redo` | −15 dB | ✅ |
| `notice` | `Save_Success` / `Validate_Fail` | −12 / −6 dB | ✅ |
| `playback` | `Playback_Tick` | −18 dB | ✅ **默认关** |

> **为什么只有 3 条总线**：总线不是越多越好。**总线的唯一作用是「让作者能成组关闭一类声音」**。当前只有「编辑反馈 / 状态提示 / 播放」三类**语义不同**的声音，因此 3 条恰好。**不需要**再分「SFX / UI / 环境」这种游戏式总线——本项目没有环境音。

### 4.2 全局静音与分项开关（**必须实现**）

| # | 能力 | 要求 |
|---|---|---|
| **S1** | **全局静音** | 一键（建议 `Ctrl+M` + 顶栏喇叭图标）关闭全部声音，**含播放音** |
| **S2** | **分总线开关** | 设置面板中 `ui` / `notice` / `playback` 各有独立开关 |
| **S3** | **主音量滑条** | 0–100%，映射到 `Master` 总线（内部线性 → 分贝） |
| **S4** | **状态持久化** | 音量与开关设置写入**工程外**的编辑器配置（**不写进工程目录**，遵守 P2「目录即工程」——设置不属于世界数据） |
| **S5** | **静音状态可见** | 静音时顶栏图标必须**视觉上明确改变**，避免作者忘记自己关过 |

> **P2 说明**：编辑器设置（音量、窗口布局）**不属于工程数据**，应存于工程目录**之外**（如 `%APPDATA%/worldview/settings.yaml` 或可执行文件旁）。若存进工程目录，会导致「拷贝工程 = 拷贝别人的音量设置」，违反 P2 的语义。

### 4.3 默认音量建议（**编辑器默认偏小**）

| 层 | 默认值 | 说明 |
|---|---|---|
| **Master** | **−6 dB**（= 滑条 ~70%） | 不是 100%。给作者留「往上调」的余量，而非让他先被吵到再往下调 |
| `ui`（撤销/重做） | −15 dB | 最高频声音 → 最轻 |
| `notice`（保存） | −12 dB | 高频声音 → 较轻 |
| `notice`（校验失败） | −6 dB | 全项目最响，但仍等同于「轻声提示」 |
| `playback` | −18 dB | 且**默认关闭** |

> **设计理由**：默认值的选择遵循「**失误代价不对称**」原则（§1.2 A3）。
> - 默认**偏小** → 作者没注意到保存音 → 他看了一眼脏标记 `●` 消失了 → **无损失**
> - 默认**偏大** → 作者连续编辑 2 小时被撤销音烦到 → **他去设置里关掉声音，从此所有提示音失效** → **永久损失**
>
> **编辑器音量的默认值，本质是在赌「作者会不会嫌吵」。必须赌「会」。**

### 4.4 音频格式与压缩（Bevy `bevy_audio` 支持）

**`bevy_audio` 原生支持格式**（截至 Bevy 0.14/0.15）：

| 格式 | 支持 | 本项目是否用 | 理由 |
|---|---|---|---|
| **WAV**（PCM） | ✅ | ✅ **推荐** | 无损、解码零成本、**短音效首选**。5 个音效总时长 < 0.6 秒 |
| **OGG Vorbis** | ✅（`vorbis` feature） | 🟡 备选 | 有损压缩，体积小。**本项目音效太短，用 OGG 反而引入解码开销与尾部瑕疵，不值得** |
| **MP3** | ❌ 需第三方 | ❌ | 专利与解码器问题，不用 |
| **FLAC** | ❌ 需第三方 | ❌ | 无损但无必要 |

**裁定：全项目音效用 WAV。**

**格式规格（全平台统一）**：

| 参数 | 值 | 理由 |
|---|---|---|
| **编码** | PCM WAV（线性 PCM） | 无解码成本，最短延迟 |
| **采样率** | **44.1 kHz** | 与常规一致。音效最高频 ~1.3 kHz，理论上 22.05 kHz 足够，但 44.1 kHz 免重采样、免兼容问题 |
| **位深** | **16-bit** | 5 个音效总体积 < 100 KB，无需为体积牺牲 |
| **声道** | **单声道（Mono）** | 音效均为 2D UI 音，**无空间定位需求**。单声道 = 减半体积 + 免去「该放左还是右」的无意义决策 |
| **响度** | 峰值归一化到 **−3 dBFS** | 各音效**相对**音量差异由 §4.3 的播放音量实现，**不靠素材本身的响度差**。素材统一响度便于维护 |

**为什么不用流式播放**：

| 音频类型 | 本项目做法 | 理由 |
|---|---|---|
| 短音效（< 1 s） | **常驻内存**（`Handle<AudioSource>` 预加载，`AudioPlayer` 播放） | 5 个音效共 < 100 KB，常驻成本可忽略 |
| 长音乐（BGM/环境音） | **不适用** | 🔴 **本项目无长音频**。若未来引入（如「事态播放配乐」），**必须流式**（Bevy 需自行实现 StreamingAudio 或分块），但**当前明确不做**，故无此实现负担 |

> 🔴 **硬约束**：**本项目不引入任何 > 5 秒的音频文件。** 因为长音频会立即引入「流式播放 / 内存 / 加载阻塞 / 3 秒启动上限（基线 §2.19）」一整套复杂度，而当前需求**完全不需要**。

### 4.5 平台差异

| 平台 | 差异 | 本项目影响 |
|---|---|---|
| **Windows / macOS / Linux**（桌面，主要目标） | 无特殊 | 统一用 WAV + 44.1 kHz + 16-bit |
| **Web（WASM，若未来支持）** | 浏览器首次播放需**用户手势**解锁 AudioContext | 🟡 **记录为已知约束**：若未来出 Web 版，音频系统须在首次用户交互后才初始化。**当前桌面版无此限制** |

> **本项目是单机桌面工具**（README P1），**不存在移动端 / 主机平台**，因此**不需要**做移动端的压缩取舍（OGG / 流式 / 内存上限）。

### 5.1 原型最小集（S0–S9，**必须有**）

| 项 | 推迟到 | 理由 |
|---|---|---|
| `SFX_UI_Playback_Tick` | Phase 5+（事态播放成熟后） | 默认关闭，非必要；且与播放机制（§3.2 约束 2）强耦合，应等播放逻辑稳定 |

### 5.3 明确不做（**写进规格，防止后续被「补上」**）

| 项 | 裁定 | 理由 |
|---|---|---|
| **BGM / 背景音乐** | ❌ **不做**（永久） | 与作者的工作音乐冲突；无信息价值 |
| **环境音 / 氛围音** | ❌ **不做**（永久） | 编辑器无「空间」，无环境一说 |
| **UI 点击音** | ❌ **不做**（永久） | 见 §2.2 |
| **笔刷/连续操作音效** | ❌ **不做**（永久） | 见 §3.2 约束 1 |
| **游戏化音效**（成就/连击/升级） | ❌ **不做**（永久） | 无游戏机制 |

| **错误分级音效**（红/黄/绿不同音） | ❌ **不做** | 见 §3.2 约束 3 |
| **空间音频（3D 衰减/遮挡/混响区域）** | ❌ **不做** | 2D 工具类界面，**无听者朝向、无空间概念**。全部音效为 2D UI 音 |

> **本表的用途**：**这份规格的主要价值是这张表。** 它明确告诉后续所有人——**这些不是「暂时没做」，是「设计上就不做」。**

## 六、实现约束

### 6.1 `bevy_audio` 使用要点

| # | 要点 | 说明 |
|---|---|---|
| **1** | **预加载 + `Handle` 复用** | 5 个音效用 `AssetServer::load` 预加载一次，播放时 `commands.spawn(AudioPlayer(handle.clone()))`。**禁止**每次播放都 `load`（会重复解码） |
| **2** | **单次播放实体自销毁** | Bevy 的 `AudioPlayer` 是一次性实体，播放完毕自动销毁。**不要**试图复用实体 |
| **3** | **音量控制走 `AudioSink` / `PlaybackSettings::with_volume`** | 音量在 spawn 时通过 `PlaybackSettings` 设定（`Volume::Decibels` 或 `Volume::Linear`） |
| **4** | **随机化在 spawn 时算，不在 asset 里** | 音高随机（±3%）通过 `PlaybackSettings::with_speed`（若可用）或**预生成 2 个变体文件**实现。**推荐预生成变体**（`PlaybackSettings` 的 speed 会影响时长，音高变体文件更可控） |
| **5** | **主音量可运行时改** | `GlobalVolume` 资源（Bevy 内置）控制 `Master`；分总线需自行聚合（在当前规模下，可简化为「每个音效 spawn 时读一次总线音量」） |
| **6** | **不要在 System 里做时间比较来判断播放** | 遵守 AGENTS §3.2：播放由「命令 / 事件」触发，不在渲染 System 里判时间 |
| **7** | **音频系统放 `wv-app`，且是可选 feature** | 音频属渲染/交互层。**`wv-core` / `wv-io` / `wv-edit` 零音频依赖**（AGENTS §2.1） |

> 🔴 **架构硬约束**：**音频代码只能出现在 `wv-app`。** 项目的音频需求极低，因此**不需要**引入独立的 `wv-audio` crate——**多一个 crate 就是多一份维护成本，而收益为零**。

### 6.2 音频资产的文件规格与放置目录

**目录结构**（在 `wv-app` 资源下）：

```
wv-app/
└── assets/
    └── audio/
        ├── ui/
        │   ├── sfx_ui_undo_01.wav
        │   ├── sfx_ui_undo_02.wav
        │   ├── sfx_ui_redo_01.wav
        │   └── sfx_ui_redo_02.wav
        ├── notice/
        │   ├── sfx_ui_save_success.wav
        │   └── sfx_ui_validate_fail.wav
        └── playback/
            └── sfx_ui_playback_tick.wav        # 可选，默认关
```

**文件规格（每个文件）**：

| 参数 | 值 |
|---|---|
| 格式 | WAV（PCM） |
| 采样率 | 44100 Hz |
| 位深 | 16-bit |
| 声道 | Mono |
| 峰值 | −3 dBFS |
| 尾部 | **必须干净**（无静音段、无淡入淡出残留）——素材末尾若有 20 ms 静音，连按时会听到「空隙」 |

### 6.3 程序化合成 vs 必须素材

| 音效 | 合成方式 | 是否需音频文件 |
|---|---|---|
| `SFX_UI_Undo` | 正弦 + ADSR 包络，频率 1175→880 Hz | ✅ **可程序化合成**（Bevy 需自建 `AudioSource`，或离线生成 WAV） |
| `SFX_UI_Redo` | 同上，频率镜像 880→1175 Hz | ✅ **可程序化合成** |
| `SFX_UI_Save_Success` | 正弦 + 三角波泛音，1046→1318 Hz | ✅ **可程序化合成** |
| `SFX_UI_Validate_Fail` | 方波 + 低通，880→698 Hz | ✅ **可程序化合成**（方波需简单滤波） |
| `SFX_UI_Playback_Tick` | 单音 + 快速衰减包络 | ✅ **可程序化合成** |

**裁定**：

> **全部 5 个音效均可程序化合成。原型阶段推荐「离线合成 WAV 素材」。**

| 方案 | 评价 | 裁定 |
|---|---|---|
| A. 运行时合成（Bevy 自建 `AudioSource`） | 需要写 DSP 代码，Bevy 支持有限，调试麻烦 | ❌ 否 |
| **B. 离线合成 WAV（用一段脚本生成素材文件）** | ✅ 一次生成，之后与普通素材无异；零运行时成本；可人工微调 | ✅ **推荐** |
| C. 采购/设计音频素材 | 本项目音效极简，采购是浪费 | ❌ 否 |

> **给主程序的建议**：写一段一次性脚本（Rust / Python 均可）**离线生成** 6 个 WAV 文件（含 2 个变体），生成后按 §6.2 放入 `assets/audio/`。**运行时只需 `AssetServer::load`**，与加载普通素材完全一致。**这样既零运行时成本，又完全避免采购/设计环节。**

## 七、术语登记建议

> 供 `GLOSSARY.md` 更新。按 AGENTS §6.1，本规格引入的新术语须即时登记。

| 术语 | 英文 | 定义 | 所属维度 |
|---|---|---|---|
| **音频节流** | Audio Throttle | 对同一音效在时间窗口内的重复触发做丢弃的策略，避免高频操作产生噪音。窗口值见 §3.3 | 音频 |

| **音频总线** | Audio Bus | 音效的语义分组（`ui` / `notice` / `playback`），用于成组控制音量与开关。本项目仅 3 条。见 §4.1 | 音频 |
| **编辑器默认音量** | Editor Default Volume | 编辑器类工具的默认音量应**偏小**（本项目 `Master` 默认 −6 dB），遵循「失误代价不对称」原则。见 §4.3 | 音频 |
| **UI 反馈音** | UI Feedback SFX | 用于「视觉够不到的反馈」的短促 2D 音效。本项目仅 5 个。见 §1.2 A1 | 音频 |

| 环境音 / 氛围音 | ❌ **明确不做** | 编辑器无空间概念 |
| 空间音频 | ❌ **明确不做** | 纯 2D 工具界面，无听者与空间 |
| UI 点击音 | ❌ **不做** | 高频骚扰，行业惯例静默 |

| **动画总监** | 面板开合、拖拽等**有动画的操作，音效一律不做**（§2.2）。无需为动画预留音频接口 |

| **技术架构** | 需在 `wv-app` 的 feature 中允许 `bevy_audio`；音频资产放 `wv-app/assets/audio/`；设置持久化**不得写入工程目录**（P2，见 §4.2 S4） |
