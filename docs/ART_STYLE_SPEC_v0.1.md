# World View 美术风格规格书 v0.1

> 项目：World View（worldview-rs）——单机优先、目录即工程、YAML 驱动的世界观构建工具
> 定位原文：**"以地理为底、时间轴为骨、人物与事件为魂的单机世界编辑器"**
> 角色：美术总监（甄塑之）· 本文为**风格定调与规格**，不含实现
> 引擎中立：不预设 Unity / Godot / UE / Bevy，规格只约束「长什么样、叫什么名、多大尺寸」

---

## 〇、一句话总纲

> **地图是「画出来的世界」（JRPG，可换皮）；软件壳是「量出来的工作台」（工具型，不换皮）。两者的唯一接头是"色板令牌"与"位图契约"，不是任何共享的视觉风格。**
>
> **2026-10-13 修正**：大地图的**默认视觉与交互**改为 Google Default Map 式地图壳（ADR-0008）。本节原文的 JRPG 结论不再约束默认地图；「软件壳工具型、地图层可替换」的分层结论继续有效。

分区依据（用户原话拆解）：

| 用户原话 | 判读 | 本文归属 |
|---|---|---|
| 「JRPG 风格」 | 整体基调来自 JRPG ——**但只允许体现在地图与叙事资产上** | §一、§三 |
| 「地图风格可以替换」 | 地图层 = **可替换层（Theme Pack）** | §二·B、§三 |
| 「软件风格偏向工具类型。不做替换」 | 软件壳 = **锁定层（Locked Shell）** | §二·A、§四 |

**为什么要分这两层（一句话给非美术同事）**：地图是**内容**——作者会想换一个世界观的味道；软件壳是**肌肉记忆**——用户第 300 小时和第 1 小时点的是同一个按钮，换皮只会制造事故。所以「地图可换、壳不可换」不是妥协，是正确切分。

## 一、JRPG 风格定义（风格锚点）

### 1.1 风格命名（可写进任何文档的唯一名称）

> **「十六位机晚期的日式 RPG 手绘质感 —— 高饱和水彩打底 + 硬边描线 + 斜投影俯瞰」**

关键词拆成四个可执行维度（**每个维度都必须能落到规格，不接受"有质感"这类表述**）：

| 维度 | 规格化定义 | 反面（禁止） |
|---|---|---|
| **视角** | **斜投影俯瞰（2.5D oblique top-down）**，非等距菱形（非 isometric）。地格为**正方形**，垂直方向按 `0.5×` 压缩表现高度 | 等距菱形网格；俯视正交平面（无立体感） |
| **描线** | **外轮廓硬边描线**，线宽 = 图块边长的 **1/16**（32px 图块 → 2px 线）；**深色描线但不纯黑**，取基色明度 −45% 同色相（见 §1.4） | 纯黑描线 `#000`；无描线；渐变柔边 |
| **上色** | **平涂为主 + 单层软阴影**；单一光源来自**左上偏上 45°**；阴影为**同色相压暗**（非加黑）；高光仅出现在水面/金属/晶体三类材质上 | 三点打光写实渲染；AO 重度烘焙；多层高光 |
| **饱和度** | 主调**中高饱和**（HSV 的 S 值区间 **45%–75%**），明度偏高（V 值 **60%–90%**）；大地色系（土/木/石）单独降到 S **25%–40%** 做呼吸位 | 全图统一高饱和（刺眼）；全图低饱和（灰暗） |

### 1.2 参考方向（画派 / 类型，不给具体作品——避免版权与"抄哪张图"的扯皮）

按**可执行度**排序，取的是「这一派解决什么问题」，不是「画成这个样子」：

| 参考派别 | 借鉴的是它的什么 | 落到本项目的规格 |
|---|---|---|
| **16-bit 晚期 JRPG 的地图表现**（斜投影、方形格、硬描线、一屏一屏的构图） | **可读性优先的格子语言**——每个格子在 1 秒内能读出"这是水/这是林/这是路" | §3.2 图块辨识度三原则 |
| **日式手绘水彩动画背景**（手绘边缘不规则、色块之间有留白、光线方向统一） | **色块的呼吸感**——不做等距噪声纹理，靠形状与色阶分区 | §1.4 色阶层级（每层最多 4 阶） |
| **日本近代地图绘卷 / 浮世绘风景版画**（分区块上色、边界不追求几何精确、山有走向笔触） | **"手绘地图"的历史感**——让作者觉得自己在画一张图，不是在刷一块网格 | §3.3 地形笔触语言 |
| **桌面 RPG 模组地图（TRPG 制图惯例）** | **符号系统**——山川城池是图标不是模型 | §3.4 地物符号语言 |

> **明确排除**：不采用 3D 写实、不采用像素风（Pixel Art）、不采用低多边形（Low-Poly）、不采用厚涂写实赛璐璐（Cel-shading 的 3D 版）。这四种各有其"必须重做全部资产"的刚性，与"地图可整包替换"的成本模型冲突。

### 1.3 主机感说明（标题里的"十六位机晚期"指什么）

指 **1–2 个世代之前的成熟 2D 主机游戏的视觉层级**，具体指标：

- **屏幕图块数**：最小可玩缩放下，**横 40 × 纵 23 格**（16:9，含 UI 遮挡后可见区 ≈ 36 × 20 格）
- **单格像素**：基准 **32×32 px**（@1x），**这是全套规格的锚点尺寸**，其余尺寸都是它的整数倍或半倍
- **可见色数**：单屏 **≤ 48 色**（含 UI）；调色板总量 **≤ 64 色**（一个 Theme Pack 的上限）
- **动画帧数**：地图静态资产**不带帧动画**（水/火的流动由程序化着色器或程序化绘制承担，见 §3.6）

#### 1.4.3 色板硬约束（验收项，可自动校验）

1. **`ui_link.*` 三色为「语义色」**，其**色相不作替换**（绿/黄/红语义在 UI 与地图两侧始终一致）；Theme Pack 只允许微调其明度，**色相差须 ≤ 8°**。
2. **派系色两两之间**：在 **CIEDE2000 ΔE ≥ 25** 且**色相差 ≥ 30°**。若是相邻势力（地图上会接壤），ΔE 提到 **≥ 35**。
3. **任意派系色 vs 任意地形基色**：ΔE ≥ 30（否则势力色块贴在同色地形上看不见）。
4. **颜色不得是唯一信息载体**（无障碍硬要求，继承设计侧 §1.3 的四维校验规则）：
   - 四态校验在**地图与 UI 两侧都**必须叠加形状/线型：可达 = 实心圆点 + 实线；迟到 = 三角 + 虚线；不可达 = 叉 + 断裂线；信息不足 = 问号 + 点线。
   - 派系势力范围除色块外，**必须带边界线型**（实线/虚线/点划线三档可组合）或**纹理填充**（斜线密度三档）。
5. 全部色值以 **sRGB 十六进制**书写；不得使用 alpha < 1 作为**语义区分**手段（半透明只用于图层叠加表现）。

### 1.5 光影基调

| 项 | 规格 |
|---|---|
| 主光方向 | **左上 45°**（与地图图标的高光/阴影方向**全局统一**，所有资产同向） |
| 明暗层数 | **最多 4 阶**（基色 / 亮部 +8% / 暗部 −15% / 描线 −45%） |
| 环境光 | 无全局环境光模拟；**图层透明度**取代之（见 §3.5 图层） |
| 地表投影 | 地物（山/建筑/树）**向右下投影**，投影长度 = 地物高度的 **0.5×**，色值 = 基色 −20% 明度、alpha 0.35 |
| 阴影色 | **同色相压暗 + 轻微偏冷**（色相 +8° 到 +12°，朝向蓝紫）；**禁止纯黑阴影** |

### 1.6 材质语言（四类，覆盖地图全部资产）

| 材质类 | 适用资产 | 平涂 | 高光 | 纹理 |
|---|---|---|---|---|
| **Matte 哑光** | 草/土/岩/木/布 | 单色平涂 | 无 | 无（靠形状分区） |
| **Water 水体** | 海/河/湖 | 双色（深浅水） | 横向条状高光 **2 条** | 无 |
| **Gloss 高光** | 金属/水晶/传送阵 | 单色平涂 | 1 个方形高光块（1/4 图块） | 无 |
| **Soft 柔软** | 雪/沙/雾 | 单色平涂 + 边界羽化 2px | 无 | 无 |

> **禁止**：噪声纹理、法线贴图、PBR 材质参数。全部资产按**"形状 + 色阶 + 描线"**三层构成，这是让地图风格能整包替换的前提（换皮时不需要重做材质管线）。

## 二、风格分层（可替换层 vs 锁定层）

### 2.0 分界总图

```
┌─────────────────────────────────────────────────────────────────┐
│  LOCKED SHELL 软件壳（工具型 · 不替换）                          │
│  · 面板架构 / 字体层级 / 间距刻度 / 控件状态 / 图标语言          │
│  · 唯一可变：3 个语义色令牌(ui_link.*) + 密度档位(紧凑/舒适)      │
│  ── 唯一接头 ── 色板令牌 + 位图契约（尺寸/命名/切分） ──        │
├─────────────────────────────────────────────────────────────────┤
│  THEME PACK 地图风格包（JRPG · 可整体替换）                      │
│  · palette / tileset / 地物符号 / 派系纹样 / 地貌笔触 / 图例装饰  │
│  · 一个 pack = 一个目录 = 一份 manifest                          │
└─────────────────────────────────────────────────────────────────┘
```

**唯一接头（这是整个可替换架构的关键）**：两层**不共享任何视觉风格元素**，只共享两样东西——

1. **色板令牌**（`ui_link.*` 三色，语义色，壳与地图同色）
2. **位图契约**（尺寸档位 / 命名格式 / 图集切分规则 —— 见 §三）

除此之外，地图的描线粗细、圆角、纹理、字体**一律不得渗透进软件壳**；软件壳的控件尺寸、间距、图标也**一律不得约束地图图块**。

### 2.A LOCKED SHELL —— 软件壳（工具型，不替换）

| 项 | 裁定 |
|---|---|
| 是否可替换 | **否**。这是产品身份的载体（"这是 World View"），也是用户的肌肉记忆 |
| 允许的变化 | 仅两项：① `ui_link.*` 语义色微调（跟随 pack，色相差 ≤ 8°）；② **密度档位**（紧凑 / 舒适，间距刻度整体 ×1.0 / ×1.25） |
| 明确拒绝 | 不做主题包、不做皮肤、不接入地图 pack 的字体与描线 |
| 视觉定位 | **工具型（Tool-like）**：中介者不是"游戏"，是"编辑器"。参考的是专业软件的中性语言，不是游戏的炫技语言 |

**为什么必须与地图风格解耦（三条硬理由）**：

1. **信息密度冲突**。JRPG 地图语言的立身之本是"大格子、大图标、一眼可读"；而编辑器要在 1 屏内同时呈现**地图 + 时间轴 + Inspector + 校验输出**（设计侧 §1.5 的四层导航、§1.10 的显示规则）。若把地图的粗描线、大圆角、高饱和带进面板，信息密度会被视觉噪声吃掉，四层时间轴导航会直接不可读。
2. **寿命冲突**。地图 pack 是**内容**，会被第三方作者替换、会随世界观变化；软件壳是**外壳**，生命周期跟着产品走。两者寿命不同步 —— 一旦耦合，每次换 pack 都要回归测试 UI，换皮成本从"换文件"变成"改代码"。
3. **承包商冲突**。地图资产可外包给画师按 pack 交付（只看 §三 的契约）；软件壳必须由主程序维护。耦合后外包边界模糊，交接必出事故。

### 2.B THEME PACK —— 地图风格包（JRPG，可整体替换）

#### 2.B.1 一个「风格包」由什么构成

> **一个 Theme Pack = 一个目录 + 一份 manifest + 5 类资产文件。换风格 = 换目录路径，不改任何代码。**

```
theme_packs/
└─ <pack_id>/                     # 例：ink_water / sumi_alt / nordic
   ├─ pack.yaml                   # ★ manifest：声明 id/name/version/格尺寸/切分规则/锚点
   ├─ palette.yaml                # 28 个色板令牌 → 十六进制（§1.4 结构）
   ├─ tiles/
   │   ├─ terrain_atlas.png       # 地形图集（§3.2 规格）
   │   ├─ terrain_atlas@2x.png    # 倍率档（可选，缺省则由引擎缩放）
   │   └─ transition_mask.png     # 地形过渡遮罩（§3.2.3）
   ├─ props/
   │   └─ props_atlas.png         # 地物符号图集（山/城/港口/关隘… §3.4）
   ├─ factions/
   │   └─ faction_marks.png       # 派系纹样（边界线型 + 填充纹理 §3.3.4）
   ├─ decor/
   │   ├─ frame.png               # 地图边框装饰
   │   ├─ compass.png             # 指北针
   │   └─ legend_*.png            # 图例底板
   └─ LICENSE.txt                 # 授权与署名（外包资产必须带）
```

#### 2.B.2 换风格时，到底换什么（逐项对照表）

| 换什么 | 是否被替换 | 说明 |
|---|---|---|
| 地形外观（色 + 图块） | ✅ 全换 | `palette.core.*` + `terrain_atlas` |
| 地物符号（山/城/港） | ✅ 全换 | `props_atlas` |
| 派系色与纹样 | ✅ 全换 | `palette.faction.*` + `faction_marks` |
| 描线粗细与颜色 | ✅ 全换 | `line.*` + 图块内自带的描线 |
| 地图装饰（边框/指北针/图例） | ✅ 全换 | `decor/` |
| **地图上承载的数据**（地点/边/势力范围/事件点位置） | ❌ 不动 | 数据与风格完全分离，换皮不触碰 YAML 数据 |
| **软件壳的所有视觉** | ❌ 不动 | 见 §2.A（唯一例外：`ui_link.*` 三语义色跟随） |
| **控件尺寸 / 间距 / 字体** | ❌ 不动 | 不接受 pack 覆盖 |

> **验收口径**：换一个 pack 后，**除地图画布区域外的任何像素都不应变化**（`ui_link.*` 语义色变化属于允许项，且必须记录在 pack 的 changelog）。

## 三、可替换性的美术侧约束（可替换层资产规格）

> 本节是**留给 tech-architect 定契约的输入**。每一条都是"美术侧能承诺的规格"，且**可被机器校验**。

### 3.1 网格与尺寸档位（全局锚点）

| 项 | 规格 |
|---|---|
| 基准格边长 | **32 px**（@1x），记作 `TILE_BASE` |
| 允许的格边长档位 | `16 / 24 / 32 / 48 / 64` px —— **必须是这 5 档之一**（pack 在 `pack.yaml` 中声明 `tile_size`） |
| 地图画面缩放 | 只允许 **整数倍**（×1 ×1.5 ×2 ×3）与 **0.5×**；**禁止任意非整数缩放**（会产生描线断裂） |
| 倍率资产 | 若提供 `@2x`，其格边长必须 = `tile_size × 2`，且**文件命名固定**（见 §3.7） |
| 地图画布最小可见格数 | 横 ≥ 36 格、纵 ≥ 20 格（与 §1.3 一致） |

### 3.2 地形图集（`terrain_atlas`）

#### 3.2.1 布局契约

| 项 | 规格 |
|---|---|
| 图集组织 | **规则网格**，从左到右、从上到下排列；**一图块 = 一格**，无 padding、无 margin |
| 索引方式 | **行列索引从 0 起**（`row 0, col 0` = 第 1 块），索引表由 `pack.yaml` 显式声明，**不可靠默认顺序** |
| 图集尺寸 | 边长 = `tile_size × N`（N 为图集列数），**必须是 2 的幂**（`1024 / 2048 / 4096`），保证 GPU 友好 |
| 块类型清单（必须齐全） | 10 种 `core` 地形 × **每地形 4 个变体**（v0/v1/v2/v3）= 40 块 |
| 变体用途 | 打散同质化的随机贴法（引擎按坐标哈希选变体，**pack 不控制概率**） |
| 边界衔接 | 相邻不同地形之间**用 transition_mask 叠加**处理（见 3.2.3），**不要求画 47 块自动瓦片（autotile）** |

#### 3.2.2 图块辨识度三原则（验收项）

单块图块在 32×32 下必须满足：

1. **剪影可辨**：把图块去色转纯黑剪影，与同图集中**任意其他地形**的剪影**形态差异明显**（靠**明度差**而非色相区分，因为去色后色相不参与）。
2. **1 秒可读**：把图块放大到 128×128，一个未受训的人 **1 秒内**能说出它属于"水/地/山"哪一类。
3. **无方向性依赖**：同一地形的 4 个变体，**不得依赖"必须与特定邻居搭配才成立"**（变体是纯打散，不承载连接语义）。

#### 3.2.3 地形过渡（`transition_mask`）

| 项 | 规格 |
|---|---|
| 形式 | 单张**灰度遮罩**（`8-bit`，白=完全显示上层，黑=完全显示下层） |
| 尺寸 | 与 `tile_size` 同尺寸（每块 1 格），**不做 47 块全集** |
| 过渡带宽度 | `tile_size / 4`（32px → 8px），**固定比例，随 tile_size 缩放** |
| 方向 | 遮罩**只提供 4 个正向（上下左右）+ 4 个对角 = 8 向**；其余由引擎组合 |

### 3.3 地貌笔触语言（手绘感的落地方式）

> 目标：让地图**看起来是画的**，而不是**看起来是格子拼的**。手段是"形状不规则 + 边界不精确"，**不靠噪声纹理**。

| 笔触规则 | 规格 |
|---|---|
| 海岸线 | 允许 **±2 px** 的抖动（在格内），**不得跨格**（跨格会破坏格子可读性） |
| 山体走向 | 山形**沿一条隐式山脊线排列**；单山高 = `tile_size × 1.0`（可溢出到上方格 0.5 格，溢出部分**允许**，但必须**向上溢出而非向下**） |
| 森林 | 用**团簇**而非单株：每格 3–5 个树冠团，树冠直径 = `tile_size / 4` |
| 河流 | 河宽 = `tile_size / 4`（32px → 8px），**不显示格界**（河流在视觉上连续） |
| 道路 | 路宽 = `tile_size / 8`（32px → 4px），两侧各带 **1px** 浅色路肩 |
| 禁止 | 任何依赖"看懂格子线"的视觉设计（格子必须是工具提示，不是画面主体） |

### 3.4 地物符号语言（`props_atlas`）

> 地物是**图标**，不是模型。这是把地图做轻、把替换做廉价的核心决定。

| 项 | 规格 |
|---|---|
| 符号尺寸档位 | `1×1` / `2×2` / `3×3` 格（即 32 / 64 / 96 px @ base 32）；**禁止非整数格尺寸** |
| 锚点 | 每个符号在 `pack.yaml` 中声明 `anchor`（`bottom_center` 默认，用于坐落在格上） |
| 统一视觉语汇 | 全部符号共用：① 同一描线宽（`tile_size/16`）；② 同一投影方向（右下，长度 = 符号高 ×0.5）；③ 同一"底座"留白（底部 1/8 不画内容，用于与地面衔接） |
| 必须齐全的符号 | 城 / 镇 / 村 / 关口 / 港口 / 桥 / 渡口 / 矿 / 神社·寺 / 战场遗迹 / 驿站 —— **共 11 类** |
| 地点类型联动 | 符号与数据层的地点类型**一一对应**（`pack.yaml` 声明 `props[].place_kind` 映射表，见 §3.7.2） |

### 3.5 图层与风格的关系（关键约束）

本项目是**图层化编辑**（README 原则五：地形/疆界/影响力/道路/事件点分层）。美术侧承诺：

| 图层 | 风格归属 | 渲染承诺 |
|---|---|---|
| 地形层 | **属于 pack** | pack 提供图集；不提供运行时生成算法 |
| 疆界层 | **属于 pack**（线型 + 色） | 提供 3 档线型（实/虚/点划）与 3 档填充纹理 |
| 影响力层 | **属于 pack**（色阶） | 提供**热力色阶 5 档**（同色相 5 个明度），alpha 由引擎按权重给 |
| 道路层 | **属于 pack**（图块） | 与地形同图集 |
| 事件点 / 故事便签 | **属于壳**（锁定） | 见 §4.6；**不进 pack** —— 因为它们是"工具的标记"，不是"世界的景物" |

> **这条边界是本设计最容易扯皮的地方，明确钉死**：**"世界的景物"归 pack，"工具的标记"归壳。**

### 3.6 程序化绘制承诺（零外部资源时的落地方式）

对**不引入任何图片文件**的 pack（合规的纯代码 pack），美术侧的等价规格：

| 资产 | 程序化等价的规格 |
|---|---|
| 地形图块 | 单色填充矩形 + 1px 内描线；水面加 2 条水平高光条（位置：块高 30% / 60%，宽 = 块宽 0.7×） |
| 森林 | 每格 4 个正圆（半径 = 块宽 0.125×，位置由格坐标哈希决定，偏移 ≤ 块宽 0.3×） |
| 山地 | 1 个等腰三角形（底 = 块宽 0.8×，高 = 块高 0.7×）+ 右侧 1 个阴影三角（偏移 +0.15× 块宽） |
| 城市符号 | 1 个正方形（边长 = 块宽 0.5×）+ 顶部 1 个小三角（城垛意向） |
| 描线 | 1px 描边（描边色取 `line.on_*` 按底明度自动选） |
| 合批建议 | **同色同尺寸的块必须可合批**：所有地形块由"1 个矩形 + 若干基础图元"组成，引擎按 `(材质, 色, 尺寸档)` 合批；**禁止逐块独立材质** |

> 这是为了让**程序化 pack 与位图 pack 能被引擎用同一套接口消费**——这是可替换架构能做到"零资源"与"全美术"双模式的前提。

### 3.7 可替换性的硬约束清单（给契约的最小集）

| # | 约束 | 校验方式 |
|---|---|---|
| C1 | `pack_id` 为 `[a-z][a-z0-9_]{1,31}`，**与目录名一致** | 正则 |
| C2 | `tile_size ∈ {16,24,32,48,64}` | 枚举 |
| C3 | 图集尺寸 = `tile_size × N`，且为 2 的幂 | 取模 |
| C4 | 图集块索引在 `pack.yaml` 显式声明（**不依赖文件内默认顺序**） | schema |
| C5 | `palette.yaml` 必须提供 §1.4.1 的 **28 个令牌全集**，缺一不可（缺则用默认 pack 补齐，但须警告） | schema |
| C6 | 派系色数量 = `faction.a..f` **6 个 + neutral + player = 8 个**，可空但键必须在 | schema |
| C7 | `ui_link.*` 色相差 ≤ 8°（相对默认 pack） | 色度计算 |
| C8 | 派系色两两 ΔE ≥ 25；相邻势力 ≥ 35；vs 地形基色 ΔE ≥ 30 | 色度计算 |

| C10 | `pack.yaml` 声明 `schema_version`，与主工程的 schema 演进解耦 | schema |

## 四、UI 视觉规格（LOCKED SHELL · 工具型软件壳）

### 4.1 定位与视觉原则（五条，按优先级）

| # | 原则 | 可执行表述 |
|---|---|---|
| **P1** | **信息优先于装饰** | 任何装饰元素（阴影/描线/圆角）不得降低相邻文字的对比度；正文对比度 ≥ **4.5:1**，关键数值 ≥ **7:1** |
| **P2** | **中性色主导，语义色稀缺** | 界面基底只用**无彩灰阶**（8 档）+ 1 个品牌色（`accent.select` 金）；语义色（绿/黄/红/紫）**只出现在语义位置**，全屏同时出现的语义色 **≤ 3 种** |
| **P3** | **层级靠间距，不靠线框** | 分组用**间距**与**背景明度差**（≥ 6% 明度）表达；**禁止**用大量 1px 边框切分（"表格化"是最常见的工具 UI 病） |
| **P4** | **可预测 > 有个性** | 同一控件在所有面板中视觉完全一致（不用"主面板大一点、侧栏小一点"）；用户第 300 小时的肌肉记忆优先 |
| **P5** | **密度可调，结构不变** | 只提供 **紧凑 / 舒适** 两档（间距刻度 ×1.0 / ×1.25）；**控件尺寸与排布结构不随档位改变** |

### 4.2 字体层级（只用系统字体栈 / 已授权字体）

| 令牌 | 用途 | 字号(px) | 字重 | 行高 | 备注 |
|---|---|---|---|---|---|
| `font.display` | 面板大标题、空态主文案 | 20 | 600 | 1.3 | 仅在空态/欢迎页出现 |
| `font.title` | 面板标题、分组标题 | 14 | 600 | 1.4 | — |
| `font.body` | 正文、属性值、列表项 | 13 | 400 | 1.5 | **主力字号** |
| `font.label` | 字段名、表头、单位 | 12 | 500 | 1.4 | 常用"次要色" |
| `font.caption` | 辅助信息、内部序号（设计侧 §1.10 的"第 N 天"） | 11 | 400 | 1.4 | **永不占主位** |
| `font.mono` | **全部数字**（日期、年份、天数、距离、耗时） | 13 | 400 | 1.5 | **等宽，硬要求** |

**字体硬约束**：

1. **数字必须等宽（tabular figures）** —— 设计侧 §1.10 明确要求"年份数字等宽字体"、超长年份（5 位）不得跳动。
2. **必须使用系统字体栈**，不引入未授权字体文件。建议栈：
   - 中文：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`
   - 数字/代码：`ui-monospace, "Cascadia Mono", "SF Mono", Consolas, monospace`
3. 中英混排：**中文字号 ≥ 12px**（低于 12px 的中文在 1x 屏不可读）；英文可到 11px。
4. **字重只用 2 档**（400 / 600）；禁止 100–300 与 700–900（低分屏糊）。

> **2026-10-16 修正（ADR-0019，用户裁定）**：硬约束 2「必须使用系统字体栈，不引入
> 未授权字体文件」被修正为「**打包授权字体**：拉丁 **Inter**、中文 **Noto Sans SC**」
> （OFL-1.1，文件入 `crates/wv-app/assets/fonts/`，编译期嵌入）。理由：设计稿锁定
> Inter，系统中文字体随平台字形差异大，打包换来跨机器渲染一致。「中文用 Open Sans」
> 的落地口径：Open Sans 无 CJK 字形，取 Google 与之配套的 **Noto Sans SC**。
> 修正后仍**只用 Regular 一档文件**（egui 无合成粗体）——本表 600 字重列待字重
> 接线任务落地，约束 1 / 3 / 4 继续有效。

### 4.3 间距刻度（8 基准网格）

| 令牌 | 值(px) | 典型用途 |
|---|---|---|
| `space.0` | 0 | 紧贴 |
| `space.1` | 2 | 图标与文字间隙 |
| `space.2` | 4 | 行内元素间距、徽标内边距 |
| `space.3` | 8 | **最小间距单位**、控件内边距（纵向） |
| `space.4` | 12 | 控件内边距（横向）、同类字段间距 |
| `space.5` | 16 | **分组内间距** |
| `space.6` | 24 | **分组之间间距** |
| `space.7` | 32 | 面板内边距、大分区间距 |
| `space.8` | 48 | 空态留白 |

规则：
- **所有间距必须取自本表**（禁止 5 / 7 / 13 / 18 等魔法值）。
- 紧凑档 = 表值 ×1.0；舒适档 = `space.3` 及以上 ×1.25 后**四舍五入到整数**（`space.1/space.2` 不缩放）。
- **控件高度刻度**：`24`(紧凑) / `28`(标准) / `32`(主操作)；**不允许其他高度**。

### 4.4 控件状态清单（只描述视觉差异，不改交互逻辑）

> 适用范围：按钮、输入框、下拉、复选/单选、列表项、标签页、开关。**每个控件必须齐备以下 5 态**。

| 状态 | 视觉差异（工具型壳） | 备注 |
|---|---|---|
| **默认 Default** | 底 `#2A2D33`（深色壳）或 `#F5F5F7`（浅色壳）；文字 `font.body` 主色；边框 = 无（P3） | 深/浅壳由 `shell_mode` 决定，**不随 pack 变化** |
| **悬停 Hover** | 底色明度 **+6%**；光标 `pointer`（**光标是交互逻辑，此处仅记录**） | 悬停**不加边框、不加阴影** |
| **按下 Pressed** | 底色明度 **−8%**；内容整体**下移 1px** | 1px 位移是"按下去"的唯一暗示 |
| **禁用 Disabled** | 整体 alpha **0.4**；文字降为 `font.label` 次要色；**不允许仅靠颜色变淡**——必须同时给**禁用姿态**（如：去掉 1px 位移基准 + 光标 `not-allowed`） | 无障碍：色觉差异下仍需可辨 |
| **选中 Selected** | 左侧 **3px** `accent.select` 竖条 + 底色 `accent.select` @ alpha 0.12 + 文字 600 字重 | 竖条是**形状**载体，不依赖颜色 |
| **聚焦 Focus**（附加态） | **2px** `accent.select` 外描边（不占布局，用 outline） | 键盘可达性硬要求 |

**校验专用状态（与设计侧 §1.3 四维校验对齐，语义色只在此出现）**：

| 语义 | 色令牌 | 形状/线型（必须叠加） |
|---|---|---|
| 可达 Reachable | `ui_link.reachable` | 实心圆点 + 实线 |
| 迟到 ArrivesLate | `ui_link.late` | 三角 + 虚线 |
| 不可达 Unreachable | `ui_link.unreachable` | 叉 + 断裂线 |
| 信息不足 Unknown | 中性灰 `#8C8C94` | 问号 + 点线 |

### 4.5 图标语言

| 项 | 规格 |
|---|---|
| 尺寸档位 | **16 / 20 / 24 px** 三档（对应行内 / 常规 / 主操作）；**不做 32+** |
| 网格 | 图标绘制在 **20×20 画布**内（16px 图标留 2px 安全边） |
| 线宽 | 统一 **1.5px**（在 20px 画布上）；**禁止混用 1px / 2px** |
| 风格 | **线性图标（outline）**，圆头端帽（`stroke-linecap: round`），圆角连接；**不做面性图标、不做渐变、不做多色** |
| 颜色 | 单色（`currentColor` 继承文字色）；**唯一例外**：校验/警告类图标可用语义色 |
| 视觉重量 | 所有图标的"墨水量"（描线总长）控制在 ±20% 内，保证一排图标视觉均重 |
| 与地图的边界 | **图标 = 工具符号（壳），不进 pack**；地图上的地物符号（§3.4）是**另一个体系**，两者不得互相借用 |

**必备图标族（阶段二起）**：地图树 / 图层显隐 / 图层锁定 / 时间轴游标 / 播放 / 跳转 / 放大 / 缩小 / 撤销 / 重做 / 校验 / 警告 / 故事便签 / 历法徽标（设计侧 §1.11 ②）/ 面板折叠。

### 4.6 面板布局原则

依据设计侧 §1.5（四层时间轴导航）与 §1.10（显示规则），壳的最小面板架构：

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏 Top                                      高 40px            │
│ [工程名] ......... [历法徽标] [密度档] [撤销][重做] [校验]        │
├────────┬──────────────────────────────────────┬──────────────────┤
│ 左栏   │  地图画布 Canvas                     │  右栏 Inspector  │
│ 240px  │  （THEME PACK 渲染区）               │  280px           │
│ 地图树 │  ── 唯一受 pack 影响的区域 ──        │  属性 / 校验输出 │
│ 图层面板│                                      │  历法徽标常驻    │
│        ├──────────────────────────────────────┤                  │
│        │  时间轴 Timeline    高 96px           │                  │
│        │  L1 全局条 / L4 纪元鸟瞰（跨度自动选）│                  │
│        │  L2 语义锚点 / L3 年月日跳转          │                  │
├────────┴──────────────────────────────────────┴──────────────────┤
│ 状态栏 Status                         高 24px                    │
│ [跨度预警横幅位] ... [内部序号诊断(仅开发模式)]                   │
└──────────────────────────────────────────────────────────────────┘
```

| 原则 | 规格 |
|---|---|
| 面板宽度 | 左 240 / 右 280 / 顶 40 / 状态 24 / 时间轴 96 —— **均为可折叠**，折叠后收成 24px 竖条（带图标） |
| 画布为唯一弹性区 | 其余面板固定宽，画布吃掉剩余空间；**画布不得小于 36×20 格**（§3.1） |
| 分组与标题 | 面板内用 `font.title` + `space.6` 上间距分组；**不用边框**（P3） |
| 信息层级 | 主显（日期/名称）用 `font.body` 主色；次显（内部序号/单位）用 `font.caption` 次要色；**次显永不占主位**（设计侧 §1.10 硬要求） |
| 空态 | 每个面板必须设计空态：居中 `font.body` 说明 + 1 个主操作按钮（`font.body` / 高 32px） |
| 超长年份（≥5 位） | 窄栏内**允许换行**；时间轴刻度**强制单行 + 省略号**（`1463…`），悬停看全（设计侧 §1.10 ①③） |
| 刻度标签 | **永不重叠**，自动降密度；**宁可少标不可叠字**（设计侧 §1.10 ①） |
| 色觉安全 | 形状/线型/文字的区分手段优先于颜色（§1.4.3 ④） |

### 4.7 壳的深/浅模式

| 项 | 规格 |
|---|---|
| 支持 | 深色（默认）/ 浅色 两套，**属于壳，不属于 pack** |
| 中性灰阶 | 各 8 档（`N0` 最暗 … `N7` 最亮）；深色壳基底 `#1E2024`，浅色壳基底 `#F5F5F7` |
| 与 pack 的关系 | **无**。pack 换皮时壳不跟随换深浅 |
| 唯一连通 | `ui_link.*` 三语义色在深/浅壳各需一个变体（保证对比度 ≥ 4.5:1），由**壳**维护，不由 pack 维护 |

## 五、命名与交付规范

### 5.1 命名格式（全项目统一）

| 类别 | 格式 | 示例 |
|---|---|---|
| 地形图块（单块导出，仅调试用） | `TILE_<terrain>_v<N>.png` | `TILE_forest_v2.png` |

| 派系纹样 | `FAC_<faction_id>_<pattern>.png` | `FAC_player_hatch_h.png` |
| 地图装饰 | `DEC_<用途>.png` | `DEC_compass.png` |
| 地图图例 | `LEG_<主题>.png` | `LEG_terrain.png` |
| **Theme Pack 目录** | `<pack_id>/`（小写下划线） | `ink_water/` |
| **Theme Pack 清单** | `<pack_id>/pack.yaml` | — |
| **Theme Pack 色板** | `<pack_id>/palette.yaml` | — |
| UI 图标 | `UI_<页面或域>_<控件>[_<状态>].svg` | `UI_timeline_play.svg`、`UI_layer_eye_hidden.svg` |
| 面板插图 / 说明图 | `ILL_<用途>_<主体>.svg` | `ILL_empty_map_state.svg` |

> **图集内不写字（零文字）**：**任何文字都不允许烘焙进图块或图集**（文字属于壳，属于字体系统，且必须可本地化）。这是硬约束 —— 违规的 pack 会因换语言而失效。

### 5.2 目录规范

```
assets/                                 # 全项目资产根
├─ shell/                              # ★ LOCKED：软件壳（不进 pack）
│   ├─ icons/                          # UI_*.svg
│   ├─ ill/                            # ILL_*.svg（空态/引导/说明）
│   └─ frame/                          # 壳自身的九宫格（面板容器）
└─ theme_packs/                        # ★ SWAPPABLE：地图风格包
    ├─ _default/                       # 内置默认 pack（必须存在，作为兜底）
    │   ├─ pack.yaml
    │   ├─ palette.yaml
    │   ├─ tiles/…
    │   ├─ props/…
    │   ├─ factions/…
    │   ├─ decor/…
    │   └─ LICENSE.txt
    └─ <pack_id>/                      # 用户 / 第三方 pack，同构
```

**规则**：
1. 壳资产与 pack 资产**物理隔离**（不同根目录），**命名前缀也不同**（`UI_` / `ILL_` vs `TILE_` / `PROP_` / `FAC_` / `DEC_` / `LEG_`）。这是可替换性的**最后一道保险**：路径与命名都不会被"顺手改一下"破坏。
2. `_default` 前缀下划线代表"内置保留"，**用户 pack 不得使用下划线开头的 id**（C1 已约束）。
3. pack 目录**自包含**：pack 不得引用 `assets/shell/` 或别的 pack 的任何文件。

### 5.3 九宫格与拉伸（壳专用）

| 资产 | 九宫格边距（@1x） | 说明 |
|---|---|---|
| 面板容器底板 | 上 8 / 右 8 / 下 8 / 左 8 | 圆角 4px 落在角块内 |
| 按钮底板 | 上 4 / 右 8 / 下 4 / 左 8 | 左右随文字伸缩 |
| 提示气泡 | 上 12 / 右 12 / 下 16 / 左 12 | 底部留尖端空间 |
| 徽标 / 标签 | 不拉伸（定宽） | 文字超长则截断 + 悬停看全 |

> 地图资产**不使用九宫格**（图块是规整网格，拉伸无意义）；这条规则**只属于壳**。

### 5.4 倍率与适配

| 项 | 规格 |
|---|---|
| 壳资产（SVG 图标） | **矢量优先**，不提供倍率档；若必须位图，按 `@1x/@2x/@3x` 三档 |
| pack 图集 | 基准 `@1x` 必须提供；`@2x` 可选，**缺省时由引擎整数倍放大（只能在 §3.1 允许的缩放档位内）** |
| 屏幕适配 | 画布按安全区留 `space.5`(16px) 内边距；顶/底栏不得被系统栏遮挡（安全区由壳负责，pack 不感知） |
| 最小窗口 | 1280×720（此时左栏可折叠，画布仍需 ≥ 36×20 格 @ tile 32 的 60% 缩放）；**建议 1440×900+** |

### 5.5 交付与版本

| 项 | 规格 |
|---|---|
| pack 版本 | `pack.yaml` 的 `version` 用 `MAJOR.MINOR.PATCH`；**任何色彩/图集改动都 +MINOR** |
| 变更记录 | pack 根目录 `CHANGELOG.md`；**`ui_link.*` 变化必须显式记录**（因为它是唯一穿透到壳的项） |
| 授权 | `LICENSE.txt` 必备；外包资产须含署名要求 |
| 交付形式 | 目录打包为 `.zip`，解压到 `assets/theme_packs/<pack_id>/` 即可用 |
| 交付校验 | §3.7 的 C1–C10 **全部通过**方可入库 |

## 六、给架构总监（tech-architect）的契约输入清单

> 以下是**美术侧必须被技术契约覆盖**的字段与约定。我把它们写成"契约必须包含什么"，而不是"引擎该怎么实现"——实现方式归你。

**A. 必需字段（缺任一，可替换性不成立）**

1. **`pack_id`**（字符串，正则 `[a-z][a-z0-9_]{1,31}`，且 == 目录名）—— pack 的唯一身份，用于切换、存档、诊断。
2. **`tile_size`**（枚举 `16|24|32|48|64`）—— 全套尺寸锚点；**它决定了图集尺寸、过渡带宽、描线宽、图标投影长度的推导基准**。若契约允许 `tile_size` 变化，则这些比例必须由它推导而非硬编码。
3. **`atlas_layout`**（块索引表：地形/地物 → `(row, col)`）—— **不得依赖文件内默认顺序**；契约必须要求显式声明。
4. **`palette`**（28 令牌全集的键名与语义：`core` 10 / `faction` 8 / `ui_link` 3 / `line` 3 / `accent` 4）—— 键名固定、值可变。**键名缺失必须报错而非静默 fallback**（可 fallback 到 `_default`，但必须给可见警告）。
5. **`asset_paths`**（每类资产的路径模板：`tiles.atlas` / `props.atlas` / `factions.marks` / `decor.frame` 等）—— 契约必须要求这些路径**从 pack 根相对声明**，且**禁止绝对路径与跨 pack 引用**。
6. **`props[].place_kind`**（地物符号 ↔ 数据层地点类型的**映射表**）—— 这是美术资产与 domain model 的**唯一连接点**。契约必须容忍"某地点类型无对应符号"（降级为通用圆点，而非崩溃）。

**B. 必需约定（不是字段，是规则）**

7. **两层物理隔离约定**：`assets/shell/` 与 `assets/theme_packs/` 必须是**两个独立的资产根**；契约必须保证**壳的任何加载路径都不经过 pack 目录**（反之亦然）。这是"地图可换、壳不可换"从设计变成事实的关键。
8. **`ui_link.*` 是唯一穿透项**：契约必须让 pack 的 3 个语义色能**单向**流向壳的语义色令牌，且**壳不得从 pack 读取任何其他值**。若实现上做不到单向，至少要在契约中**显式声明这 3 个键是唯一允许的覆盖项**，其余覆盖一律拒绝。
9. **缩放白名单**：地图画面缩放只允许 `{0.5, 1, 1.5, 2, 3}`；契约必须拒绝任意非整数缩放（描线会断）。
10. **`@2x` 缺省语义**：`@2x` 缺失时**不得报错**，须按整数倍档位降级；契约要写明降级策略与警告文案。
11. **零外部资源模式**：若 pack 不提供位图（纯程序化 pack），契约必须允许 **`atlas` 字段为空**，并由引擎走 §3.6 的程序化绘制分支；**两种 pack 必须被同一接口消费**。
12. **`schema_version` 与主工程解耦**：pack 的 schema 版本独立于工程的 schema_version（后者按设计侧 §2.8 已升 3）。pack 契约必须能"读旧 pack + 给警告"，**不得因工程升级而使旧 pack 失效**。
13. **切换的原子性与"状态不动"**：切换 pack 时**不得触碰任何工程 YAML 数据**（这是 §2.B.2 的验收口径）；契约需保证切换是**纯渲染层资源替换**，不产生 `EditCommand`、不进 Undo 栈。
14. **可校验性**：§3.7 的 C1–C10 必须能被一个**独立的校验器**跑出来（命令行即可），输出**逐条 pass/fail**，而不是一个笼统的"pack 无效"。

**C. 我的承诺（美术侧对契约的反向承诺）**

15. 美术侧承诺：**任何 pack 都遵循同一套命名（§5.1）、同一套目录（§5.2）、同一套尺寸档位（§3.1）**。若你需要新增一个尺寸档位或一类资产，**由我先改本规格书**，再进契约 —— 不允许"某个 pack 特例"。
16. 美术侧承诺：**`_default` pack 永远存在且永远满足 §3.7 全集**，可作为任何校验失败时的兜底基准。
