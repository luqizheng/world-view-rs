### 5.1 必须改口径的条目（锁值与实现不兼容）

#### T19 —— 字面公式不可实现（自相矛盾）

锁值为 `amp = clamp(2.0×scale, 0.05, 0.45)`，注记要求「scale 大 = 远观取 0.45；
近观编辑 `scale ≈ 0.25` 取 0.05」。但 `scale` 的两种可能读法都走不通：

| 读法 | 远观（0.5 px/格） | 近观编辑（4 px/格） | 与注记一致？ |
|---|---|---|---|
| `scale` = 每像素格数 = `1/px_per_cell` | `2×2.0 = 4.0` → 0.45 ✓ | `2×0.25 = 0.5` → **0.45**（注记要 0.05） | ✗ |
| `scale` = 每格像素数 = `px_per_cell` | `2×0.5 = 1.0` → 0.45 ✓ | `2×4 = 8` → **0.45** | ✗ |

即时按字面公式，**近观编辑恒得最大抖动**，与「保证点选精度」的设计意图
完全相反。故字面公式作废。

**实际口径**（`material::warp_amp()` 的唯一实现源，带 3 条单测锁住端点与值域）：

```
amp = clamp(0.225 / px_per_cell, 0.05, 0.45)     [单位：格]
```

标定依据是注记的两个端点：0.5 px/格 → 0.45（恰好触上限）；4 px/格 → 0.0563 ≈ 0.05。
若后续裁定回到字面公式，只需改函数体，shader 与 uniform 布局不动。

**待你裁定**：是否将上式升为 T19 v1.1 正式值。在此之前代码与锁表**不一致
且代码为准**——这是本表唯一的「代码领先规格」处。

#### T2 —— R 通道是 0/255，不是 0/1

锁值写 `R = surface(0 水 / 1 陆)`。实现必须改成 **255 陆 / 0 水**：
`Rgba8Unorm` 采样后归一化，字节 `1` → `1/255 ≈ 0.0039`，shader 里
`attr.r > 0.5` **恒为假**——实测表现为 90% 陆地全被当成水渲染。
**语义未变**（仍是水陆二值），变的是编码刻度。

#### T24 —— biome 边界做不到 0.8 屏幕像素

锁值 `LINE_PX = 0.8`。但 T27 的 4 邻检测只能给出**整格**判定，天然渲成
「1 格宽」的带，其屏幕宽度 = `px_per_cell`：

| 缩放 | 4 邻检测的带子宽度 | T24 目标 0.8 px |
|---|---|---|
| 0.8 px/格 | 0.8 px | ✓ 恰好 |
| 8 px/格 | 8 px | **10×** |
| 32 px/格 | 32 px | **40×** |

实现按 T24 的精神（「边界是暗示不是划线」）在 `px_per_cell ≫ 0.8` 时**淡出**，
而不是画一条 1 格宽的假线。**结论**：T24 的 0.8 px 只在远观档成立；
近观档该线的实际语义是「淡出的暗示」，不是定宽线。与 Q3 裁定（不做 biome SDF）
一致——精确亚格边界需 SDF，属 P4。

### 5.4 需要你注意的一处真实风险（T32/T33 未做）

意味着 `cell_px < 1` 时 GPU 只能对 1 个 texel 邻域做双线性——**是欠采样不是平均**。

demo 的截图看着没问题，因为测试地形是平滑 fbm；换成高频地形（细碎岛屿、
笔刷画的噪点）在远观档会闪。这不是观感偏好，是**采样定理层面的缺失**。
建议把 T33 的盒式平均提到 P3 之前做（约 30 行 WGSL）。

## 七、追记三：三条待裁项的裁定与执行（2026-10-23，用户授权「你安排」）

> 本节是 §五、§六 里三处「待裁定」的收口。T19 与 T23 的**锁值已就地修改**
> （本表状态行写明「后续改动须回到本表并留痕」，故改动在表内 + 在此留痕，
> 不属静默改值）。

### 1. T19 升 v1.1：采用 `clamp(0.225 / px_per_cell, 0.05, 0.45)`

v1.0 的字面式 `clamp(2.0×scale, 0.05, 0.45)` 已被证明**不可实现**（§五 5.1：
`scale` 两种读法都得不出注记要求的两个端点）。裁定采用按**注记端点**拟合的
公式，标定依据：

| px/格 | `0.225 / px_per_cell` | 钳制后 | 与注记一致 |
|---|---|---|---|
| 0.5（远观） | 0.450 | 0.450 | ✓ 取上限 |
| 4（近观编辑，诊断基线） | 0.056 | 0.056 | ✓ ≈0.05 |
| 16 | 0.014 | 0.050（下限） | ✓ 不得更大 |

实现：`material::warp_amp()`，3 条单测锁端点与值域。若将来要回到字面式，
只改函数体，shader 与 uniform 布局不变。

### 2. T23 定为「1.2 目标 / 1.0 当前可达下限」

无符号距离场下岸线墨线只能用 `fwidth` 的掩码跳变定位，线宽**恒为 1 屏幕
像素**——`fwidth` 的分辨率下限就是一像素，表达不了 1.2。实测 32 / 16 / 8
px/格 都是 1 px（跨缩放恒定，T11 的核心判据成立）。

裁定：**不改 1.2 这个目标值**（它与参考图一致），把 1.0 记为「当前实现
可达的下限」，并在 SPEC §3.8.1 追写该下限。若将来采用有符号距离
（见下 §3），墨线可精确到 1.2，此下限自然消失。

### 3. 台阶：甲案维持，但已备好可切换的 Signed 变体

已实现 `CoastEncoding::{Unsigned, Signed}`——**同一张纹理、同样字节数**，
只换语义（Signed 存 `(sd + 32) / 64`，岸线两侧格心为 `+1` / `−1`，
插值穿过 0）。默认仍是 `Unsigned`（甲案）。

为免「凭印象判断」，加了 **45° 受控合成地形**（`FIELD_SYNTH=1`）作测量夹具：
真实 fbm 岸线是曲线，放大后「哪段是阶梯、哪段本来就直」分不清；45° 直线
则一目了然。实测岸线**水平直段长度**（越短越像曲线）：

| 缩放 | Unsigned（甲，现行默认） | Signed（乙变体） |
|---|---|---|
| 3 px/格 | 4 px | 4 px |
| 16 px/格 | **24 px** | **12 px** |
| 32 px/格 | **40 px** | **20 px** |

结论：**Signed 把台阶幅度减半，但没有消净**，因此不足以单独推翻已锁定的
T3/T5 数据模型——甲案维持。

### 4. 由 A/B 得到的一条结构性认识（重要）

台阶消不净的**残余**来自 EDT 的**整数量化**：距离只取 1 / 2 / 3…，
双线性插值后等值线仍呈波纹（两版岸边那圈「齿」就是它）。也就是说：

> 想让岸线真正平滑，**不是换编码能解决的**，需要把距离场本身做成亚格精度
> （如更高分辨率的 SDF，代价是显存 ×4 或生成时间 ×4）。

这条把问题的性质说清了：它不在 T3/T5 的「符号」上，而在「距离场的采样率」
上。将来若要投入，评估对象应当是 **SDF 分辨率**，而不是继续在编码格式上试。

2. **纤维必须锚屏幕空间**（T45 明写）：视口像素尺寸变化要重传 uniform，
   否则窗口拉伸时纤维被拉成条纹。

### T37 的规格缺口：屏幕像素恒定尺寸在远观档失效

T37 规定符号显示尺寸以**屏幕像素**恒定（32/64/96），与线宽同口径。
但常数尺寸意味着**缩小时符号不变小**：远观档（0.4 px/格）整幅图才 400 px 宽，
一个 96 px 的山盖住四分之一个岛——符号从「信息」变成「遮挡」。

实测表现为：不加门控时，850 个符号在远观档铺满全图、把地形完全盖住。

**现行处置**（演示口径，非锁值）：`px_per_cell < 1` 时全部符号退场；
其上按族分档——山 / 地标 1.0、聚落 1.5、树 2.5。

**建议补一条 T37b**（**已裁定，见追记八**）：符号的尺寸档是否应随缩放升档而不是恒定？
两种做法：
- **甲**：保持屏幕像素恒定 + 缩放门控（现行），语义与线宽一致；
- **乙**：尺寸档随缩放切换（近观用 3×、远观用 1×），符号永远可见但会「变种」。

甲更简单且不引入「符号随缩放变形」的怪感；乙信息更全但需要第二套变体图。

## 十、追记六：T49/T50 实测（2026-10-23）

> §五 5.3 把 T49/T50 记为 ⏳，本节给实测数据与一条**推翻 T49 估值**的发现。

### 测量方法与其局限（先写清楚，免得数字被误用）

Bevy 0.19 **没有** `RenderDiagnosticsPlugin`（该插件在此版本已不存在），
GPU 时间戳需要自建 query 与异步回读，成本远高于本次要回答的问题。

折中做法：`FIELD_BENCH=1` 关垂直同步（`AutoNoVsync`）、预热 90 帧、
采样 300 帧，统计 CPU 帧间隔。在全屏片元着色器这种 GPU-bound 场景下，
交换链的 in-flight 限制会把它反馈到帧间隔。

**局限**：这个数是「整帧吞吐」，含 CPU 侧 ECS 与提交开销，**不是 shader 的
独占耗时**。要拆占比必须做 A/B 或用分辨率斜率（见下）。

### T50 帧时间（release，RTX 4060 Laptop 8GB，1600×900，各配置 3 次取中位）

| 配置 | p50 | 说明 |
|---|---|---|
| 空场景（地形/纸面/符号全关） | **1.395 ms** | 引擎固定开销 floor |
| + 地形着色器 | 1.433 ms | 增量 ≈0.04 ms（噪声内） |
| + 纸面 + 符号 | 1.591 ms | 增量 ≈0.16 ms |

**结论一：1600×900 下地形着色器的成本被引擎 floor 掩盖。** 整帧由约 1.4 ms
的引擎开销主导，不是 shader 主导。T50 的「<1.5 ms @1600×900」**已满足**，
但满足的原因不是 shader 快，而是它根本没成为瓶颈。

### 用像素斜率把 shader 成本逼出来

`FIELD_RES=3200x1800`（4× 像素，空场景 floor 仍在 1.7–2.2 ms）时，
地形增量变成 **3.0–4.8 ms**。按斜率换算 1600×900 的真实着色器时间
≈ **1.0 ms**——在 1.5 ms 预算内，但已用掉三分之二。

**结论二：当前分辨率下做 P5 低配档（fbm 3→2 octave、bicubic→bilinear）
省不到可测量的时间。** 低配档的价值要到 4K 或集显才体现——这与「为了
省时间做低配档」的直觉相反，值得记下。

### T49 的采样数被严重低估（4.3 倍）

锁表写「≈20（16 bicubic + 5 attr + 2 sdf + 3 noise）」。按代码实数：

| 来源 | 采样数 |
|---|---|
| `h` 一次双三次 | 16 |
| 梯度 dx（2 次双三次） | 32 |
| 梯度 dy（2 次双三次） | 32 |
| coast 距离 | 1 |
| attr 水陆/biome | 1 |
| biome 边界 4 邻 | 4 |
| **合计** | **86** |

远观档还要加 `box_avg` 的 8 + 8 = 16，即 **102**。

**根因**：梯度用「四次完整双三次求差」（共 4×16 = 64 tap），而不是在
**同一次 4×4 采样**里对 Catmull-Rom 权重解析求导。后者可把 80 tap 降到 16。

**这是 P5 最高性价比的一项**——比降 octave 有效得多（octave 只影响 6 次
噪声求值，而梯度占了 64/86 = 74% 的采样）。

**建议**：T49 的估值改为 **86（近观）/ 102（远观）**，并在 P5 里加一条
「梯度改用解析导数」的施工项。数值待裁定后再改表。

## 十一、追记七：P5 落地 + T49 估值二次修正（2026-10-23）

> 追记六说「80 tap 可降到 16」——落地后发现还能更省：**值与两个偏导共享
> 同一次 4×4 采样**，不是各算各的。本节修正该估值并给出实测。

### T49 采样数二次修正：86 → **22**（近观）

追记六的算法是「h 用 16 tap + 梯度另用解析导数 16 tap」= 32 tap。
实际实现时发现三个量共享同一窗口：

```text
h     = Σᵢⱼ texel(i,j) · wxᵢ(f.x) · wyⱼ(f.y)
∂h/∂x = Σᵢⱼ texel(i,j) · wx′ᵢ(f.x) · wyⱼ(f.y)
∂h/∂y = Σᵢⱼ texel(i,j) · wxᵢ(f.x) · wy′ⱼ(f.y)
```

`height_texel` 只取一次，三套权重并行累加。账目变为：

| 来源 | 采样数 | 追记六旧账 |
|---|---|---|
| h + 解析梯度（一次 4×4） | **16** | 16 + 32 + 32 = 80 |
| coast 距离 | 1 | 1 |
| attr 水陆/biome | 1 | 1 |
| biome 边界 4 邻 | 4 | 4 |
| **合计（近观）** | **22** | 86 |

远观档不变：+ `box_avg` 8 + 8 = 16 → **38**（旧账 102）。

### 实测（RTX 4060 Laptop，release，`FIELD_BENCH=1`，p50 取中位）

3200×1800（4× 像素，让 shader 成本露出引擎 floor）：

| 配置 | 旧·中心差分 | 新·解析导数 |
|---|---|---|
| floor（全关） | 2.16 ms | 1.79 ms |
| terrain-only | 4.61 ms | 2.26 ms |
| **地形增量** | **2.45 ms** | **0.47 ms** |
| 全场景 | 5.15 ms | 2.66 ms |

**地形着色器约 5.2×**，与 tap 数 −74% 方向一致且略超——省掉的 64 tap
正是同一批纹素的重复取样，纹理缓存命中率随之改善。

1600×900 下两种算法 p50 都是 ≈1.59 ms：增量被引擎 floor（≈1.4 ms）掩盖，
不可测。**低配档的必要性进一步下调**——解析导数已把 3200×1800 的地形
增量压到 0.5 ms 以内，P5 原计划的「fbm 3→2 octave、bicubic→bilinear」
暂无必要，除非目标平台是集显或 4K。

### 机制变更声明（不是等价替换，按 T5 留痕）

- **T14 `GRAD_STEP` 失效**：中心差分的步长旋钮随差分一起消失。解析导数
  对 16 tap 窗口内全频段一视同仁。远观噪声抑制由 T33 `lod_t → 1` 把
  relief 收敛到 1.0 承担，T14 的意图未被绕过；`shape.w` 槽位保留
  （ABI 不动），语义标记为「已停用」。
- **数值差异**：旧差分在 `fract()` 不连续处（格边界）会跨窗口取样，
  精度塌陷；解析导数在窗口内处处成立——这正是 T13 买 C1 连续性时
  想要的性质。画面上近观山体明暗在格边界处更干净。
- **验证**：新增 `bicubic.rs` 宿主镜像（纯 Rust，无 Bevy），7 项单测
  钉死解析导数 ≡ 同核数值导数、格边界两侧连续、权重和 1 / 导数和 0、
  仿射场精确还原、格心无偏移。WGSL 与宿主镜像**双边同步**改动。

### 施工位置

worktree `feat/terrain-field-p1` @ `5f95170`：`terrain_field.wgsl`
（`cubic_weights_deriv` + `sample_height_bicubic_grad`）、
`bicubic.rs`（新增）、`mod.rs`（导出）。闸门：clippy 0 告警 / fmt 绿 /
wv-render 491 通过（含 7 项新单测）。

**T49 状态**：⏳ → ✅（实测 86/102 → 修正为 **22/38**，shader 成本实测
见上表）。**T50 状态**：✅（维持追记六结论，1600×900 满足 <1.5 ms，
成因是 floor 主导而非 shader 快）。
