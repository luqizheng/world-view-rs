## 〇、总纲：这是编辑器，不是游戏

> **本文定义的「特效」，不是技能光效、不是爆炸、不是打击感。它只有两个职责：**
> **① 让地图信息更清楚（视觉表达）　② 让编辑操作有确定反馈（编辑反馈）。**

**三条不可动摇的原则**（每一条设计必须能通过这三关）：

| # | 原则 | 判据（答不出来就不做） |
|---|---|---|
| **V-P1** | **可读性优先于表现力** | 「它让作者多看清了什么？」——答不出 → 砍 |
| **V-P2** | **信息不遮挡** | 视觉强化不得盖住作者必须看清的信息（地形细节 / 弹幕式提示 / 文字标签 / 正在编辑的笔刷范围） |
| **V-P3** | **一动即明，静观不噪** | 静态画面零噪声；只有「状态改变」才动。作者会连续看 300 小时，**任何常驻动画都是负担** |

**四条与既有文档的硬对齐**：

| 对齐项 | 来源 | 本规格的承诺 |
|---|---|---|
| **色值只用色板令牌** | 美术 §1.4.2 | 全文所有颜色均写为 `令牌名`，**不出现裸十六进制**（默认色值附注仅作参考） |
| **颜色不是唯一载体** | 美术 §1.4.3 ④ / 设计 §1.3 | 任何语义区分（势力性质、事件三态、校验四态）**必须叠加形状/线型/纹理** |
| **时间语义只能来自 `TimelineQuery::at`** | AGENTS §3.2 / 基线 §2.14 | 一切随时间变化的视觉（势力易主、事件点亮、轨迹生长）**由 `PlaybackState.current_day` 驱动**，视觉层**不自己做动画、不自己比时间** |
| **LOD 只改显示不改数据** | 基线 §1.16 L1/L3 | 视觉强化随缩放降级，**降级不丢信息**，读数（点数/面积）始终走 Inspector |

**一句话交付口径**：
> **本规格的全部产物 = 一套「按色板令牌着色、按 LOD 分级、由时间轴驱动、性能有硬上限」的视觉表达层。不含任何游戏化特效。**

### 1.3 「状态 / 动效 / 语义动效」抑制三分类（★ 双方共识硬规则）

> 由本人与动画总监（关建帧）在三轮接口仲裁中提炼，**统一了两文全部「降级 / 抑制」逻辑**。凡新增任何视觉元素，**先过这一条**。

**分类（三档，非两档）**：

| 类别 | 定义 | 抑制行为 | 本项目实例 |
|---|---|---|---|
| **① 状态**（State） | **恒定值**，或其**变化本身就是信息**的视觉；去掉它 → **丢失信息** | **永不抑制**（任何 `intensity` / 任何播放速率） | 底环（事件「进行中」标记）、事件三态形状、笔刷光标与 falloff 双环、势力描边与填充、计数徽标、LOD 降级后的元素**存在性** |
| **② 动效**（Motion） | **往复 / 扫掠 / 弹跳**的装饰性运动；去掉它 → **信息仍在** | 在 `intensity = off`/`reduced`、或**高速播放**（30 天/秒）时**抑制** | 涟漪环、拐点点亮弹跳、易主过渡的**扫光**、蚂蚁线爬行 |
| **③ 语义动效**（Semantic Motion） | 运动本身**携带「世界正在变化」的语义**；去掉它 → **语义丢失** | **不适用高速抑制**，仅适用「**触发条件消失即停**」（如停止播放） | **流光线**（播放中才开，停止播放即关，**不随速率抑制**） |

**判别口诀（两步）**：

1. **「去掉它，作者会少看懂什么吗？」** —— 不会 → 它是 **② 动效**，该抑制就抑制。
2. **会 → 再问：「去掉它，是丢了『某个事实』，还是丢了『正在变化』这件事？」** —— 丢**事实** → **① 状态**，永不抑制；丢**「正在变化」** → **③ 语义动效**，只受触发条件控制。

> **第三类的存在理由**：流光线**既不往复也不扫掠**（不是典型动效），但在高速播放时抑制它会**丢掉「时间在推进」的语义**（也不是状态）。二分类无法安置它——**必须三分类**。这是本轮接口仲裁最重要的结构补全。

**边界案例裁定**（实现者最易踩的 4 处）：

| 元素 | 判定 | 理由 |
|---|---|---|
| **流光线**（轨迹方向流动） | **③ 语义动效** | 携带「时间正在推进」语义；恒定 40px/s 不随速率放大；**只受「是否播放」控制** |
| **事件三态**（休眠/进行中/已结束） | **① 状态** | 三态是「事件在哪个阶段」这一**事实** |
| **笔刷光标 falloff 双环** | **① 状态** | 表达「影响范围」这一**精度信息**（本文 §3.1 硬契约） |
| **易主过渡的描边 alpha + 扫光** | **① 状态 ⊕ ② 动效 的混合** | alpha 终态是**状态**（不抑制）；扫光是**动效**（可抑制）——**这正是 §2.6.2「复用同一 progress」的深层理由**，规格化见下 |

**混合案例的实现规格**（状态与动效共存于同一元素时的标准写法）：

```
同一个 progress（day 空间插值，§2.6.1）+ 两个独立的强度乘子：

  alpha = 终态alpha × ease_out_cubic(progress) × k_state   // k_state ≡ 1，永不抑制
  sweep = progress × k_motion                              // k_motion ∈ {0,1}，高速档 / off 时为 0
```

> **关键**：两者**共享 `progress`**（保证扫光与 alpha 不脱节）+ **各自独立乘子**（保证终态 alpha 不被抑制、扫光可被抑制）。
> **这正面回答了「为什么 `u_sweep` 必须复用同一 `progress`」**——**不是为了省事，而是因为状态与动效必须共享同一时间参数、却能各自独立降级**。
> **禁止**：为 `sweep` 单独开计时器（会与 alpha 脱节）。

> **本规则已登记进 §10 术语表**（登记为**上位概念「抑制三分类」+ 其三个成员「状态 / 动效 / 语义动效」**，采用一条带三成员的结构，不平列），并建议在 `GLOSSARY.md` 单列，作为**跨成员通用判据**（动画规格 `ANIMATION_SPEC_v0.1.md` §7.2/§8.5 已同构收录，两文分类一致）。

**判据的自检机制（★ 比覆盖案例更重要）**：

> **若两步口诀对某个新元素给出「矛盾答案」（第一步说该抑制、第二步却说丢事实不该抑制，或反之），那就是「第四类」出现的信号——届时必须扩充分类，而非硬套现有三档。**

本判据的完整性与「能覆盖多少元素」无关，而与**它能否自己报出「我不适用了」**有关。**三档是当前的最小完备集，不是封闭集**；新增类别的触发条件是**判据自身的失败**，不是人的偏好。这使得后续扩展有客观依据、无需重新争论。

## 二、势力层的视觉强化（最高优先级）

> 基线依据：§1.10 视图模式 C、§2.5 势力层模型、§2.5.3 的 R1′–R5′、§2.10 多边形集合。
> 核心问题：**多个势力层重叠时，如何让每一层都可辨、都干净、都不打架？**

### 2.1 势力层视觉的总体架构：**填充 / 描边双层分离**

**裁定**（对齐基线「填充色只由唯一底图层提供、其余层描边共存」）：

```
┌─ 势力图的视觉分层（自下而上）──────────────────────────┐
│  ① 地形底图（淡化，ViewMode C 下 alpha ≈ 0.35）          │  ← 保地形骨架
│  ② 底图层填充（唯一，作者指定，单色 + 半透明 + 纹理）     │  ← 唯一"面上色"
│  ③ 其他势力层描边（多，共存，线型/色彩区分）             │  ← "线共存"
│  ④ 重叠计数徽标（≥3 层处）                              │
│  ⑤ 城市点 / 势力名 / 选中态                              │
└────────────────────────────────────────────────────────┘
```

**为什么必须分离**（三条理由，缺一不成立）：

| # | 理由 |
|---|---|
| 1 | **n 层填充必然互相遮挡**，作者看不到下面那层 → 填充只能有一层（底图层） |
| 2 | **但「归属集合」是 n 元的**（R2′ 返回多归属）→ 其余归属只能用**不占面积**的手段表达 → 描边 |
| 3 | 美术 §1.4.3 ④ 要求「颜色不是唯一载体」→ 描边必须带**线型**，填充必须带**纹理**，二者各自独立可辨 |

### 2.2 底图层填充的视觉（对应基线：填充只由唯一底图层提供）

| 项 | 规格 | 理由 |
|---|---|---|
| **指定方式** | 图层管理面板中，每个势力层可标记「作为底图填充（唯一）」，同时只能有一个 | 保证面上只有一种颜色语言 |
| **填充不透明度** | **alpha 0.45**（默认，可调 0.2–0.7） | 低于 0.35 与地形分不清；高于 0.6 地形被吞 |
| **填充色** | `faction.<a..f>` / `faction.neutral` / `faction.player`（每势力一色） | 色板 §1.4.2 |
| **混合模式** | **Normal（Alpha 混合）**，**禁止 Multiply / Screen / Overlay** | P3 数据是纯色，混合模式会引入不可预测的色偏，破坏 ΔE 契约 |
| **与地形的共存** | 渲染顺序：地形 → 填充（alpha 0.45）→ 描边。**同一 `DrawCall` 内合批**（同材质同色） | 单纹理地形 + 半透明色块叠层，1 次额外的四边形批 |
| **填充纹理** | 见 §2.5「纹理区分性质」；**默认无纹理**，仅在作者开启「按性质区分」时叠加 | 默认关 → 零额外成本；开启 → 见 §6 成本 |

> **给主程序的实现口径**：底图填充 = 「用 `territory: Vec<GeometrySpan>` 的每个多边形生成一个三角化 Mesh，材质 = `ColorMaterial { color: faction色, alpha: 0.45 }`，`Z = -0.3`」。**不走着色器**（纯色平铺，无需 fragment 计算）。

### 2.3 描边系统的完整规范（「描边共存」的核心）

> 这是第 1 部分最重要的产出。目标：**5 个势力层重叠时，5 条边都能被区分且不互相打架。**

#### 2.3.1 描边的四维区分语法（**颜色 + 粗细 + 线型 + 偏移**，四维正交）

| 维度 | 档位 | 取值规则 |
|---|---|---|
| **① 颜色** | 跟随该势力层的主色（`faction.*`） | 每层色相不同（色板 ΔE 契约保证） |
| **② 粗细** | **3 档**：粗 4px / 中 2.5px / 细 1.5px（@1x，随缩放同比） | **按「势力层的层序」分配**——底图填充层最粗，越上层越细 |
| **③ 线型** | **3 档**：实线 / 虚线（dash 6-4）/ 点划线（dash 8-3-2-3） | **按「势力性质」分配**：政治类=实线，行政类=虚线，派系类=点划线（见 §2.5.3） |
| **④ 偏移（offset）** | **0 / ±2px / ±4px** | **同一几何被多层引用时**（如同一省界），向外逐层偏移，避免完全重合 |

> **四维正交的意义**：即使两个层颜色相近（同类势力），也能靠粗细+线型+偏移区分。**单靠颜色 = 违反美术 §1.4.3 ④。**

#### 2.3.2 描边的视觉增强（让描边「清楚但不刺眼」）

| 增强手段 | 规格 | 何时开 |
|---|---|---|
| **内描边（内侧 1px 亮线）** | 沿多边形内缘 1px，取该势力色的**亮部变体**（明度 +25%） | 恒定开（让描边在深色地形上也有边界感） |
| **外光晕（halo）** | 外缘 2px，该势力色 alpha 0.35；**仅在鼠标悬停该势力层时出现** | 悬停态，**不常驻**（V-P3） |
| **选中高亮** | 选中势力的描边换为 `accent.select`（金），**粗细 +50%**，并出现外光晕 | 选中态 |
| **描边交汇点圆头** | 相邻两段描边夹角处用 `round` 端帽 | 恒定（避免尖刺） |

**光晕的「远处淡出」规则**（关键，防噪）：

| 缩放范围 | 描边呈现 |
|---|---|
| `0.15×–0.6×`（战略） | 描边粗细 ×1.5，**关光晕**，虚线的 dash 拉长（6-4 → 10-6），保证低缩放下仍可辨 |
| `0.6×–2×`（战术，默认） | 全规格呈现 |
| `< 0.15×`（概览） | **只显示底图层填充 + 最粗的一层描边**，其余层收起（LOD 降级，见 §8） |
| `> 2×`（局部） | 描边变细（避免线条过粗压住地形），保留线型 |

> **术语**：描边「共存」，但在低缩放下是**分级共存**（不是全部同时画）。这符合基线 §1.16 L3「低缩放下必须简化」的精神。

#### 2.3.3 描边系统的实现方式

| 手段 | 用在哪 | 为什么 |
|---|---|---|
| **Mesh `LineStrip`（CPU 生成顶点）** | **主力方案**。基线 §2.11 已定「矢量图层自建 Mesh」 | 复用道路/轨迹同一管线；虚线用 **顶点属性 `uv.x = 累计长度/周期`** 在 shader 里 discard 实现（见 §6.3） |
| **不做的方案** | ❌ 几何扩边描边（每段画四边形） —— 顶点数 ×4，超 §2.19 的 10 万顶点上限风险 | 用 LineStrip + shader 线宽模拟 |
| **线宽实现** | 2D 俯视下用**屏幕空间线宽**（顶点着色器按法线方向扩 1px×width/scale） | 保证任意缩放下线宽物理一致（美术 §3.1：禁非整数缩放已消除断裂风险） |

> **给主程序的着色器需求（`SH_Vector_Outline`）**：
> - 输入：`a_position: vec2`（点列）、`a_normal: vec2`（点法线，CPU 预计算）、`a_arclen: f32`（累计弧长）
> - Uniform：`u_width, u_dash(3 段), u_color, u_zoom, u_offset`
> - 顶点：`pos + a_normal * u_width * (0.5/zoom) + u_offset * a_normal_screen`
> - 片元：`dash = fract(a_arclen / (u_dash.x+u_dash.y+u_dash.z))`；按档位比较 discard；输出 `u_color`
> - **成本**：`O(顶点数)`，无纹理采样，无循环。**这是唯一必须有自定义着色器的 2D 元素。**

### 2.4 重叠区域的强化（对应基线：≥3 层 → 计数徽标）

#### 2.4.1 计数徽标的定义

| 项 | 规格 |
|---|---|
| **触发** | 某点/某区域**归属集合 size ≥ 3**（R2′ 返回的 `Vec<(layer_id, faction_id)>` 长度） |
| **计算** | `query_at_point` 已是现成 API（基线 §2.5.4）。**在「重叠热点」处（如区域重心、鼠标停留处）求值** |
| **形态** | **圆形徽标**：直径 20px（@1x），**外圈 2px** `line.on_light` 描边，**底** = 各层的「混合色」的**中性化版本**（避免误导为某一势力） |
| **内容** | 徽标中央为**数字**（如 `4`），字体 `font.mono` 13px，色 `line.on_dark`。**数字是唯一信息载体之外，必须叠加「层叠环」形状**（见下） |
| **层叠环** | 徽标外圈画 **n 段短弧**（n = 重叠层数），每段弧用该层的势力色。**形状（弧段数）+ 颜色 双载体** |
| **位置** | 重叠区域**重心**；若区域过小则贴合鼠标位置 |
| **可关** | 图层面板提供「显示重叠徽标」开关（默认开） |

> **「数字 + 层叠环」是硬要求**：美术 §1.4.3 ④ 要求颜色不是唯一载体；同时数字解决「作者要知道到底叠了几层」这个**编辑刚需**（写 YAML 时最常问「这块地到底属于几个势力」）。

#### 2.4.2 是否有背景色变化？（裁定：**不做大面积背景变化**）

| 方案 | 裁定 | 理由 |
|---|---|---|
| 重叠区域整块变暗/变色 | ❌ **不做** | 大面积色变会与「底图填充色」混淆，且吃掉地形 → 违反 V-P2 |
| **描边密度表达** | ✅ **做** | 重叠层数越多，该区域的描边**越密**（因为更多层的描边穿过）——**这是重叠的天然视觉副产品，零额外成本** |
| **区域轮廓外扩微光** | 🟡 **可选，默认关** | 仅在作者「框选重叠区域」时高亮，不常驻 |

> **结论**：**重叠的强化 = 描边自然叠加 + 计数徽标**，不需要新的背景色层。这既省成本，又避免「一张地图上出现 3 种背景色」的混乱。

### 2.5 纹理区分性质（程序化实现）

> 对应基线「用纹理区分性质（政治类斜纹/网点，行政类实线）」。裁定：**性质 → 图案** 的映射表。

#### 2.5.1 性质 → 图案映射（默认预设，可配置）

| 势力层性质（作者标注） | 填充纹理 | 描边线型 | 说明 |
|---|---|---|---|
| **政治类**（国界、同盟） | **斜纹**（45° hatch） | **实线** | 最高权重，实线最醒目 |
| **行政类**（省份、郡县） | **网点**（dot grid） | **虚线** | 中等权重 |
| **派系类**（教团、行会、党派） | **十字纹**（cross-hatch） | **点划线** | 散点式势力，纹理最轻 |
| **贵族领**（封地） | **无纹理**（纯色） | **细实线** | 与政治类区分靠线宽（细） |
| **无主地** | **斜纹（45% 灰，密）** | **点线** | R4′：灰显，不报错 |

> **纹理密度 3 档**（对应美术 §3.3.4 的「斜线密度三档」）：`d1` = 12px 周期 / `d2` = 8px / `d3` = 5px（@1x）。

#### 2.5.2 程序化实现的三种方式与取舍

| 方式 | 实现 | 成本 | 裁定 |
|---|---|---|---|
| **A. 预生成平铺贴图 + UV 平铺** | 生成 32×32 可平铺纹理（斜纹/网点/十字纹各 3 档密度 = 9 张），Mesh UV = 世界坐标 / 32 | **极低**（1 张纹理采样，与纯色同批次） | ✅ **采纳（默认）** |
| **B. 着色器程序化图案** | fragment 里用 `fract(x+y)`/`step` 算条纹 | 中（每像素若干 ALU，无采样） | 🟡 **备选**（若想零资源模式） |
| **C. 逐像素 CPU 生成进纹理** | 运行时生成一次进 `Assets<Image>` | 低（一次性） | ✅ **与 A 等价**，用 A 的贴图管线 |

**裁定**：**默认走 A（预生成可平铺贴图）**。理由：
1. 与美术 §3.6「程序化 pack」兼容——有资源的 pack 用位图，无资源的 pack 由引擎生成这 9 张 32×32 贴图（代码 ~40 行），**同一接口消费**；
2. 单次采样，**不增加 drawcall**（同材质同贴图合批）；
3. 比起色器方案 B，**移动端/低端 GPU 更友好**（无逐像素 ALU）。

> **纹理贴图不属 Theme Pack 位图资产**，属引擎内置（`PAT_Faction_*`）；但**颜色跟随 `faction.*`**（用 `ColorMaterial` 的 color 与纹理相乘）。

### 2.6 「势力易主」的视觉（时间轴驱动，硬约束）

> 对应基线：`GeometrySpan` 边界跨越（`from`/`to`）时的视觉过渡。**必须由时间轴驱动，不能自己跑动画（AGENTS §3.2 / 基线 §2.14）。**

#### 2.6.1 触发与求值链（必须走 `TimelineQuery::at`）

```
作者拖时间轴 → PlaybackState.current_day 变化
   ↓（拉动式刷新，基线 §2.14）
TimelineQuery::at(faction_spans, current_day) → 当前有效的势力几何集合
   ↓
与上一帧的集合做 diff → 产出 FactionDelta 资源
   ↓
视觉层只读 FactionDelta，不做任何时间判断
```

**`FactionDelta` 的定义**（提给主程序）：

| 字段 | 含义 |
|---|---|
| `appeared: Vec<(layer_id, faction_id)>` | 本帧新出现的势力块 |
| `vanished: Vec<(layer_id, faction_id)>` | 本帧消失的势力块 |
| `changed: Vec<...>` | 几何变化（罕见） |

#### 2.6.2 「易主」的过渡光晕（视觉表现）

| 事件 | 视觉 | 时长（**由 day 空间派生**） | 载体 |
|---|---|---|---|
| **势力块出现**（`appeared`） | 该块描边**从 alpha 0 → 1 淡入**，同时有一条**沿边界向外扩散的 1px 光带**（1 个描边周期的宽度）划过一圈 | `progress = clamp((current_day − span.from)/0.25, 0, 1)` | 描边 shader 的 `u_color.a` + `u_sweep` uniform |
| **势力块消失**（`vanished`） | 描边 alpha **1 → 0 淡出**（不扩散） | `progress = clamp((span.to − current_day)/0.20, 0, 1)` | 同上 |
| **新旧交替（同一块）** | 旧色**减弱**的同时新色**增强**（交叉淡化） | `p = clamp((current_day − swap_day)/0.35, 0, 1)` | 两个描边 Mesh 各自 alpha 插值 |

> **权威修订（v0.1 · 与动画规格接口）**：上表的**权威表述是「day 空间插值」，不是壁钟秒数**。这是接受动画总监（`ANIMATION_SPEC_v0.1.md` §1.6）的裁定，**它比本文原「时长上限」方案更强**。原文的 0.4s/0.3s/0.5s 上限，现降级为「**1 天/秒 推进速率下的派生值**」（0.25/0.20/0.35s，均在上限内）。
> **曲线**：ease-out-cubic，**作用在 day 参数上**（非壁钟上）。**曲线归动画规格**，本文接受。
> **边界扫光 `u_sweep`**：与描边 alpha **复用同一个 `progress`**，**不另立计时器**。
> **`wv-core` 归属**：该插值函数是**纯函数**（可单测），放 `wv-core`；`wv-app` 只把结果喂给 shader uniform。

**关键约束**：

| # | 约束 | 理由 |
|---|---|---|
| **T1** | **过渡时长由 `current_day` 推进速率派生，不独立计时** | 若作者把时间轴拖得飞快，过渡**必须立刻完成**（不能卡在中间态）。day 空间插值**天然满足**：30 天/秒 → 0.008s ≈ 瞬变 |
| **T2** | **拖时间轴加速时，过渡落终态** | day 空间插值的自然结果（一帧跨过整个 Δ_day 即落终态） |
| **T3** | **常驻态零动画** | 势力色块稳定时**完全静止**（progress 恒为 0 或 1）（V-P3） |
| **T4** | **不做粒子** | 「易主」不是「爆炸」；用描边 alpha + 扫光即可。**粒子在这里是纯噪音** |
| **T5** | **天然可逆** | `current_day` 回拖时 progress 同步回退（公式对称）——这是选 day 空间插值而非壁钟计时的最大收益。**回拖是编辑常态，过渡必须可逆** |

> **实测口径**：过渡是**一次性事件**（非循环），仅在时间轴跨越边界时发生，**对帧率影响 ≈ 0**。
> **填充稳态 alpha = 0.45**：**权威归本文**（动画规格原写 0.35，已让步作废）。

### 2.7 势力层视觉的完整参数汇总表

| # | 元素 | 视觉 | 实现 | 优先级 |
|---|---|---|---|---|
| 1 | 底图填充 | alpha 0.45 纯色（+可选纹理） | 三角化 Mesh + `ColorMaterial` | P0 |

## 三、编辑工具的特效

### 3.1 笔刷光标（**精度不可妥协**）

> 基线 §1.13：笔刷类型 = 圆形（可调半径）/ 方形（网格化）/ 套索（自由形状）。模式 = 涂抹/擦除/平滑/替换。
> **本文最高优先级约束**：**光标必须精确反映「将要影响的范围」——这是工具，误差不可接受。**

#### 3.1.1 三类光标的形态规格

| 光标 | 形态 | 精度要求 | 绘制方式 |
|---|---|---|---|
| **圆形软边（falloff）** | 外圈（**硬边界实线**，表示「影响半径 R」）+ 内圈（**虚线**，表示「50% 强度半径 R/√2」）+ 中心十字 | 外圈半径 = **真实笔刷半径（世界单位→屏幕像素换算）**，误差 **= 0** | 屏幕空间程序化绘制（非贴图，避免缩放模糊） |
| **方形（网格化）** | 正方形边框，**边长 = 笔刷格数 × 单格像素**，边线与格线对齐 | 边界必须**贴合格线**（误差 0；若非整数格则就近吸附并提示） | 同上 |
| **套索** | 自由曲线闭合路径，闭合后填充 alpha 0.15 的选区色 | 路径点必须与鼠标采样点一致（无平滑拖尾延迟） | `LineStrip` 闭环 |

#### 3.1.2 falloff 可视化（关键：让作者「看见衰减」）

**裁定**：圆形笔刷用**双环 + 径向渐变填充**表达衰减：

```
        ╭──────────╮  ← 外环：实线，= 影响半径 R（强度 0 处）
       ╱  · · · · · ╲
      │  · · · · · · │  ← 内环：虚线，= 50% 强度半径
      │  · · · ✛ · · │  ← 十字准星（精确瞄准）
       ╲  · · · · · ╱   ← 环内：径向渐变 alpha（中心 0.18 → 边缘 0），
        ╰──────────╯       色 = 当前笔刷「将要写入的色」
```

| 项 | 规格 | 理由 |
|---|---|---|
| 渐变填充 | 中心 alpha 0.18 → 边缘 0（线性或高斯同外貌） | 作者一眼看到「中心最强、边缘最弱」 |
| **渐变必须与真实 falloff 公式一致** | 光标渐变曲线 = `wv_terrain::edit` 实际使用的衰减函数 | **否则作者会被误导**（可视与实际不符 = 工具失信） |
| 半径调节反馈 | 拖 `Ctrl+滚轮` 时，外环**实时缩放**，并显示半径数值（`font.mono`，如 `R=32格`） | 基线 §1.16：`Ctrl+滚轮` = 只缩放笔刷 |
| 模式区分 | 涂抹=实心外环；擦除=外环 + **斜线填充**；平滑=外环 + **波纹环**；替换=外环 + **双色分半** | 颜色不是唯一载体（美术 §1.4.3 ④） |

> **给主程序的实现口径**：光标 = **屏幕空间叠加层（egui / 独立 2D pass）**，**不进世界 Mesh**。坐标换算走基线 §2.15 的 `coord` 模块（世界→屏幕）。
> **性能**：屏幕空间两个环 + 一次径向渐变 = **< 0.05ms**，可忽略。

#### 3.1.3 光标的「真实影响范围」二次校验（防呆）

| 场景 | 视觉提示 |
|---|---|
| 笔刷半径 > 视窗可容纳 | 外环部分超出屏幕时，**在屏幕边缘画箭头指示**（避免作者以为笔刷很小） |
| 内存中的 falloff 被 LOD 降级 | **不降级笔刷精度**（V-P2：编辑工具误差不可接受）→ 光标**永远全精度**，与 LOD 无关 |
| 0.05× 极值缩放（基线 §1.16 L2） | 光标外环保留，但**整体变红 + 斜线**，表示「此缩放下禁止画地形」（见 §3.4） |

### 3.2 选区（海拔圈选）的视觉

> 基线 §1.14：圈选 → 海拔调整浮层 → 整体抬升 / **羽化抬升（默认）** / 山丘生成。
> 基线 §2.4：选区升降用高斯衰减 `h' = h + amount * exp(-d²/2σ²)`。

| 元素 | 视觉规格 | 说明 |
|---|---|---|
| **选区轮廓** | 闭合 `LineStrip`，色 `accent.select`，宽 2px，**蚂蚁线**（虚线沿周长爬动） | 蚂蚁线是「选区」的通用符号（壳语言一致） |
| **蚂蚁线速率 / 相位** | **6 px/s**（屏幕空间恒定）、沿周长**顺时针**、dash **6-4**；**跨选区改动保持相位连续**（不重置，否则高频编辑会晕）｜ `[交动画]` 已裁定 | 速率/节奏归动画规格，本文接受 |
| **选区填充** | `accent.select` @ alpha **0.12** | 足够说明「这块被选了」，不盖地形 |
| **羽化可视化** | 选区轮廓**内侧**再画一条虚线（= σ 边界），并用**径向渐变**（向内加深）表示衰减带 | 与笔刷 falloff 语言一致 |
| **抬升预览** | 拖 amount 滑块时，**实时刷新地形高度着色**（见 §5 着色方案），选区上叠加**等高线密度变化** | 基线 §1.14「参数实时预览」 |
| **抬升方向提示** | 抬升 = 选区外沿画**向外箭头**（向上的小箭头序列）；降低 = 向内 | 方向不能只靠颜色/数值 |

> **关键裁定**：**选区抬升不自动改地形类型**（基线 §1.14）→ 视觉上**不做地形类型的暗示**，只体现高度变化。作者需要「建议」时，在浮层里给文字建议 + 一键采纳按钮。

### 3.3 「自然化」过程的视觉反馈

> 基线 §1.13：松手后自动 / 手动触发 / 参数实时预览。技术 = 形态学开闭 + 边界重采样 + 样条平滑。

| 阶段 | 视觉 | 时长 |
|---|---|---|
| **触发** | 被自然化的边界**短暂高亮**（1.5px 亮线，`accent.select`，alpha 1 → 0） | 0.3s（**attack 60ms ease-out + decay 240ms ease-in-out**｜ `[交动画]` 已裁定曲线，时长归本文） |
| **进行中** | **不做进度条动画**（自然化 < 100ms 完成，做动画反而拖慢感知） | — |
| **结果对比** | **可选**：按住 `Alt` 时显示「原始边界」的幽灵虚线（`line.on_light` alpha 0.4） | 按住期间 |
| **过度自然化的警示** | 若某段边界被抹掉的长度 > 阈值（如 > 8 格），该段**闪烁一次黄点** `ui_link.late` + 状态栏提示 | 一次性 0.5s |

> **理由**：基线 §1.13 🔴 风险是「自然化过头 = 抹掉作者的刻意锯齿」。**用一个一次性黄点提示「这里被改动很大」= 让作者多看清了什么**，比任何动画都有用。
> **`[交动画]`**：高亮的淡出曲线由动画规格定。

### 3.4 非法操作的视觉提示

> 基线 §1.16 L2：「0.05× 缩放时禁用画地形并提示」。

| 非法场景 | 视觉提示 | 载体 |
|---|---|---|
| **缩放过低禁画地形**（< 0.15×） | 光标外环**变红**（`ui_link.unreachable`）+ **斜线填充** + 光标旁 tooltip「请放大到 0.15× 以上编辑地形」 | 形状 + 颜色 + 文字（三载体） |
| **图层被锁定** | 光标加**锁形角标**，笔触**不产生任何地形改动**，状态栏提示「图层 X 已锁定」 | 图标 + 文字 |
| **无权限区域**（如子图未打开） | 光标外环变**灰**（`faction.neutral`），笔触无声失败 | 颜色 + 状态栏 |
| **回退阻止**（Undo 栈满/快照失败） | 顶部脏标记 `●` 变**橙色警告**，一次性 toast | 状态栏 |
| **面板抢夺输入** | 鼠标进入面板区域时，地图光标**隐藏**（基线 §2.13：egui 要了输入则地图不吃） | — |

**硬约束**：**非法提示必须「一动手就出现」，不得延迟**。作者在 0.05× 下画地形若半秒后才提示，他会以为自己画上了 → 失信。

## 四、事件与轨迹的视觉

### 4.1 事件点三态的视觉差异（基线 §1.9）

> 基线 §1.9：事件点图层 + 当前 `t` 落在其 `span` 内的事件**视觉上「点亮」**；事态当前节点高亮；整条链淡色路径。

| 态 | 触发条件 | 形态 | 色 | 尺寸（@1x） |
|---|---|---|---|---|
| **休眠（未开始）** | `t < span.from` | **空心圆点** + 细描边 | `accent.event` @ alpha 0.45 | 8px |
| **进行中（点亮）** | `span.from ≤ t < span.to` | **实心圆点 + 外脉冲环**（见 §4.2） | `accent.event` @ alpha 1.0 | 12px |
| **已结束** | `t ≥ span.to` | **实心圆点 + 中心对勾/短横**（形状区分） | `accent.event` @ alpha 0.7 | 10px |

**形状元组**（不可只靠颜色，美术 §1.4.3 ④）：

| 态 | 形状 | 线型 | 透明度 |
|---|---|---|---|
| 休眠 | 空圆 | 实线 | 0.45 |
| 进行中 | 实圆 + 脉冲环 | 实线 + 动态环 | 1.0 |
| 已结束 | 实圆 + 内符 | 实线 | 0.7 |

> **「进行中」与「已结束」的区分靠尺寸（12 vs 10）+ 脉冲环的有无**，即使去色也能分辨。

### 4.2 「进行中」的脉冲（**必须不刺眼**）

> 硬约束：**作者会长时间盯着地图，脉冲必须克制。** 且基线 §1.9：多事态同时播时，非当前事态降透到 40%。

> **修订（v0.1 · 与动画规格接口）**：脉冲结构由**单环**改为**两层结构**——**常驻底环 + 涟漪环**。这是接受动画总监（`ANIMATION_SPEC_v0.1.md` §2.2）的增补，**直接补强本文 V-P3「静观不噪」**：原单环在 alpha 归零后有「无环空窗」，2.4s 循环往复对长时注视就是**闪烁**。底环把标记的基线存在感固定住。

**脉冲的两层结构**：

| 层 | 形态 | 色/透明度 | 作用 |
|---|---|---|---|
| **底环**（常驻，不闪） | 固定 `1.0R` | `accent.event` @ alpha **0.25** | **保证「进行中」标记永不消失**——消除闪烁感的根因 |
| **涟漪环**（脉冲） | `1.0R → 1.6R` 外扩，alpha `0.5 → 0`，周期 2.4s | `accent.event` | 表达「此刻正在发生」——一次心跳/一次雷达波 |

| 项 | 规格 | 理由 |
|---|---|---|
| **周期** | **2.4 秒**（慢） | 快于 1.5s 会明显分心；2.4s 是「注意到但不干扰」的甜点 |
| **涟漪幅度** | 环半径从 `1.0R` → `1.6R`，**alpha 从 0.5 → 0** | 幅度小、alpha 低 = 不刺眼 |
| **涟漪扩张曲线** | **ease-out-cubic**（先快后慢，向外减速）｜ `[交动画]` 已裁定 | 真实涟漪是减速的；线性扩张偏机械。**曲线归动画规格**，本文接受其裁定 |
| **涟漪 alpha 曲线** | **线性**（0.5 → 0）｜ `[交动画]` 已裁定 | 线性消散读作「能量耗散」，此处线性正确 |
| **亮度** | 涟漪最大 alpha **0.5**；底环恒定 **0.25**（不高亮） | 对比度 Δ 保持在低水平 |
| **同屏脉冲上限** | 同屏**最多 5 个**事件涟漪；第 6 个起**只静态点亮 + 底环，不涟漪** | 防「20 个点在闪」的灾难（V-P3） |
| **非当前事态** | alpha 降 40%（基线 §1.9）× **涟漪幅度 ×0.5**（两者**相乘**，不取其一）｜ `[交动画]` 已裁定 | 视觉层次：当前事态是主角 |
| **可关闭** | 图层/视图设置里「事件脉冲动画」总开关（默认开）；工具栏一键「静音动效」 | **长时编辑的作者一定需要这个开关** |
| **关闭后的状态** | `intensity = off` → **只留底环**（0.25，不闪） | 关掉动效**不等于丢掉状态**：「进行中」仍可辨（靠实心点 + 底环） |
| **播放中 vs 静止** | 静止（未播放）时涟漪**同样运行**（提示「现在有事件在发生」）；播放中不变 | 一致 |

> **成本**：脉冲 = 每点 2 个环 Mesh（`LineStrip`，8 段圆），**≤ 64 顶点/点**。50 个事件点 = 3200 顶点，可忽略。
> **AGENTS §3.2 说明**：涟漪是**时间驱动**的局部 UI 循环计时器，**不是 day 驱动**——「事件是否进行中」这一世界状态已由 `TimelineQuery::at(current_day)` 求出，涟漪只是叠加在**已解析状态**上的装饰。渲染层无 `if time > event.day`。**底环则完全不是动效**（恒定值），**任何情况下都不被任何 intensity/速率设置抑制**。

### 4.3 轨迹的视觉（线段 / 箭头 / 流光线）

> 基线 §1.6：轨迹是 waypoint 点列；§1.8：World 层轨迹**逐段生长**；§1.16 L3：低缩放用 Douglas-Peucker 简化。

#### 4.3.1 轨迹的静态视觉

| 元素 | 规格 | 实现 |
|---|---|---|
| **主线段** | 宽 3px（@1x），色 = 该轨迹主体色（Character 主色 或 `accent.select`），**圆头端帽** | `LineStrip` + `SH_Vector_Outline` |
| **描边** | 主线上下各 1px `line.on_light`（alpha 0.5），保证任何地形上可见 | 同 shader 双线模式 |
| **方向箭头** | 沿轨迹**每 8 格**（或每 64px）画一个箭头（**不流动，静态**） | 顶点属性标记，fragment 里按 `arclen % 64` 画三角 |
| **箭头/航点的生长上界** | **生长过程中，箭头与航点只能画在「已生长段」上**（未生长段无箭头、无航点）｜与动画规格接口已裁定 | 复用 `SH_Vector_Outline` 的 `arclen`，加 `u_arclen_max` uniform（**零额外顶点**） |
| **航点** | 小方点（4px），有时间戳的 = 实心，无的 = 空心（对齐 T1/T2 规则） | Sprite 或 Mesh 点 |
| **起终点** | 起点 = **空心圆**（推算轨迹）/ **实心圆**（时间戳轨迹）；终点 = **实心圆 + 内星** | 形状区分 |
| **生长笔尖**（当前 `t` 位置） | 一个**实心圆点**（6px，比航点大）沿轨迹位于插值位置 `lerp(pi, p(i+1), u)`（基线 §2.14：渲染层只读 `TrackPositions` 资源）。**这是唯一的「当前时刻」地图侧视觉锚点** | 独立 Sprite |

> **术语与配色（与动画规格统一，见 §10）**：本文原称「发光游标」，与动画规格的「**生长笔尖**」为同一物，**统一取「生长笔尖」**；色 `accent.cursor`——该令牌语义确认为「**当前时刻指示色**」，同时呈现于**时间轴游标**与**轨迹生长笔尖**两处（同一 `current_day` 的两个视图）。

#### 4.3.2 流光线：**要不要做？**

| 方案 | 评价 | 裁定 |
|---|---|---|
| **静态箭头**（每 64px 一个） | 零动画成本；方向清晰 | ✅ **默认** |
| **流光线**（纹理 UV 滚动，表示方向） | 好看，但**是常驻动画** → 违反 V-P3（作者长时间注视会累） | 🟡 **可选，默认关** |
| 播放中的流光线 | 播放时「流动」表达「时间在推进」，是**有语义的**，可接受 | ✅ **仅在播放中开启** |

**裁定**：
- **静止编辑时** → 静态箭头（零成本，方向可读）；
- **播放事态时** → 开启流光线（`uv.x -= speed * dt`，即 **由播放状态驱动**，符合 AGENTS §3.2：不是特效自己跑，是时间轴在跑）；
- **成本**：流光线 = 在 `SH_Vector_Outline` 里给一个 uniform `u_flow_speed`（0 或 >0），fragment 里对箭头位置做偏移。**零额外 drawcall，零额外顶点**。

#### 4.3.3 轨迹的 LOD（基线 §1.16 L3）

| 缩放 | 轨迹呈现 |
|---|---|
| `< 0.15×` | 只画主线（Douglas-Peucker 简化），**无箭头、无航点** |
| `0.15×–0.6×` | 主线 + 每 16 格一个箭头，航点合并 |
| `> 0.6×` | 全元素（箭头每 8 格、全部航点、当前位置游标） |

> **Inspector 始终显示完整航点数**（基线 §1.16 风险表：LOD 简化后作者以为「点丢了」）。

### 4.4 角色 / 城市图标的视觉（「表达这是谁」而不缩小）

#### 4.4.1 角色图标（City / Interior 层，基线 §1.8「角色图标在街道上移动」）

| 项 | 规格 | 理由 |
|---|---|---|
| **基础形态** | 圆形底色（**势力/阵营色**，直径 20px）+ **白色首字**（角色名首字，`font.title` 13px 居中） | 文字是最不依赖色觉的身份载体 |
| **朝向/移动** | 移动时图标**轻微朝向偏移**（剪影方向），**不旋转整个图标**（首字必须可读） | 首字可读 > 朝向感 |
| **多角色区分** | 极多角色时，用**图标形状**（圆/方/菱形，按角色重要度或类型）分流 | 形状承载类别 |
| **缩小保护** | 若缩放导致图标 < 16px，**图标不缩小**（保底 16px），改用**密度聚合**（附近 3 个角色合并成一个带数字的簇） | 保证「这是谁」永远可读 |
| **悬停** | 放大到 28px + 显示名字标签（`font.body`） | 按需放大，不常驻 |

#### 4.4.2 城市 / 室内图标（`props_atlas`，美术 §3.4）

| 项 | 规格 |
|---|---|
| **符号** | 用 Theme Pack 的地物符号（城/镇/村/关/港…），锚点 `bottom_center`（美术 §3.4） |
| **势力归属提示** | 符号**底座**加一圈势力色（1.5px 弧），表示「这个城的归属」——**不改变符号本体**（符号属 pack，不可改） |
| **选中/当前** | 选中 = `accent.select` 外框 + 上浮 2px；当前事态节点所在 = 一次脉冲环 |
| **文字** | 城名标签（`font.body`）**永不重叠**（基线 §1.16 L4），低缩放自动降密度 |

## 五、地形渲染强化

> 基线依据：§1.10 视图模式 A（真实地形）/ B（色块地形）；§2.3 地形 = 栅格（I16 高度 + U8 类型双通道）；§2.11 单纹理 + 增量重传。

### 5.1 视图模式 A「真实地形」的强化

> 上下文：真实地形模式依赖美术资源（贴图），且基线 K5 标注「若美术资源不足则砍 A 模式」。**因此 A 模式的强化必须「低成本、可降级」。**

| 强化项 | 方案 | 成本 | 裁定 |
|---|---|---|---|
| **① 山体阴影（hillshade）** | 由高度场算**光照值**（左上 45°，对齐美术 §1.5 光源方向），烘焙进地形纹理的**一个通道**或单独一张纹理 | **低**（离线烘焙一次；高度变了才重烘焙脏块） | ✅ **采纳（主力强化）** |
| **② 等高线（contour）** | 由高度场算 `fract(height / interval)` 的等值带 | **低**（烘焙，或着色器 1 行） | ✅ **采纳（可开关）** |
| **③ 水面反射（简化）** | **不做实时反射**。用「水面**横向 2 条高光条** + 轻微色带」表达（美术 §1.6 Water 材质） | **极低** | ✅ **采纳（规范化为美术约定）** |
| **④ 环境光遮蔽（AO）** | ❌ **不做** | 美术 §1.5 明确「无全局环境光模拟」「禁止 AO 重度烘焙」 | ❌ **砍** |
| **⑤ 法线贴图 / PBR** | ❌ **不做** | 美术 §1.6 明确禁止 | ❌ **砍** |
| **⑥ 高度雾 / 景深** | ❌ **不做** | 2D 俯视，无 Z 轴，雾无意义 | ❌ **砍** |

**hillshade 的实现口径**：

```
输入：heightmap（I16）
   ↓ 对每个纹素求梯度（Sobel，6 邻域）
   ↓ 与光方向（左上 45°，高度角 45°）点乘 → 光照值 L ∈ [0,1]
   ↓ 输出：明暗 = base_color × (0.6 + 0.4 × L)   // 压扁对比，防噪
   ↓ 写入地形纹理（与 base_color 相乘）或单通道附加纹理
```

> **关键**：hillshade **不是**「让画面好看」——它让作者**看清山脉走向与坡度**，是**编辑海拔时的刚需**（V-P1：它让作者多看清了坡度）。

**等高线的实现口径**：

```
等高线间距 interval = 自适应（按高度跨度分成 ~12 档）
fragment: c = fract(height / interval)
若 c < 0.03 或 c > 0.97 → 输出等高线色（line.on_light @ alpha 0.5）
```

**A 模式的降级（K5 兜底）**：若资源不足 → **只保留 hillshade + 等高线**（纯高度场即可生成，零美术资源），砍掉贴图 → 退化为「阴影色块图」。**海拔编辑能力不受影响**（基线 K5 明确：不砍海拔编辑）。

### 5.2 视图模式 B「色块地形」的强化（纯色如何不廉价）

> 色块地形 = 每种地形一种纯色（基线 §1.10）。风险：看起来像「Excel 色块」。

| 强化手段 | 规格 | 成本 |
|---|---|---|
| **① 每地形四变体打散** | 直接用美术 §3.2.1 的「每地形 4 变体」（坐标哈希选变体） | 零（已在 pack 里） |
| **② 内置 1px 内描线** | 每个色块内侧 1px 描线（`line.on_light` 按底明度自动选），让色块有「卡片感」 | 极低（美术 §3.6 已规范） |
| **③ 地形过渡遮罩** | 用美术 §3.2.3 的 `transition_mask`（8 向，带宽 `tile/4`） | 低（一次采样） |
| **④ 海岸线硬描线** | 见 §5.3 | 低 |
| **⑤ 高度微阴影（可选）** | 色块模式下也可叠加**极淡的 hillshade**（alpha 0.15），让平原/丘陵有立体感 | 低 |
| **⑥ 禁止** | ❌ 渐变填充、❌ 噪点纹理、❌ 圆角 | 违反美术 §1.6「禁止噪声纹理」 |

> **结论**：色块不廉价的秘诀是 **①变体打散 + ②内描线 + ③过渡遮罩**，这三项**全是美术侧已承诺的规格**，特效层**额外只加 ⑤ 的淡 hillshade**。
> **B 模式的定位**：它是**战略视角**，要的是「区域清晰」，不是「地貌真实」→ 强化克制。

### 5.3 海岸线 / 河岸的视觉处理

| 元素 | 规格 | 实现 |
|---|---|---|
| **海岸线** | 水陆交界处画 **2px 硬描线**，色 = `line.on_light`（在浅水上）/ `line.on_dark`（在深色陆地上），按两侧明度自动选 | 由地形类型图算边界（Marching Squares 或 **沿 U8 类型图求 4-邻域差异**），生成 `LineStrip` |
| **海岸浅水带** | 紧邻陆地的水域，用 `core.water_shallow` 画 **1 格宽**的浅水带（区别于深海） | 已是颜色/类型数据，直接渲染 |
| **河岸** | 河流（美术 §3.3：河宽 `tile/4`、不显示格界）→ 特效层**不加额外描线**（河流本身已连续） | — |
| **入海口** | 河流汇入海处，用**喇叭状渐变**（河宽 → 3× 宽）过渡 | 顶点级宽度插值 |

> **海岸线描线的成本**：依赖地形类型边界提取。**原型阶段可用「笔刷软边缘」（基线 §2.4）近似，延后 Marching Squares**（基线已裁定原型延后）。
> **特效层立场**：海岸线描线是 **P1**（好看但不阻塞原型），**原型可先不做**。

### 5.4 海拔色阶的着色方案（着色器 vs 预生成贴图）

#### 5.4.1 方案对比

| 方案 | 实现 | 优点 | 缺点 | 裁定 |
|---|---|---|---|---|
| **A. 预生成贴图** | 高度变化时**离线重生成**地形纹理（含色阶 + hillshade + 等高线） | 运行时零成本、1 次采样、移动端友好 | 高度改变需重烘焙脏块（笔刷时的小延迟） | ✅ **主力** |
| **B. 着色器实时** | fragment 里按高度查色阶表（1D LUT / 分段函数） | 高度改变零延迟 | 每像素 ALU + LUT 采样；移动端成本高 | 🟡 **备选（笔刷实时预览时用）** |
| **C. 顶点色** | 网格顶点存高度 → 色 | 成本极低 | 分辨率受网格限制，色阶带锯齿 | ❌ **不做**（色阶需要平滑） |

#### 5.4.2 裁定：**分层方案**

```
① 静态地形（未编辑）：预生成贴图（A）—— 含 base_color + hillshade + 等高线
② 笔刷实时编辑中：切换为着色器实时（B）—— 对「脏块」实时算色阶，松手后重烘焙回 A
   （这样作者拖笔刷时零延迟看到色阶变化，松手后回到零成本贴图）
③ 高度色阶表：一条 256 项 1D LUT（按 elevation min/max 归一化）
```

> **为什么笔刷要用 B**：基线 §1.13「参数实时预览」——作者拖笔刷时要**即时看到**海拔/地形变化。预生成贴图有烘焙延迟 → 因此**编辑态走着色器，静态态走贴图**。这是「实时性」与「性能」的最优切分。

**海拔色阶带的颜色来源**：由 Theme Pack 的 `core.*` 地形基色按高度插值（浅水→沙滩→草→丘→山→雪）。**不做独立的海拔色板**（避免与地形色板冲突，符合美术 §1.4 的 28 色结构）。

### 6.2 必须走着色器的（仅 3 项）

| # | Shader | 为什么不能省 | 复杂度 |
|---|---|---|---|
| **1** | `SH_Vector_Outline` | 虚线 + 屏幕空间线宽 + 箭头 + 流动 **无法用固定管线表达**；且是**所有矢量元素（势力描边/道路/轨迹/选区）的统一管线** | 中（~80 行 GLSL/WGSL） |
| **2** | `SH_Terrain_Live`（笔刷实时） | 编辑态需要**零延迟**反映高度色阶变化 | 中（LUT 采样 + 等高线） |

### 6.3 `SH_Vector_Outline` 规格（提给主程序 / 技术架构）

| 项 | 规格 |
|---|---|
| **顶点属性** | `position: vec2`（图内局部坐标）、`normal: vec2`（点法线，CPU 预计算）、`arclen: f32`（累计弧长） |
| **Uniform** | `u_view_scale`（缩放）、`u_width`、`u_color: vec4`、`u_dash: vec3`（三段周期）、`u_offset: f32`、`u_flow_speed: f32`、`u_arrow_period: f32` |
| **顶点阶段** | `screen_pos = to_screen(position)`；`screen_pos += normal_screen * u_width * 0.5`（线宽在屏幕空间恒定） |
| **片元阶段** | ① dash：`if fract(arclen/(d1+d2+d3)) in gap → discard`；② 箭头：`if fract((arclen - t0)/period) < gap → discard`；③ flow：`arclen += u_flow_speed * time`（播放时） |
| **合批** | 同 `u_color` 同 `u_dash` 的段**必须合批**（用顶点属性承载差异，少用 uniform 分支） |
| **注意** | **不需要 MSAA 抗锯齿**（2D 俯视，线条本身粗）；若需边缘平滑用 `smoothstep(arclen)` 而非硬件 MSAA |

### 6.4 性能预算（对照基线 §2.19）

| 指标 | 基线目标 | 本文承诺 | 超阈处置 |
|---|---|---|---|
| **帧率** | ≥ 60 FPS（1080p，全图层） | 视觉层总开销 **< 3ms/帧** | 自动降级（见 §8） |
| **单图层顶点** | ≤ 100,000 | 描边/轨迹/道路共用此预算，**合计不超 10 万** | 超阈 → 简化 Mesh（Douglas-Peucker） |
| **笔刷响应** | ≤ 16ms | 光标 < 0.05ms，**不占用笔刷预算** | — |
| **描边层数** | （新增） | **同屏可辨描边 ≤ 6 层**；超 6 层 → 只画最粗 6 层 + 计数徽标兜底 | LOD 分级 |
| **凸徽标数** | （新增） | 同屏 ≤ 32 个 | 超阈 → 合并/降密度 |
| **事件脉冲** | （新增） | 同屏 ≤ 5 个脉冲 | 超阈 → 静态点亮 |
| **纹理内存（图案）** | — | 9 张 32×32 RGBA = **36KB** | 可忽略 |
| **Drawcall（视觉层）** | — | 填充 1 + 描边 ≤6 + 轨迹 ≤4 + 图标 ≤2 + 光标 1 ≈ **≤ 15** | 超阈 → 合批优化 |

### 6.5 明确「不做」的清单（成本 > 收益）

| ❌ 不做 | 理由 |
|---|---|
| **粒子系统**（任何形式的粒子） | 编辑器无「命中/爆炸/魔法」；粒子 = 纯噪音 |
| **泛光 / Bloom 后处理** | 会让文字与细描线发虚，损害可读性（V-P1） |
| **色差 / 屏幕扭曲 / 扫描线** | 游戏化效果，工具不需要 |
| **运动模糊** | 2D 俯视无快速运动物体 |
| **实时水面反射 / 折射** | 美术 §1.6 已定为「2 条高光条」简化表达 |
| **法线贴图 / PBR** | 美术 §1.6 明确禁止 |
| **敌人/单位的「打击感」类效果**（顿帧、震屏、冲击波） | **本项目没有战斗** |
| **环境粒子**（雪花飘落、落叶） | 与「编辑效率」无关；若作者需要氛围，属叙事资产，不属编辑器 |
| **轨迹的拖尾残影** | 会让「当前 `t` 位置」读不清 |
| **面板进出场的粒子/光效** | 动画规格已管面板过渡；光效是噪音 |
| **hover 时地图元素的缩放弹跳** | 会造成地图抖动，破坏「坐标稳定」心智 |

> 这份清单本身就是交付物：**它保护了 60 FPS 预算与作者注意力。**

### 6.6 关键技术约束（对齐 AGENTS）

| # | 约束 | 对应 |
|---|---|---|
| 1 | 视觉层**不得**直接读 `TimeSpan` 做比较，一律读 `TimelineQuery::at` 产出的资源 | AGENTS §3.2 |

## 八、降级策略（高负载时降什么、降成什么样）

> 对齐基线 §2.19「自动降级」与 §1.16「LOD 只改显示不改数据」。

| 触发条件 | 降级动作 | 降级后长什么样 | 信息损失 |
|---|---|---|---|
| **缩放 < 0.15×（概览）** | 描边只留最粗 1 层；关光晕；关纹理；关箭头；关航点 | 底图填充 + 1 层粗描边 + 城市点 + 事态链总览 | **无**（Inspector 仍显示全量；数据不变） |
| **缩放 < 0.3×** | 地形换 1/4 降采样纹理（基线 §2.19） | 地形略糊，色块仍可辨 | 无 |
| **描边层 > 6 层** | 只画最粗 6 层 + 计数徽标 | 6 条描边 + 徽标数字说明「还有 N 层」 | 徽标承载（不丢信息） |

| **同屏事件脉冲 > 5** | 超出者改静态点亮 | 多数点静止，≤5 个脉冲 | 无（点亮状态仍在） |
| **帧率掉到 < 50 FPS** | 依次关：① 纹理图案 → ② 易主过渡 → ③ 描边内亮线 → ④ 事件脉冲 | 逐级变「更朴素」 | 核心信息（描边/态/位置）全保留 |
| **面板抢占输入** | 地图光标隐藏（基线 §2.13） | 无光标 | 无（交互本就不在地图） |
| **势力几何缺失（D5 期）** | 无填充无描边，只显示势力名 + 归属关系（`memberships_of`） | 纯文本/列表 | 关系信息**完全保留**（基线 §2.5.4） |

**降级硬规则**：

| # | 规则 |
|---|---|
| **D1** | **降级只改「画多少」，不改「是什么」**（基线 L1） |

| **D3** | **降级必须可逆**：缩回原级 → 视觉完全恢复 |
| **D4** | **状态栏提示当前降级级别**（让作者知道「为什么变朴素了」） |

动画规格原文「30 天/秒 脉冲暂停」已**作废**，改为「**暂停涟漪环、保留底环**」。动画总监承认原文把「脉冲」当整体抑制，**未区分「状态（底环）」与「动效（涟漪）」**。本文三条论据全被认同（底环属状态 / 30 天/秒是概览模式恰需全局活跃提示 / 3 天 span 在 30 天/秒下约 6 帧非一闪而过）。

**由此提炼的双方共识硬规则（★ 本文 §1.3）**：

> **「状态」不被任何 `intensity` / 速率抑制；「动效」（往复、扫掠、弹跳）才被抑制。**

此规则**统一了两文全部抑制逻辑**（本文的「事件三态不降级 / 光标不降级」，动画的「底环恒在 / L0–L2 不受 intensity 影响」），已写入本文 §1.3 并要求登记 GLOSSARY。

**唯一后续接口**：若美术（线型/色板）或程序（day 插值函数落 `wv-core`）侧出现新约束，特效与动画双方**直接对接**，不再经汇编层。

## 十、术语登记建议（供 GLOSSARY.md）

|---|---|---|---|
| **视觉表达层** | Visual Expression Layer | 编辑器「让信息更清楚」的视觉手段集合（相对游戏特效）。含信息视觉与编辑反馈 | 视觉 |
| **编辑反馈** | Edit Feedback | 编辑操作产生的即时视觉回应（光标范围、非法提示、自然化警示） | 视觉 / 编辑 |
| **填充 / 描边双层分离** | Fill-Outline Split | 势力图渲染规则：面上填充只由唯一底图层提供，其余归属层用描边共存 | 地理 / 视觉 |
| **底图层** | Base Fill Layer | 势力图中唯一被允许提供面填充的势力层（作者指定） | 地理 / 视觉 |
| **计数徽标** | Overlap Badge | 归属集合 ≥3 的重叠处显示的圆形徽标（数字 + 层叠环） | 地理 / 视觉 |
| **四维描边语法** | Outline Grammar (4D) | 描边的四个正交区分维度：颜色 / 粗细 / 线型 / 偏移 | 视觉 |
| **势力易主过渡** | Faction Transition | `GeometrySpan` 边界跨越时由时间轴驱动的描边淡入/淡出与扫光 | 地理 / 视觉 |
| **笔刷精度契约** | Brush Precision Contract | 「光标所见范围 = 实际影响范围，误差 0」的硬约束 | 编辑 |
| **衰减可视化** | Falloff Visualization | 笔刷/选区光标的径向渐变与双环，须与实际衰减函数一致 | 编辑 |
| **非法操作提示** | Invalid Action Cue | 缩放过低/图层锁定等场景下，「一动手即出现」的视觉警告 | 编辑 |
| **事件三态** | Event Tri-state | 事件点的休眠 / 进行中 / 已结束三态视觉（形状 + 尺寸 + 颜色 + 脉冲） | 事件 / 视觉 |
| **事件脉冲** | Event Pulse | 「进行中」事件点的**两层结构**：常驻**底环** + 周期性**涟漪环**（周期 2.4s、同屏 ≤5、可关闭） | 事件 / 视觉 |
| **底环** | Baseline Ring | 脉冲结构中**恒定不闪**的 `1.0R` 环（`accent.event` @ alpha 0.25）。**属「状态」不属「动效」**——任何 intensity / 播放速率下都不被抑制，保证「进行中」标记永不消失 | 事件 / 视觉 |
| **涟漪环** | Ripple Ring | 脉冲结构中每 2.4s 外扩一次的环（`1.0R → 1.6R`，alpha 0.5 → 0，ease-out-cubic 扩张）；`intensity=off` 时关闭 | 事件 / 视觉 |
| **生长笔尖** | Growth Head | 轨迹已生长段末端 / 当前 `t` 插值位置的 6px 实心圆点，色 `accent.cursor`。**是唯一的「当前时刻」地图侧视觉锚点**（与时间轴游标同色同源）。原名「发光游标」，统一取本名 | 事件 / 视觉 |
| **当前时刻指示色** | Present-time Accent | `accent.cursor` 的确认语义：呈现在 **① 时间轴游标 ② 轨迹生长笔尖** 两处（同一 `current_day` 的两个视图） | 视觉 / 时间轴 |
| **静态箭头 / 流光线** | Static Arrow / Flow Line | 轨迹方向表达的两种形态；箭头零成本常驻，流光线仅播放时开启（`u_flow_speed`，恒定 40 px/s） | 事件 / 视觉 |
| **day 空间插值** | Day-space Interpolation | 过渡进度是 `current_day` 的**纯函数**（非壁钟计时）：`clamp((current_day − 边界day)/Δ_day, 0, 1)`。时长自动由推进速率派生、天然可逆、可进 `wv-core` 单测。**本文「时间轴驱动过渡」的默认实现范式** | 视觉 / 时间轴 |
| **抑制三分类**（含成员：状态 / 动效 / 语义动效） | Suppression Classes | **上位概念**：元素按三档分类，决定其在高速档与 `intensity=off` 下的行为。**跨成员通用判据**（本文 §1.3，动画规格 §7.1/§8.5 同构） | 视觉 / 动效（通则） |
| ├ **状态** | State | 分类之①：恒定值或其变化本身即信息的视觉；去掉 → **丢事实**。**永不抑制**（底环、事件三态、笔刷光标 falloff、势力描边） | 视觉 / 动效（通则） |
| ├ **动效** | Motion | 分类之②：往复/扫掠/弹跳的装饰性运动；去掉 → **信息仍在**。**可抑制**（涟漪环、扫光、蚂蚁线爬行） | 视觉 / 动效（通则） |
| └ **语义动效** | Semantic Motion | 分类之③：运动本身携带「世界正在变化」语义；去掉 → **丢语义**。**仅受触发条件控制，不受速率抑制**（流光线：停止播放即关） | 视觉 / 动效（通则） |
| **海拔色阶** | Hypsometric Shade | 由高度场生成的色带（浅水→雪），静态烘焙、编辑态实时 | 地理 / 视觉 |
| **山体阴影** | Hillshade | 由高度场按左上 45° 光方向烘培的明暗，用于表达坡度与山脊走向 | 地理 / 视觉 |
| **矢量统一管线** | Unified Vector Pipeline | 描边/道路/轨迹/选区共用的 `SH_Vector_Outline` 着色器管线 | 视觉 / 技术 |

| 严重度 | 风险 | 兜底 | 回退成本 |
|---|---|---|---|
