# ADR-0009：分级瓦片缩放（世界 → 街道）

**状态**：已接受（Accepted）
**日期**：2026-10-13
**决策者**：用户（要求「google地图那样，缩放到街道」；范围与数据源由用户拍板「1. 都要 / 2. Overture / 3. 你决定。」——第 3 项「连续还是分级」由用户**委派给实现方**，备选与代价已先行呈交）

## 1. 处境（Context）

用户要求地图能像 Google 地图那样**缩放到街道**。这不是换一套色板，而是把「能看多远」这件事从「一张图的内部缩放」升级为「跨层级的缩放」。

现状与目标的差距，有四条硬证据：

1. **只有一张全局栅格**。`World.terrain: Option<TerrainData>` 是**单值**字段，加载器只取第一张声明了 `raster` 的图（`crates/wv-io/src/project.rs` 的 `maps.iter().find_map(...)`）。城市图即使声明了自己的 `raster`，也**不会被加载**。
2. **层级坐标没有嵌套**。`Extent` 此前只有 `width` / `height`——子图不知道自己落在父图的哪个位置，「子图局部坐标」无法上溯为世界坐标。
3. **两套坐标系口径已经分叉**。地形外框按**根图** `extent` 绘制，而图标按**当前图** `extent` 归一化摆位。结果是 1024×1024 的城市图上 `anchor: [0.5, 0.5]` 的图标，会落在 4096×4096 世界帧的左上四分之一处。
4. **变焦跨度差三个数量级**。相机当前 `SCALE_MIN = 0.1` / `SCALE_MAX = 8.0`，即单图内 **80×**；从世界图看到街道需要约 **10⁴–10⁵ ×**。

第 4 条还牵出一个数值问题：世界坐标是 4096 量级，`f32` 尾数约 7 位有效数字，`x = 4090.123` 处相邻可表示间距约 `0.0005` 单位；在 10⁵ 倍缩放下，这等于**约 50 像素的坐标抖动**。世界坐标是全局唯一参考系，一旦抖动，网格线、路缘、图标会在缩放时互相错位。

## 2. 决策（Decision）

1. **缩放采用「分级 + 级间平滑插值」**：级别是**离散**的整数档，档与档之间用缩放动画与交叉淡化过渡。**不做**无极连续缩放。
2. **级别由「图在层级树中的深度」派生，不扩充 `MapLevel` 枚举**。规划为 6 级：世界 → 大区 → 区域 → 城市 → 城区 → 街道。`MapLevel` 的 `World/Region/City/Interior` 四值保持不动——这是 ADR-0001 D2「开放集用数据承载、不用枚举」的同一取舍：级数将来要调，那是**参数**变化，不该是数据结构变化。
3. **每个级别自带栅格与自带原点**。`Extent` 增加 `origin: Point`（本图左上角在**父图局部坐标系**中的位置，世界层恒为 `(0, 0)`，缺省值 + 序列化跳过，既有 YAML 无需改动）。每张图可以声明自己的 `raster`。
4. **坐标变换只有一个实现点**：新增 `wv_core::coord`，集中实现「图内局部坐标 ↔ 世界坐标 ↔ 归一化坐标（UV）」及逐层上溯（`MapFrame`）。基线 §2.15 的「禁止多 System 各写一遍」由此成为**可执行的约束**，而不是一句告诫。
5. **相机缩放上下限按级别重算**。`SCALE_MIN` / `SCALE_MAX` 从「全局常量」改为「当前级参数」，每级释放自己的变焦跨度（每级 80×–200×，级数相乘得总跨度 10⁴–10⁵）。
6. **每级独立遵守既有的纹理预算**：整张纹理 ≈ 4096² ≈ 67 MB，分块 256×256 上传、视口外不加载（沿用 ADR-0008 §7 与基线性能口径）。
7. **级间过渡只做缩放与淡化，不做位移插值**。位移插值的中间态会落进「大坐标 + 小增量」的区间，正是第 4 条要规避的精度陷阱。

## 3. 理由（Rationale）

- **精度**：分级之后，每一级都在**自己的原点附近**工作——顶点坐标始终是小量，`f32` 全程够用。这是分级相对无极缩放的**决定性**优势，而不是工程偏好。
- **Google 自己就是这么做的**：用户所说的「连续」体验，底层是整数 `z` 瓦片 + 缩放动画。模仿它的**模型**比模仿它的**表象**更接近用户想要的。
- **与既有 LOD 口径同构**：项目已经有「`scale < 0.3` 降纹理分辨率 / `scale < 0.5` 隐藏道路细节 / `scale > 2.0` 显示地点名」的分档阈值（基线性能章节）与 256 分块视口加载。分级缩放只是把「同一张图内部的 LOD」扩展成「跨图 LOD」，两者同一套机制。
- **P2 / P3 不受损**：每级仍是「YAML 索引 + 声明的二进制栅格」，没有新格式；`terrain_bin.rs` 的 `WVTR` magic + `format_version` + 校验和机制原样复用。二进制例外仍只覆盖栅格网格数组，没有扩大。
- **P4 不受损**：级与级之间仍是 `children` 的 `Id` 引用 + `Extent.origin` 参数，**不复制**任何子图内容。
- **P5 不受损**：分级只影响底图与相机，图层开关依然是逐层控制。
- **可回退**：第 2 条的「级 = 深度」把级数变成了纯参数。若 6 级不合适，改规划不动数据模型——这正是 §12 待决问题所要求的「最容易回退的方案」。

## 4. 代价（Consequences）

**负面后果，必须承认：**

1. **必须有级间过渡**。没有过渡，级别切换会生硬跳变；过渡本身要写动画与交叉淡化代码。
2. **每级一份栅格带来驻留问题**。多图同时驻留的内存会有峰值，退化为「一张 67 MB × 层数」是不可接受的。驻留策略（懒加载祖先链 / 同时驻留数上限 / 卸载时机）**尚未收敛**，已登记为 README §12 第 19 条待决。
3. **作者多了一个必须理解的概念**。「图有范围、范围有位置」从可选变成坐标正确性的前提——城市图不写 `extent`，图标摆位退化（`coord` 对此返回 `None` 而非 `NaN`，可判定但需要调用方回退到哈希摆位）。
4. **地面尺度仍缺**。「缩放到街道」的可用性依赖「一格 = 多少公里」，而该字段已于 2026-10-12 撤除。真实地图可由 `geographic_source.bbox` 派生，虚构地图没有真值——登记为 README §12 第 20 条待决。**本 ADR 不重新引入 `width_km`**。

**被否决的备选方案：**

| # | 备选 | 否决理由 |
|---|---|---|
| A | **无极连续缩放**（单图内连续放大到街道） | `f32` 大坐标精度崩溃（见 §1 第 4 条，10⁵ 倍下约 50 像素抖动）+ 跨级 LOD 无自然切换点。收益（少一层「级」的概念）不值这个代价 |
| B | **单张全局栅格**（把世界做成一张超大图） | 4096² 是硬上限（`terrain_bin.rs` 的 `MAX_TERRAIN_CELLS = 16_777_216`）。要同时满足「20 km 城市 @ 4.9 m/格」与「全球一张图」，两个尺度在一张纹理里不可兼得 |
| C | **接入 Google 在线瓦片 / 以 Google 为地图源** | 违反 P1（单机可运行）。ADR-0008 已明确否决，本 ADR 不重新讨论 |
| D | **所有级别共用一张 10000² 超大栅格** | 400 MB RGBA 与 P2 的单机现实冲突；且卸载粒度变粗（想释放一条街却必须丢掉整个世界） |
| E | 保留 `SCALE_MIN/MAX` 全局常量、靠单图 `extent` 撑起跨度 | 正是第 4 条精度问题的来源。跨度越大，同一个 `f32` 世界坐标越无法同时服务两端 |

## 6. 追加（2026-10-13，同日）：`origin` 的未声明语义与落点派生

> 本节依 `AGENTS.md` §6.3「文档追写不改机制」**追加**，不修改上文任何结论。
> §2 第 3 条（每级自带栅格与自带原点）不变；这里细化的是它的**缺省语义**。

### 6.1 处境：Phase 1 落地时暴露的两个缺口

1. **「未声明」与「声明为 `(0,0)`」不可区分**。§2 第 3 条把 `origin` 定为 `Point`、缺省 `(0,0)`，
   于是「作者没写」与「作者明确写了左上角就是 `(0,0)`」在数据上等价。
   但两者该有不同行为：前者应可派生，后者是作者的权威声明。
2. **既有示例工程已经在别处表达了同一件事**。`examples/xinhai-1911` 的城市图只写了
   `extent: {width: 1024, height: 1024}`，而「武汉在哪」**只**由世界图上那个
   `drill_into: map_city_wuchang` 的图标 `anchor` 表达。若要求作者再写一遍 `origin`，
   就是把同一个位置维护成两份会各自漂移的数据——与原则四「只存引用，不重复存储」
   的精神相悖（§2 第 1 条同此口径）。

### 6.2 决策

1. `Extent.origin` 类型定为 **`Option<Point>`**；`None` = 未声明（序列化跳过，既有 YAML 零迁移）。
2. 落点优先级：**显式 `origin`** ＞ **父图上第一个 `drill_into == 本图` 且显式声明了 `anchor` 的图标** ＞ `(0,0)`。
3. 派生语义：图标标记的是子图的**中心**，故子图左上角 = 图标点 − 子图 `extent/2`。
   由此「双击图标的落点」与「钻入后相机的落点」天然一致（都是那个图标点），不需要两处各写一遍。
4. 只有**显式 `anchor`** 参与派生。哈希回退摆位是渲染层为避免标记重叠而做的权宜，
   不是作者声明的位置，不能反过来决定世界坐标。
5. 两个入口各司其职：`resolve_frame` 是**纯声明口径**（只看 `origin`），
   `resolve_frame_in` 是**作者口径**（含上述派生）。`wv-app` 一律用后者。

### 6.3 理由

- **单一真源**：位置只在作者已经会写的地方（父图图标）写一次。
- **与既有世界坐标数据相容**：轨迹、地点点、距离边全部用**世界图**局部坐标
  （辛亥示例里武汉 = `(1650, 1700)`，`places.yaml` 与 `icon_wuhan` 的 `anchor` 同源）。
  城市帧以该城市的地点坐标为心之后，钻入城市时这些数据仍落在**本图范围之内**
  （该城自己的地点点出现在城市中心附近），不需要为「子图里怎么画世界坐标系的数据」
  再定一套规则。
- **零迁移**：既有示例工程不改一行 YAML，城市级摆位即从「世界帧左上四分之一」回到正确位置。
- **多入口仍可权威**：同一子图有多个入口图标时，`origin` 由作者显式指定（取「第一个」只是兜底）。
- **可回退**：派生规则只在 `coord` 内，删掉它不影响 §2 的任何决策。

### 6.4 代价

1. **派生是隐式的**：作者挪动父图上的入口图标，整张子图在世界里的位置会跟着挪。
   对「把城市拖到该在的地方」是便利，对「只想换个像素位置」则可能意外——已写入
   `GLOSSARY.md` 的「图原点」条目与 `README.md` §12 第 22 条。
2. **多入口取「第一个」有歧义**：未显式声明 `origin` 且父图有多个指向本图的图标时，
   结果依赖 `icons` 的声明顺序。登记为 README §12 第 22 条待决。

### 6.5 被否决的备选

| # | 备选 | 否决理由 |
|---|---|---|
| A | 保持 `origin: Point`，`(0,0)` 一律视为未声明并派生 | 无法表达「左上角恰在 `(0,0)`、而入口图标在图上别处」——这正是多入口或整图覆盖型子图的常见写法 |
| B | 保持 `Point`，改为在示例/新工程 YAML 里补写 `origin` | 同一位置两份数据，必然漂移；与原则四精神相悖，且给作者增加纯机械负担 |
| C | 让派生落点等于图标点（图标 = 子图左上角） | 钻入后相机停在子图左上角，只能看到右下四分之一；要么再加一条「相机移到子图中心」的规则，要么画面错位 |

## 7. 追加（2026-10-13，同日）：栅格继承与「来源图」

> 本节依 `AGENTS.md` §6.3「文档追写不改机制」**追加**，不修改上文任何结论。
> §2 第 3 条（每级自带栅格 + 自带原点）不变；这里补的是它隐含的一个问题：
> 某张图**没有**声明自己的 `raster` 时，它显示什么。

### 7.1 处境：渐进工程与空白视图

Phase 2 落地时 `World.terrain: Option<TerrainData>`（全局单张）变成按图存放的
`World.terrains: BTreeMap<Id, TerrainData>`。随之出现一个新问题：作者建了一座城市图、
**还没刷**它的地形时，城市视图该显示什么？

- 若答案是「必须用自己的栅格，没有就空白」，则钻入城市的瞬间画面全空——而这并不是
  数据错误，只是作者还没做到那一步，工具不该让他面对一块黑板。
- 若答案是「把父图那一块**复制**一份给城市」，则同一份地形在工程里存了两份，
  与原则四「只存引用，不重复存储」相悖，而且「复制哪一块、什么分辨率」还要再定一套规则。

### 7.2 决策

1. **继承**：某张图没有自带栅格时，沿 `parent` 向上取**最近**一张自带栅格的图，
   渲染它的地形，**不复制数据**。
2. 该图称为本次渲染的**来源图**；`TerrainTexture.last_map` 记录它，用于判断
   「换图了要不要重建纹理」。
3. **帧与格子同源**：`grid.cell_size` / `grid.origin` 一律由**来源图**的 `extent`
   与 `coord` 帧算出，不得一半取自当前图、一半取自来源图（否则地形与标记错开半幅）。
4. 来源图**不是**「当前图」字段：它每帧由 `DrillState` 的当前图 + `parent` 链**推导**
   得出，不落进 `World`（P7）。
5. 纹理重建的判据从「模式变了」扩展为「模式 ∨ 淡化 ∨ **来源图变了**」。
6. 世界上**一张**栅格都没有时（空工程），给**根图**塞一张占位地形——仍是 `World` 里的
   普通地形，笔刷与撤销因此有明确的落脚图，而不是一个「只存在于纹理里」的幽灵。

### 7.3 理由

- **渐进工程不黑屏**：作者刷出城市 `terrain.bin` 的那一刻，纹理自动切到城市，不需要额外动作。
- **零复制**：地形仍是「一图 0 或 1 份」，与 `MapNode.raster` 元数据一一对应。
- **与帧设计自洽**：`coord` 的父子嵌套是**纯平移**（`local_to_world = origin + local`，
  无缩放），城市 `extent` 与世界 `extent` 是同一个单位。于是继承来的父图地形铺在
  **父图帧**上、城市标记铺在**城市帧**上，两者落在同一个世界坐标系里——把相机放进
  城市窗口，看到的正是父图底图上城市所在的那一块。
- **可回退**：删掉继承只会让无栅格的图重新空白，数据结构与 IO 都不用动。

### 7.4 代价

1. **继承来的精度就是父图的精度**：世界图 4.9 m/格 的底图放到街道级缩放会糊成色块。
   街道级要好看，城市终究得有自己的 `raster`（或走 [ADR-0010](ADR-0010-street-vector-layer.md)
   的矢量路面）。登记为 `README.md` §12 第 24 条——按 §7.5 V1，校验层**提示**而非阻止。
2. **内存**：当前实现每图一份、**全部常驻、不淘汰**。级数一多就会撞上「一张 67 MB × 层数」
   的天花板——这正是 §12-19 待决的内容，本 ADR 未收敛该策略。
3. **换图整张重建纹理**：`image_from_terrain` 会逐格重着色整图。单张 4096² 的代价与
   模式切换同量级；频繁来回钻取时同样需要 §12-19 的缓存/淘汰策略来兜。

### 7.5 被否决的备选

| # | 备选 | 否决理由 |
|---|---|---|
| A | 无自带栅格即空白 | 渐进工程一钻进城就黑屏，作者会以为工程坏了 |
| B | 首次钻入时把父图那一块复制成城市的 `terrain.bin` | 同一份地形存两份、必然各自漂移（P4「只存引用」）；复制边界（哪一块、什么分辨率）还要另定一套规则 |
| C | 用一个「当前图栅格」这样的可变字段挂在 `World` 上 | P7：这是随视图变化的量，不该进世界数据；快照与撤销也会把它一并算进去 |
| D | 继承时把父图栅格**采样**成子图分辨率的副本 | 为省内存反而多一份放大后的数据；放大不增加信息，「糊」的问题依旧（见 §7.4 第 1 条） |

## 8. 追加（2026-10-13，同日）：分级的边界语义与钻取过渡目标

> 本节依 `AGENTS.md` §6.3「文档追写不改机制」**追加**，不修改上文任何结论。
> §2 第 ⑤、⑦ 条不变；这里细化的是它们落地时**必须补上的三条语义**——否则
> 相机会在级别交界处来回抖（见 §8.4 备选 A）。

### 8.1 处境：§2⑤ / §2⑦ 落地时暴露的三个空白

1. §2⑤ 只说「每级 80×–200×」，没说**区间锚在哪**。锚在绝对常量上（如 `[0.1, 8.0]`）
   会让深处几级挤在同一个区间里，越缩越推不动；锚在「整幅图适配窗口」的尺度
   `fit` 上，则每往里一级区间自然整体下移，级数相乘才真的换来量级跨度。
2. §2⑦ 只说「不做位移插值」，没说**换级那一刻 `scale` 取什么值**。若取级区间的
   端点，画面会跳一下——而浮点精度正是 §1 第 4 条要防的东西。
3. 钻取（双击/面包屑）的**过渡目标缩放**原先是硬编码 `4.0`。分级后 `4.0` 可能落在
   新级区间之外（1024 的子图在 800px 窗口是 `[0.016, 2.0]`），过渡终点非法，
   随后第一次滚轮被 `clamp` 硬拽，LOD 与比例尺读数也自相矛盾。

### 8.2 决策

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | 区间锚在 `fit`：`fit = max(w/window.w, h/window.h)`，`min = fit/80`，`max = fit*1.5625` | `zoom_level::LevelZoom::for_map` |
| 2 | `1.5625 = 8.0/5.12` 由历史 `SCALE_MAX` 反推，**世界级外界与升级前逐值相同**；`80` 即 §2⑤ 的 80× | `LEVEL_ZOOM_SPAN` / `LEVEL_OVERVIEW` |
| 3 | 换级**不改 `scale`**：子图 `min` 比父图更小，故父图内界落在子图区间内（反之亦然）——换级只换「显示哪张图的哪一块」 | `zoom_level` 的不变式测试 + `drill::apply_zoom_cross` |
| 4 | 换级触发 = 「已在边界 + **继续同向**滚动」，而非进入区间即触发；意图写进 `ZoomCrossRequest`，由 `drill::apply_zoom_cross` 独家消费 | `camera_zoom` / `apply_zoom_cross` |
| 5 | 换级的落点 = **指针所在的世界点**（就是缩放的锚点），不做位移插值；因此换级时**抑制**钻取的飞行过渡（吃掉 `take_depth_change()`） | `apply_zoom_cross` |
| 6 | 钻取过渡目标缩放 = `fly_in_scale(child_size, window, from_scale) = clamp(min(from_scale, child.fit))`：整幅子图铺满窗口，但不把更近的视野拉远，且必落在子图区间内 | `zoom_level::fly_in_scale` |

### 8.3 理由

- **连续性有证明，不是手感**：`child.fit < parent.fit` ⇒ `child.max < parent.max`；
  而 `parent.min = parent.fit/80` 与 `child.max = child.fit*1.5625` 的大小关系由
  `child.fit ≥ parent.fit*1.5625/…` 保证——测试
  `adjacent_levels_each_contain_the_other_ones_crossing_point` 直接钉住
  `parent.min ≤ child.max ≤ parent.max` 与 `child.min ≤ parent.min ≤ child.max`。
  这条不变式一旦破，换级就会跳，所以它是**回归线**而不是注释。
- **手感与升级前对齐**：世界级外界 8.0、内界 0.064（旧 0.1 是**更紧**的约束），
  即升级不夺走已有能力；总跨度 8000× ≈ 10⁴ 落在 §1 第 4 条的精度预算里。
- **`fit` 而非绝对常量**：`fit` 与图尺寸挂钩，所以「世界 4096 / 城市 1024 / 城区 256」
  这一串同单位的 `extent` 自动给出四个量级的区间阶梯，无需为每级配常量。
- **钻取目标取 `fit`**：双击一座城的意图就是「进去看这座城」，`fit` 正好是
  「整座城铺满窗口」；而 `min(from_scale, …)` 保证作者已经贴到地面看细节时，
  换级不会把他拉回高空。

### 8.4 代价

1. **级区间有意重叠**：`scale` 到 `current_map` 是多对多的，因此**不能**由 `scale`
   反推「现在几级」（会抖）。级只能是状态（`DrillState` 的路径）。这是 P7 的
   直接推论，但确实意味着 `scale` 单独不足以描述视图。
2. **换级是硬切换**：§2⑦ 的淡化未做，换底图那一帧是整张重建（见 §5 Phase 3 行、
   README §12-25）。
3. **每级要一次窗口尺寸**：`fit` 依赖窗口，窗口尺寸变化会轻微改变各区间的边界
   （同一 `scale` 可能从「合法」变成「需 clamp」）。当前只在滚轮/按钮/过渡时求值，
   窗口 resize 不主动重夹。

### 8.5 被否决的备选

| # | 备选 | 否决理由 |
|---|---|---|
| A | 换级时把 `scale` 取成新级区间的端点 | 级别交界处会跳；连续性的证明（§8.3）本可以避免，却主动引入不连续 |
| B | 让 `scale` 反推判断当前级（区间不重叠，即每级独占一段绝对 `scale`） | 级数一多每级区间被压得很窄，滚轮几步就换级；且反推在边界必然抖 |
| C | 换级时播放一段位移插值（相机飞到子图中心） | §2⑦ 已否决；且换级的视觉预期是「原地放大」，飞走会让作者丢失上下文 |
| D | 保留 `SCALE_MIN` / `SCALE_MAX` 常量并在其上乘级数 | 与 §2⑤ 冲突（区间必须按级算）；且乘级数会得到 10¹¹ 量级的荒谬跨度（见 §1 第 4 条） |
| E | 钻取过渡继续用硬编码 `4.0` | 越出新级区间，过渡终点非法；已在 §8.1 第 3 条说明 |

## 9. 追加（2026-10-14）：两套原点——栅格空间与图帧空间

> 本节依 `AGENTS.md` §6.3「文档追写不改机制」**追加**，不修改上文任何结论。
> §7「底图继承」的方向不变；这里补的是它落地后才显形的一环：**继承让
> 「栅格原点」与「图帧原点」不再相等**，而在此之前渲染链上只有一个 `grid.origin`。

### 9.1 处境：一个字段同时承担两个空间的原点

§7 定下「没有自带栅格的图直接渲染最近祖先的栅格」之后，视图里出现**两个不同的零点**：

- **栅格原点** `raster_origin`：当前**显示的那张栅格**在世界里的左上角。栅格属于某张祖先图，
  故它恒等于根图图帧原点 `(0, 0)`。地形采样、笔刷、chunk 划分、小地图都必须用它。
- **图帧原点** `map_origin`：**当前这张图**的 `extent` 左上角在世界里的位置，由 §6 的
  `Extent.origin` 沿 `parent` 链累积（`wv_core::resolve_frame_in`）得到。地点、街道、
  街道名、地图外框这些「本图局部坐标」内容必须用它。

两者只在**当前图自带栅格**时相等——所以这个坑在世界级永远看不到，只在钻入「继承底图」的子图时
整条链偏移 `map_origin − raster_origin`：

- 实测（`examples/xinhai-1911`，武昌城 `map_city_wuchang` 1024² 且无自带 `terrain.bin`；父图世界图
  4096² / 512² 栅格）：`map_origin = (1138.688, 1187.84)`、`raster_origin = (0, 0)` → 城级街道 /
  地点 / 外框全被画到 `0..1024`，即**世界图左上角那一小块**，在视野之外。
- 标记层（`MapNode.icons`）此前已改用图帧原点（`drill::map_origin` 的注释即此处），
  因此症状是「城里的十字图标位置正确，街道与地名却不见了」——**同一个坑只修了一半**。

### 9.2 决策

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | `GridConfig` 拆两套原点：`raster_origin`（原 `origin` **更名**）+ `map_origin`（新增），并加 `map_size`（当前图 `extent` 长边，`f32`，与 `cell_size` 同口径）；「本图局部 → 视图」的唯一换算是 `GridConfig::map_to_view` | `crates/wv-app/src/state.rs` |
| 2 | 图帧原点的**唯一实现点**是 `drill::map_origin(world, node, grid)`（`resolve_frame_in` 累积原点；未声明时回退 `raster_origin`），`sync_grid_config` 与街道编辑路径都调它 | `crates/wv-app/src/drill.rs`、`terrain_view.rs`、`streets.rs` |
| 3 | `sync_grid_config` 的早退条件加 `!drill.is_changed()`：继承底图时钻入**不改纹理**，只看纹理变化会漏掉换图 | `crates/wv-app/src/terrain_view.rs` |
| 4 | 地形侧（笔刷、chunk、地形回退 sprite）一律用 `raster_origin`；本图局部侧（地点、街道、街道名、地图外框、编辑预览）一律用 `map_to_view` | `editing.rs`、`terrain_chunks.rs`、`vector_layers.rs`、`streets.rs`、`projection.rs`、`map_frame.rs` |
| 5 | 视图空间**就是**根帧：轨迹 / 事件坐标不换算，函数改名 `root_to_view` 把「这份数据属于根帧」写在调用处；删掉原先两帧共用的 `world_to_view` / `world_to_view_pub` | `crates/wv-app/src/projection.rs` |
| 6 | 系统顺序：`sync_grid_config` 前移到 `compute_projection` **之前**（消费方都读它）；`rebuild_texture_on_mode_change` 仍在 `sync_grid_config` 之前（`cell_size` 取自纹理尺寸） | `crates/wv-app/src/gui.rs` |

### 9.3 理由

- **改名而不是加别名**：混用两个原点是 bug 的**成因**，不是笔误；把 `origin` 保留成别名，
  会让漏改的调用点照旧编译通过——那正是要避免的事。改名后每个调用点被迫表态「我要哪个空间」。
- **图帧原点复用 `resolve_frame_in`**：§6 已把「父图局部 → 世界」的累积放进 `wv-core`，
  渲染层复用同一条链，就不会长出第二套坐标系实现（与 §4.2「唯一换算入口」同类纪律）。
- **两条回归线钉住**（均做过 RED 验证：去掉 `!drill.is_changed()`、或把 `map_to_view` 换回
  `raster_origin`，测试都失败）：
  `street_strokes_use_the_map_frame_origin_when_the_raster_is_inherited`（街道 mesh 落在
  `map_origin + 局部坐标`）与 `grid_map_origin_follows_the_drilled_map_when_the_raster_is_inherited`
  （换图当帧、纹理不变时 `map_origin` 仍更新）。
- **实机复核**：修前钻入武昌城只有 3 个十字图标；修后同一次钻取可见地标文字（起义门 / 楚望台军械库 /
  蛇山炮位）、地图外框与 1/4 参考网格、以及完整路网（11 段，含多段折线）——均在城级 1024 幅面内。

### 9.4 代价

1. **多两个字段要维护**：`map_origin` / `map_size` 必须在每次换图时更新；漏更新的症状是
   「本图内容偏移」，且**只在继承底图时显形**（自带栅格的图上看不出来）。
2. **`map_origin == raster_origin` 只是约定**：代码里无法用类型系统表达「仅当当前图自带栅格时二者相等」
   （未引入 `enum RasterSpace::{Own, Inherited}`，见 §9.5 备选 C）。
3. **根帧内容仍是隐含约定**：轨迹 / 事件坐标今天恒等映射（`root_to_view`），数据里没有所属帧声明
   → 记为 README §12-26 待决。

### 9.5 被否决的备选

| # | 备选 | 否决理由 |
|---|---|---|
| A | 只修街道 / 地点，保留 `grid.origin` 单字段 | 正是本次的症状（标记层修好、其余没修）；下一个消费点会再踩一次同样的坑 |
| B | `origin` 保留为 `raster_origin` 的别名（不改名） | 漏改的调用点静默编译通过，等于把 bug 留在编译期之外 |
| C | 用 `enum` 区分 `Own` / `Inherited` 两种原点状态 | 表达力更强，但会把「当前图是否自带栅格」这一**数据侧**事实复制进渲染状态；今天两套原点都在 `sync_grid_config` 一处算齐，够用且改动面小——待它再次成为负担时再引入 |
| D | 把街道坐标也当祖先栅格坐标（统一按栅格空间偏移） | 与 §6「图标锚点在**本图** `extent` 内归一化」的口径冲突：作者写的是本图坐标 |
| E | 为继承底图的子图生成一份「偏移后的坐标副本」 | 复制子图内容而非引用 = P4 的同类错误；且每换一级都要重算 |
