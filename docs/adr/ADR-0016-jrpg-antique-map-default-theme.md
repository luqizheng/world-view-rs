# ADR-0016：古舆图主题定稿为默认地图观感（日间默认 + 暮色切换）

**状态**：已接受（Accepted，2026-10-14 用户四问裁定）
**日期**：2026-10-14
**决策者**：用户（2026-10-14 配色方案讨论，四项裁定：成为浏览态默认 / 暮色本期一起落 / Rust 常量先行 / 渲染增强纳入）
**关联**：[ADR-0008](ADR-0008-google-default-map-experience.md)（§2② 色板语义被本 ADR 显式取代）、[ADR-0012](ADR-0012-terrain-default-vector-flat-shading.md)（技法层不动）、[ADR-0013](ADR-0013-layer-frame-binding.md)（图层帧不冲突）、`docs/ART_STYLE_SPEC_v0.1.md` §1.4（新增 §1.4.4）、`docs/STYLE_SWAPPABLE_ARCHITECTURE.md`（Theme Pack 接口的常量层前身）、README §12-30/31/32
**约束**：本 ADR 一旦「已接受」，正文按 AGENTS §6.3 / §6.4 不再修改；反向修正须新开 ADR。

---

## 1. 处境（Context）

**地图观感的配色轴现状**：`wv-app/src/theme/` 已有三套同构色板——`colors.rs`（「深海」包，2026-11 用户指定，现行默认）、`colors_google.rs`（GoogleMap 模式专用）、`colors_jrpg.rs`（高饱和 JRPG）。其中 `ViewMode::JRPG` **连色板带 shader 早已接线，但从未对外暴露**（不在 `ViewMode::ALL` 七档、也不在 `BROWSING` 两档），是有线无产品的悬空状态。

**语义混淆**：`ViewMode` 实际混合了两个正交语义——「渲染技法」（等值线平涂 / 亚像素纹理 / 色块）与「配色」（Google / JRPG）。JRPG 档尤其如此：它与技法无关，只是一套色板。

**用户输入**（2026-10-14）：提出「日间古舆图」主配色（泛黄宣纸底 `#F2EAD8`、褐墨线条、灰蓝水、灰橄榄绿——历史感 JRPG，低饱和纸张感）与「暮色旧纸」暗调变体（深褐灰纸底 `#3A342E` 一族），明确**「优先用这套」**，并附五条渲染规则（柔和阴影 / 纸张噪点 / 缩放降饱和 / 图层顺序 / 线条柔化）。

**既有规格与实现的缺口**：palette.yaml Theme Pack 加载机制规格已写（ART_STYLE_SPEC、STYLE_SWAPPABLE_ARCHITECTURE、基线 §3.3）但**代码未实现**——色板目前全是 Rust 常量。硬编码色散落 5-6 处（等值线墨色、网格线、标注回退白等），未走令牌。

---

## 2. 决策（Decision）

1. **日间古舆图色板成为默认地图观感**：`theme/colors.rs` 的全部令牌重写为古舆图值（`colors.rs` 是 ART_STYLE_SPEC §1.4 的代码投影，冲突时改 `colors.rs`——这是文件头既有纪律）。浏览态默认**技法**仍是 `VectorFlat` 等值线矢量平涂（ADR-0012 不动，本 ADR 只换配色轴）。
2. **暮色旧纸为运行时可切变体**：新增 `MapPalette { Daylight, Dusk }`（`ViewState` 字段），**与 ViewMode 正交**；顶栏分段切换 + 命令面板 + `ui-layout.yaml` 持久化（`map_theme` 字段）。GoogleMap 模式继续绑定 `colors_google`，不受 MapPalette 影响。
3. **`ViewMode::JRPG` 移除**：其从未对外暴露，色板切换职责由 MapPalette 承接；`shade_jrpg` shader 与 `colors_jrpg.rs` 一并清理（git 历史可回溯）。ViewMode 回归「渲染技法 + 图层组合」单一语义。
4. **色板载体本次仍为 Rust 常量**：palette.yaml Theme Pack 机制**显式延期**（README §12-30 待裁保留）。改动路径 = 渲染调用点从「直引常量」改为「经 `theme/palette.rs` 分发」，为将来 YAML 化立好切换接口——届时接口不动、只换数据源。
5. **硬编码色全部令牌化**：等值线墨色、网格线、标注回退白、淡化固定灰收进色板令牌；矢量层主干道 / 次级街巷 / casing / 街名按古舆图令牌走。
6. **渲染规则对账**：纸张噪点、缩放雾霭（缩放联动降饱和）、文字晕边纳入本期实施；图层绘制顺序经核实已吻合用户要求，不动。2.5D 建筑挤出为独立功能（数据走「街道同款」作者数据路径，ADR-0010 模式），其配色令牌（建筑顶 `#D4C8BB` / 侧 `#9A8B7A`）入色板，阴影遵循 ART_STYLE_SPEC §1.5 既有规格（左上光、右下投影、长度 0.5× 高度、alpha 0.35、禁纯黑）。

---

## 3. 理由（Rationale）

1. **「优先用这套」= 主配色 = 默认**。用户明示这套是主配色，挂成可切换主题之一不满足其意图；ADR-0008 的「近白 Google 风」已先后被「深海包」（事实取代）与本 ADR（显式取代）让位。
2. **技法 × 配色解耦是 ADR-0012 的自然延伸**。观感 = f(技法, 配色) 二维化后：ADR-0012 定技法轴（等值线平涂），本 ADR 定配色轴（古舆图 / 暮色）。未来任何技法模式（色块、真实地形）都自动获得两套配色，组合数从 N×M 特判降为两个独立轴。
3. **MapPalette 是 Theme Pack 接口的常量层前身**。STYLE_SWAPPABLE_ARCHITECTURE 的终态是「L1 外观 100% 由 Theme Pack 驱动」；先在常量层把「切换接口」立起来并让全部调用点走它，YAML 化时只换数据源、不动接口——这是通往终态成本最低的一步。
4. **常量先行符合待决处置原则**（AGENTS §12「选最容易回退的方案」）。色值尚需实机视觉迭代（暮色 8 项以外全是推导值），常量改一处即整体回退；YAML 化在色值定稿前是过早固化。
5. **不破既有原则**：P1 不动（纯离线）；P3 部分触及（配色仍代码常量——延期已显式登记 §12-30，建筑数据走 YAML 合规）；P5 不动且增强（建筑走逐层开关）；P6/P7 不动（不涉时间轴与存储形态）；ADR-0013 图层帧语义不受影响（palette 只换色，不动 Z 槽位与绑定）。

## 4. 代价（Consequences）与被否决的备选

### 4.1 代价（必须承认）

1. **默认观感全局变更**：所有现存工程打开即古舆图观感；「深海」色板退场（git 历史保留）。这是用户明示选择，但须承认老工程截图 / 教程素材失配。
2. **作者暂不能自改配色**：色板在代码里，改色要重编译。palette.yaml 延期已显式登记，不是沉默欠账。
3. **分发接线的遗漏风险**：调用点从直引常量改为经 palette 分发，漏改一处表现为「切暮色没反应」——以「Dusk 镜像完整性测试」（槽位一一对应）+ 渲染层 clippy 全量对冲。
4. **暮色色值大半为推导**：用户只给了 8 项，其余由日间色系同法压暗推导，实机校准前存在偏差（值表标「待复核」）。
5. **一次性机械改动面较大**：硬编码令牌化 + 分发改动约十余个渲染文件；全部在 `#[cfg(feature = "app")]` 下，须跑渲染层测试闸门。

### 4.2 被否决的备选（按推荐度倒序）

| # | 备选 | 否决理由 |
|---|---|---|
| B | JRPG（古舆图）作为可切换 ViewMode 开放 | ViewMode 继续背负技法+配色双重语义；浏览态刚收敛为两模式（2026-10-14 裁定），塞第三档稀释产品收敛；切技法才能换配色在组合上爆炸 |
| C | 本次实现 palette.yaml Theme Pack 机制 | scope 显著变大（schema + loader + 校验 + 热切换 + 持久化）；色值未定稿前 YAML 化是过早固化；违反「最小可回退」的待决处置惯例。接口层（palette.rs）已为本备选预留 |
| D | 暮色版下期再做 | 用户裁定本期一起落；且暮色与日间同构，M1 一次成型边际成本最低，拖后反而要二次接线 |
| A | 日间古舆图直接成为默认色板（即本 ADR §2.1-2） | ✔ 选中 |
