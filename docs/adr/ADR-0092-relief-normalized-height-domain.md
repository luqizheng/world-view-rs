# ADR-0092：晕渲夸张改归一化高度域——修正 ADR-0077 D2 的米制量纲纪律

- 状态：**已接受**（2026-10-30，用户三案裁定取 A；实施于 `feat/relief-zexag-calibration`）
- 关联：[ADR-0077](ADR-0077-cellmap-relief-shading.md)（本 ADR **修正其 D2 量纲纪律**——按只增不改，D2 原文保留、以本文为准）、[ADR-0088](ADR-0088-field-mode-routing-fingerprint.md)（WV_STRIP 探针家族与 Themed 观感核查的前置轮）、[ADR-0053](ADR-0053-terrain-gpu-field-rendering.md)（GPU 场管线）
- 决策者：用户（「2D 地图用高度图 + 坡度 + 光照呈现起伏」的算法确认 + 三案取 A）

## 1. 处境（Context）

ADR-0088 收尾后用户实报：「browse / map / cell-map **都没看到**（地形高度）效果」。首轮校准（Z_EXAG 2→6，追记于 ADR-0077 §9）交付后用户在近距机位复核：**依然没有山体起伏**。第二轮取证把根因钉死：

| # | 证据 | 结论 |
|---|---|---|
| 1 | uniform dump：`shape.z=0.05, light_dir.w=1000` 正确送达 GPU | 探针与接线无恙 |
| 2 | `WV_Z_EXAG` ∈ {0.05, 0.15, 0.3, 6} 渲染**逐像素相同**（最大差 13/255） | Z 旋钮跨 120 倍无效——不饱和/饱和两端解释不通，唯一自洽解释是 shader 的梯度域与 s 的量纲错配 |
| 3 | 浮雕整层剥离（WV_STRIP=16）vs 全开：**仅差 9.7/255** | 浮雕输出 ≈ 常数乘子（均匀变暗），无任何起伏信息 |
| 4 | terrain.bin 解码：demo 高度占满 i16 域（−32767..32526），三尺度平滑后梯度中位 ~2500 作者单位/格 | 作者高度单位与「米」无任何绑定 |

**根因（两处除法的量纲错配）**：GPU 梯度在**纹理归一化域**（h_norm = (h+4000)/10000 ∈ [0,1]，`pack.rs` 固定域），梯度值 ~0.25/格；而 `s = Z_EXAG / 米每格` 是米制口径（demo 米每格 = 1000）。有效夸张 = 0.006 × 0.25 ≈ **0.0015**，比可读带（≈0.5–2）小 **~650 倍** → 法线恒近平 → relief ≈ 常数 0.824。CPU 烘焙路径（raw 作者域梯度 × 同一米制 s）则是**饱和端**（s·梯度 ≈ 15）——同一旋钮两管线一头平一头死。

深层原因：ADR-0077 D2 的「i16 高度直接作米」假设对**作者高度单位任意的虚构图**不成立——这正是 README §12-53「无比例尺地图的米制假设」待决在晕渲侧的显影。首轮校准（2→6）落在这 650 倍缺口里，等于白调（z2 vs z6 地形区像素差仅 1.4/255，此结论修正 ADR-0077 §9 追记里「z6 山脊明显可读」的误读）。

附带发现：demo 高度远超纹理固定域 [−4000, 6000]，超出部分被 `pack` **硬钳位**——demo 雪峰顶的「平台」即此 artifact（数据侧问题，本 ADR 不处理，见 §6 遗留）。

## 2. 决策（Decision）

**D1 · 梯度统一到「归一化高度域」：`s = Z_EXAG / 本图高度跨度`**

- CPU：`shading::slope_gain_of(height_span)`，`height_span_of(data)` 每次烘焙现场 O(N) 算 max−min（下限 1 防平图除零）；
- GPU：WGSL `s = p.shape.z / max(p.shape.w, 1.0)`，`shape.w`（原 T14 `grad_step` 死槽）由桥接在材质创建时写**数据跨度**（恒等缺省 = 纹理固定域跨度 10000，即 `shading::DEFAULT_HEIGHT_SPAN`）；
- 两管线同式（ADR-0077 D4「CPU/GPU 同公式」精神保住）：作者单位梯度 × (Z/跨度)，逐项相等。

**D2 · Z_EXAG 语义改「相对高差格数」**：无量纲，含义 =「把本图最高差按 Z 格起伏打光」。米制机器退役：`meters_per_cell_of` / `DEFAULT_METERS_PER_CELL` / `bridge_meters_per_cell` / `bake_meters_per_cell` 删除，CPU 接线封装改 `bake_height_span(data)`；`light_dir.w` 米/格槽不再消费（槽位保留，uniform 布局稳定）。

**D3 · 落参 Z = 25**：可读带由本图中位宏观坡度反推（跨度 65293 ÷ 中位梯度 2497 ≈ 26）；对比帧组 {12, 25, 50}（远机位）用户复核，`WV_Z_EXAG` 可运行时微调不重编译。旧值沿革：2.0（米制初值）→ 6.0（无效校准轮）→ 25.0。

**D4 · 测试锚点随域改写**：跨图幅不变性测试由「同物理坡同法线」改为「**同相对高差同法线**」（跨度不同、梯度/跨度相同 → 法线相同）；受光方向 fixture 用 `span = 50×Z_EXAG` 钉 45° 坡（公式不变，量纲换名）。

## 3. 理由（Rationale）

- **可读性优先于物理真值**：与 ADR-0077 D1「美术化光照」同一哲学——晕渲的目标是让山体可读，不是渲染真实日照；「同相对高差同法线」恰好是手绘世界图的正确归纳（作者的「高度」本来就不是物理量）。
- **跨度自适应一视同仁**：虚构图（单位任意）、真实 DEM（raw=米）都自动落进同一可读带，换图不再需要重校准——这达成了 D2 原本想用米制达成的目标（换图观感稳定），且不依赖任何单位假设。
- **§12-53 顺势收敛（晕渲侧）**：无比例尺图的米制回落假设从晕渲路径整体退场；比例尺信息（`unit_per_km`）保留给比例尺条等真实需要米的地方，晕渲不再掺和。

## 4. 代价与风险（Consequences）

- 「同物理坡同法线」退役：真实 DEM 与虚构图之间不再有物理意义上的亮度可比性（各自内部一致）。对「协助创作者整理世界设定」的定位，这是正确的取舍。
- 编辑会改变全图夸张基准：笔刷抬高最高峰 → span 变 → 全图浮雕强度微调（每次烘焙现场算，无缓存）。单方向（增高）下表现为「其余山头略变平」——量级可控，观察期若有体感再引入 span 平滑。
- 纹理固定域钳位 artifact **仍在**：数据超出 [−4000, 6000] 的部分烘焙成平台（demo 雪峰平顶）。修复需要扩域或数据重映射（会动 hypsometric 归一化口径），另立 ADR。
- 米制语义从晕渲退役后，`unit_per_km` 在晕渲侧不再有消费方——若未来要「物理正确晕渲」（真实 DEM 项目），需在桥接侧按比例尺把作者单位映射回米（预注册路径，非本轮）。

## 5. 被否决的备选（Alternatives）

| # | 备选 | 否决理由 |
|---|---|---|
| B | **数据侧归真**：声明作者单位=米，把高度约束/重映射进 [−4000, 6000]（demo 重生成），米制 s 原样 | 虚构创作被迫关心物理单位（与「作者随便改」对立）；已有工程要迁移；钳位平台 artifact 依旧存在（只是换个域被钳） |
| C | **自动曝光**：s = C/中位梯度，Z 作乘子 | 最鲁棒，但每次编辑中位梯度漂移 → 同一张图编辑前后观感漂移；实现面最大（三尺度各自中位还是全局中位、增量补丁路径怎么办）。C 可日后**叠加**在 A 上当默认值策略，不与本轮互斥 |

## 6. 涉及与不涉及（AGENTS §10 自检）

**触及**：§6.4（本文即留痕；对 ADR-0077 D2 的修正关系入索引）；渲染层门禁（`app-test` / `app-clippy` / smoke-gui 全跑）。

**未触及**：P1–P7（零存储字段、零格式变更——span 为运行时派生量不落盘；高度数据本体不动）；分层（改动落 `wv-world-cell-map`（shading/cells/material/WGSL）+ `wv-render`（桥接）+ `wv-app`（两处烘焙接线），依赖方向不变）；固定色禁令不涉；§3.3 零新命令；§7.5 无交叉。

**遗留（另行立项）**：纹理固定域钳位平台（扩域会动 hypsometric 归一化口径，需复验色带）；C 案自动曝光作为默认值策略的后续可能。

## 7. 验收（Acceptance）

1. 三工作区（Browse / Map / CellMap）同机位 WV_SHOT 山体明暗可读（本轮已采：远机位 {12, 25, 50} 三档梯度分明、Map 档呈专业制图观感）。
2. `WV_Z_EXAG` 探针跨值出图不同（本轮 0.05 vs 6 已可分辨——修复前的失败判据反转为通过判据）。
3. 全门禁绿（fmt / clippy-ws / nextest-ws / clippy-app / nextest-app / smoke-gui）。
4. CPU/GPU 同式：`slope_gain_of(span) × 梯度_raw` 与 `s(shape.w=span) × 梯度_norm × H_RANGE_M` 数值相等（D4 测试钉住）。

## 8. 追记（2026-10-30 当日）：落参修正 25 → 200

> 本文 §2 D3 的「落参 Z = 25」在用户实机复核中被否——按只增不改，正文保留，本节为修正记录。

用户远观实报「远看也没有看出来」（实机截图经比对与采集帧逐位一致，排除环境差异）；逐档扫描 {25, 100, 200, 400}（远机位）+ 近距机位复核：

- **25 内陆不可读**：D3 的反推值（跨度 ÷ 全图中位宏观坡度 ≈ 26）失真 ~8×——全图中位被**海岸悬崖**拉高，内陆实际宏观坡度平缓得多（实测弧带区域宏观坡度 ≈ 主峰区的 3/4、仅海岸带的零头）。
- **200 起山脉链远近皆可读**：远观两岛中央山脉链清晰成链；近距出现沿山脊的受光条纹且无碎噪斑（detail 饱和噪声在实拍中呈山脊同向条纹）；**400 过浓**。
- **落参 200.0**（`shading::Z_EXAG`）；`WV_Z_EXAG` 探针保留，后续复校准不重编译。
- **教训**：「跨度 ÷ 全图中位梯度」的反推被海岸像素污染——反推只能给初始值，校准的最终裁判是用户目验；宏观中位若要用于反推，应按**内陆采样**或取分位数下沿。
- **小地图对照**（用户提问引出）：小地图走 CPU 烘焙路径，raw 域梯度 + 同 gain 在同夸张下呈饱和噪声斑驳，恰在小尺寸下被读成「山的质感」；主图（GPU 三尺度、远观宏观档主导）如实呈现内陆缓坡。两路径观感不同源的根因与本文 D1 的归一化统一同源，CPU 侧的多尺度对齐留待后续。
