# ADR-0084：撤回 `wv mcp` stdio 代理轮（ADR-0083）——agent 接入方式重做

- **状态**：已接受（Accepted，2026-10-28，用户裁定「放弃这次，重新重做」+ 范围拍板「只弃 MCP 轮，ADR-0082 保留」）
- **决策者**：用户对话拍板（2026-10-28）
- **关联**：**撤回 [ADR-0083](ADR-0083-mcp-stdio-proxy-and-skill.md)**（正文按 §6.4 留档不删）；[ADR-0014](ADR-0014-mcp-http-server.md) HTTP 服务**不受影响继续有效**；[ADR-0078](ADR-0078-http-ui-control-tools.md) UI 操控工具面**不受影响**；[ADR-0082](ADR-0082-nature-naming-and-comments.md) 自然层命名**不受影响**

## 1. 处境

ADR-0083（`wv mcp` stdio 代理 + `.mcp.json` 注册 + wv-mcp skill）落地当晚暴露三重摩擦：

1. **注册面不可用**：目标 agent（ZCode）不读 `.mcp.json`（那是 Claude Code 的格式），
   注册须用户手工走 Settings→MCP 逐机配置——每个用户重复一次，与产品愿景
   「用户下载软件 → 自己的 agent 直接驱动」相悖：**标配入口必须开箱即用**。
2. **产品定位已定调**（2026-10-28 愿景讨论）：**skill+HTTP = 标配入口，MCP = 可选增强**。
   代理补的是「可选增强」的协议面（initialize 握手），投入（proxy.rs 298 行 +
   skill 82 行 + 注册与缓存机制）与收益倒挂。
3. 当晚工作树事故（并行会话 `reset --hard b84adaa` 残留 + plumbing 移动 main ref）
   使该轮与既有成果的边界一度混淆，促成本次整体复核——复核结论：撤回范围
   收敛到 MCP 轮本身，其余成果保留。

## 3. 理由

- **注册摩擦在客户端侧，不在文件格式**：04d7974 已试过「删 `.mcp.json` + mcp.md 双接入文档」
  的治标路线——ZCode 侧依旧要手工注册，摩擦未除。根因是「MCP 客户端注册」这个动作
  本身不满足「开箱即用」，与格式无关。
- **stdio 代理解决的问题正在消失**：HTTP 工具面（15 个）+ skill 引导（curl / HTTP 调用）
  已覆盖 agent 驱动验收的主路径；screenshot 直回图、get_ui_state 一行 JSON 等
  省 token 手段都在 HTTP 侧，不依赖 MCP 协议层。
- **维护面**：代理承担协议兼容责任（initialize/ping/转发/缓存），每加一类 MCP 客户端
  怪癖都要在代理侧跟——为「可选增强」背持续成本，不划算。

## 4. 代价 + 被否决的备选

**代价：**

- `initialize` 握手能力随 `proxy.rs` 一并移除——真 MCP 客户端（ZCode / Claude Desktop）
  仍无法直连 GUI HTTP 面；若「可选增强」日后立项，从撤回提交前的历史取回或重做。
- `mcp.md`（双接入使用文档，157 行）一并撤下；skill+HTTP 的标配文档在重做轮补齐。
- 远端历史里 1835b4a / 04d7974 永久可见——非代价，是留痕（来龙去脉完整可溯）。

**被否决的备选：**

| 备选 | 否决理由 |
|---|---|
| A. 两轮全弃（连 ADR-0082 自然层命名一起回退到 b84adaa） | 用户裁定否决：0082 与 MCP 摩擦无关、是四连裁定的成果，保留 |
| B. 保留代理、只删 `.mcp.json`（04d7974 已走的方向） | 治标不治本：注册摩擦在 ZCode 客户端侧而非文件格式，代理维护成本照付 |
