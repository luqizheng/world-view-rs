# ADR-0003：跨地图引用（绝不复制子图内容）

- **状态**：已接受（Accepted）
- **日期**：2026-10-11
- **决策者**：创意总监 游有方（跨图缝合点 = `Place`）／技术架构总监 柯桥良（引用关系图）／用户裁定 **D4**（视图模式四态，跨图播放的载体）／主理人 范可控（把 A3 列为必须写进 ADR 的硬约束）
- **关联**：`docs/MAP_EDITOR_BASELINE_v1.md` §1.6、§1.7、§1.8、§2.5、§2.7、§2.8、§2.15、§5.1；`AGENTS.md` §1 P4、§4.3；`README.md` §3 原则四；**ADR-0001**、**ADR-0002**；硬约束 **A3**

---

## 背景与问题

用户在编辑器需求中明确要求：**一个工程有多个地图**（世界地图 / 城市地图 / 室内地图）。《README.md》§5 的工程目录与 §6.3 的「每实体一文件」已确立四级地图层级：

```
World（世界） → Region（区域） → City（城市） → Interior（建筑/室内）
```

同时，用户要求「**每个地图都有它播放事件的能力**，在地图上显示正在发生的事件。城市地图/室内地图可以看到**角色的移动**」（基线 §0.2 D 组 D-1）。

于是出现一个**核心矛盾**：

> 一条事态（如「四渡赤水」）需要同时发生在**世界地图**（行军）与**城市地图**（入城占领遵义）上。**两张地图如何关联？**

### 诱惑性的错误做法：复制子图内容

最容易实现（也最致命）的做法是：**把城市地图的内容「复制」到世界地图里**，或者**把世界图的行军轨迹复制进城市图**。表面上看这样「一张图就能看全」。

**为什么这是灾难**：

| 后果 | 具体表现 |
|---|---|
| **改一处不同步** | 城市图里改了「衙门」的位置，世界图里那份副本**不会跟着变**。作者会看到两个版本的同一座城 |
| **数据量爆炸** | 城市图有几百个 `Place`，若每个都复制进父图，世界图 YAML 体积成倍膨胀 |
| **违反 P4** | `AGENTS.md` §1 明确：P4 的违反形态就是「子图内容被复制进父图，而非 ID 引用」 |
| **级联失效** | 城市图再下辖室内图 → 复制会形成指数级的副本爆炸 |

**若不决策会怎样**：P4 是本项目**七条不可动摇原则**之一。跨地图事态若按复制实现，等于在**最核心的用例上**直接推翻 P4。基线把它列为 🔴 高风险（§1.19）并要求**写进 ADR 作为硬约束**。

---

## 决策

**跨地图的事态只能靠 `Place` 的 ID 层级串联，绝不能复制子图内容。**

### （1）一条链可以、而且应该跨地图层级

**裁定：一条事态链可以、而且应该跨地图层级。**

**靠什么引用**：**靠 `Place` 锚点串联，不靠 ID 嵌套。**

```
       世界图（World）                     城市图（City）
   ┌──────────────────┐              ┌──────────────────┐
   │   ●─────────●    │              │   ┌───┐  ┌───┐  │
   │  遵义  ─────┘    │  ← 同一 Place │   │南门│──│衙门│  │
   │   (Place)         │    被两边引用 │   └───┘  └───┘  │
   └──────────────────┘              └──────────────────┘
```

**核心洞察**：**链的节点顺序由时间决定**（ADR-0002 不变式 I2），**不靠物理连接**。

> **物理上世界图与城市图是断开的（P4 要的：不复制），但时间上是连续的（时间轴要的）。**

### （2）三层引用规则

| 层 | 规则 |
|---|---|
| ① **地图树用 ID 父引子**（已有） | `City` 图的 `parent = World` 图 ID |
| ② **链的节点可归属不同地图** | 每个链节点带 `map: MapId`（省略 = 继承链的默认地图） |
| ③ **跨图的缝合点是 `Place`** | 同一地方的两个粒度通过 `Place.parent` 建立关系 |

**「遵义」在世界图上只是 1 个 `Place`（点）**；在城市图上，「遵义」内部的「南门、主街、衙门」是另一批 `Place`。两者通过 `Place.parent` 建立父子关系——**世界图上不画街道**。

**为什么不需要「跨图缝合 ID」**：因为链的顺序由时间决定，不靠物理连接。**时间轴天然跨越了地图边界**——作者拖到 `t = 103000`，世界图上显示行军轨迹；拖到 `t = 103030`（遵义入城段），当前地图切到城市图，显示角色在街道上移动。**同一个 `t`，两张图各自投影。**

### （3）四级地图的引用方式

| 层级 | 父引用 | 跨图串联的锚 | 典型内容 |
|---|---|---|---|
| **World** | 无（根） | — | 大陆轮廓、主要城市点（每个是 1 个 `Place`） |
| **Region** | `parent = World` 图 ID | `Region` 内的 `Place` 通过 `Place.parent` 指向世界图上的对应 `Place` | 中等跨度地形、次级城市 |
| **City** | `parent = Region` 图 ID | **城市本身就是世界图上的一个 `Place`**；城市内的街道是它的子 `Place` | 街道、建筑、城门 |
| **Interior** | `parent = City` 图 ID | 建筑本身就是城市图上的一个 `Place`；房间是它的子 `Place` | 房间、走廊 |

**统一模式**：**在父图上，这是一个点（1 个 `Place`）；在子图上，它是这个点内部的展开（N 个子 `Place`）。** 父子通过 `Place.parent` 关联，**几何内容永不跨越层级**。

### （4）轨迹的跨图处理

`Track` 带 `map: Id` 字段——**它只属于一张图**。

- 世界图上的行军轨迹（大跨度折线）**不会出现在**城市图上；
- 城市图上的街道路径（`Place` 序列）**不会出现在**世界图上；
- 需要「同一段运动在两图上都可见」时，**表达为两条轨迹**（各带自己的 `map`），而不是把一条轨迹复制两份。

> **这是 A3 的直接落地**：轨迹带 `map` 字段，**它只属于一张图**（基线 §1.7 P4 满足方式表）。

### （5）`Place` 序列表达轨迹——P4 与距离维度的自然复用

在 City/Interior 层，轨迹**强烈推荐**用「`PlaceId` 有序列表」表达（ADR-0002 §1.6 的两种写法取舍）：

> 城市/室内图上的「南门、主街、衙门」天然是 `Place`。**用 `Place` 序列表达轨迹 = 免费得到距离校验。**

这同时是 **A3 的正面验证**：轨迹靠 `Place` 的 ID 引用串联，而非复制坐标。世界/区域层因荒野无 `Place` 可用坐标点列——但这**不构成对 A3 的违反**，因为坐标点列是**该图内部**的局部坐标，**不是从子图复制来的内容**。

### （6）P4 满足方式（基线 §1.7）

| P4 的违反形态 | 本设计怎么避开 |
|---|---|
| 把城市图的街道画进世界图 | ❌ 世界图上「遵义」**只是 1 个点** |
| 把世界图的行军轨迹复制进城市图 | ❌ 轨迹带 `map` 字段，**它只属于一张图** |
| 把「红军在遵义」存两遍 | ❌ 由**轨迹的点 + 时间戳**表达，**只存一份**，两张图各自**投影** |

### （7）引用关系图（基线 §2.8）

```
Character ──(owner)──→ Track ──(map)──→ MapNode
    │                    │
    │                    └──(waypoints[].place)──→ Place
    │
    └──(participants)──→ Event ──(place)──→ Place
                          ↑
                          │(steps[].event)
                     Situation ──(maps)──→ MapNode
                          │
                          └──(protagonist)──→ Character

Faction ──(memberships[].to)──→ Faction / Character
    └──(territory: Vec<GeometrySpan>)──→ MapNode（经 span.map）
```

**引用方向全部单向，无环。**（这也是「不复制」的结构性保证：若无复制，则每条数据只有一个「家」，引用图必然可构成 DAG。）

### （8）播放时的跨图切换

`Situation.maps: Vec<Id>` 列出该事态涉及的全部地图。播放时：

- 若 `current_day` 落在某节点的时间范围内，且该节点的 `map` 与当前渲染地图不同 → **播放器自动切换当前渲染的地图**（基线 §2.14「跨图播放」）；
- 切换地图 = 切换坐标系与 LOD（`AGENTS.md` §3「投影」），**不移动时间轴**。

> **这不是复制**：城市图的数据**从未**进入世界图的文件；切换只是「换一个投影源」。

## 硬约束

本 ADR 承载 **A3**。以下**逐字引用**基线 §6.3（第 1540 行）原文。

### A3

| # | 硬约束 | 违反后果 |
|---|---|---|
| **A3** | **跨地图事态只能靠 `Place` 的 ID 层级串联，绝不能复制子图内容** | 直接违反 P4，改一处不同步，数据量爆炸 |

**它如何约束本决策**：

- **`Place.parent` 是跨图层级串联的唯一机制**：同一地方的两个粒度（世界图上的「遵义」点 ↔ 城市图上的遵义城内部）**只通过 `Place.parent` 建立关系**，不通过复制几何。
- **`Situation.maps` / `SituationStep.map` 是「`Id` 引用列表」**，不是「地图内容的内联」——`maps: [map_world, map_city_zunyi]` 是 ID，不是把两张图的数据塞进事态。
- **`Track.map` 是单个 `Id`**：一条轨迹只属于一张图，跨图需两条轨迹，**绝不复制**。
- **`wv-io` 加载时不得「展开」子图**：把城市图的数据内联进世界图是 A3 的**直接违反**，即使是为了「方便渲染」也不允许。
- **写代码时的判据**：任何「把 `MapNode` 的 `children` 从 ID 列表改成内联对象」的改动，都**违反 A3**。`AGENTS.md` §11 反模式速查已列：「地图 `children` 里内联子图数据 → 违反 P4 → 只存子图 `Id`」。

> **本 ADR 之所以存在**：基线 §1.19 把「跨地图事态被实现成「复制子图内容进父图」」列为 🔴 **高风险**，并明确要求「**写进 ADR 作为硬约束**」（§6.3 A3）。本 ADR 就是该要求的落地。

## 理由

**（1）P4 的正面要求（最高优先级理由）。**

`AGENTS.md` §1 的 P4 条款与违反形态「子图内容被复制进父图，而非 ID 引用」**逐字对应 A3**。跨地图事态是本项目**最典型的 P4 用例**——如果这里有例外，P4 就名存实亡。

**（2）P4 与时间轴驱动的兼容性由「时间是跨图的连续量」保证。**

一个自然的担忧是：「不复制，两张断开的图怎么表达一条连续的链？」
答案是：**链的连续性来自时间，不来自空间**（ADR-0002 I2）。世界图与城市图在**空间上断开**（这是 P4 要的），但在**时间上是连续的**（这是 P7 要的）。**时间轴是跨越地图边界的公共坐标系**——同一个 `t`，两张图各自投影自己的部分。

**（3）`Place` 是天然的跨图缝合点。**

城市/室内图上的「南门、主街、衙门」在距离维度里天然是 `Place`（《README.md》§2 距离维度：「地点构成图」）。**复用 `Place` 作为缝合点，不需要发明新的「缝合 ID」概念**——这是概念的节省，也直接连接 ADR-0002 的「轨迹用 `Place` 序列表达」。

**（4）`AGENTS.md` §4.3「只存引用，不重复存储」的应用。**

层级关系（地图父子、事件参与者、角色所在地点）**一律用 `Id` 引用**。本 ADR 是这条纪律在「地图 × 事态」交叉面上的实例。

## 后果

### 正面

- **P4 在最核心的用例上得到保持**。
- **改一处即可全同步**：修改城市图上的 `Place`，引用它的世界图轨迹自动对齐。
- **数据量可控**：不随「跨图引用次数」增长。
- **无环引用图**（§2.8）：每条数据只有一个「家」，可静态校验。
- **免费获得距离校验**：`Place` 序列表达轨迹时，城市/室内层的路径可校验「路走不通」、可算耗时。
- **跨图播放自然成立**：`current_day` 驱动「换一个投影源」，不需要把两张图合并。

### 负面 / 代价

- **两条图之间「看不见的关联」需要工具提示**：作者在世界图上看到「遵义」一个点时，**需要能感知**它与城市图的关系。**兜底**：`Place` 详情显示 `parent` / `children`；双击可下钻（`README.md` §5 地图树）。
- **同一段跨图运动需要作者建两条轨迹**（一条 World 的、一条 City 的）：作者要理解「轨迹带 `map`，只属于一张图」。**兜底**：详见 ADR-0002「待裁 · 跨节点轨迹归属」，两条轨迹可挂在**同一个事态节点的 `tracks` 列表**下，减少认知负担。
- **`Place.parent` 的正确性完全依赖作者输入**：若作者把城市图上的「遵义城」`Place` 的 `parent` 指向了错误的世界图 `Place`，跨图拼接会错位。**兜底**：记入校验（引用完整性，`AGENTS.md` §7.2「悬空引用必须被检出并报错」）。
- **渲染期需要遍历「当前图 × 当前 `t`」的 `Place` 与轨迹**：跨图引用的投影成本略高于单图。**兜底**：基线已定「拉动式刷新」（`AGENTS.md` §3.4），只在 `t` 或当前图变化时重算。

### 待裁

| 项 | 状态 | 说明 |
|---|---|---|
| **`Place` 是否允许跨多级 parent 链** | **待裁**（**本 ADR 新增发现**） | 基线 §1.7 说「同一地方的两个粒度通过 `Place.parent` 建立关系」，是**一对一（单 parent）**。但现实中「遵义」可能同时在「区域图」与「城市图」上有节点。**一个 `Place` 是否可有多个 parent（多粒度）需裁定**。倾向：单 parent（`parent: Option<Id>`），多粒度用「中间 Place」表达 |
| **`Region` 层的跨图关联语义** | **待裁**（**本 ADR 新增发现**） | 基线 §1.7 的三层规则只说了 World↔City 的缝合（遵义例子），但**未说明 `Region` 层如何与上下层缝合**。Region 是中间层，其 `Place` 与 World / City 的关系未定义 |
| **跨图轨迹的「自动拆分」是否要做** | **待裁**（**本 ADR 新增发现**） | 一段连续运动（世界行军 → 入城）目前需作者手工建两条 `Track`。**是否提供一个「跨图轨迹」的作者体验（自动按 `map` 切分）需裁定**。倾向：第一版不做，先让作者手工拆 |
| **`Situation.maps` 与实际节点 `map` 的一致性校验** | **待裁**（**本 ADR 新增发现**） | 若某节点的 `map` 不在 `Situation.maps` 列表内，是否报错？基线未规定。倾向：报**警告**（非错误），因 `maps` 是描述性的播放范围 |
| **`Place.parent` 的引用完整性错误分级** | **待裁** | `AGENTS.md` §7.2 说「悬空引用必须被检出并报错」。但 `Place.parent` 为空（根图上的独立地点）是**合法**的。**「悬空」与「为空」的区别需明确定义** |

## 备选方案（被否决的）

| 方案 | 否决理由 |
|---|---|
| **A. 把城市图内容复制进世界图** | ❌ **直接违反 P4 与硬约束 A3**。改一处不同步、数据量爆炸、级联失效（基线 §1.19 🔴 高风险） |
| **B. 引入「跨图缝合 ID」（新的实体连接两张图）** | ❌ 不必要的概念。**链的顺序由时间决定，不靠物理连接**；`Place` 已是天然的缝合点（基线 §1.7） |
| **C. 一条轨迹同时属于多张图**（`Track.map: Vec<Id>`） | ❌ 轨迹的坐标系是**单张图**的局部坐标；跨图轨迹的几何无法在单一坐标系表达。**正确做法是拆成两条轨迹**（各带自己的 `map`） |
| **D. 在父图上「隐式展开」子图**（加载时内联） | ❌ 违反 A3。即使是为了渲染方便也不允许。投影应在**渲染时**从各自的源求值，而不是在**加载时**合并数据 |
| **E. 跨地图事态由「容器地图」承载**（新建一张覆盖全层级的图） | ❌ 违反 P4（制造数据的第三个副本，与两张源图都不同步），且破坏四级层级语义 |
| **F. 世界图上也画街道（不管层级）** | ❌ 违反 P4。世界图上「遵义」**只是 1 个点** |
| **G. 把「红军在遵义」在两张图上各存一份** | ❌ 违反 A3。**由轨迹的点 + 时间戳表达，只存一份**，两张图各自投影 |
