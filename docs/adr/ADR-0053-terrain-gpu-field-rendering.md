## 1. 处境（Why Now）

**观感问题已连调三轮**（ADR-0016 → 0035 → 0042 → 0048），每轮结论都是「截图好看一点、放大还是糊」。本轮诊断出两个**可复算的物理上限**（已实地复核：`tile_atlas.rs:141` `tile_res_for(1024)=4`；`state.rs:1083` `cell_size=8.0`）：

1. **近观**：烘焙纹理硬上限 4096² ÷ 1024 格 = **4 px/格**；近观一格 ≈32 屏幕px → 放大 8×。规格书 §3.1「描线 = 边长 1/16」在 4px 格上 = 0.25 texel，**物理不可实现**——不是没画，是画不出来。
2. **远观**：fit 时一格 ≈1.56 屏幕px，细节全灭，只能靠大尺度构图（区域色块 / 山链 / 海岸色带 / 纸面材质）——而现行管线没有构图层。

**结论：这不是配色问题（调三轮已证），是「位图有分辨率上限」的架构问题。** 同日的《地图渲染实施方案 v0.1》（柯桥良章）主张「维持 CPU 烘焙 + 补全」，与本方案构成 T0 路线之争；用户裁定 **甲（GPU 路线胜出）**。

## 2. 决策（Decision）

采纳 `TERRAIN_VISUAL_OVERHAUL_PLAN_v1.0` 的 D1–D9，含一处交叉修正（D3）：

| # | 决策 | 类型 |
|---|---|---|
| D1 | 底图默认路径：CPU 烘焙单张整图纹理 → **GPU 逐像素求值**（3 张数据纹理 8MB + `TerrainFieldMaterial` WGSL） | 推翻 |
| D2 | 边界处理：像素级 `wobble_px` 抖动 → **SDF 距离场 + 世界坐标域扭曲**（幅度 `clamp(2×scale, 0.05, 0.)`，远观手绘感 / 近观编辑精度） | 推翻 |
| D3 | 地物：Mesh2d primitive → **图集 Sprite 实例化**，**按 T1 同款双轨修正**：程序化符号保留为 `_default` 基准（甄塑之判「超集/资产」），图集 Sprite 为位图 pack 能力，**不删程序化路径** | 推翻+修正 |
| D4 | 数据模型 `TerrainData{height, surface, biome}` 三通道不动 | 保留 |
| D5 | 色板 `PaletteColors`/`ThemePack` 令牌体系不动，改为 shader uniform 消费 | 保留 |
| D6 | `ViewMode` 七档全保留，改 uniform 分支 | 保留 |
| D7 | 主题可换：换 pack = 换 uniform + 换图集，零代码 | 保留 |
| D3 补充：D8 | 构图：新增「区域层」与「纸材质层」为独立 Z 序图层 | 新增 |
| D9 | 规格书增补 §3.8「渲染实现契约」（屏幕像素口径），原文不改 | 新增 |

**与 T1–T5 待裁基线的合并**（`RENDER_IMPLEMENTATION_PLAN_v0.1.md` 第三部分）：本 ADR 的 D3 修正与 T1（双通道）一致；M2/M-A（色板+文档追记）不受本裁定影响，照常先行。

## 3. 理由（Why This）

1. **位图有分辨率上限，逐像素求值没有**——这是唯一能同时解决「放大糊」与「缩小散」的架构。
2. **被否决备选已穷尽**：提高纹理上限（16384²=1GB 显存）、分块高分辨率烘焙（视口 9 块=600MB）、autotile 47 块（不解决放大糊）、再调色板（三轮已证无效）、全矢量等值线（成本更高且海面仍需栅格求值）。
3. **已验证资产原样迁移**：SeaRecipe / 色板 / soften_keep 0.92 / VEIL 0.12 / mountain #9E9070 等历史调参成果全部搬 uniform，不推翻（R5 处置）。
4. **回退保险**：`FieldRender` 一行开关，关=完整回到现行烘焙路径。

## 4. 代价与风险（Cost）

- 新增 shader 管线（P1 约 900 行含测试）；`cells.rs` 烘焙主路径退役为回退；`terrain_chunks.rs` 从「性能命脉」降级为「可选批处理优化」。
- **Bevy 版本耦合加深**：WGSL import 段随版本变（R1）——P1 第一步先跑官方示例核验 import 路径，不凭记忆写。
- 集显需低配档（R2，fbm 降 octave / bicubic 降 bilinear，uniform 开关）。
- **性能预算**：8MB 显存（vs 67MB+mip）；每像素 ≈20 采样，1600×900 预期 <1.5ms（4060 级），集显 4–6ms；笔刷一格 <0.05ms（vs 重烘脏区 1–8ms）。
- **实施方案柯章 §3.1 主管线描述让位**：M1 中的「CPU 烘焙语境下的斜投影 texture-bake」需重新评估与 GPU 路线的衔接（T3 斜投影在 GPU 路线下改为 shader 内变换，机制简化但需重写实现路径）。

## 追记一：P1 实机验收与「海陆交界格级台阶」的裁定（2026-10-23）

> 按 AGENTS §6.3「追写不改机制」追加，§1–§8 正文一字未改。
> 本节同时修掉一处**格式化缺陷**：§6 表格的分隔行原为 `|---数字|---|`
> （非法），已改回 `|---|---|` 以恢复表格渲染。属笔误修复，不涉决策。

### 1. P1 已实机验证（此前只有编译期证据）

`cargo check` / clippy / 单测全绿**不足以证明能跑**。本轮真跑 demo 后修掉
**十处**编译期不可见的缺陷（详见 worktree 提交 `33b49ad` / `21fb4c0`），
按性质归为五类：

| 类别 | 典型缺陷 |
|---|---|
| uniform 布局 | encase 把 `[f32; 4]` 当 `array<f32, 4>`（stride 4）→ 运行期 panic，须一律 `Vec4` |
| 资源路径 | `fragment_shader()` 的路径相对 **asset 根**；example 的根在 exe 目录 |
| 渲染管线归属 | 自定义 `Material2d` 挂在 `Sprite` 上会被**静默忽略**（`Sprite` 不消费 `MeshMaterial2d`） |
| 纹理归一化 | 标志位写字节 `1` → unorm 采样后是 `1/255`，`r > 0.5` 恒假 |
| 色彩空间 | sRGB 常量喂进线性 uniform → 整体偏亮发灰 |

**结论（流程性）**：图形代码的「已验收」定义必须是**跑起来 + 出图 + 图对**，
编译与单测只是前置门。P1 的 `FIELD_ACCEPT=1` 自动出图模式已随 demo 落盘，
9 档覆盖 T31–T34 三档判据，可复跑。

### 2. 遗留问题：海陆交界的格级台阶

**现象**：近观（≥8 px/格）时水陆交界呈一格宽的阶梯；放大到 32 px/格 时
台阶宽达 32 px，已不读作「线」。

**根因**：§1 的 T5 规定「双通道（水→陆 / 陆→水），**不用带符号 SDF**，
符号由 `surface` 通道给出」。而 `surface` 住在 `attr` 纹理且必须 `Nearest`
（T2：biome 是 ID，插值会出 `biome 5`）。**符号是 per-texel 的阶跃函数**，
其翻转必然对齐格边界——台阶是该数据模型的必然结果，不是实现缺陷。

三段色带（T7–T9）本身由距离场连续驱动、是平滑的；跟着格子走的只有那条
水陆分界。

**裁定（用户 2026-10-23 回「甲」）**：**维持 T3/T5 现状**，接受格级台阶，
交由 **P2 域扭曲（T19–T22）**缓解——域扭曲的设计目的本就是「把格网对齐
打散成手绘抖动」，相位扰动后台阶会变成不规则的手绘边缘。

**被否决的乙案**：把 `coast_tex` 改存**有符号**距离
（`sd = (is_land ? +1 : −1) × (d − 0.5)`，重映射到 `[0,1]`），P1 即得平滑岸线。
否决理由：

1. 直接推翻已锁定的 T3/T5 数值与语义（P0 表已锁定，改动须回表留痕）；
2. 与 P2 域扭曲**叠加**后语义变复杂：扭曲作用在一个已平滑的场上，
   幅度公式 `amp = clamp(2.0×scale, 0.05, 0.45)` 的调参基准要重推；
3. P1 的目标是「解决约 60% 的丑」（§7），岸线色带层级已达成；
   交界锐度属手绘化的范畴。

**亦排除的第三条路**：给 `attr` 单独绑一个线性采样器只取 R 通道（保持 G 的
`Nearest`）。Bevy 0.19 的 `AsBindGroup` **不支持显式 `Handle<Sampler>`**
（`sampler_type` 只控制布局类型），要这么做得复制一份 4MB 纹理，
显存代价不值。

### 3. 对 §8 验收项的修正

§8 原写「P1 验收：放大 4× 海岸线连续曲线无阶梯」。按本节裁定，该条应读为：

> **P1 验收**：放大 4× 时**海岸三段色带**连续过渡、**岸线墨线**粗细恒定
> （屏幕像素口径）；**海陆交界的格级台阶为已知限制**，P2 域扭曲后复验。

§8 正文保留原样（§6.3 不改机制），以本节为解释口径。

### 4. 更正：域扭曲**不能**缓解格级台阶（实现后实测）

上面 §2 的裁定理由里写了「交由 P2 域扭曲（T19–T22）缓解——相位扰动后
台阶会变成不规则的手绘边缘」。**P2 实现完成后，这条判断被证伪，此处更正。**

#### 结构性论证（不依赖具体档位）

T19 把幅度锁在 `[0.05, 0.45]` **格**，即 **`amp_max = 0.45 格 < 0.5 格`**。
而「1 格阶跃」的几何含义是：水陆的 texel 归属在第 n 与第 n+1 格之间翻转。
要让这条边界移出它所在的格区间，扰动至少需要 **0.5 格**——`amp_max` 差一点都
够不到这个下界。

这不是「量不够、调大就行」的问题：**`0.45 < 0.5` 是硬约束**。T19 的上限设计
（远观 0.45 格「明显手绘起伏」）本身就假定扰动不得跨格——否则会把地形画歪，
比台阶更糟。所以域扭曲在**结构上**不可能消解格级台阶，无论怎么调参。

#### 各档位实测值（附更正）

初版本节表格算错过一处：`warp_amp` 有 `clamp` **下限** 0.05，8 px/格 的
`0.225/8 = 0.028` 会被抬回 **0.05**，我误记成未钳制的 0.028。更正后：

| 缩放 | `0.225/px_per_cell` | `amp`（格，已钳制） | `amp` 折合屏幕 px |
|---|---|---|---|
| 32 px/格（极限近观） | 0.0070 | **0.0500**（下限） | 1.60 px |
| 16 px/格 | 0.0141 | **0.0500**（下限） | 0.80 px |
| 8 px/格 | 0.0281 | **0.0500**（下限） | 0.40 px |
| 4 px/格 | 0.0563 | 0.0563 | 0.23 px |
| 3 px/格 | 0.0750 | 0.0750 | 0.23 px |
| 0.8 px/格 | 0.2812 | 0.2812 | 0.23 px |
| 0.4 px/格 | 0.5625 | **0.4500**（上限） | 0.18 px |

工作区间（3–16 px/格）折算到屏幕后都在 **0.23–0.8 px**，仍在亚格量级——
即便不看上面的结构性论证，实测也支持同一结论。

#### 更根本的原因

`amp` 的设计意图（T19 注记）是**近观收敛保编辑精度**，它天生被压在亚像素量级；
而格级台阶是**格**量级的现象。域扭曲在设计上就不是治它的药。

**结论**：格级台阶是**永久性限制**，除非改用乙案（`coast_tex` 存有符号距离）。
甲案的实质含义应读作「接受它」，而不是「先放着、P2 会好」。
本次裁定不作废——只是把理由改正为「接受，无 P2 remedy」。

实测补充：P2 的其他两项（T28–T30 水彩、T31–T34 缩放自适应）**确实有效**：
远观档墨线按 `smoothstep(1, 3, px_per_cell)` 全关后，彩色噪点与缩放闪烁消失；
海拔色阶由硬阈值改窄平滑（±0.02）后，远观锯齿也一并消除。
