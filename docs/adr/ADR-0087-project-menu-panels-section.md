# ADR-0087: 工程菜单回填「面板」分组——面板显隐入口降为两步

- 状态：已接受（2026-10-29，随 UX round-2 审计 quick-wins 批次实施）
- 关联：推翻 2026-10-19 代码注释裁定（`project_menu.rs` 旧模块文档「面板开关不进工程菜单」）；UX-009 / UX-027（`docs/UX_AUDIT_2026-10-29.md`）

## 处境

七原则 P5（图层化编辑）的入口——图层面板——默认隐藏且无快捷键；2026-10-19 裁定把面板开关从工程菜单裁撤后，唯一完整入口是设置对话框（打开设置 → 「浮动窗口」分组 → 勾选 = 三步，且「设置」里放「浮动窗口」本身命名错位），命令面板（Ctrl+K）对新用户不可见。round-2 反向审计（UX-009 修正版）判定这构成「图层化编辑入口最难找」的信息架构缺陷：**入口被裁撤后没有补等价发现面**。

## 决策

工程菜单回填「面板」分组：

1. 分组列出 `Panel::ALL` 全部面板，可见者以 `✓` 前缀行内标注；点击排 `CommandId::TogglePanel(p)`，与命令面板走同一分发。
2. 标签键收敛到单一真源 `ui_command_palette::panel_toggle_label_key(p)`——命令面板「面板」组与工程菜单共用一份 match，不再两处漂移。
3. 「重置面板位置」**不**回填菜单（保持设置对话框 + 命令面板两处）。
4. 设置对话框的 12 复选框保留（两入口并存，服务不同心智：菜单=快速开关，设置=一次性配置）。

## 理由

- 菜单行点击 = 1 步可达任意面板（原 3 步），满足审计验收「冷启动新用户 ≤3 次操作打开图层面板」。
- 不新增任何顶栏控件（round-1 曾提议顶栏加面板按钮，因违反减法原则被 round-2 修正为回填既有菜单）。
- 每帧零成本：分组行只在菜单展开时绘制。

## 代价 + 被否决的备选

- **代价**：菜单从 2 组变 3 组（+12 行），菜单长度接近翻倍；键盘导航行数随之变长（既有 `selected` 循环自适应，无代码成本）。设置对话框与菜单两入口并存需要同步——标签键已单真源，`Panel::ALL` 同源，漂移面只剩「分组顺序」一处（可接受）。
- **否决 A**：顶栏右区加「面板」按钮——新增常驻控件，挤占右区已满的几何（`readout_segment` 从右往左排已到底），违背减法原则。
- **否决 B**：右键画布空白弹面板清单——画布右键在三个工作区语义不同（测量/线 POI 收笔），新增上下文菜单与既有手势冲突面大。
- **否决 C**：维持现状（只靠设置+命令面板）——被 round-2 审计实测否定：新用户任务「找到并编辑指定图层 ≤3 次操作」不达标。
