# ADR-0030: POI 呈现级别（rank）与屏幕密度预算

> 状态：**提议**（2026-10-18 起草；实现按本 ADR 进行，用户可否决后重开）
> 关联：ADR-0027 / ADR-0029（同扩 `Place`，互为可选字段零冲突）、ADR-0022、
> `vector_layers.rs` A2 合批（2026-10-18）、`state.rs` LodTier 文档（「数据模型补
> `rank` 再做」的预告在此兑现）

## 处境

广东工程（examples/guangdong）实机消融实验（2026-10-18，探针五档）钉死了两个性能问题：

1. **深缩放塌陷 = POI 池**：越过 Region 档后珠江三角洲一个视口内 ~1.8 万路口点全部涌入，
   实体数 704 → 35,988；且点半径 ∝ `view.scale`，缩放期间每个点的 mesh **每帧**重建 +
   每点每帧重绑材质/Transform，帧率 1.8。关掉 Place 图层即回 14（残余为道路重建，见 D5）。
2. **缩放途中 = 道路层**：`world_thickness = px × view.scale` 进合批 key，每个缩放帧
   重建 2×87k 段 mesh 并上传 ~12MB；`compute_projection` 另每帧无条件重推 87k 段 + 指纹。

同时，现有 LOD 只有「城市（有 w/h）vs 普通点」隐式两级，与 Google/百度式「POI 分级别、
越放大出现越多层级、同屏按重要性限量」的呈现模型差距是本次用户裁定的需求（2026-10-18「POI
也要分级别呈现……加级别 go」）。而 `Place` 数据模型没有级别字段——`state.rs` 的 LodTier
文档早已预告「后续数据模型补 `rank` 再做」。

## 决策

**D1 · 数据模型 = `Place.rank: Option<u8>`（呈现级别，数值越大越重要）**。
词汇表（登记 GLOSSARY「呈现级别」）：`3` 国家级（省会/大都会）、`2` 市镇级、`1` 普通地点、
`0` 网络节点/微点（路网交点这类只为锚定边存在的点）。`None`（缺省）= **按旧两档折算**：
有 `w/h` → 3，否则 → 1——既有工程（xinhai 等）零迁移、零行为变化；导入器/作者显式写
`rank` 才进入分级体系。serde `default + skip_serializing_if`，与 `feature`/`biome` 同款。
理由：向后兼容是硬约束（旧 YAML round-trip 不许变）；折算点写在 `Place::effective_rank()`
单一入口。代价：`None` 的语义依赖折算规则（规则变化 = 旧工程行为变化），故折算规则本身
视为冻结契约、写测试钉死。被否决：**enum 类型**（`feature: u8` 已立裸 u8 + 词汇表先例，
enum 断旧 YAML）；**不加字段纯上限**（无重要性时「裁掉谁」不可解释——PRD 里按名字长度
裁点标是荒谬的；分级是 Google 模式的根）。

**D2 · 呈现门槛 = 视野档位 × 最低级别（硬门）**：Nation 档可见 rank ≥ 3，Region 档
≥ 2，Edit 档全可见（≥ 0）。纯函数 `poi_visible_at_rank(rank, tier)`（wv-render::state，
与 `lod_tier` 同居）。**以硬门取代非城市淡出带**：旧 `lod_fade(LOD_REGION_SCALE)` 的
1.0–1.125 过渡带删除，POI 在档位边界直接出现/消失（缩放运动掩盖 pop-in，Google 同款）。
`is_city` **只剩材质语义**（有 w/h 用城市材质），不再参与可见性。理由：淡出带与多级门槛
正交组合的状态空间是这次事故的温床；硬门口径可穷举测试。代价：档位边界处点标硬切（v2
如需平滑再按 rank 门槛配淡出带）。被否决：**保留淡出带 per-rank**（每级一条 fade 曲线
= N 个阈值常数，测试面爆炸）。

**D3 · 屏幕密度预算 = `POI_MAX_DOTS = 400`，超出按优先级裁剪**。优先级序：
`(rank, is_city, name.chars().count())` 降序（名字更长者信息量更大，与标签碰撞优先级
同一惯例）。这是**纯渲染投影**：裁剪只影响画不画，不写数据、不阻止编辑（V1 无涉）。
理由：视口裁剪只是第一道门，「看到的地方」本身在 PRD 就有 1.8 万个；成本预算必须与
屏幕挂钩而非数据总量。400 的量级 = 800 实体（合批后 ≤4 mesh），高密度城区接近
Google 同缩放的视觉密度。被否决：**聚类聚合**（mapbox 式「+99」气泡是新视觉概念，
超出编辑器需求）；**不设上限**（合批后渲染虽扛得住，1.8 万碎点仍是不可读的噪声——
本次截图实证）。

**D4 · POI 渲染 = 按材质合批 ≤ 4 个 mesh + Mesh 资产原地复用**。可见集（视口 ∧ 门槛
∧ 上限）按 4 个材质句柄（ring/dot/city_ring/city_dot）分桶，每桶一个合批 mesh
（Annulus 12 段 / Circle 12 扇区手工三角化，同 `build_stroke_batch_mesh` 口径）；
半径/集合/Z 任一变化才重建，重建走 `Assets::get_mut` **原地改写顶点**，不新增/销毁
资产（A2「每帧零资产新增」纪律的延伸）。每点每帧的材质/Transform 重绑命令随之消亡
（淡出修正 #4 的语义由「材质 alpha 全局刷」天然继承）。理由：36k 实体 × 每帧重建
是塌陷根因；4 mesh 把「每点成本」变「每桶成本」。代价：ring 三角化自绘（12 段近似，
圆度损失在 ≤10px 半径下不可见）；丢逐点 alpha（本就无人用）。被否决：**GPU instancing
/ 自定义 shader**（顶点着色器展开厚度/半径——需要 wv-render 自维护 shader 管线，v1
成本收益不成立，挂账 v2）；**保留逐点实体**（即现状，已证伪）。

**D5 · 道路 = 段列缓存 + 线宽量化节流 + mesh 原地复用**。
(a) `compute_projection` 的路段循环与指纹改为**有变化才重算**：`WorldProjection` /
`DrillState` / `GridConfig` 变更检测 + Road/Place 可见开关组成的缓存键，其余帧零工作
（段坐标不依赖相机/缩放——它们在根图帧坐标系）。
(b) `sync_road_strokes` 的重建判据从「线宽精确相等」放宽为「相对漂移 > 4%」：
`|thick_new / thick_baked − 1| > 0.04` 才换几何，连续缩放下的重建频率降 ~3 倍
（0.985/帧时），屏幕线宽误差 ≤ 4%（6px casing 差 0.24px，不可见）。
(c) 几何重建同样走 `get_mut` 原地改写（含 D4 的资产复用）。
理由：三点合力把缩放帧的道路成本从 ~60ms 压到「填 6MB 顶点 + 上传」的毫秒级。
代价：线宽在缩放中有 ≤4% 阶梯（刻意接受）；缓存键漏列会画出陈旧路网——用测试钉死
键组成。被否决：**每缩放帧精确重建**（现状，已证伪）；**厚度进 shader**（同 D4 否决）。

**D6 · 标签候选 = 视口裁剪 + 级别门槛 + 走锚定桶**。`update_place_labels` 改经
`PlaceIndex::anchored_by_map` 直取本图桶（与 `compute_projection` 同口径），先视口
后门槛过滤，碰撞过滤（O(n²)，ADR-0017 v0.1 的「n ≤ 200」假设）输入有界化。理由：
81k 候选全量进 O(n²) 是悬顶之剑（本次实验证明它不是深缩放主因，但Nation 档一过
它就是 81k 输入）；桶 + 视口把输入压到屏幕量级。代价：碰撞优先级语义不变，仅输入
收窄。被否决：重写碰撞为 sweep-line / 空间索引（输入有界后 O(n²) 在 n ≤ 数百时
足够，不过度工程）。

## 代价汇总

- `Place` 增一可选字段；折算规则冻结契约化（`effective_rank` 测试钉死）。
- 非城市 POI 的 1.0–1.125 淡出带删除（档位边界硬切）。
- 道路线宽缩放中有 ≤4% 阶梯。
- ring 圆度 12 段近似。
- 兼容性：ADR-0029 同扩 `Place`（`biome`/`envelope`），互不触碰。

## 关联原则

P3（YAML 为主格式，rank 为可选字段零迁移）、P6/P7（rank 是静态属性非时变量，不入
span；若未来需要「某时期级别不同」再按 §4.1 区间化，当前不做）、V1（密度裁剪纯渲染
投影，不写数据不阻编辑）。
