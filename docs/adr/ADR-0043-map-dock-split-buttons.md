# ADR-0043：地图工具条改 11 槽 + 两组分裂按钮

**状态**：已接受（Accepted）
**日期**：2026-10-20
**决策者**：用户（对话拍板 + 两轮实机反馈迭代）
**关联**：取代「地图工具条一比一平铺 Figma `3:21848` 十三项」的 v0.6 布局（该布局**无 ADR**，仅见 `map_controls` v0.6 模块注释——本 ADR 是它的第一份留痕）；**不取代**任何已接受 ADR；`MapToolId::Brush / Continent / MeasureEraser` 三个变体的**快捷键与命令面板入口不受影响**（ADR-0009 分级缩放、ADR-0025 命中优先级、ADR-0033 选区保留均不涉）
**GLOSSARY**：已登记「分裂按钮」「框选」「底图橡皮」三条词条

---

## 1. 处境（Context）

工具条 v0.6 把 Figma 设计稿 `3:21848` 的 13 项**一比一平铺**：选择 / 抓手 / 笔刷 / 测量橡皮 / 折线 / 生成大陆 / 矩形 / 撤销 / 重做 / 磁吸 / 网格 / 朝向切换 / 吸附。平铺在功能少时成立，功能长起来后暴露三个问题：

1. **同族工具各占一格，读者要自己归纳「这几个是一伙的」**。三种选区形状、两种测量方式在平铺里是并列的独立瓷砖，「我现在用的是哪一个」要靠图标辨认。
2. **尺寸吃紧**。横排 11 瓷砖 + 4 图标钮 + 3 分隔 + 17 间距 ≈ 590px，在 1280 窗口里只剩 3% 裕量；纵排按 40×38 排会压到时间轴（2026-10-19 实测截图）。
3. **磁吸的入口错位**。它的唯一真实消费点是「势力划分」对话框的默认边界模式（`intent_menu.rs` 读 `MapDockState.snapping`），挂在工具条上是把它抬成了全局工具。

作者同期还提了两条新需求：**矩形 / 椭圆选择器**（业界选框标配）与**地形橡皮刷**。平铺布局每加一个同类工具就再吃一格，纵向空间已经见底——所以问题不是「再加两个按钮」，而是**信息架构该换了**。

## 2. 决策（Decision）

### 2.1 布局：11 槽

```
⇅    ✋    ┊    ◆◢    ◻    ┊    📏◢    ┊    ↷   ↶   ▦
grip pan  sep 选择组 橡皮  sep  测量组  sep  redo undo grid
```

| 槽 | 内容 | 快捷键 |
|---|---|---|
| 0 | grip：拖动 = 移动工具条，单击 = 切换横/纵 | — |
| 1 | 抓手 | `H` |
| 2 | 分隔条 | |
| 3 | **选择组**（分裂按钮）：多边形（默认）/ 矩形 / 椭圆 | `V` = 多边形 |
| 4 | 地形橡皮刷 | `E` |
| 5 | 分隔条 | |
| 6 | **测量组**（分裂按钮）：线段距离（默认）/ 面积 | `L` / `M` |
| 7 | 分隔条 | |
| 8 | 重做 | `Ctrl+Shift+Z` |
| 9 | 撤销 | `Ctrl+Z` |
| 10 | 网格开关（开启高亮） | `G` |

**redo 排在 undo 之前**——按需求方明确规格执行，与主流软件相反；这是刻意保留的「按图索骥」顺序，不做「悄悄纠正」。

### 2.2 分裂按钮（split button）

「选择组」与「测量组」是两枚**分裂按钮**：主区点按 = 立即用当前子项；右下 / 下缘小三角 = 弹出菜单换子项。**主区图标跟着当前子项走**（选了矩形，主区就显示方块）。控件落在 `wv-ui::widgets::split_button`（零领域依赖，AGENTS §2.1）。

小三角方位随朝向（用户两轮反馈后的终版）：

| 朝向 | 方位 | 三角朝向 | 图标让位 |
|---|---|---|---|
| 横排 | 右缘垂直居中 | 朝下 | 向左让位（**垂直方向不挤**） |
| 纵排 | 下缘水平居中 | 朝下 | 向上让位（水平方向不挤） |

「右下角」这个第一版方案被否：角落方位会把图标往上挤（实机反馈），改为「右缘居中」后图标沿水平让位、垂直回到中线。

### 2.3 选择器三形状

- **多边形**（默认）：逐点点击 + 橡皮筋，锚点可拖 / 双击删 / 点边插——Figma pen 手感，**一行不改**。
- **矩形 / 椭圆**：**框选（marquee）**——按住左键拖出框、松手成形（Figma / PS / AI 同款）。成形后整体可拖、拖角缩放，**不做逐锚点编辑**。

关键实现约定：**矩形与椭圆在成形时把边界合成成一条闭合点环**，写进 `SelectionState.closed`（`Vec<(f32, f32)>`）。于是下游——意图菜单、大陆生成、城镇意图、地物标记对话框、势力划分、CellMap 批量改——读到的仍是同一份环，**零改动**。

### 2.4 测量：只换图标，功能不变

| | 图标 | 语义 | 实现 |
|---|---|---|---|
| 6.1（默认） | `ruler-dimension-line` | 线段距离 | **现有** `MeasureMode::Line`（多点累积，每段读数 + Σ 总长） |
| 6.2 | `squares-unite` | 面积 | **现有** `MeasureMode::Rect`（两点定对角，长 × 宽） |

因此**不新增任何测量模式、不动 `MeasurementKind`、不碰 YAML**。`MeasurementKind` 仍是 `Polyline | Rectangle` 两项。

### 2.5 地形橡皮刷 = 重置为底图

`BrushTool::Eraser`（**枚举末位追加**）：把笔下格子**整格回填成本图的 `MapBase` 态**——底图是海洋就擦成海洋（-3500 m 整片深水），是陆地就擦成陆地（+80 m 整片草原）。老工程缺 `base` 字段时兜底 **Ocean**，与 `ResetTerrainToBaseCommand` 同口径。

底层：`wv_terrain::edit::Brush` 新增 `exact: Option<TerrainCell>`——整格直写通道，**优先级高于** `target`，完全绕过「跨域必须把高度推过海平面」的自动规则。`PaintTarget` 那条规则是给「涂抹」设计的软化高度（`PAINT_SEA_DEPTH = -40`），够不着底图那两个整值。

配套：笔刷面板在橡皮模式下**不渲染 10 格地形材料选择器**（材质不参与，画出来是谎话）；笔刷光标在橡皮下换危险色；`E` 快捷键从「测量橡皮」让给地形橡皮，测量橡皮退到命令面板。

### 2.6 退出工具条的三件

**画笔（B）/ 生成大陆（P）/ 磁吸**三枚瓷砖退出工具条。**对应 `MapToolId` 变体不删**——删了会让快捷键与命令面板入口静默失效。磁吸的 `MapDockState.snapping` 开关、随工程落盘、势力划分对话框的读取路径全部原样保留。

### 2.7 其它

- 网格新增 `G` 快捷键（此前该命令无快捷键）。
- 工具条 tooltip 全部接 i18n（原先是硬编码中文，且 `MapControls*Hint` 系列 key 已定义却从未被引用）。
- 工具条**不画快捷键字母**（用户裁定）：字母统一退到 tooltip。
- 11 槽**等宽等高**——grip / 重做 / 撤销 / 分隔条与瓷砖占同样大小的槽，视觉钮画在槽正中。两条朝向都因此天然成列。

## 3. 理由（Rationale）

1. **分裂按钮是业界对「同族多工具」的成熟答案**（Figma / PS 工具栏同款）。多数帧作者只关心「我现在用的是哪件」，主区必须**一瞥即得且一击即用**；换件是低频操作，付一次弹层成本可接受。拆成两枚并排的独立瓷砖会让工具条在窄屏上翻倍，也让「当前是哪件」在视觉上散成两个高亮位。
2. **合成点环而非新形状类型，是代价最低的决定**。`SelectionState.closed` 是六个下游的公共接口，动它 = 六处连改；合成环 = 零处。新增矩形 / 椭圆对下游完全不可见——这正是数据层「只存引用 / 单一真源」纪律在交互层的延续。
3. **橡皮走 `MapBase` 整格直写，而非 `PAINT_SEA_DEPTH`**。需求方明确「擦回底图」；且 `MapBase::cell()` 选整图同值正是为了让 VectorFlat 双线性采样无陡坎——整格直写保住这个性质，走 `target` 那条软化路径则会把底图抄成 -40 m 的浅滩，且紧邻浅水处出现等值线陡坎。
4. **槽位统一解决对齐**。小钮（28 / 32 px）落在瓷砖（34 / 40 px）行里默认贴左 / 贴顶，整条看着歪。两种方案：一是交叉轴 `Align::Center`，二是**槽位统一 + 视觉居中**。前者被否——egui 的 `Frame` 按内容包围盒收缩，而大框的内容区铺满整屏，`Center` 会把小钮摆到屏幕中央，包围盒从锚点一路撑过去，整条工具条鼓成一块盖住半个屏幕的面板（2026-10-20 实机反馈）。槽位统一是零副作用的做法：帧自然贴合，命中区还顺带大了一圈。
5. **`Brush.exact` 的优先级写成显式约定**（`exact` 高于 `target`）并配两条单测，防止未来读代码的人把「谁写在 `if` 前面」当成巧合。

## 4. 代价 + 被否决的备选

### 代价

1. **画笔没有工具条入口**，新作者发现性下降（靠 `B` 与笔刷面板补偿）。
2. **redo 排在 undo 前**，与主流软件相反（按需求方规格刻意保留）。
3. **矩形 / 椭圆不做逐锚点编辑**：整体拖动 + 拖角缩放；多边形仍是逐点编辑。要完全对齐需把 `SelectionState` 的锚点语义从「环上的点」升级为「形状手柄」，改动面大一档（`rebuild_closed` 已为此留了单点入口）。
4. **`Brush::exact` 让 wv-terrain 的笔刷语义多了一条旁路**（原本只有「目标 + 自动规则」一条）。靠优先级约定与单测钉住。
5. **橡皮在底图为陆地的工程上，会把该处抹成 +80 m 草原**（`MapBase::Land.cell()` 的定义）——擦掉一座山得到一片平原而非洼地。这正是「擦回底图」的语义，且 `MapBase` 的整图同值是有意口径，不是实现取巧。

### 被否决的备选

| 备选 | 否决理由 |
|---|---|
| 末尾追加保留画笔 / 大陆 / 磁吸三瓷砖 | 工具条回到 14 项，纵排重新压时间轴，违背「重组」初衷 |
| 画笔 / 大陆 / 磁吸移入顶栏工程菜单 / 势力划分对话框 | 功能不丢，但这两处的**可见入口**从「一瞥即得」变成「在别处找」；需求方直接裁定「不要」 |
| 橡皮做成 `Intent::Erase`（归意图族） | 意图是「给骨架、程序生成」，橡皮是「确定性地回到已知态」，语义不容；且 `BrushToolGroup` 三组划分会被撑出第四组 |
| 小三角贴右下角（第一版） | 角落方位把图标往上挤（实机反馈），改「右缘居中」 |
| 用交叉轴 `Align::Center` 对齐小钮 | 会把工具条鼓成半屏面板（见 §3 理由 4） |
| 新增 `MeasureMode::Segment`（两点线段） | 需求方裁定「测量就两种，只换 icon，功能不变」；且现有多点折线已覆盖「线段距离」语义 |
| 矩形 / 椭圆引入新的选区数据类型 | `SelectionState.closed` 是六个下游的公共接口，动它 = 六处连改；合成点环 = 零处 |
