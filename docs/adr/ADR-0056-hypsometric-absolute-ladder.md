# ADR-0056：分层设色阈值改「绝对地形学阶梯 + 窄域兜底」——修正 ADR-0055 的百分位口径

**状态**：已接受（Accepted）
**日期**：2026-10-24
**决策者**：用户（对话裁定「绝对 + 窄域兜底」）
**关联**：**修正 [ADR-0055](ADR-0055-cellmap-hypsometric-tint.md) 决策 3「逐图百分位」**（正文不改，头部标注）；[ADR-0042](ADR-0042-hand-drawn-nation-style.md)（山地 1150–1500 / 雪线 2250–2750 的语义锚点来源）；[ADR-0053](ADR-0053-terrain-gpu-field-rendering.md)（同一条 GPU 场管线，仅换 uniform 数据）；[ADR-0051](ADR-0051-mode-content-matrix.md) §5（固定色不变）

---

## 1. 处境（Context）

ADR-0055 落地后（8 阶叠层、强度 `0..1`、两条渲染路径共用一份色表），用户追问「如果不选择百分比，有什么更好的选择」。复盘时发现百分位在**编辑器**里有两条具体缺陷，而 ADR-0055 只写了抽象的「无绝对海拔含义」：

1. **编辑反馈漂移**：抬一格山头 → 全图 7 条阈值移动 → 别处颜色跟着变。CellMap 的首要职责是**编辑**（ADR-0052 的连续绘制工作流），颜色变化应当只跟着被刷的那几格走。
2. **增量补丁出接缝**：CPU 路径的 `patch_terrain_image` 每次建 `CellRenderer` 都重算阈值，却只重画脏矩形——**脏区内用新阶、区外用旧阶**，边界两侧同高度不同色。

这两条都不是「观感偏好」，是口径选错。

---

## 2. 决策（Decision）

1. **绝对地形学阶梯**（替换百分位）：7 条内边界 = `200 / 500 / 1000 / 1500 / 2500 / 4000 / 6000` 米，常量 `hypsometric::DOMAIN_CUTS`。
   - 锚点与生成侧已有的地形语义同源（山地 1150–1500 / 雪线 2250–2750，ADR-0042）——颜色的含义与世界生成规则是同一套；
   - 阈值是**常量**，不随数据漂移：笔刷只改被刷的格，别处绝不变色；
   - 读图者可直接把颜色换算成高度（`1000 m` 起即「山地」阶）。
2. **窄域兜底**：陆地高程跨度 `< NARROW_SPAN_M = 300 m` 的图，改用该图自身 `[min, max]` 等分 8 阶（保住起伏可读）。理由：绝对阶梯头两档合计 500 m，一张 100 m 高的岛在绝对口径下只会落到 1 阶、整幅同色。
   - 兜底区间按 `RANGE_QUANT_M = 100 m` **向外量化**：小幅笔刷（同桶内）不改阶梯，降低「整图重洗」的概率。
3. **计算成本**：`cuts_for_cells` 只求 min/max（`O(N)`，**不排序**），整图重打 / 每次补丁都可廉价重算。相对百分位的 `O(N log N)` 是净收益。
4. **水格仍排除**：高程区间与着色都只对陆格（`surface == LAND && height >= 0`）。
5. **色带、uniform、shader、UI 滑条全部不动**：只换「阈值从哪来」这一件事——证明 ADR-0055 把「阈值提供者」与「着色」分开是对的。
6. **数据层零改动**：阈值是渲染常量，不落盘（P3）。

---

## 3. 理由（Rationale）

- **编辑器要的是稳定反馈，不是人口均衡**：百分位的「每阶人口相等」是**制图出图**的优点，在「一边刷一边看」的场景里反而是 bug。
- **绝对阶梯在极端图上「不均衡」是诚实信号**：小岛只有低阶、高原挤满高阶——这正是读者想知道的「这里根本没有高山」。
- **兜底只覆盖真正需要它的图**：跨度 < 300 m 时绝对阶梯必然退化，此时用区间等分；量化把残余的不稳定性压到「跨 100 m 桶才发生」。

---

## 4. 代价（Consequences）

### 4.1 负面后果（必须承认）

1. **兜底路径仍有残余漂移**：窄域图里跨越 100 m 量化桶的笔刷会让该图的兜底阶梯整体移动，进而可能出现接缝（脏区新阶 / 区外旧阶）。已量化缓解，未消除；触发条件是「窄域图 + 跨桶编辑」，可接受。
2. **同一高度在不同图上可能不同色**：一张高原图的 1200 m 是「山地」阶，一张窄域图的 120 m 可能落在第 6 阶。这是兜底的有意代价——窄域图本来就没有绝对参照。
3. **绝对阶梯的档宽不等**（200 / 300 / 500 / 500 / 1000 / 1500 / 2000）：不能按「每阶 200 m」线性换算，读图时需查表。
4. **最高阶（≥ 6000 m）几乎不出现**：pack 的 `H_MAX = 6000` 钳位，超过即落在最高阶——这是数据编码上限，不是本 ADR 的新问题。

### 4.2 被否决的备选

| # | 备选 | 否决理由 |
|---|---|---|
| A | 维持百分位（ADR-0055 原案） | 编辑反馈漂移 + 补丁接缝（§1 两条），编辑器场景不可接受 |
| B | 纯绝对阶梯（不加兜底） | 100 m 高的沿海图会退化成 1–2 阶、整幅同色，起伏完全丢失 |
| C | 对数绝对 `log(1+max(0,h))` | 保住「0 = 海平面」锚点且反馈稳定，但阶宽非线性、不能按米换算；用户选 A 语义（可换算） |
| D | Jenks 自然断点 / 1D k-means | 仍属数据驱动，笔刷照样让阈值漂移；`O(N²)` 或 DP 比 `O(N log N)` 更贵 |
| E | 用生成侧 fbm 参数反推每图阶梯 | 生成侧参数不随作者手改高度更新，会与编辑结果脱节 |

## 7. 验收

- 单测：`DOMAIN_CUTS` 严格升序且等于锁表；宽域图 → 绝对阶梯；0–100 m 图 → `[13,25,38,50,63,75,88]` 且 8 阶全用上；95 m 笔刷不改阶梯、150 m 笔刷才改；水格不影响区间；平地图不 panic。
- 实机：在 CellMap 刷一座山，确认**其他格颜色不动**（这是本 ADR 的核心判据）。
- 门禁：`cargo test --workspace` / `clippy --workspace -D warnings` / `fmt --check` / `app-test` / `app-clippy` / GUI 烟测。
