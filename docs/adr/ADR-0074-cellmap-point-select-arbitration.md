# ADR-0074：CellMap 点选三段裁定（图钉 > 群系区 > 格）

| | |
|---|---|
| **状态** | 提议态（2026-10-27，随 feat/cellmap-pointselect-poi-biome 实施） |
| **处境** | 工具条槽 1（点选工具，ADR-0057 补记 6）在 CellMap 工作区只认格：`commit_point_select_on_click` 反查 `(gx, gy)` 写统一选区，POI 与群系区完全不在它的字典里。而 CellMap 里两者**画得出**——地物图钉（`landmarks_want` 绕过 Poi pass 的 Topographic 例外）与群系 Nature 区（`nature_overlay` 旁路）——却**选不了**：浏览态承担实体选中的 `drill_pick` 在 Topographic 下被 MODE_TABLE 的 `DrillMarkers=false` 早退，`LabelHits` 也因 `PlaceLabels=false` 恒空。作者看见图钉/群系色块，点下去却只能选到钉底下那格。 |
| **决策** | ① CellMap（Topographic 档）内点选单击按**三段裁定**：**图钉**（rank ≥ 2 点状地点，18px 屏幕半径内取最近）> **群系区**（`nature_overlay` 开时，光标落在 Nature 区多边形内）> **格**（原 ADR-0057 行为与修饰键语义原样保留）。② 命中前两段写 `WorldProjection.selection`（Place / Region `SelectedEntity`），不再写格。③ **单焦点模型**：实体选中与格选区互斥——选实体清格选区、选格清实体选中、点图外/`Esc` 双清。④ 实体命中**不吃修饰键**（Shift/Alt 并/差只对格有意义）。⑤ 浏览态零改动（仍走 `drill_pick` 标签命中）。 |
| **理由** | ① 用户原话即裁定输入：「开启群系的时候，他是选择群系……讨论什么时候是选择 POI，什么时候是 cell」+「先解决 cell map：能够选择 POI 和群系」。② 优先序=目标特异性：图钉是最小、最上层、作者瞄得最准的目标（与 ADR-0017 §2.7「标签命中优先于一切点击语义」同一精神）；群系区是面状语义目标，仅在作者显式开了群系 overlay（「我现在按群系思考」的意图声明）时才接管；格是兜底。③ 单焦点的技术动因：`resolve_form` 里 Cell 表单**恒优先**于实体选中（设计稿 §11 Q4「我在改格子」心智），若不清格选区，选了 POI 表单也看不见，等于白选。④ 只做 CellMap：浏览态已有成熟入口，重复做会与 `drill_pick` 抢点击。 |
| **代价** | ① **线段 POI（河/路）仍选不到**——无图钉、命中需折线距离测试，本轮不装（后续可用 `RiverLine.pts` 视空间折线 + 屏幕px 容差补第三段之前的并列段）。② CellMap 里想选「群系色块底下的格」必须先关 `nature_overlay`（overlay 开 = 群系接管），这是用户自己定的语义，接受。③ `Esc` 语义微扩：原只清格选区（ADR-0057 补记 3），现一并清实体选中——手势优先级（笔触/圈选先吃 Esc）不变。④ 图钉命中不走 `LabelHits` 注册表而是点击时直查当前图锚定桶：单发动作免每帧注册成本，代价是与 `landmark_dots` 的可见性口径（viewport 裁剪）有一处**宽容差**——视口外一两个身位的图钉也可点中，视为特性不是 bug。 |
| **被否决的备选** | ① **修饰键分流**（如 Ctrl 点=选 POI）：作者要先记快捷键，「单项选择器」的直觉是点谁选谁，否。② **命中也注册进 `LabelHits`**：要动 wv-render 三标签系统的清场时序（place 标签系统负责 clear，CellMap 下它空转），且每帧注册只为单击服务，否。③ **新增第四个工具槽**（「实体选择工具」）：工具条已 14 槽，用户明确要的是「第一个图标随上下文变形」，否——后续轮（笔刷态变形）同此理。 |

## 实施落点

- `crates/wv-app/src/edit/editing/cell.rs`：纯函数 `point_in_flat_polygon` / `pick_place_pin` / `pick_nature_region` + `commit_point_select_on_click` 的 Topographic 裁定分支 + `clear_cell_selection_on_escape` 双清。
- 测试：`crates/wv-app/src/edit/editing/tests.rs`（夹具 `pin` / `nature_region` / `cellmap_world`，10 条新断言）。

## 追记一：浏览族图钉命中收编进 drill_pick（2026-10-27 实机反馈）

**处境**：首轮把图钉命中只装在 CellMap（Topographic）分支。用户实机在**浏览族模式**点城市图钉无反应——浏览族里点图标本来只认**文字标签**（`LabelHits`），图钉图形本身没有命中区，「这个工具选不中图钉」。

**决策**：`pick_place_pin` 纯函数**下沉到 `wv_render::drill`**（wv-app/wv-render 两边共用，消除双份实现）；`drill_pick` 在**标签命中之后、下钻判定之前**插入图钉段——门控 `!is_double ∧ point_select.tool_active`（外加函数内的 place 层可见）。语义：**单击图钉 = 选中该 Place；双击 = 让位 `marker_hit` 下钻进城**（守住「单击选中 / 双击进入」既有手势约定）。

**理由**：① 浏览族的点击语义归属地就是 `drill_pick`（ADR-0017 §2.7 优先级链的延长线：标签 > 图钉 > 下钻 > 空白清除）；② 若留在 wv-app 侧做，跨插件 schedule 的系统先后序不可控，`drill_pick` 的「空白单击清除选中」可能后写覆盖选中——收进同一系统无竞态；③ CellMap（Topographic）不受影响：`drill_pick` 在 `DrillMarkers=false` 时早退，三段裁定仍在 wv-app，两边按模式互斥。

**工具门控的含义**：笔刷/量测等其他工具激活时，点图钉**不**误选（老行为照旧：点标签文字仍会选中——那是既有语义，不动）。点选工具激活时才多出「图形命中」这条路。

**代价**：① rank < 2 的微点（路网交点等）无图钉命中——在 guangdong 这类 8 万点工程里给每个微点开 18px 命中区会吃掉大量点击，微点仍只认标签文字；② GoogleMap 等 DrillMarkers=false 的浏览变体不走 `drill_pick`，图钉命中在那边暂缺（后续如需，走同函数在别的系统补一段）。

**测试**：`crates/wv-render/src/drill.rs`（`pin_pick_world` 夹具 + 3 条：单击选中 / 双击让位 / 工具未激活不接管）。

## 追记二：点选器升格万能选择器 + Ctrl+右键直选格（2026-10-27 实机反馈二则）

**处境**：用户在 CellMap 用**泛洪选择**（槽 13 魔杖）点城市图钉，淹出 4011 格选区而非 POI；随后两条裁定输入——①「我更希望用第一个图标替代，因为工具栏太多了」（附截图：竖排工具条第一格红框）；②「Cell map：1. 选择 poi 图钉 2. 选择 region 3. 选择单个格子，我觉得 ctrl+right click 就是选格子」。

**决策**：
1. **点选器 = CellMap 万能选择器**（方向确认）：其三段裁定（图钉 > 群系区 > 格）即用户列举的 1/2/3 三种选择。本轮三段已齐（群系区选择此前已实现）。
2. **Ctrl + 右键 = 直接选格**：替换式抓取光标那一格，优先级**压过**图钉/群系区裁定（放在三段之前）——「我就要那格」的显式指令高于命中推断。全模式可用（格选区本就不分模式）。点在图外**不动**选区（误触右键不误清）。
3. **泛洪选择不加图钉裁定**（曾试装，已回退）：用户方向是「选实体用第一个图标」，泛洪保持**纯格工具**——若泛洪也让位图钉，「淹出钉子底下的群系区」这一合法操作就被堵死（钉子周边 18px 内点不了格）。

**理由**：工具栏收敛的方向是「少而通用的工具 × 修饰键分档」，而不是「每个语义一个瓷砖」。点选器三段 + Ctrl+右键逃生舱 + Shift/Alt 并差，已覆盖 CellMap 的选择语义全集；泛洪和套索仍各自承担「连通区批量选」「形状批量选」，与点选器不重叠。

**代价与待裁**：① 工具条**实际退役清单**（泛洪/套索/EditCell 哪些瓷砖可删可合）**待裁**——本轮只增不改瓷砖，退役涉及 ADR-0052/0057 既有决策，须列清单另开裁定；② 泛洪点图钉仍淹格——若作者真点钉，会得到钉底连通区而非 POI，按第 3 条这是特性；③ Ctrl+右键在极少数右键有其他绑定的上下文（如选中工具的右键撤锚）由工具互斥天然隔离，无冲突。

**测试**：`crates/wv-app/src/edit/editing/tests.rs` +3（Ctrl+右键压图钉抓格 / 压群系区抓格 / 裸右键与图外不动）。

## 追记三：图钉交互闭环——拖动挪钉 + 双击属性（2026-10-27 用户指令）

**处境**：用户对选中后的图钉提出完整手势表：「POI，click 一下，选中地标。按着不妨，拖动设置新坐标，double click，弹出地标属性窗体，可以更改名字信息。」

**决策**：点选器手势闭环为三段——①单击选中（本 ADR 正文）；②**按住拖动** = 挪钉：4px 屏幕门槛内是单击、超出即激活拖动，预览位写在 `wv_render::state::PinDragState`（帧构建的点标/图钉与标签三处渲染读它做覆盖，**世界数据松手前不动**），松手一次性提交 `UpdatePlaceCommand`（可撤销，经 `update_place_now` 既有通道）；③**双击** = 选中 + 拉起 Inspector（地点表单的名字/呈现级别/锚点编辑全部现成，不另造窗体）——**仅 CellMap**，浏览族双击保留「下钻进城」（追记一的约定不破）。

**理由**：② 沿用 `BiomeBoundaryState`（拖线扫格、松手提交）确立的「会话态预览 + 单命令落账」手法，§3.3 零妥协；③ 「属性窗」的最小正确实现是复用统一 Inspector 的地点表单（已有名字文本框与锚点编辑），新造浮窗是重复建设。

**代价**：① 拖动预览要喂三处渲染（点标 / 图钉 / 标签），标签位置在 `update_place_labels` 加资源参数（该系统参数触 16 上限，呈现参数折成元组——仓内既有手法）；② 双击属性在浏览族缺席（双击已被下钻占用）——浏览族改名走 Inspector 手动打开，后续如需可在非 marker 图钉上放行；③ 双击检测自带 0.40s/6px 窗口（与下钻同数值），连击三次的第三击重新起算（drill 同口径）。

**测试**：`crates/wv-app/src/edit/editing/pin_drag.rs` +4（拖动提交含「松手前世界不动」/ 单击不提交 / 双击选中+拉面板+清态 / 预览助手纯函数）。
