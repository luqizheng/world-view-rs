# ADR-0049: 地物贴图通道——森林族走手绘图集，底图仍是程序化

- 状态：已接受（Accepted，2026-10-21，用户选定「贴图通道（image-gen 树图集）」路线）
- 范围：森林族（`DecorKind::Forest`）**已落地**；草 / 丘陵 / 山 / 雪 / 沼 / 沙 / 白波仍走程序化
- 关联：ADR-0031（地形装饰分层）、ADR-0039（cell 驱动变体）、ADR-0043（主题层抽 crate）、
  ADR-0048 追记二（`DecorRecipe` 抽取——本 ADR 在其上再加贴图槽位）、
  `ART_STYLE_SPEC_v0.1` §2.B / §3.4（`props_atlas`）与 §1.3（瓦片图集弃用）

## 处境

三件事同时成立，逼出一条决策：

1. **规格要求地物是图标**：`ART_STYLE_SPEC` §2.B 的 pack 目录里有 `props/props_atlas.png`，
   §3.4 明确「地物是**图标**，不是模型」，并给了符号尺寸档位与统一描线/投影规则。
2. **实现只有程序化图元**：`terrain_decor.rs` 把森林画成 3 颗 2.6px 圆（阔叶）/ 3 根细三角
   （针叶），且文件头写着「**不引入位图瓦片**（JRPG 图集已弃用；全部程序化三角化）」。
3. **用户要手绘地表树**：2026-10-21 要求「地图上需要一些覆盖物，如地表树木，可以通过
   image-gen 按需生成」，并选定贴图通道路线。

第 2 条的注释与第 1、3 条表面冲突，实际是把两类资产混为一谈了：

| 资产类 | 规格位置 | 现状 | 本 ADR |
|---|---|---|---|
| **底图瓦片图集**（每格地表纹理） | §3.2 `terrain_atlas` | **已弃用**（会淹没路线与地标） | **继续弃用**，底图仍由 `terrain_view::cells` 逐格程序化合成 |
| **地物 / 覆盖物符号**（树、山、城…） | §3.4 `props_atlas` | 只有 `Place` 地界走 PNG（`feature_overlays`） | **开通位图通道**，首个接入族 = 森林 |

## 决策

**D1 边界：位图只用于地物符号，不碰底图。**
`terrain_decor` 的职责不变（按栅格群系采样落位），变的只是「一个站点画成什么」：
有贴图 → 一个 UV quad；无贴图 → 原来的三角 / 圆。底图管线（`cells.rs` / `terrain_chunks`）
零改动。

**D2 契约：贴图属于主题，路径与格数进 `DecorRecipe`。**
新增 `wv-theme::decor::DecorArt { atlas: &'static str, cells: u8 }`，`DecorRecipe` 增
`forest_art: Option<DecorArt>`。日间 / 暮色两套配方各指各的图集（暮色必须浅墨版：
Bevy 材质 tint 是乘法，深墨乘浅色仍是深墨）。**格序是契约**：针叶 0 / 阔叶 1 / 稀树 2，
与 `DecorVariant` 一一对应。

**D3 运行时：UV quad + 纹理材质，缺资产回退程序化。**
- 每站点一个轴对齐 quad（4 顶点 / 6 索引），**底边锚定**在采样点（树根坐地）；
- 一个族一个 mesh、一个材质（`ColorMaterial { color: WHITE, texture, alpha_mode: Blend }`），
  仍满足 §3.6「禁止逐块独立材质」；
- 纹理句柄与材质跨帧缓存，键 = 图集路径；解码失败 / 未知键只 `warn!` 一次并回退程序化
  ——不 panic、不空帧；
- `DecorBatchKey` 增 `tex: Option<&'static str>`：换主题时顶点可能完全相同，只有图集变了，
  不把图集算进重建判据会继续用旧图。

**D4 资产与产线：image-gen 出图 → 脚本归一化 → 3 格横排图集。**
- 运行时资产：`crates/wv-render/assets/overlays/forest/decor_atlas_{day,dusk}.png`
  （384×128，3×128），`include_bytes!` 编译期嵌入（与 `feature_overlays` 同手法，不走
  `AssetServer`）；
- 生产：`scripts/build_decor_atlas.py`（涂白水印 → 白底键控 → bbox 底部居中 → 横向拼接，
  `--light` 出暮色浅墨版）；
- **提示词与复现步骤入档** `docs/theme/default/overlays.md`（提示词是唯一权威，
  重制时照抄，不凭记忆重写）。

## 理由

- **规格本来就这么要求**：`props_atlas` 是 pack 契约的一部分，本 ADR 只是把已存在的
  契约接上执行端，不是新发明风格。
- **树是最高频的覆盖物**：全图森林格远多于地界/POI，手绘树对观感的边际收益最大；
  其余族继续程序化，避免一次引入 8 张图集。
- **可替换性不破**：图集路径在主题配方里，换主题 = 换键；底图与界面壳都不受影响
  （ADR-0043 的「加新风格 = 加新 crate」仍成立）。
- **回退是硬的**：`Option` + 编译期嵌入 + 解码失败回退，三层保证「缺资产不崩、不空帧」。

## 代价

- **位图不能随主题调色**：tint 是乘法，一套墨色只能服务一套底色——所以日 / 暮必须
  两张图集，换色要重出图，不能只改配方。
- **格数固定 3**：加第 4 个变体要同时改 `DecorArt.cells`、图集、`forest_art_cell` 映射；
  契约面窄，但改起来是跨 crate 的。
- **首帧一次同步解码**（~68 KB PNG ×2）；解码在首次可见帧完成，之后走缓存。
- **两套树风格并存风险**：`feature_overlays` 仍用旧的 `tree_atlas_*`（淡彩）。若观感差异
  明显，后续应把两条通道合并到同一份图集（本 ADR 不做，避免一次改两处）。

## 被否决的备选

| 备选 | 为什么不做 |
|---|---|
| **A. 只强化程序化树形**（多瓣树冠、分层针叶） | 零资产零 ADR，但仍是矢量点阵，达不到「手绘地表」的观感；用户明确要 image-gen 产物 |
| **B. 直接复用 `feature_overlays` 的 `tree_atlas_*`** | 能立刻出效果，但把地界覆盖物与地表装饰绑成同一份资产：改一处影响两处，且那批图是按 128px 淡彩设计的，小尺寸偏糊 |
| **C. 整幅地形瓦片图集**（每格一张 32px 地表） | 早已被否决（ADR-0031 前史 / 规格 §1.3）：饱和纹理碎会淹没路线与地标，且资产量 ×40 |
| **D. 贴图放渲染层常量表、不进主题** | 少一次跨 crate 改动，但违反 ADR-0043「风格是内容不是机制」——第三方主题包将无法自带树图集 |

## 后续

- 其余七族（草 / 丘 / 山 / 雪 / 沼 / 沙 / 白波）是否也走贴图，按「观感收益 ÷ 资产成本」
  逐个评估；山的优先级最高（§3.4 的 11 类地物符号里山体尚无手绘版本）。
- 两套树图集（地界 / 地表）合并为一份，作为独立小任务。
- 图集加变体（第 4 格）时，需同步改 `DecorArt.cells`、`forest_art_cell` 与本文 D2。
