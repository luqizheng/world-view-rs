# ADR-0005：相遇检测与「未写事件」提示

- **状态**：已接受（Accepted）
- **日期**：2026-10-11
- **影响**：wv-core（新增 `encounter` 模块）、wv-io（新增 `diagnostics` 模块）、基线 §2.21
- **相关**：ADR-0004（Unit 本体）、AGENTS §7.5（校验不是闸门）

---

## 用户原话（唯一权威规格）

> 「他们独立地在地图上移动，再某一刻相遇发生的事情叫做事件，如果他们相遇，但是没有事情发生，那么就是啥事都没有。」

> 「例如男女主角再某地相遇，本应该发生什么，作者故意没写。后期安排再相遇，然后安排促进感情的内容就可以提及此地。」

---

## 背景与问题

ADR-0004 确立了 `Unit`（在地图上独立运动的主体）与「相遇 → 事件」的关系，但**只做了本体**（`Unit` 实体 + `Track.unit`），没有回答一个问题：

**工具怎么知道「他们相遇了，但作者没写事件」？**

这不是伪需求——用户的第二段话说明了场景：作者**故意**让男女主角在某地相遇而不写任何事件，作为后续推进感情线的伏笔。这个伏笔需要被工具：

1. **提示**（作者可能忘了此处有相遇）
2. **可回访**（后期回来时能重新找到「此地」）

ADR-0004 §待裁 U4 记录了「相遇提示的呈现形态」未定，本 ADR 闭合该项。

### 若不决策会怎样

「提示」有两种截然不同的实现，理解错了会直接违背用户意图：

- ❌ **弹窗报错**——作者每次遇到伏笔点都被告知「你漏写了事件」，无法保存、无法忽略 → 工具变成负担，作者会关闭校验。
- ✅ **提示 + 可回访**——作者看到「此处相遇未写事件」，可以立刻写事件、也可以标记「这是伏笔，知道了」，后期能重新翻到。

前者违背 AGENTS §7.5 V1（校验只提示不阻止），后者才是本 ADR 的内容。

---

## 决策

### （1）相遇是**派生数据**，不建实体

**决定**：相遇 = 两条轨迹时空交叉的**计算结果**，不落盘为任何实体。

**理由**：相遇是「两条轨迹的交集」，不是「作者写的东西」。落盘会产生两个真相——轨迹改了，相遇记录不会跟着改。派生即自动正确。

**代价**：每次校验都要重算。O(单位对数 × 锚点数)，对史实规模（数百轨迹）完全可接受。

### （2）判定 = 三道门，全过才提示

```
判定一 · 时间重叠    两条轨迹同一天都在场
判定二 · 空间贴近    同地点，或距离 ≤ 阈值
判定三 · 未被覆盖    该时空没有事件记录
```

**跨地图轨迹直接跳过**（`ta.map != tb.map`）：坐标系不可比（ADR-0003 规定跨图靠 `PlaceId` 串联，不靠坐标）。

**已被事件覆盖则不提示**——这是本 ADR 最重要的一条。判定口径是**宽进严出**：

- 相遇处**有事件**（`span` 重叠 + `place` 相同）→ 已覆盖，静默。
- 相遇无显式 `place` 时只比时间，不做坐标比对。

> **为什么宁可漏不可扰**：误报代价（作者养成忽略提示）远高于漏报代价（少提醒一次）。

### （3）候选日用 waypoint 锚点，**不逐日枚举**

**决定**：候选日 = 轨迹 A 的**带 `day` 的 waypoint**，且落在轨迹 B 的 `span` 内。

**理由**：`day` 是天数计数器。逐日枚举在跨千年的史实（用户示例：康熙 1654-1722）会**卡死**。锚点法与时间跨度无关，且**同样精确**——因为锚点就是轨迹确切存在的位置。

**代价**：无 `day` 的顺序点（T2 规则）不参与判定。已在模块文档与 `Track::sample_at` 中说明。

### （4）指纹**不含日期**——这是「可回访」的技术前提

**决定**：`fingerprint = {unit_a}|{unit_b}|{place}`，单位 ID 按字典序归并，**不含日期**。

**理由**：如果指纹含日期——

- 两条轨迹在同一地停留三天 → 生成**三条**提示（刷屏）；
- 作者微调一个锚点日期 → **全部提示的 ID 全变** → 无法「认领」。

日期是「这次相遇持续多久」，不是「这是哪一次相遇」。因此按**「谁在哪相遇」归并**，日期取交集区间。

**回访路径**：校验面板按 `place` 分组列出全部相遇提示 → 点击 → 通过 `DiagAnchor { map, at, day }` 跳到地图坐标并拨动时间轴。

### （5）提示与错误在**类型层面**分开

**决定**：新增 `wv_io::diagnostics` 模块，`DiagLevel::{Hint, Error}`。

| | `Project::validate()` | `Project::diagnose()` |
|---|---|---|
| 悬空引用 | 返回 `Err`（硬失败）| 记为 `Error` 条目 |
| 相遇未写事件 | 不产出 | 记为 `Hint` 条目 + 定位锚点 |
| 能否保存 | 有错误则不能 | **只要无 Error 级就能存** |

**理由**：AGENTS §7.5 V1 要求「校验只提示、不阻止」，但 `validate()` 的 `Err` 语义天然是硬阻断。混在一个 `Vec<String>` 里，UI 无法可靠地「只显示提示、不拦保存」，也无法给提示做跳转定位。

**`HintSeverity` 只有一级**——「相遇未写事件」**永远不是错误**。保留 enum 而非单元结构，是为了让 UI 将来过滤/分组有据可依。

## 被否决的备选方案

| 方案 | 否决理由 |
|---|---|
| **显式 `Encounter` 实体**（作者手标「某日某地谁遇到谁」）| 用户裁定「相遇」是**派生**的（由轨迹交叉得出），不是作者标注的。且它与 P4「派生不落盘」冲突 |
| **弹窗报错** | 直接违背 AGENTS §7.5 V1。作者要能随便改、留白是创作手段 |
| **逐日枚举做时空交叉** | 跨千年史实会卡死。作者示例「康熙帝 1654-1722」正是 68 年 × 365 天 |
| **指纹含日期** | 无法认领；停留多日则刷屏 |
| **复用 `validate()` 返回 `Vec<String>`** | 提示与错误无法区分，UI 不能「只提示不阻止」 |
| **跳过判定三（不做「已被覆盖」检查）** | 大量误报——作者写了事件仍被提示，是最扰民的情形 |

## 代价与后果

### 正面

- 伏笔类创作（有意留白）被工具**保护**而非惩罚——提示文案明确说「若为有意留白可忽略」。
- 提示可回访、可定位（地图坐标 + 时间）。
- 零新增落盘格式——`schema_version` 不变，不需要迁移。
- `World` 聚合不变——诊断纯派生，不影响 YAML round-trip。

### 负面

- 每次校验 O(单位对数 × 锚点数)，不是 O(1)。
- 顺序点（T2）不参与相遇判定，可能漏报。
- 空间贴近阈值硬编码 `PROXIMITY = 1.0`（见待裁 H2）。
- 「已被覆盖」的判定在相遇无显式 `place` 时退化（只比时间）。

### Schema 版本处置

**不变**（仍为 v2）。全部新增项都是：
- `Event.narrative` / `Character.died_at` —— `#[serde(default)]` + `skip_serializing_if`，旧文件照常读。
- `encounter` / `diagnostics` 模块 —— 纯计算，不落盘。

与 §2.16 「schema 1→2 不做自动迁移」同源：**不为假设的将来付现在的成本**。

## 待裁（本 ADR 未闭合项，**不得据以实现**）

| # | 待裁项 | 现状 / 倾向 |
|---|---|---|
| **H1** | 相遇的时间粒度（day / 时 / 更细）| 现为 day，与 `TimePoint` 一致。若将来事件需小时粒度，相遇检测须同步细化 |
| **H2** | 空间贴近阈值 `PROXIMITY` | 现硬编码 `1.0`。**倾向随地图缩放级别自适应**（格 / 世界坐标 / 屏幕像素三套阈值），否则大地图上相邻两地会被误判相遇 |
| **H3** | 「作者已知悉」的标记存储 | 现**不做**。提示靠 `fingerprint` 稳定可认领；若将来要做「我知道了」的持久标记，需决定存 YAML 还是编辑状态 |
| **H4** | 跨地图相遇（同一地点 ID 但不同图）| 现**不判定**。ADR-0003 允许靠 `PlaceId` 层级跨图串联，相遇是否也该如此，待定 |
| **H5** | 加载期硬失败 vs 编辑期软提示是否统一 | `validate()` 硬失败、`diagnose()` 软提示并存。是否应收敛为同一强度，待定 |
