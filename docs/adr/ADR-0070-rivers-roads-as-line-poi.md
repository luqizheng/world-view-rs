# ADR-0070: 河流与道路=线段 POI——群系退役、起终点算法、线即路网

> **状态**：已接受（Accepted，2026-10-26 用户批准设计稿裁定「go」；实施计划见 `docs/superpowers/plans/2026-10-26-river-road-poi.md`）
> **日期**：2026-10-26
> **决策者**：用户（D1–D5 逐轮拍板）；助手裁量清单见设计稿 §5
> **关联**：**取代 ADR-0037 D5**（河流=rivers_seed 派生数据）；**修订 ADR-0046**（双供给收敛为单供给，正文不改、以本 ADR 为准）；**修订 ADR-0054 §1.1-1**（cell map 职责措辞中「河流」移出）；沿用不破：ADR-0030 / ADR-0047（rank × 档位体系）、ADR-0052 / 0057 / 0058（CellMap 编辑与统一属性表单生态）、ADR-0064（`Place.kind` 点分类——线判别另开 `LineKind` 不混载）；设计稿：`docs/superpowers/specs/2026-10-26-river-road-poi-design.md`

## 1. 处境（Context）

作者在 cell-map 涂河流/道路时体会到线性地物与面状群系的语义错位：格子分辨率撑不住
线状物（远看一格一格、拐弯生硬），且河/路在数据里同时活在三个地方——涂格群系
（编号 16 归 `BiomeFamily::Water`、20 归 `BiomeFamily::Road`，`wv-terrain/biome.rs`）、
`rivers_seed` 每帧程序派生（ADR-0037 D5，仅模板世界）、作者 `Place.line` 手绘河
（ADR-0046，双供给）。道路另有第四处：`distances/edges.yaml` 的 PlaceEdge 路网
（导入与逻辑连接共用，渲染按 ADR-0047 D4 rank 三档切割）。

作者裁定：**河/路是 POI 的一种，在 edit 区画，不在 cell-map 涂**；河流要一套
「钉起终点 → 算法出路径」的算法（绕行或下切成河谷）；道路与行程计算**全量统一**
为线（选项 C：线即路网，边由线推导）。

## 2. 决策（Decision）

| # | 决策 |
|---|---|
| **D1 群系退役** | 编号 16（河）/ 20（路）退出可涂集合；编号保留不复用（开放集既有约定）；cell-map 只管「地形 + 面状群系」。存量涂格一次性转换（16→`SURFACE_WATER`、20→`BIOME_NONE`）+ 诊断计数，不自动骨架化成线 |
| **D2 线段 POI 模型** | 河/路 = `Place.line` 中心线（图内局部 wu，ADR-0046 约定沿用）+ 新增可选字段 `line_kind: Option<LineKind{River,Road}>`（缺省=River，ADR-0046 存量零迁移）与 `line_width_m: Option<f32>`（河=河口基准宽；路按 rank 折算不落盘）。不新开 `rivers/` 集合（ADR-0046 已裁先例） |
| **D3 起终点算法** | 作者钉起点/终点，wv-terrain 新模块 `line_path` 在高度场上 A* 出折线。两模式：**绕行**（默认；上坡重罚 + 确定性蜿蜒噪声，贴谷绕山）与**强制改变地形**（近直连 + 下切：河复用 `apply_river`（含 `SURFACE_WATER`），路压平走廊**不写水面**）。**折线即为准**：生成后可拖顶点微调不自动重算；下切一次性，重拖/延伸后旧下切保留。模板/RegenWorld 自动河统一走本算法落实体，`rivers_seed` 每帧派生管线删除 |
| **D4 入口与面板** | 地图工具条加**线段 POI** 按钮（Lucide `route`，仅 Edit 浏览档出现）→「道路/河流」二选一 → **河流和道路面板**（一浮窗两段设置，兼任新建设置与选中属性编辑，ADR-0058 统一属性表单先例）。河段：名字/宽度/模式；路段：名字/级别（rank）/模式（与河同款，默认绕行）。渲染宽度：河=**锥形**（源头≈基准 30%→河口=基准，弧长插值）；路=按级别描画。存量编辑：拖端点延伸（续算路径，下切只作用新增段）、端点吸附目标河成**汇流**（v1 仅几何重合） |
| **D5 线即路网** | 陆路 PlaceEdge **不再手存**：路 `Place.line` 两端容差吸附 Place → 运行时推导边（`distance_km`=线长÷`unit_per_km`、`terrain="road"`、rank 继承），**不落盘**——推导边注入 `World.distances.edges` 带 serde-skip derived 标记（消费者零改动、round-trip 不变；同端点对已有手写边则不推导）；路缺省 rank 沿用 PlaceEdge 公里折算表（显隐零回归）；无 `unit_per_km` 跳过推导+诊断。行程计算照旧 `DistanceGraph::segment_days`。非道路连接（`terrain!="road"` 的海路/抽象边）原地保留手存。存量迁移：`edges.yaml` 中道路边**链式合并**（仅穿 2 度顶点串长线，≥3 度路口为线端点，拓扑无损；2 度中间节点保留不删），落 `Place.line`（Road）；迁移加载时自动跑、链 ID 确定性幂等、转线与移除边同命令进 History，诊断列计数 |

## 3. 理由（Rationale）

- **语义对齐**：群系是面分类，河/路是线性地物——放 POI（`Place.line`）才是对的容器；
  ADR-0046 已验证该容器可承载作者线且渲染通路现成（`author_river_polylines` 池）。
- **单一事实源**：三河源收敛为一（`Place.line` 实体），消除「派生 ∪ 作者」双供给的
  两世界并存；道路同理，线即真相、边是投影——与「YAML 是 source of truth，其余是
  投影」的总纪律同构。
- **P6/P7 干净**：折线为准（作者意志落盘）、下切一次性进 History（可撤销）、推导边
  纯运行时（`distance_km` 从几何换算，不固化结论——AGENTS §4.2「距离只存参数」的
  几何化身）。
- **作者体验**：钉两点出一条河（绕行/下切两性格）远优于逐格涂抹；存量路网链式合并
  后从 8.4 万边收敛为千量级长路，可选中、可改名、可改级别。

## 4. 代价（Consequences）

- 推翻 ADR-0037 D5 的派生河管线（`river_polylines` 每帧推导、模板河重抽即变）——
  换来实体可编辑；RegenWorld 重建这批实体（重生成仍一键）。
- `edges.yaml` 语义收窄为非道路连接 + 推导容器；导入器（Overture 路网）后续产线
  而非边（迁移期兼容旧工程）。
- 迁移是破坏性整理（涂格转换、边合并）——靠单条 History 条目 + 诊断计数兜底；
  涂格 16 转 `SURFACE_WATER` 后不再有「涂出来的河」，需重画为线（诊断提示）。
- 测试面扩大：A* 算法、链式合并、推导边换算、迁移计数各有手算 fixture 门槛
  （AGENTS §7.2）。

**被否决的备选**：

| 备选 | 否决理由 |
|---|---|
| 河流三源并存（维持 ADR-0046 双供给，仅删涂格） | 河仍活在两个世界，与「河是 POI」定位相拧 |
| 派生河「生成即落盘」独立成案（第 4 轮选项 B 单独做） | 被 D3 吸收：统一为「生成器调用同一算法落实体」，少一条特设管线 |
| 手画路纯视觉不接行程（选项 A） | 看得见走不通，作者困惑 |
| PlaceEdge 保持手存、线只做视觉层 | 两套真相源，P4/§4.2 纪律破口 |
| 涂格河自动骨架化转线 | 细化算法复杂度不值，诊断 + 重画更诚实 |
| `PoiKind` 扩 `River`/`Road` 变体 | 点分类（ADR-0046 语义：kind 说「点代表什么」）与线判别混载；另开 `LineKind` 正交 |
| 新开 `rivers/` 独立集合 | ADR-0046 D2 已裁（untagged 坑 + 语义稀释），沿用其结论 |
