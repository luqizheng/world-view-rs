# ADR-0105: 世界图局部加密裁定——边缘带自动子图（DF 式）

- 状态：已接受（2026-11-06，用户在 README §12-55 三候选中拍板 (c)。〔2026-11-11 追记〕原稿因工程目录迁移（worldview-rs → world-view-rs）丢失且未提交，本稿按会话档案原样重写，裁定内容不变）
- 关联：README §12-55（本 ADR 的待裁来源，随本 ADR 关闭）、GLOSSARY「局部加密 / 边缘带」、ADR-0009（分级缩放：子图自带 raster + `Extent.origin`，路线 (c) 的地基）、ADR-0038（钻入图标——子图进出交互）、ADR-0088（分块指纹——父图↔子图过期同步的现成词汇表）、ADR-0103（呈现档位与数据分辨率解耦，城市图 Nation 档解锁）、ADR-0046（亚格线状矢量先例）、ADR-0099（HTTP 地形写面，自动生成子图可脚本化）、`docs/pending.md` 条目 24 / 47（同族待裁）

## 处境

世界尺度地图若以单一稠密格网承载，「分辨率 × 体积」互斥（4000×2000 km @100 m/格 ≈ 8 亿格、@12.5 m ≈ 512 亿格）——业界无一例用单一张表承载世界，标准解法是分层（LOD 金字塔 / 嵌套网格 / 区域细化 / 稠密-矢量混合）。本项目数据真源为「每图一张全域单一分辨率稠密表」（`World.terrains` 行优先 Vec + terrain.bin v2），**跨图**变分辨率已在产（P4 子图自带 raster + `wv raster-slice`），**图内**变分辨率机制不存在；且全链共享「全域单一均匀格网」前提七处（`TerrainData`/`TerrainGrid`、terrain.bin v2、EditCell/PaintTerrain 命令族、FieldPack 三纹理、`coast_sdf`/`biome_sdf`、256² 分块指纹、`patch_region`「局部重算=全量重算」契约）——2026-11-06 复核确认七处原样在位，另有四处跟随项（`AddRidgeDetailCommand`、`ReplaceFactionFacesCommand`、HTTP 写面、isoline 读数层）。

实际痛点并非「根图不够细」，而是**群系边缘带**（GLOSSARY 口径：距 `coast_sdf`/`biome_sdf` d≈0 等值线 N 格的带状区——海岸线、草原边缘等）在粗格下的**数据/编辑粒度不足**；观感台阶已由 `biome_sdf` smoothstep 亚格过渡部分缓解，那条管观感、本裁定管数据。README §12-55 列三候选：(a) 图内嵌套寻址（quadtree patch）；(b) 粗底+细化补丁叠加；(c) DF 式边缘带自动子图。

## 决策

选 **(c) 边缘带自动子图**：

1. **不动 CellMap 数据模型**——上述七前提与四处跟随项全部保持；不引入 terrain.bin v3、不做图内层级寻址。世界根图永远粗格（按 Nation 档一屏密度定尺寸），细节全在子图。
2. 系统在**边缘带**自动生成/维护**细化子图**（Dwarf Fortress「世界粗格 + 局部细格」拓扑），复用 P4 子图机制：`raster-slice` 切片逻辑建栅格、`resolve_frame` 坐标链挂父图、ADR-0038 钻入图标进出。
3. **父图↔子图失效同步**用 ADR-0088 分块指纹做过期检测：父图边缘带脏块 → 关联子图标脏 → 提示/自动重切（实施期细化）。
4. 原 §12-55 五个待裁点处置：① 裁定 (c)；② 边缘带=候选区口径，采纳；③「图内 T-junction/距离场跨界」随 (a)(b) 否决而**消解**，问题转化为「父图↔子图失效同步」（决策 3）；④ 存储**不需要 v3**（子图各一张 raster，走既有 RasterRef + `docs/BINARY_FORMAT_SPEC.md`），关闭；⑤ 编辑走现有命令族在子图内进行，混合分辨率命中问题消解，关闭。

## 理由

1. **问题形状匹配**：需求是局部、带状、稀疏的边缘带细节，子图就是现成的「局部加密补丁」——坐标帧、钻入、渲染、编辑全链路已在产；(a)/(b) 要新造的核心件（层级寻址 + 跨界语义）(c) 天然不需要。
2. **待裁纪律（AGENTS §12）**：收敛前选最容易回退的方案。(c) 是纯增量层，失败即拆，数据模型零承诺。
3. **数学够用**：根图按 Nation 档密度定格（百万格量级）无体积问题，缺的只是边缘带细节。
4. **不堵死升级**：(c) 跑通后暴露真痛点可平滑升 (b)（子图降格为图内 patch）；反之先做 (a)/(b) 是为尚未证明的「无缝图内缩放编辑」需求预付 v3 成本。
5. 顺风件：ADR-0103 已把呈现档位与数据分辨率解耦（钻入后的档位语义在小图上可用）；ADR-0099 HTTP 写面使「边缘带自动生成子图」可脚本化。

## 代价 + 被否决的备选

**代价**

1. **钻入不是无缝缩放**：作者跨粗/细边界作画要经过子图进出（ADR-0038 图标钻入语义），存在断点感。
2. **父图↔子图失效同步是新代码**：生成/维护/过期提示的生命周期管理全部待实施（检测词汇表 ADR-0088 已在）。
3. **世界根图自身的精度上限仍在**（`docs/pending.md` 条目 24 同族）：根图永远粗格，精细表达只在子图内成立。
4. 边缘带宽度 N、子图栅格分辨率等参数未定，属实施期调参，不回退本裁定。

**被否决的备选**

- **(a) 图内嵌套寻址（quadtree patch）**：七前提一次性重构 ≈ terrain.bin v3 + 寻址 API 改造，代价最大，且为「通用 AMR 能力」预付——目前没有任何需求超出边缘带。
- **(b) 粗底+细化补丁叠加**：仍需动存储/命令/跨界语义（T-junction 采样规则、距离场「局部重算=全量重算」契约跨界维持），硬骨头在动工前就要啃；作升级路径保留。

**升级触发条件**：当「作者频繁进出边缘带子图、断点感成为实际抱怨」时，新开 terrain.bin v3 ADR 升 (b)；(a) 的层级寻址仅在 (b) 也被证明不足时再议。

## 落地范围（实施另行立项排期，不在本 ADR 内）

边缘带检测（消费现成 `coast_sdf`/`biome_sdf` 距离场）→ 自动建子图（`raster-slice` 逻辑 + 钻入图标）→ 失效同步（分块指纹）→ 编辑闭环（现有命令族）。每步独立可 revert。
