## 1. 处境（Context）

工程当前 UI 文案**唯一语言**为简体中文：241 处硬编码中文字面量散落 22 个文件
（`crates/wv-app/src/ui/` + `render/` 子树 + `state.rs` + `ui_time.rs` +
`ui_command_palette.rs` + `main.rs` / `overture_cli.rs` + `http/` 的 user-facing prose）。
字体栈已就绪（`theme/fonts.rs`）——CJK 注册到位，但 GUI 启动后任何位置都无法切到英语。

工程**不存在任何 i18n 基础设施**：无 `fluent` / `unic-langid` / `phf` /
`sys-locale` 依赖；无 `tr!` / `T!` / `localize` 宏。`icu_provider` 已声明为
`optional` 依赖，但仅作 logging shim 用（`wv-app/Cargo.toml` 注释）：
> 启该 feature（已在依赖树内，无新二进制）让告警走 `log` facade，
> 由 gui.rs 的 LogPlugin filter（icu_provider=off）静默。

并不参与文本查表。

**与既有约束的张力**：
- **AGENTS §1 P2「目录即工程」**——禁止把状态写进 AppData / 注册表 /
  XDG 等 OS 全局位置。但 `crates/wv-app/src/state.rs:1014-1027`
  `RecentProjects` 注释原文已显式承诺「不当 P2 的口子」，
  主动把「最近工程」列表锁在会话内。
  工程内**唯一**合规的偏好落盘点是
  `<project_dir>/ui-layout.yaml`（由 `ui_layout.rs:78-98` 维护），
  作者手写友好且可选纳入版本控制（`ui_layout.rs:13-15` 注释）。
- **AGENTS §9 默认拒绝新依赖**——除非 (1) 不引入渲染/网络/异步到数据层
  （i18n 在 `wv-app` 渲染层，安全），(2) 标准库 / 现有依赖有等价物，
  (3) 不破 YAML round-trip。

## 2. 决策（Decision）

1. **手写键查表引擎**。新增 `crates/wv-app/src/i18n/` 模块：
   - `Locale` 枚举（`Zh` / `En`，`Default = Zh`）；
   - `I18nKey` 枚举（按面板 / 层分组的 `// —— 段名 ——` 段；预计 80–110 个变体）；
   - `t(locale, key) -> &'static str` 与 `t_key(&CurrentLocale, key) -> &'static str`；
   - `table` 私有模块：两个 `pub(crate) fn lookup_xxx(I18nKey) -> &'static str` 用 `match` 覆盖所有变体；
   - `CurrentLocale(pub Locale)` 派生 `Resource`，在 `app_bootstrap::run` 的现有 init 列表里 `.init_resource::<CurrentLocale>()` 一并初始化（默认 `Zh`，与现行唯一语言一致）。
2. **持久化复用 `ui-layout.yaml`**。给 `LayoutFile` 加
   `#[serde(default)] pub language: Option<String>` 字段——
   与现有 `theme` / `density` / `map_theme` 同口径
   （snake_case、`#[serde(default)]`、缺字段 / 字段无法解析静默忽略，与 V1 守约对齐）。
   `ui_shell::load_map_theme_on_project_open` 重命名为 `load_layout_on_project_open`，
   解析 `file.language` 后灌进 `ResMut<CurrentLocale>`；`persist_layout_on_change`
   diff 比对 `file.language` 与 `current_loc.0.as_str()`，不一致则置 `changed = true` 触发落盘。
3. **不引入插值**。`t(locale, key)` 直返 `&'static str`；调用点要拼参数时自行 `format!`。
   理由：241 处文案皆为短标签 / 一短句，**无复数 / 性别 / 计数 / 选择变体**；
   强行引入 Fluent ICU MessageFormat 会从「无依赖」滑向「3 个新依赖 + FTL 文件 + 启动成本」。
4. **不变更字体装配**。CJK 字体已在 `PreUpdate` 注一次
   （`fonts.rs:81-165`），egui 字体回退栈天然能「Latin 主、CJK 兜底」——
   不含 CJK 的 Latin 文本不会触发 CJK fallback，**EN 用户无副作用**。
   不新增 locale-aware 的字体切换接口。
5. **CLI（`wv` / `wv overture`）输出纳入 i18n**（Q2 拍板）。
6. **HTTP/MCP skill 文案范围：仅 Claude Desktop 可见文字纳入 i18n**（Q1 拍板）。
   LLM 协议字段（`run summary` 等纯 JSON 字符串）保留常量，
   不让 LLM 提示上下文随用户语言漂移，
   避免对提示工程（prompt engineering）的稳定性造成不必要冲击。

## 3. 理由（Rationale）

1. **引擎选择 — 手写键查表的最小化立场**。
   - 241 处文案平均长度 < 12 汉字 / < 9 词；ICU MessageFormat 处理不了的语义
     都用 `format!` 在调用点兜底。
   - AGENTS §9 的「默认拒绝」立场直接否决 Fluent（3 个依赖 + 编译期膨胀）。
   - 缺非工程师翻译参与 v1 时无 FTL 文件必要——表就在 `table.rs` 里，
     提 PR 时 diff 友好（diff 看得懂谁改了哪条文案）。
2. **持久化复用 `ui-layout.yaml` 是 P2 唯一出口**。
   - `state.rs:1014-1027` 注释明确承诺不擅自开 P2 口子；
     `RecentProjects` 都压着不动，本 ADR 自然沿用同条约束。
   - `ui_layout.rs:7-22` 注释已写明「只写 UI 偏好、不写世界数据」——
     新增 `language` 字段完全属此范畴，无字段越界。
   - 字段兼容零代价：现有 4 个字段都 `#[serde(default)]`，新字段同口径——
     双向兼容（新老 yaml / 新老代码组合均加载成功）。
3. **可回退性**（AGENTS §12 守约）。
   - 切换语言是 O(1)：`ResMut<CurrentLocale>` 一个字段；落盘是 O(1)。
   - 整个 i18n 模块**完全在 `#[cfg(feature = "app")]` 下**——
     `cargo test --workspace`（默认 features）不编译，等价于「未引入」，
     与现有 `theme` / `ui` / `render` 模块守约一致。
4. **范围裁定的一致性**（Q1 / Q2 拍板依据）。
   - Claude Desktop 「问什么 + 返回什么」字面是 LLM 体验 → 用户可见 → 跟随语言。
   - LLM 协议字段是 LLM 推理的稳定输入 → 与语言无关 → 保持常量。
     例：`run_summary: "Read map 'foo', 3 layers, ok."` 这种纯 ASCII 摘要
     在双语下保持相同，LLM 推断行为不变。
   - CLI 面向开发者 → 跟随语言；`--help` 不另作特殊处理（统一随语言切换）。
5. **不动字体**。egui 字体回退栈已经在两条路径上都工作——CJK 注册是「可选全局备用」，
   不让 EN 用户付出代价，但也不让 ZH 用户失去既有行为。
   引入 locale-aware 字体 = 多一个 system + 一处状态 = 把字体探测从 0 耦合变 1 耦合，
   不划算。

## 4. 代价（Consequences）与被否决的备选

### 4.1 代价（必须承认）

1. **新增语言的成本线性**：要让日语 / 韩语参与，每条文案都需手动扩
   `lookup_zh` / `lookup_en` / `lookup_ja` 三个 match 分支。
   不过 v1 表内 ~100 变体，全语言一次补完 ~2 小时内可投产。
2. **i18n 与 FTL 文件不兼容**——当文本真的需要复数 / 选择变量 / 上下文变体
   （如英文 "1 layer" vs "3 layers"），按字面字符串平移会失败。
   按 ADR 流程届时新开 ADR-N+1 引入 Fluent，
   `t()` 签名同步改为 FTL key 字符串，迁移面在调用点已经分散、可控。
3. **顶栏切换器位置受 UI 演进影响**：当前挂在「已选：…」与「?」帮助之间
   （ADR-0016 顶栏三区结构中的右侧区段）。后续若顶栏三区重构，
   切换器随右侧内容一同迁移（变更面可控、单一区段）。
4. **CLI `--help` 行为改变**：旧用户可能习惯中文输出，新装英文环境后阅读不便
   ——这是「跟随语言」的固有代价，按 §10 Q2 拍板承担。
5. **L1 / L2 文案体系尚未引入**：v1 仍是单一固定文案；
   Theme Pack / Style Pack 设计若要支持「主题自带文案」（古风 vs 现代），
   留待后续 ADR。本 ADR 不为该方向埋点。

### 4.2 被否决的备选（按推荐度倒序）

| # | 备选 | 否决理由 |
|---|---|---|
| A | sys-locale crate + OS 自动探测（无显式切换） | 用户在「随工程持久化」问题上已明确选择「保存每次选择」；自动探测仅在空编辑器（无 ui-layout.yaml）时兜底，不单独做事 |
| B | 全局 XDG / AppData 落盘 | 违反 P2（AGENTS §1）；`state.rs:1014-1027` 注释明确承诺不开口子 |
| C | 自增 int ID 替代 `I18nKey` enum | 违反 AGENTS §4.4 精神（ID 应当可读、可手工引用）；diff 难读；enum 编译期保证完整性 |
| D | Mozilla Fluent (`fluent-bundle` + `unic-langid` + `fluent-syntax`) | 违反 §9 默认拒绝；FTL 文件对 v1 是过度工程；241 变体平均 12 字符纯文本无 ICU 选择变量需求 |
| E | 在进程内 fork 一个独立 `wv-i18n` crate | i18n 是渲染层辅助设施，不是数据模型叶子（§2.1）；唯一外部接口是 `pub fn t()`，fork 出 crate 仅增加构建图复杂度，无架构收益 |
