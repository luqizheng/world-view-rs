# ADR-0004：单位本体（Unit）——运动归于单位，事态只是归纳容器

- **状态**：已接受（Accepted）
- **日期**：2026-10-11
- **决策者**：用户裁定 **Q1 = 甲 / Q2 = 乙 / Q3 / P1 / P2 / P3**（2026-10-11，见下方「用户原话」）
- **关联**：`docs/MAP_EDITOR_BASELINE_v1.md` §1.1、§1.5、**§1.6（本 ADR 修正其原口径）**、§2.7、§2.8、§2.9、§2.21、§5.1；`AGENTS.md` §1 P4/P6/P7、§6.1（术语即时登记）、§7.2 / §7.5（校验不是闸门）；**ADR-0002**（事态本体，本 ADR 修正其 Q4 的答案）、**ADR-0003**（跨地图引用）

---

## 用户原话（唯一权威规格）

> 「新增实体用于地图上，你复杂取名字，暂时我叫 Unit。他们独立地在地图上移动，再某一刻相遇发生的事情叫做事件，如果他们相遇，但是没有事情发生，那么就是啥事都没有。Situation 更像是 group，把这一系列归纳位一起。如果地图放大，可以看到发生过程，如果地图缩小，那么就显示【四渡赤水】正在发生，然后大地图上也可以看到其他正在发生的事情。同样地人物视图下的，假设康熙帝在位那么就显示 康熙帝(1654-1722）。」

> 「q1 甲。Q2：乙(警告，说明他们相遇，但是你没有写事件，例如男女主角再某地相遇，本应该发生什么，作者故意没写。后期安排再相遇，然后安排促进感情的内容就可以提及此地)，Q3：Situation 就是要给 parent，它包含了 多个 Event，多个 Unit，Unit 可以包括多个角色，如红一军中的领导人物，他只是把一堆 event、人物、unit 进行归纳。event 更像是一个描述过程，如他们相见发生什么，结果是什么。」

> 「这个软件即使定位网文/游戏工作者/历史爱好者，协助工具。帮助他们整理世界的关键人物/地理/事件/关系信息。**所以他们可以随便改的**」

---

## 背景与问题

ADR-0002 落定「事态」本体时，把「**谁怎么动**」记在了**事态节点**上（基线 §1.6 原口径：`Track.owner: Id`，注释写作「角色或势力」）。该口径在随后的讨论中暴露出三个问题：

| # | 问题 | 具体表现 |
|---|---|---|
| **P1** | 「一条运动横跨多个事态节点，归谁？」 | 作者写「土城 → 扎西 → 遵义」是**一段连续行军**，却横跨「一渡」「二渡」两个节点。§1.6 的「挂在节点上」没有答案 |
| **P2** | 「谁在动」含糊 | `Track.owner: Id` 注释写「角色或势力」，但**一支军队（如「中央红军」）两者都不是**；`Character` 是「人」，不是「在地图上移动的主体」 |
| **P3** | 事态到底是不是**拥有**运动 | §1.6 主张「轨迹挂在事态节点上」，并用「防止同一段运动在多事态间复制」作为论据——但该论据只成立于**把运动内联进事态**的写法 |

**用户的说明把这三条一次解决**：引入了「在地图上独立移动」的实体（Unit），并明确 **`Situation` 是 group**（归纳容器）——于是「归谁」这个问题**从根上消失**：运动归**它自己**（Unit），事态只**引用**。

### 若不决策会怎样

- 作者不得不为**同一段行军**在多个节点重复输入 waypoint（违反 P4「不复制」的精神，也违反「别为难作者」的定位）；
- 或者强行把跨节点的运动塞进某一个节点，使另一个节点的播放**看不出队伍怎么来的**；
- `Track.owner` 继续承担「角色或势力」这种**二义**语义，任何校验都只能保持宽松（现状代码即如此：`owner` 校验被显式跳过）。

---

## 决策

### （1）新增「单位（Unit）」作为独立顶层实体

| 项 | 值 |
|---|---|
| 中文名 | **单位** |
| 英文名 | **Unit** |
| 代码 ID 前缀 | `unit_` |
| YAML 路径 | `units/<id>.yaml`（与 `characters/`、`tracks/` 平行） |
| 所属维度 | 事件 / 距离 |
| 依据 | 用户裁定 **Q1 = 甲** |

```rust
pub struct Unit {
    pub id: Id,
    pub name: String,
    /// 归属主体（角色或势力）。**可无主**——如「中央红军」不隶属任何个人。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub owner: Option<Id>,
    /// 成员角色 ID 列表。复合单位的领导 / 成员；单人单位填 1 个。
    #[serde(default)]
    pub members: Vec<Id>,
}
```

**与 `Character` 分离（用户裁定 P2）**：不是「角色变成单位」，而是 Unit **引用**角色。

| 场景 | 做法 |
|---|---|
| 单人移动（「康熙帝西巡」） | 建一个 Unit，`members` 长度为 1 |
| 复合单位（「红一军」） | 建一个 Unit，`members` 列出其领导人物 |
| 无主单位（「中央红军」） | 建一个 Unit，`owner = None` |
| 只作为整体运动、未指定人物的部队 | 建一个 Unit，`members` 可为空 |

**为什么 `owner` 与 `members` 并存**：两者分工不同——`owner` = 这个单位**属于谁**（人 / 势力），`members` = 这个单位**由谁组成**（角色列表）。都只是引用，不复制被引用对象（原则四）。

### （2）运动归单位，不归事态（**本 ADR 修正 ADR-0002 的 Q4 答案**）

| 关系 | 形态 |
|---|---|
| 轨迹的动者 | `Track.unit: Id`（指向 `Unit`）——**取代** 原 `Track.owner: Id` |
| 事态 ⟷ 轨迹 | `SituationStep.tracks: Vec<Id>`——**多对多引用**，一条轨迹可被多个节点引用 |
| 事态 ⟷ 单位 | `Situation.units: Vec<Id>`——归纳容器（见决策 4） |

**一句话**：**运动先于事态存在**。一支队伍在地图上走，不因为「被写进某个事态」才开始动；事态**引用**它，不**拥有**它。

**渲染推论（本决策的必要配套）**：播放某条事态时，只渲染**相关单位在该事态 `span` 内**的轨迹片段。轨迹自身的可见性由 `track.span` 与当前时刻的关系判定，**不由「某节点是否引用它」判定**。

### （3）「相遇」不建实体；「相遇却未写事件」只提示，不报错

用户对 Q2 选择了**乙（派生校验）**，并给出了**理由**（这段理由是本决策的核心依据）：

> 「他们相遇，但是没有事情发生，那么就是啥事都没有」
> 「说明他们相遇，但是你没有写事件，例如男女主角在某地相遇，本应该发生什么，**作者故意没写**。后期安排再相遇，然后安排促进感情的内容就可以提及此地」

因此裁定为：

| 项 | 裁定 |
|---|---|
| 「相遇」是否建实体 | **否**。事件在作者**写的时候**才诞生；不建 `Encounter` 实体 |
| 「相遇但未写事件」 | **完全合法**，是一种**创作手段**（留白 / 埋伏笔），不是疏漏 |
| 工具行为 | 由单位轨迹**派生**时空交叉，若交叉但无事态/事件覆盖 → 给出**提示** |
| 提示的措辞 | 「此处可能**有意留白**」——**不是**「你漏写了」 |
| 是否阻止 | **永不报错、永不阻止保存**（`AGENTS.md` §7.5 V1；项目定位「可以随便改」） |
| **留痕要求** | 提示必须**可回访**——作者后期回来提及此地时，要找得到「这里曾相遇但没写」。**只在当次弹一下就消失的提示不满足本要求** |

> 「相遇提示」已按 `AGENTS.md` §6.1 即时登记进 `GLOSSARY.md`。

### （4）事态是**归纳容器**（`Situation.units`）

用户裁定 Q3：`Situation` **直接**持有 `Event ×N` 与 `Unit ×N`，把「一堆 event、人物、unit」归纳在一起。

| 项 | 裁定 |
|---|---|
| `Situation.units: Vec<Id>` | **要**（与 `steps` 平行） |
| `Situation` 直接列**角色**（P3） | **不要**——角色只能经 `Unit.members` 间接进入。直接再列一份 = 冗余 = 两个真相 |
| `Situation.parent`（嵌套，P1） | **预留，不落地**。用户：「可能是嵌套，但找不到例子，你可以放弃」。未来若需要，以 `parent: Option<Id>` + `#[serde(default)]` 兼容扩展 |

**LOD 表现（用户原话的落地）**：地图放大 → 看得到发生过程；地图缩小 → 显示「**四渡赤水 正在发生**」，且大地图上同时可见其它正在发生的事态。这是**纯渲染规则**，不新增数据（事态在低 LOD 下退化成一个标签）。

## 被推翻的旧口径：基线 §1.6

§1.6 原话：

> **裁定：轨迹挂在「事态节点」上**（不是 Event 的属性，也不是 Character 的终身属性）。
> **为什么**：轨迹是「在这个节点上，谁怎么动的」——它需要同时知道：① 属于哪个事态节点（语境）② 谁在动（主体）③ 在哪张图（坐标系）。**只有事态节点同时持有这三个上下文。**

逐条核对：

| §1.6 的论据 | 实际情况 |
|---|---|
| 「角色不持有**地图上下文**」 | `Track.map` 本来就是这个字段——**Track 自己持有**坐标系，与事态无关 |
| 「挂主体会导致同一段运动**在多事态间复制**」 | 只成立于**把运动内联进事态**的写法。`Track` 独立成实体、事态只持有 `tracks: Vec<Id>` 时 → **零复制** |
| 「只有事态节点同时持有三个上下文」 | ① 语境：事态**引用**即可，无需**拥有**；② 主体：`Track.unit`；③ 坐标系：`Track.map` |

**§1.6 把「语境归属」与「运动拥有者」当成了同一件事。** 按用户模型，正确的裁定是：**`Track` 归 `Unit`，`SituationStep` 引用 `Track`（多对多）**。

> 按本目录纪律，ADR-0002 已接受，其正文**不改**。本 ADR 修正的是 ADR-0002 中 **Q4（「谁怎么动」记在哪里）** 的答案；ADR-0002 关于**排序只能由时间派生（A1）**与**轨迹必须可选可粗略（A2）**的裁定**继续有效**。

## 代价与后果

### 正面

1. **「跨节点轨迹归谁」问题消失**——运动归 Unit，事态只引用，不存在归属争议；
2. **P4（不复制）零成本满足**——一条 `Track` 被 N 个节点引用，只存一份；
3. **`owner` 的二义性消失**——`unit: Id` 指向明确实体，可以被**严格校验**（此前 `owner` 的校验只能显式跳过）；
4. **模型与作者直觉一致**——「队伍在马走」是**先于**「把这件事写进某条事态」的。

### 负面

| 代价 | 说明 |
|---|---|
| **破坏性字段改名** | `Track.owner` → `Track.unit`。旧数据里 `owner: char_x` 会被 serde 忽略，随后报 `missing field 'unit'`——**错误信息不够可操作** |
| 新增顶层集合 | `World.units`，`wv-io` 校验集合 +1 |
| 新增渲染规则 | 轨迹可见性判定从「节点是否引用」改为「`track.span` 与当前时刻的关系」 |
| 示例工程与测试需同步 | `examples/minimal-world/` 新增 `units/`，`track_shenyan_route.yaml` 的 `owner` 改为 `unit` |

### Schema 版本处置（**本 ADR 显式留痕**）

决定：**不 bump `schema_version`（保持 v2）**。理由：

1. v2 处于**骨架落地期**（基线 §2.16），**从未发布**，不存在在野 v2 数据；
2. 唯一 v2 数据是 `examples/minimal-world/`，本次同步修改；
3. 遵循项目哲学「**不为假设的将来付现在的成本**」（与「schema 1→2 不做自动迁移」同源）。

> **例外条件**：若在本次修改之前**已经存在**任意外部 v2 工程数据，则必须改为 bump 到 **v3**，并由 `Project::open` 给出可操作的迁移指引。**请在发现此类数据时立即上报。**

## 被否决的备选方案

| 备选 | 内容 | 否决理由 |
|---|---|---|
| **Q1 乙** | 不新建目录，`Character`/`Faction` 在需要移动时**投影**成 Unit | 「中央红军」这类**无角色主体**无法表达；且投影出来的 Unit 没有稳定 ID，事态无法引用 |
| **Q1 丙** | Unit 只是把 `Track.owner` 那句「角色或势力」形式化，不算新实体 | 等于没解决二义性：`Id` 仍需猜指向哪个集合 |
| **Q2 甲** | 「相遇」完全不建模，一切交给作者 | 丢掉了「你可能漏了」的**提示价值**；用户明确要提示 |
| **Q2 丙** | 显式 `Encounter` 实体，作者手标「某日某地谁遇到谁」 | 与项目定位（**协助**作者整理、**可以随便改**）冲突：逼作者做**数据录入**而非创作 |
| **Q3 直接列角色** | `Situation` 同时持有 `characters: Vec<Id>` | 角色已能经 `Unit.members` 进来，再列一份 = **两个真相** |
| **轨迹挂 `Character`** | 回到「角色终身属性」 | ADR-0002 已否决（会变成终身属性）；且无角色主体无法表达 |
| **按节点拆 Track** | 一条跨节点运动拆成多条 `Track` | 作者为**同一段行军**重复输入 waypoint；拆点在语义上是**人为**的 |
