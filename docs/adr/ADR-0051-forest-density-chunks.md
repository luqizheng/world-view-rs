# ADR-0051: 森林密度场的 Chunk 级生成与世界锚定采样格

- **状态**：已接受（Accepted，2026-10-22，用户裁定「做 §九-3 Chunk 级生成」）
- **关联**：ADR-0031 追记一（密度场接入疏密）、ADR-0050（森林视觉层：位图树冠与林底；其「待裁」中的 §九-3 由本 ADR 落地）、`codex_forest_design.md` §九-3

## 处境

ADR-0050 把 Codex 的 §九-3（Chunk 级生成）列为待裁，理由是「待大地图性能/接缝
问题显现再启」。落码后问题**当天就显形了**，而且不是一处：

1. **整场计算的内存与首帧成本**：密度场原先是「一次算全图、`Arc<Vec<f32>>` 常驻」。
   1024² 是 4 MB（可接受），**4096² 是 64 MB**，且每次地形变化都要重算整图
   ——而渲染层每帧只扫视口那几十块。
2. **树冠采样格是视口锚定的**：抖动的熵源是 `(col, row)`（从视口左上角数起）。
   于是**平移相机 = 整张采样格错位 = 所有树换位置**。这不是性能问题，是正确性
   问题（Codex §九-3 原话：「避免接缝与局部重生成后树木随机变化」）。
3. **Codex §九-3 的原始解法不适用**：原文按 Chunk 生成泊松盘树点、**块边界共享
   邻域采样信息**（否则最小间距在边界处破功）。本仓库没有树点列（见 ADR-0050
   D6：树是逐格确定性判定的结果），所以「共享邻域」这件事在因果上不需要——
   但需要证明。

## 决策

**D1 · 密度场按块惰性计算，块 = 128×128 格。**

- 只在**视口扫到**的块上计算（装饰与树冠都按步距扫视口）；
- 块大小 128 格：一块 64 KB，落在 L2 缓存量级；与地形纹理分块（256 px）
  同数量级但更细，减少「算了却没人读」的浪费；
- 常驻预算是 512 块（32 MB 上界），超出按「最久未用」淘汰（当前块永不淘汰）。

**D2 · 帧首同步一次、帧内逐格取值。**

`terrain_data_hash` 是 O(N) 的，**不能**进逐格快路径。故 API 拆成两步：

| 调用 | 频率 | 成本 |
|---|---|---|
| `sync(data)` | 每帧每系统一次 | O(N) 哈希（与既有离岸场 / 等值线缓存同口径） |
| `density_at(data, cx, cy)` | 每扫到的格一次 | 块内一次数组索引（切块时一次 `Arc` 克隆） |

`sync` 只在身份（hash + 尺寸）变化时清块；同地形反复 `sync` 是空操作。
`density_at` 带 `debug_assert` 校验「尺寸已同步」，漏同步在测试里立刻炸
（本轮实现中确实由它抓到一处漏调）。

**D3 · 块边界无接缝——由构造保证，不靠数据共享。**

`wv_terrain::forest::forest_density_cell` 是**点态**函数：一格的值只依赖该格
自己的 `(群系, 海拔)` 与格坐标上的两层 Perlin 噪声，**不读邻格**。因此
「分块算」与「整图算」**逐字节相等**（单测 `chunked_values_match_the_pointwise_formula`
逐格 `assert_eq!` 钉死）。

**这条是本 ADR 的核心**：Codex 原文要求「块边界共享邻域采样信息」，前提是
生成器**有跨块依赖**（泊松盘最小间距）。本仓库的树不是生成出来的点列，而是
「逐格哈希 → 是否长树」的判定结果，跨块依赖为零——于是接缝问题**在因果上
不存在**，不需要邻域池、不需要块间握手。

**D4 · 树冠采样格改为世界锚定。**

- 格点位置 = `格号 × 步距`（世界坐标），抖动由**格号**哈希给出；
- 后果：平移相机时同一棵树的世界坐标不变，只会在视口边缘进出；
- 反证：视口锚定写法下 `(col, row)` 随视口起点变化 → 整片重洗。
  单测 `tree_positions_stay_pinned_when_the_camera_pans` 取「两视口交集内缩
  80 wu」的树做逐棵比对，旧写法必失败。

**D5 · 候选量兜底。**

单帧候选格上限 40,000（`MAX_CANDIDATES`）。正常情况下候选量 = 视口 ÷ 步距，
两者都乘 `view.scale`，与缩放无关；但主题若给出极小步距或视口被外部放大，
候选数按平方增长——**宁可这一帧不画，也不要在渲染线程里跑百万次哈希**。

**D6 · 仍然不落盘（P7）。**

块是**派生缓存**，不进工程目录、不进 `terrain.bin`。重开工程按同一张地形
重算出同一片林（确定性来自固定种子 + 点态公式）。

**被否决的做法**：

- **块间共享邻域采样信息**（Codex 原文）：本仓库没有跨块依赖，加了是纯开销。
- **逐块脏区**（作者改一格只重算那一块）：`terrain_data_hash` 只能回答
  「变了没」，不回答「哪变了」。当前做法是「变了就清空、视口内重算」——
  重算量被视口封顶，代价可接受。真要做脏区，需要 terrain 侧提供变更矩形
  （已有 `diff_bbox`），列为后续优化，收敛点就在 `ForestDensityCache::sync`。
- **生成期把树实例整图落盘**：ADR-0031 追记一已否决（§5 二进制分块纪律 +
  LOD 纪律），本 ADR 不改变该结论。
- **空间索引（四叉树 / 网格桶）**：候选本身就被视口与步距限定在千级，
  索引收益不抵复杂度。

## 代价

- 每帧每个系统一次 O(N) 哈希（与既有离岸场 / 等值线缓存同量级）。
  1024² 实测无感；4096² 若成为瓶颈，收敛点是「把 hash 换成 terrain 侧的
  变更计数」，一次改动即可。
- 块切换时一次 `Arc` 克隆（引用计数，不拷数据）。
- 内存上界 32 MB（512 块），远小于整场 4096² 的 64 MB。
- 候选量兜底会让**极端缩放**下这一帧没有树（画面上是「树突然消失」而不是
  「卡死」）——按设计取舍。

## 待裁

- **逐块脏区**：需要 terrain 侧给变更矩形（`diff_bbox` 已存在），
  时机是「大地图上连续笔刷编辑出现可感卡顿」。
- **块大小自适应**：128 是否对所有视距都最优，未做测量；调整点是
  `forest_density::CHUNK_CELLS`。
- **树实例的对象池 / 批渲染**：当前一张 mesh 一把绘制，千级 quad 足够；
  若单帧树数上万再考虑 GPU instancing（ADR-0031 的 v2 挂账同源）。
