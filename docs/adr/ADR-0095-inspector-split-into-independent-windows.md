# ADR-0095: 统一 Inspector 拆独立浮动窗——势力层/事态复辟为第一类面板

- 状态：已接受（2026-10-31 用户裁定：「属性检视窗……全部改为独立的浮动窗体，起码看上去是独立的」）
- 关联：统一 Inspector 设计（2026-10-22，本 ADR 修订其「三页签共一窗」聚合）、ADR-0094（双击分流已把格子编辑引向笔刷窗）

## 1. 处境（Context）

2026-10-22 的统一 Inspector 把属性 / 势力层 / 事态三个面板收进一个浮动窗 + 页签条。实机反馈的问题：

1. **一窗多职**：势力层管理（层的增删改 + 动刀入口 + 势力清单）与逐实体属性表单挤在同一窗，切换靠页签——窗体不能各自停靠/对比/并排；
2. **看上去是附属**：页签内容再宽也是「属性检视窗的一页」，没有独立窗体的份量（用户原话：起码看上去是独立的）；
3. **页签禁用是灰点**：CellMap 工作区把势力层/事态页签灰化——存在但不可用，不如不出现。

## 2. 决策（Decision）

1. **三页签 → 三张独立浮动窗**：`Panel::Inspector` 收窄为「**属性**」窗；`Panel::Faction`（**势力层**窗）与 `Panel::Situation`（**事态**窗）从退役状态**复辟**回 `Panel::ALL`，成为第一类可开关面板（标题沿用原页签名）。
2. **页签条与 `InspectorTab` 退役**；`InspectorState` 保留空壳（签名/夹具零扰动）。
3. **工作区语义延续**：CellMap 工作区内势力层/事态两窗**整窗不渲染**（页签禁用 → 窗不出现）。
4. **既有入口零改名**：`property_window`（双击/编辑城市）开属性窗；命令面板的 `CmdTogglePanelFaction/Situation`、HTTP 面板快照（`Panel::ALL` 驱动）自动复活；ui-layout.yaml 的 `faction:` / `situation:` 布局条目直接复用（位置尺寸沿用退役前缺省）。

## 3. 理由（Rationale）

- **窗体即职责**（ADR-0026 面板架构的延伸）：势力层是「集合层」管理台、属性是「单体层」表单、事态是登记流——三件事的停靠需求本就独立；
- **退役面板复活是最小改动**：`Panel::Faction/Situation` 的枚举变体、标题键、布局缺省、命令面板臂、HTTP 映射全部健在，只需回 `ALL` + 重接内容；比新增两个变体少动一半管线；
- **CellMap 聚焦语义不回退**：工作区内两窗不渲染，比灰页签更彻底（用户裁定的延续）。

## 4. 代价（Consequences）

- **多窗管理**：屏幕上可能同时有三张 Inspector 系浮窗——靠各窗可关 + 菜单/命令面板/HTTP 可开关兜住；
- **布局文件兼容**：旧工程的 `faction:` / `situation:` 条目直接生效（字段同构）；新工程缺条目走缺省布局（ui-layout 缺省机制已有）；
- **`InspectorState` 成空壳**：留着是为签名稳定，下轮清理时可删（收敛点明确）；
- **被否决的备选**：
  - 单窗内嵌「子窗体」视觉（假独立）：不解决停靠/并排的真实需求，弃；
  - 全新 `Panel::FactionLayers` / `Panel::Situations` 变体：与退役变体重复占位，旧 ui-layout 条目作废，弃。
