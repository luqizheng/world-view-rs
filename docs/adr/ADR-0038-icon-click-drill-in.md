# ADR-0038：进入子图的唯一手势是双击钻入图标（撤销「缩放越界进入」）

**状态**：已接受（Accepted）
**日期**：2026-10-19
**决策者**：用户（对话拍板「合理……开工」）
**关联**：[ADR-0009](ADR-0009-graded-tile-zoom-to-street.md)（**§2 决策 ⑤ 的「往里」半边被本 ADR 修正**；分级区间、`Extent.origin` 坐标嵌套、`MapFrame`、级间过渡动画全部保留）、ADR-0022（`outline_polygon`）、ADR-0025（D2 命中优先级里的「图标下钻」不受影响）、GLOSSARY「换级」（词条已按本 ADR 修正）

---

## 1. 处境（Context）

ADR-0009 把「缩放到街道」定为**分级 + 级间平滑**：滚轮撞到当前级内界后继续往里滚，且指针恰好压在某张子图的钻入图标上，就切换进那张子图（`camera_zoom` 写 `ZoomCross::Into(child)`，`drill::apply_zoom_cross` 消费）。实机用下来，这条「往里」路径的代价大于收益：

1. **换级沦为时机事故**。是否进城取决于撞界那一瞬间光标在哪——「我只是想看清地形细节，画面突然切进了一座城」。意图（缩放）与效果（换图）脱钩，用户无法预判。
2. **进入与数据模型不符**。P4 下子图是 `Id` 引用的**另一份独立创作**（街道、建筑、场所），不是父图的「放大版连续影像」；Google 式连续缩放的前提（同一数据集的多级瓦片）在这里并不成立，级间过渡本质是交叉淡化伪装的硬切。
3. **图标入口本来就在，且是唯一书面锚点**。`AddCityCommand` 建城时自动落 `IconSpec { drill_into }`——父图上「这座城在哪」的表达就是这颗图标。让「双击图标」与「悬停图标 + 缩放越界」两条路径并存，前者反而被稀释。
4. **性能风险集中在缩放途中换内容**。广东工程深缩放塌陷的归因（POI 池每帧重建、缩放途中道路 mesh 重建）都说明「边缩放边换数据集」是高风险区；离散入口给子图资源一个确定的加载点。
5. **参考观感本就是图标进城**。项目的地图观感参照（手绘/JRPG 一族）均为「点城名/图标进入」，无连续缩放入城。

## 2. 决策（Decision）

1. **进入子图的唯一手势 = 双击钻入图标**（既有 v0.2 §B 行为，本 ADR 将其升格为唯一）。缩放（滚轮 / 缩放条 / 快捷键）在当前级区间内工作，**撞到内界后继续往里滚不再触发换级**——缩放被夹在内界上停住。
2. **删除 `ZoomCross::Into(child)`**：`ZoomCross` 只剩 `Out`；`camera_zoom` 不再做 `marker_hit`，`apply_zoom_cross` 只处理「回父级」。`DrillState` 的写入口收敛为「双击图标 / 面包屑」两处。
3. **撞外界继续往外滚 = 回父级，保留**（与进入**不对称**是刻意的）：缩小的心智是「想看周边环境」，滚轮退出去符合直觉；往里则必须是明确的点选意图。
4. **双击维持，不改单击**：单击与「选中图标 / 笔刷落笔」冲突（ADR-0025 的命中优先级依赖第一下按下即可判定）。
5. **数据模型零改动**：`MapNode` / `IconSpec` / `Extent` / `DrillState` 全部不动；本 ADR 只收敛交互入口，YAML 与 round-trip 无涉。
6. **级内最大放大收浅：`LEVEL_ZOOM_SPAN` 80 → 32**（2026-10-19 用户拍板，与决策 1 同轮）。旧的 80× 是决策所撤销的「滚轮越界进城」的遗产——深放大的终点本是「滑进子图」，级内糊一点无所谓；进城改双击后，矢量平涂底图（ADR-0012）与装饰（ADR-0031）在栅格分辨率之上没有内容支撑，80× 只会得到放大的色块。32× 取「糊线以下、刷格子仍可用」的折中：4096² 满配栅格（1 wu/格）在 720px 窗口约 5–6 px/格，1024² 栅格约 22 px/格。世界级内界相应从 0.064 收到 0.16（比历史 `SCALE_MIN = 0.1` 收紧 1.6×）；外界 `fit × 1.5625` 与逐级尺寸比提供的总跨度不变。

## 3. 理由（Rationale）

- **意图与效果对齐**：点击（双击）是明确的「我要进去」；缩放是「我要看更细」。两者分开后，撞界缩放的行为变成可预判的「停住」。
- **可发现性有既有锚点**：钻入图标用界面蓝菱形（区别于金色选中语义），加 `outline_polygon` 轮廓后视觉存在感更强；「看见城 → 双击城」的映射无需教学。
- **删除比修补便宜**：往里路径的歧义没有廉价修法——「越界时弹提示问进不进」打断手感、「按住某键才进城」是隐藏快捷键。删掉后 `camera_zoom` 少一次命中测试、`apply_zoom_cross` 少一个分支，代码与心智同时变简单。
- **缩放上限与入口一致**（决策 6）：既然后续动作不再是「进城」，级内深放大就失去内容支撑——上限应该钉在「本级内容还能辨认」处，而不是旧入口需要的深度。
- **ADR-0009 的其余决策不受损**：分级区间（级内夹紧）、每级独立原点与栅格、`fly_in_scale` 飞入过渡（双击仍用）、外界回退，全部继续有效。被修正的只是「往里靠缩放触发」这半边与其配套的 80× 深度。

## 4. 代价（Consequences）

**负面后果，必须承认：**

1. **习惯 Google 地图的人会先拿滚轮怼进城**，发现怼不动后需要一次学习（双击图标）。缓解：图标本身醒目；后续可补 hover 气泡「双击进入」。
2. **「级间平滑」不再完整**：往里变成「双击 + 飞入动画」的离散跳转，ADR-0009 §2⑦ 的连续性只剩 Out 方向。这是接受「子图是独立创作」后的诚实呈现。
3. **无图标覆盖的子图入口（作者删了图标又没删图）只能靠面包屑之外无入口**——现状即如此（`drill_into` 是唯一钻取语义），本 ADR 不新增也不恶化。
4. **32× 对满配栅格（4096²，1 wu/格）意味着格子只有 5–6 px**，格子级精修（雕 1 格海岸线）会偏紧；低分辨率栅格工程无感。若将来确需格子级工作深度，正确修法是**按栅格分辨率自适应**（上限 = 一格 ≈ 12px），需在 `wv-render` 解析底图继承链——登记为后续可选项，不随本 ADR 实施。

**后续可能（不构成本 ADR 决策）**：把 `outline_polygon` 轮廓整体作为双击热区（比菱形大得多，更接近「点城名进城」的手感）；hover 气泡提示。两者均为 `marker_hit` / 悬浮层的局部扩展，随时可做，不需要新 ADR。

**被否决的备选方案：**

| # | 备选 | 否决理由 |
|---|---|---|
| A | **维持 ADR-0009 缩放换级**（现状） | §1 第 1 条的时机事故是实机体验硬伤；修不掉（歧义源于「用缩放表达进入」本身） |
| B | **单击图标进入** | 与选中 / 笔刷落笔争第一下（ADR-0025 D2 的命中判定在按下时就要分派）；误触率不可接受 |
| C | **退出也收编为按钮 / 面包屑专属** | 缩到外界「撞墙」比自动退出差；不对称（点进、滚出）符合两个方向的自然心智 |
| D | **无极连续缩放**（彻底抹掉「级」） | ADR-0009 §4 备选 A 已否决（`f32` 大坐标精度崩溃），本 ADR 不重开 |
