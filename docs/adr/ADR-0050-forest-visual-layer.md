# ADR-0050: 森林视觉层——林底蒙版（CPU 烘焙）与位图树冠形态

- **状态**：已接受（Accepted，2026-10-22，用户拍板「§七 A + §九-1 A（视觉向）」）
- **关联**：ADR-0031（程序化地形装饰；D5 形态由本 ADR 追记二修正为「默认形态」）、ADR-0044（5×5 水彩渗色烘焙）、ADR-0048（主题配方纪律：数值住主题层）、ADR-0043（主题 crate 抽取）、ADR-0023（主题包契约）、ADR-0032 D2（`FeatureOverlaySet` 字段一次定型）、`codex_forest_design.md` §七 / §九-1 / §十一-8

## 处境

两条独立的视觉缺口，都出自 `codex_forest_design.md`（Codex 建议）的「仍未做」清单：

1. **§九-1 森林底色蒙版**：平铺图上森林与草地同色（同一个绿），森林**不可读**——
   读者看不出哪里是林、哪里是野地。Codex 的方案是「WGSL 混深绿」。
2. **§七 Sprite 形态**：Codex 的手绘树图集方案与 ADR-0031 D5「符号 = 程序化三角化」
   直接冲突。ADR-0031 追记一（2026-10-22）已把 §七 挂账为「留待『手绘森林是
   产品硬需求』时独立裁决」——本次用户裁定即**那个裁决**：**形态进主题契约**。

两条缺口的共同点：**视觉参数（颜色 / 形态 / 疏密）该由谁决定**。ADR-0031 追记一
已经把「位置 / 疏密 / 形态」拆成三层各归其位；本 ADR 把「形态」这一层落地，
并给「林底」这一层找到与本仓库管线相容的落点。

## 决策

**D1 · 形态契约扩展：位图形态是主题可选的第二形态，程序化仍是默认形态。**

`DecorRecipe` 新增 `forest_symbol: Option<ForestSymbolSpec>`：

| 字段 | 含义 |
|---|---|
| `texture` | 内嵌资产表里的树图集键（如 `overlays/forest/tree_atlas_day.png`） |
| `variants` | 图集横向变体数 |
| `alpha` | 整体不透明度 |
| `band_edit` / `band_region` / `band_nation` | 三档的（步距像素，符号边长像素） |
| `tint_sparse` / `tint_normal` / `tint_dense` | 疏 / 常规 / 密三级的顶点 tint |

`None` = 程序化形态（ADR-0031 D5 原样）；`Some` = 位图形态。
**形态是主题的一次性选择，不是运行时开关**——主题换包 / 换日暮即刻换形态。

**D2 · 林底蒙版走 CPU 烘焙，仓库不引入 WGSL / `ShaderMaterial`。**

林底色在 `terrain_view::cells::base_color_of` 里混入：底色 → 渗色（ADR-0044 的
5×5 水彩渗色）→ **混林底**。**为什么烘焙而不是着色器**：

- 本仓库**零自定义材质**：地形是 CPU 烘焙的 RGBA 纹理 → 分块 → `ColorMaterial`。
  引入 WGSL 意味着重写 tint / soften / alpha / mip 四段逻辑，且与 ADR-0044 的
  「笔触感来自烘焙」管线正面冲突。
- 烘焙位点选在 `base_color_of` 内 → **林底色跟着渗色一起晕开**：森林边缘不是
  硬边，是水彩洇出来的——这正是「手绘古舆图」的观感（ADR-0042/0044）。
- 烘焙态式有限：瓦片图集档（RealTerrain）与分析档（Topographic / GoogleMap /
  Event / Coastline）**不受林底影响**（按设计如此：分析档要的是真值，不是氛围）。

**D3 · 林底参数住主题层**（ADR-0048 追记二的配方纪律）：

| 参数 | 位置 | 默认 | 含义 |
|---|---|---|---|
| `forest_floor` | `PaletteColors` | 日 `0x2E5535` / 暮 `0x2A3324` | 林底色本身 |
| `forest_base_strength` | `DecorRecipe` | `0.55`（暮 `0.62`，水墨 `0.28`） | 混色强度（0 = 关闭林底） |
| `forest_base_min_density` | `DecorRecipe` | `0.40` | 低于此密度不着林底 |

**为什么要有 `forest_base_min_density`**：密度场给草原 0.22 / 稀树草原 0.12 /
丘陵 0.35——没有下限门槛，整片草原都会被染绿。`0.40` 对齐 `classify_forest` 的
「常规林」边界，但仍留给主题调。

**D4 · 底色与树冠共用同一片密度场。**

`ForestDensityCache`（按 terrain hash 键控，ADR-0031 追记一）同时供：
程序化森林桶保留率、林底混色强度、位图树冠的落点与大小。
**两处各算一片会「底色一片林、树长在别处」**——故 `get_or_compute` 提为
`pub(crate)` 复用。

**D5 · 形态二选一：位图形态下，程序化森林桶让位。**

主题声明 `forest_symbol` 时，`terrain_decor` 的 `DecorKind::Forest` 采样点跳过
（否则「树上长树点」）。**不回退**：贴图缺失时告警一次并不画树，**不静默换回
程序化形态**——形态是主题的一次性选择，静默替换会让人以为「换了主题没生效」。

**D6 · 树冠层 = 独立渲染层 `wv_render::forest_canopy`。**

- 采样：视口矩形（外扩 32 屏幕像素余量）内的**屏幕像素恒定步距**网格，
  落点抖动 ±0.35 步距（防棋盘感），按**落点所在格**查群系与密度；
- 保留率 = 密度场 × 主题增益（复用 `forest_keep_prob`）；
- 树冠大小 = `尺寸 × (0.72 + 0.56 × 密度) × (0.88 + 0.24 × 逐树抖动)`；
- tint = 密度分级（疏 / 常规 / 密）→ 走**顶点色**（Bevy `ColorMaterial` 的
  最终色 = `材质色 × 顶点色 × 贴图`），单 mesh 单材质，不按密度拆批；
- 前后关系：**画家算法**（按 y 升序）——拆批会破坏前后关系，故不拆；
- Z = `0.078`（地形装饰 0.075 之上、道路 0.09 之下）；
- 资产纪律：贴图按 key 缓存复用（PNG 解码成本远高于重建 mesh），几何指纹变了
  才原地改写 mesh（ADR-0030 D4 纪律）。

## 理由

- **形态进主题契约**是用户原始设计意图的直接落地：「**由 theme 决定在这个地方
  采用什么方式进行覆盖**」（ADR-0031 追记一引）。之前「形态」只由渲染层写死，
  主题无法表达；D1 之后，**加一种森林形态 = 改主题包，零改渲染层源码**
  （ADR-0043 D2 的纪律）。
- **林底色是氛围，不是真值**：它该在烘焙期与笔触一起晕开，而不是在着色器里
  硬混。烘焙方案让林底**免费继承**了 ADR-0044 的渗色与 ADR-0042 的笔触。
- **不动地形着色管线**：仓库至今零 WGSL；为一条装饰需求引入自定义材质，
  代价（重写 tint/soften/alpha/mip + 与渗色管线打架）远大于收益。

## 代价

- 主题包新增两个字段（`forest_symbol` / `forest_base_*`）：外部主题 crate
  （如 `wv-theme-chinese-ink`）需跟进——`DecorRecipe` 尚未冻结（ADR-0032 D2
  只冻结了 `FeatureOverlaySet`）。
- **水墨主题保持程序化形态**（`forest_symbol: None`）+ 弱林底（`0.28`）：
  水墨的树是「点苔」，位图树会破坏画意。代价是「同一产品两种森林观感」——
  这是主题差异的**目的**，不是缺陷。
- 树冠层每帧重采样视口（1024² 地图、Edit 档约 3–5 千棵候选）；
  单帧兜底上限 4000 棵。
- 树图集当前只有 **3 个变体**（Codex 参考图有 100+ 资产）——变体数是
  `ForestSymbolSpec.variants` 的参数，补资产即补变体，无需改代码。

## 被否决的备选

- **WGSL 林底着色器**（Codex §九-1 原文）：需引入 `ShaderMaterial`，重写地形
  的 tint / soften / alpha / mip，并与 ADR-0044 的烘焙渗色争夺同一段管线。
- **位图瓦片图集**（Codex §七 原案）：ADR-0031 D5 已否决（JRPG 图集已弃用）；
  本 ADR 只把**位图用于符号**，底图仍是 CPU 烘焙纹理，**D5 的否决结论不受影响**。
- **按温度分流树种**（Codex §十一-4）：温度是生成期派生量、**不落盘**，渲染期
  拿不到 → 只能按**群系 / 气候带**近似分流（当前按密度分级 tint，不分流树种）。
- **树实例整图落盘**（Codex §二的 `trees: Vec<TreeInstance>`）：违反 §5 二进制
  分块纪律（须走 `RasterRef` + 格式规格），且与 LOD 纪律（ADR-0031 D2/D3）冲突。
- **程序化与位图形态并存**（两套同时画）：画面脏（「树上长树点」），且作者
  无法判断自己在看哪一套。

## 待裁

- **§九-3 Chunk 级生成**：大地图（>2048²）的树冠生成是否需按 chunk 惰性生成
  （接缝 / 性能），待大地图实例显现问题再启。
- **树种分流**（针叶 / 阔叶 / 棕榈）：当前按密度分级 tint 分流，不分流树种。
- **树图集资产扩充**（3 变体 → 更多）：属美术资产补齐，不改代码。

## 追记一（2026-10-22，实机验收）：远档步距收紧 120→72

**处境**：首次实机截图（`examples/jrpg-world`，1600×1000 窗口、20% 视距）按
A/B 对拍（`WV_NO_CANOPY` 开/关逐像素相减）量到**整屏只画了 2 棵树**。

**原因（算得清）**：森林只占该图幅 **6.75%**（`terrain.bin` 群系直方图实测），
而 Nation 档步距 120px ⇒ 整屏候选仅 `1600/120 × 1000/120 ≈ 104` 个，落到林地
约 7 个、再乘保留率（密度 × 增益）后只剩 2 个。**不是缺陷，是参数选得太疏**。

**决策（不改 D1–D6，只调主题数值）**：`WATERCOLOR` 的 `band_nation` 由
`120px / 46px` 收到 **`72px / 36px`**（暮色 `126/46` → `78/36`，中间档同比例
微调为日 `56/32`、暮 `60/32`）。同屏候选提到 ~300 个 ⇒ 林地十余棵，成片感
回来；远档符号同时从 46 收到 36（远档不该比近档大出一半）。

**边界**：数值住主题层（D3 的配方纪律），换地图 / 换手绘包可再调；
**不新增任何运行时开关**（验收用的 `WV_NO_CANOPY` 是临时调试开关，已移除）。

**代价**：远档单帧树数从个位数升到十余棵（仍是同一张 mesh、同一次绘制）；
候选量上去后每帧的哈希 / 查格次数线性增加（百级，可忽略）。

## 追记二（2026-10-22）：§九-3 Chunk 级生成已由 ADR-0051 落地

本 ADR「待裁」里的 **§九-3 Chunk 级生成** 当日晚些时候由用户裁定开做，
决议见 **ADR-0051**（密度场按 128² 块惰性计算 + 树冠采样格世界锚定）。
两处对照如下——**D1–D6 的形态与林底结论不受影响**，改动只落在「密度场怎么
算」与「采样格锚在哪」两件事上：

| 本 ADR 原状 | ADR-0051 之后 |
|---|---|
| 密度场整场一次算完、`Arc<Vec<f32>>` 常驻（4096² = 64 MB） | 按 128² 块惰性计算，只算视口扫到的块；常驻上界 512 块（32 MB） |
| 树冠抖动熵源 = `(col, row)`（视口左上角起数）→ 平移即重洗 | 熵源 = **世界格号**（`格号 × 步距`）→ 平移后树的世界坐标不变 |

**待裁更新**：§九-3 从本 ADR 的待裁清单里划出（已落地）；剩下两项
（树种分流、图集扩充）不变。
