> 「不要用枚举吧。万一有新增其他势力的可能？假设欧洲法国，有贵族控制多个省或者一个省，几个贵族属于一个雅各宾派。那么贵族领地可能不够分。我的想法是：**国界、省份、贵族等等，都叫做势力层。可以命名，然后绘图。**」

## 1. 设计篇（来源：游有方 · 创意总监）

### 1.1 核心裁定：「事态（Situation）」本体

**用户说「我不知道如何定义」的那个东西，定名为「事态」。**

| 用户原话 | 裁定答案 | 一句话 |
|---|---|---|
| 「不知道如何定义四渡赤水」 | **事态（Situation）** = 一条**事件链**，链上节点是事件，节点可选挂**轨迹** | 链回答「发生了什么、为什么」，轨迹回答「怎么动的」 |
| 「一个地图有多个地图」 | 已有 `MapLevel`（World/Region/City/Interior）**够用，不新增层级** | 用户说的三种地图 = 已有四级中的三级 |
| 「播放事态进程」 | **播放 = 时间轴自动推进**，不是新播放器 | 播放就是「拖着时间轴自己走」 |
| 「真实地形图 vs 色块图」 | **不是图层开关，是「视图模式（ViewMode）」** | 它同时改**基底渲染** + **布局**，比图层高一档 |

**术语定位**：

| 项 | 值 |
|---|---|
| 中文名 | **事态**（口语可叫「事态进程」，实体名是「事态」） |
| 英文名 | **Situation** |
| 代码 ID 前缀 | **`sit_`**（如 `sit_four_crossings_chishui`） |
| YAML 路径 | `timeline/situations/<id>.yaml`（与 `events/` 平行，**不进** `events/`） |
| 所属维度 | 事件（事件维度内的**组织层**） |

**为什么叫「事态」**：用户自己的用词就是「事态」——**这是最省概念的命名**（不造新词，把用户的词正式化）。且「事态」= 「事情的态势」，中性、可大可小、天然带「一段时间内持续演进」的语义。

**作者语言定义（可做成 tooltip）**：

> **事态 = 「一段时间内，一件有始有终的大事，拆成几个先后发生的关键事件。」**
>
> 判定口诀：
> - 「它是不是**一件有开头有结尾的大事**？」→ 是 → 建**事态**
> - 「它有没有**几个先后的关键节点**？」→ 有 → 事态的**链**
> - 「其中一个节点，**要不要画出它是怎么动的**？」→ 要 → 挂**轨迹**

**四渡赤水的对号入座**：

| 概念 | 实例 |
|---|---|
| **事态** | 「四渡赤水」（1935 年 1–3 月，红军在川黔滇边界的机动作战） |
| **第 1 个节点（事件）** | 一渡赤水（土城失利 → 西渡赤水入川南） |
| **该节点的轨迹** | 土城 → 扎西 的行军点列（带逐段时间） |
| **第 2 个节点** | 二渡赤水（回师黔北 → 再占遵义） |
| **…** | 共四渡 + 若干伴生事件 |
| **归属地图** | 世界地图（行军），其中「占遵义」可下钻到城市地图（入城） |
| **参与方** | 红军（势力层）、若干人物 |

### 1.2 「事态」与「故事（Story）」的分界（必须钉死）

| 判定问题 | 建**事态** | 建**故事（Story）** |
|---|---|---|
| 它有确定的时间范围吗？ | ✅ 有（`from..to` 都是真实天数） | ❌ 没有 |
| 它要参与四维校验吗？ | ✅ 要 | ❌ 不要 |
| 它能被播放吗？ | ✅ 能 | ❌ 不能（无轴位置） |
| 它能下钻到地图吗？ | ✅ 能 | ❌ 不能 |
| 典型例子 | 四渡赤水、赤壁之战、玄武门之变 | 创世神话、上古传说、家族史散文 |

> **口诀**：**「能排期 → 事件；能播、能下钻 → 事态；只用来讲故事 → 故事。」**

### 1.3 事态与既有 `Event` 的关系（裁定：Event 之上新的一层）

| 方案 | 评价 | 裁定 |
|---|---|---|
| A. Event 的扩展（加 `chain_id` 字段） | 链属性无处安放；链不能跨地图；链时间范围要遍历算 | ❌ 否 |
| **B. Event 之上新的一层（Situation 聚合 Event）** | 链元数据有家；可跨地图；与 P4 一致；**Event 一个字都不用改** | ✅ **采纳** |
| C. 并列的新实体 | 链上节点是事件就失去了 | ❌ 否 |

**关键不变式**：

| # | 不变式 | 违反时的表现 |
|---|---|---|
| **I1** | Situation **不复制 Event 内容**，只引用 `EventId`（P4） | 事件内容出现两份，改一处另一处不同步 |
| **I2** | Situation **不引入第二种时间顺序**：链排序 = 节点的时间顺序 | 作者要解释「为什么链上第一个事件是 3 月，第二个是 1 月」 |
| **I3** | **Event 可以不属于任何 Situation**（孤立事件合法，一等公民） | 逼作者「每写个事件都要先建链」——极大抬高入门门槛 |
| **I4** | **一个 Event 可以属于多条 Situation** | 逼作者复制事件（违反 P4），且史实上多归属是常态 |
| **I5** | Situation 必须有时间范围（`span`），且**必须覆盖其全部节点的时间** | 播放时出现「链已结束但还有节点」 |

> **I3 的创作理由（最重要）**：作者写稿顺序**不是**「先规划链再写事件」——他通常**先想起某个具体事件**，后来才串成链。**强制「事件必须属于链」= 把工具的痛苦转嫁给作者。**

### 1.4 链的排序依据（裁定：时间，且只能时间）

| 候选依据 | 评价 | 裁定 |
|---|---|---|
| **时间**（节点事件的 `span.from`） | 唯一能从数据推出的、无歧义的顺序 | ✅ **唯一排序依据** |
| 序号（`order: 1,2,3`） | **会和时间打架**：两个真相 = 必然有一个是假的 | ❌ 由时间**派生**，不单独存储 |
| 因果依赖 | 需要完整的因果图 + 环检测，**本轮不做** | ❌ 见 K2 |

- **节点展示顺序 = 按节点事件时间升序**。作者**不需要也不允许**手排顺序。
- **UI 上节点列表只读**（可拖动改变的是「事件的时间」，不是「列表的位置」）。
- **两个节点时间相同**：按 `EventId` 字典序兜底（确定性排序）。
- **倒叙编排**：由可选的 `narrative_order` 承载（见 §2.2），它**不影响时间轴的任何求值**。

### 1.5 分支/条件的裁定（数据预留，UI 不做）

| 层 | 裁定 | 理由 |
|---|---|---|
| **数据形态** | **保留**分支能力（轻量父子关系），但**当前结构尚未落地**——本轮只做线性，`SituationStep` 现无 `parent` 字段 | 史实本身有分支（主力渡河 / 后卫阻击是并行两支）；但**找不到具体实例**，不为假设的将来付成本（ADR-0004 P1） |
| **UI 呈现（本轮）** | **只做线性主链**，分支只以「并行的多个节点」呈现，**不画分支树** | 一人开发，分支树编辑器成本极高 |
| **条件（if/then）** | **本轮完全不进** | 条件表达式引擎本身仍是待裁问题（README §12-3） |

### 1.6 轨迹（Track）的数据形态

> **本节已于 2026-10-11 被 [`docs/adr/ADR-0004-unit-ontology.md`](adr/ADR-0004-unit-ontology.md) 修正。**
> 原口径「轨迹挂在**事态节点**上」**不再成立**——轨迹归**单位（Unit）**，事态节点只**引用**它。
> 被推翻的原论据（逐条核对）见 ADR-0004「被推翻的旧口径」一节。

**裁定：轨迹归「单位（Unit）」**——不是 Event 的属性，不是 Character 的终身属性，也不是事态节点的属性。

**为什么**：**运动先于事态存在。** 一支队伍在地图上走，不因为「被写进某个事态」才开始动。事态只是把若干事件与单位**归纳**到一起的**容器（group）**，它**引用**轨迹，不**拥有**轨迹。

| 关系 | 形态 |
|---|---|
| 轨迹的动者 | `Track.unit: Id`（指向 `Unit`） |
| 事态 ⟷ 轨迹 | `SituationStep.tracks: Vec<Id>`——**多对多引用**，一条轨迹可被多个节点引用 |

> **由此「跨节点的一段行军归谁」这个问题消失。**「土城 → 扎西 → 遵义」从头到尾就是**一条 Track**，一渡、二渡两个节点都引用它——不存在归属争议。

**渲染推论**：播放某条事态时，只渲染**相关单位在该事态 `span` 内**的轨迹片段；轨迹自身的可见性由 `track.span` 与当前时刻的关系判定，**不由「某节点是否引用它」判定**（ADR-0004）。

**时间戳三条规则**：

| # | 规则 | 理由 |
|---|---|---|
| **T1** | **有 `day` 的点 → 该主体在该天确定在此位置**（参与四维校验） | 四维互相校验在事态上的落点 |
| **T2** | **无 `day` 的点 → 视为「顺序点」**，由插值决定，**不参与校验** | **「未声明 ≠ 矛盾」**（沿用第四态哲学） |
| **T3** | **只填两端点的轨迹，其时间由两端点事件的时间范围给出** | 让「粗略轨迹」零成本可用 |

> **为什么时间戳可选是硬要求**：作者写小说时，「他沿着赤水河走了六天」比「他第 3 天在古蔺」重要得多。**逼作者标每一点的日子 = 把创作变成打卡。**

**四级地图的轨迹形态**：

| 层级 | 轨迹是否存在 | 典型形态 | 推荐写法 |
|---|---|---|---|
| **World** | ✅ 主要战场 | 大跨度折线（跨州跨国） | 坐标点列（荒野无 Place 可引用） |
| **Region** | ✅ 存在 | 中等跨度 | 坐标点列 |
| **City** | ✅ **用户明确要求** | 街道级路径 | **地点序列（`PlaceId` 列表）** |
| **Interior** | ✅ 存在，形态不同 | 房间级路径点 | **地点序列**，且默认只画起终点 |

**两种写法的取舍**：

| 写法 | 形态 | 适用 | 优点 |
|---|---|---|---|
| **坐标点列** | 直接给 x,y 点 | World / Region | 表达任意路径 |
| **地点序列** | `PlaceId` 有序列表 | City / Interior | ✅ **强烈推荐**：可校验「路走不通」、可自动算耗时、**作者不用画坐标** |

> **这是 P4 与距离维度的自然复用**：城市/室内图上的「南门、主街、衙门」天然是 `Place`。**用 Place 序列表达轨迹 = 免费得到距离校验。**

### 1.7 跨地图的链（P4 的正面考验）

**裁定：一条链可以、而且应该跨地图层级。**

**靠什么引用**：**靠 `Place` 锚点串联，不靠 ID 嵌套。**

```
       世界图（World）                     城市图（City）
   ┌──────────────────┐              ┌──────────────────┐
   │   ●─────────●    │              │   ┌───┐  ┌───┐  │
   │  遵义  ─────┘    │  ← 同一 Place │   │南门│──│衙门│  │
   │   (Place)         │    被两边引用 │   └───┘  └───┘  │
   └──────────────────┘              └──────────────────┘
```

**三层引用规则**：

| 层 | 规则 |
|---|---|
| ① 地图树用 ID 父引子（已有） | `City` 图的 `parent = World` 图 ID |
| ② 链的节点可归属不同地图 | 每个链节点带 `map: MapId`（省略 = 继承链的默认地图） |
| ③ **跨图的缝合点是 `Place`** | 同一地方的两个粒度通过 `Place.parent` 建立关系 |

> **为什么不需要「跨图缝合 ID」**：**链的节点顺序由时间决定**（I2），不靠物理连接。**物理上世界图与城市图是断开的（P4 要的：不复制），但时间上是连续的（时间轴要的）。**

**P4 满足方式**：

| P4 的违反形态 | 本设计怎么避开 |
|---|---|
| 把城市图的街道画进世界图 | ❌ 世界图上「遵义」**只是 1 个点** |
| 把世界图的行军轨迹复制进城市图 | ❌ 轨迹带 `map` 字段，**它只属于一张图** |
| 把「红军在遵义」存两遍 | ❌ 由**轨迹的点 + 时间戳**表达，**只存一份**，两张图各自**投影** |

### 1.8 「播放（Playback）」的定义

**裁定：`播放 = 时间轴以固定速率自动推进`。工具里没有独立的「播放器」实体。**

| 项 | 内容 |
|---|---|
| 播放 = 什么 | **自动拖时间轴** |
| 播放速率 | `1 天/秒` / `5 天/秒` / `30 天/秒`（**跨度自适应**：链多长都让它 ~20 秒播完） |
| 控件 | 播放 / 暂停 / 上一节 / 下一节 |
| 播放对象 | **不是整条时间轴，而是某个事态**——播放时锁定在该链的 `span` 内循环 |
| 播放中可否编辑 | ❌ **只读**（避免「边播边改」的 Undo 混乱） |

> **为什么必须锁定在事态内**：作者的意图是「我要看四渡赤水是怎么走的」。**若播放整条 500 年时间轴，作者要等 500 秒。**

**四种尺度的播放差异**：

| 层级 | 播放时看什么 | 画面主角 | 交互重点 |
|---|---|---|---|
| **World** | 战略态势 | 轨迹线 + 势力色块，角色是小图标 | 轨迹**逐段生长**；势力染色**淡入淡出** |
| **Region** | 战役细节 | 轨迹线 + 地形 | 轨迹可显示逐点时间戳；某段耗时过长显示黄色警示 |
| **City** | **城市内角色走动**（用户明确要） | 角色图标在街道上移动 | 角色沿路径**平滑移动**；到达 Place 时高亮；多角色可同时播 |
| **Interior** | 室内走位 | 房间平面图 + 角色点 | 轨迹默认只画起点终点；到达房间时该房间高亮 |

### 1.9 「在地图上看正在发生的事件」的裁定

| 问题 | 裁定 |
|---|---|
| 「正在发生」是哪个时刻？ | = **当前时间轴位置 `t`**。拖动/播放时间轴 → 地图刷新。**没有「实时时钟」** |
| 事件怎么显示在图上？ | **事件点图层** + 当前 `t` 落在其 `span` 内的事件**视觉上「点亮」** |
| 事态怎么显示？ | **当前节点**高亮；**整条链**可在图上显示为**淡色路径**；**只有当前节点是「亮」的** |
| 一图多事态同时播？ | ✅ 能。**播放时只锁定一个事态**，其余按 `t` 投影但**降透明度至 ~40%** |

### 1.10 视图模式（ViewMode）—— 不是图层开关

**裁定：是「视图模式」，比图层高一档。**

| 候选 | 评价 | 裁定 |
|---|---|---|
| 图层开关 | 图层开关只控制「叠不叠某一层」；而用户描述的是**改变基底本身的渲染方式**，且真实地形与色块是**互斥**的 | ❌ |
| **视图模式（ViewMode）** | 同时决定 ① 基底渲染方式 ② 默认图层组合 ③ 可用编辑工具 | ✅ **采纳** |

**四态清单**：

| 模式 | 基底渲染 | 典型用途 | 自动启用图层 | 默认工具 |
|---|---|---|---|---|
| **A. 真实地形** | 高度图 + 法线光照 + 贴图 | 看地形、画海拔 | 地形（贴图）· 河流 · 道路 | 海拔笔刷 |
| **B. 色块地形** | 每种地形一种颜色 | 区域划分、战略视角 | 地形（色块）· 道路 · 事件点 | 地形笔刷 |
| **C. 势力图** | 颜色 = 势力，底色淡化地形 | 看国境、势力消长 | 势力层 · 势力名 · 城市点 | 国境/区域工具 |
| **D. 事件图** | 极简底图（灰白）+ 事件高亮 | **播放事态**、看事件分布 | 事件点 · 轨迹 · 事态链 | 只读（播放用） |

**模式切换规则**：

| 规则 | 内容 |
|---|---|
| **不改数据** | 只改渲染与图层可见性。**换的是眼镜，不是世界** |
| **保留 `t`** | 切换视图模式**不移动时间轴** |
| **记住缩放** | 保持当前缩放与中心点 |
| **每模式独立记忆图层状态** | 从 A 切到 B 再切回 A，**恢复 A 的图层状态** |

### 1.13 地形笔刷与自然化

| 项 | 裁定 |
|---|---|
| 笔刷类型 | 圆形（可调半径）+ 方形（网格化）+ 套索（自由形状） |
| 笔刷模式 | **涂抹 / 擦除 / 平滑 / 替换** |

| 「自然化」技术语义 | **形态学开闭（去毛刺）+ 边界重采样 + 样条平滑（Catmull-Rom / Chaikin）**；**保留大尺度特征，只抹小尺度锯齿** |

| 🔴 关键风险 | **自然化过头 = 作者的刻意锯齿被抹掉**（如锯齿海岸线表达「多礁石」） |

### 1.14 海拔圈选

### 1.15 道路（三类）

| 类型 | 视觉 | 通行语义 |
|---|---|---|
| **大路** | 粗实线、浅色 | 全天候、快（高 `speed_mult`） |
| **小路** | 细实线 / 虚线 | 一般（基准速度） |
| **山路** | 点线 / 锯齿线 | 慢、受天气影响（低 `speed_mult`） |

> **关键裁定**：**道路不是画在地图上的线，而是距离图里的边（Edge）的可视化投影。**
> - 画道路 = **在地图上画一条线，同时在距离图里建一条边**（一个动作，两个产出）
> - 收益：免费得到行程计算 + 路径搜索；作者**不需要重复输入距离**
> - ⚠️ **给技术侧的约束**：`Edge` 必须**允许引用坐标点而非 Place**——否则画一条路要先建两个地点，摩擦太大

### 1.16 缩放交互

| 项 | 裁定 |
|---|---|
| **缩放范围** | `0.05× ~ 64×`（约 1280 倍跨度）。默认 `1×` = 整图入窗 |
| **缩放锚点** | **鼠标指针位置**（不是窗口中心） |
| **缩放方式** | 滚轮 / `+`/`-` 键 / 双指捏合 / 预设级按钮 / `Ctrl+滚轮` = 只缩放笔刷大小 |
| **平移** | **右键拖动优先** / 中键 / 空格+拖动 |
| **边界处理** | 允许拖出约 20% 视窗，不允许无限拖 |

**LOD 分级**：

| 缩放 | 名称 | 显示什么 | 隐藏什么 |
|---|---|---|---|
| 0.05×–0.15× | 全图概览 | 大陆轮廓、势力色块、主要城市点、事态链总览 | 道路、小地名、地形细节 |
| 0.15×–0.6× | 战略 | 全部城市点、主要道路、国境线、势力名、轨迹（简化） | 小地名、地形细节 |
| 0.6×–2× | **战术（默认）** | 全部 Place、全部道路、**完整轨迹**、地形、事件点 | 无（全开） |
| 2×–8× | 局部 | 上述 + Place 名称全显 + 更细地形 | 无 |
| 8×–64× | 室内/街道 | 房间/建筑轮廓、轨迹精细段、可编辑单点 | 大区域名 |

**LOD 硬规则**：

| # | 规则 |
|---|---|
| **L1** | **LOD 只改「显示多少」，不改「数据」** |
| **L2** | **LOD 不影响编辑能力**（极值级除外，如 0.05× 时禁用画地形并提示） |
| **L3** | **轨迹在低缩放下必须简化**（Douglas-Peucker，保留端点与拐点） |
| **L4** | **文字标签永不重叠**（按缩放自动降密度） |

### 1.17 核心创作循环：作者的典型一天

> **作者的每个动作都只落在「一个维度」上，但四维是同一份数据的五种视图，所以动一处，其他三处自然跟着动。**

| 作者的动作（一个界面） | 自动联动的维度 | 联动机制 |
|---|---|---|
| **改事件的时间** | 时间轴节点移动；事态链重排；校验重算 | 事件是 `span`，一切由 `TimelineQuery::at` 求值 |
| **改事态节点的地图** | 切换视图；切坐标系；切 LOD | 节点带 `map` |
| **画一条轨迹** | 距离图校验地点间是否有边；校验该主体位置是否矛盾 | 轨迹点引用 Place |
| **画一条道路** | 距离图新增 Edge；所有行程计算立刻更新 | 道路 = Edge 的投影 |
| **改角色的位置区间** | 与事态轨迹对照，矛盾则红/黄 | 四态校验 |
| **画势力边界** | 势力图色块变化；若带区间则随时间变化 | `GeometrySpan` |
| **拖时间轴** | 图层投影刷新；校验重算；顶栏日期变化 | `TimelineQuery::at(t)` |
| **切视图模式** | 基底与图层变；可用工具集变 | ViewMode |

### 1.20 UI 降级总则（跨文档通用规则 · 全项目单一权威）

> **来源**：Phase 2 动画总监（关建帧）与特效总监（霍炜然）经 3 轮往复共同提炼。
> **地位**：**不属动画或特效任何一家的私有章节**。后续任何新增视觉元素（含人物面板、时间轴面板、关系图谱）的降级取舍，**一律以本节为准**。
> **依据**：`docs/ANIMATION_SPEC_v0.1.md` §8.4/§8.5、`docs/VFX_SPEC_v0.1.md` §1.3。

#### R1 · 抑制三分类

| 类别 | 是否被抑制 | 判定含义 | 典型例子 |
|---|---|---|---|
| ① **状态** | **永不抑制** | 承载「当前是什么样」的信息 | 事件脉冲**常驻底环**、轨迹**节点点亮**、笔刷光标 **falloff 双环**、势力易主过渡的**描边终态 alpha** |
| ② **动效** | 可抑制（受 `intensity` / 速率控制） | 装饰性的往复、扫掠、弹跳 | 涟漪环、拐点弹跳、边界扫光 |
| ③ **语义动效** | **只受「触发条件」控制，不受速率抑制** | 携带「时间正在推进 / 事态仍在发生」这一语义 | 播放中的**流光线**（抑制它 = 丢失信息） |

> **结构说明（术语同构）**：「抑制三分类」是**上位概念**，① ② ③ 是它的**三个成员**。GLOSSARY 登记时按此层级结构并入，勿平列为 4 条。
>
> ```
> 抑制三分类（上位概念）  Suppression Classes
>   ├ ↳ 状态      State            成员①（永不抑制）
>   ├ ↳ 动效      Motion           成员②（高速档 / intensity=off 时抑制）
>   └ ↳ 语义动效  Semantic Motion  成员③（仅受触发条件控制，不受速率抑制）
> ```
> 两份规格（动画 §7.1 ↔ 特效 §10）已按此结构**逐行同构**，合并时可直接并。

#### R2 · 抑制判别口诀（两步可判定测试）

> **第 1 步**：「去掉它，作者会少看懂什么吗？」
> - **不会** → 属 **② 动效** → 可抑制。判定结束。
> - **会** → 进第 2 步。
>
> **第 2 步**：「丢的是**事实**，还是**『正在变化』**？」
> - 丢**事实** → 属 **① 状态** → **永不抑制**
> - 丢**「正在变化」** → 属 **③ 语义动效** → **不受速率抑制**（仅受触发条件控制）

两步判定比单步更稳：单步只能分离「状态 vs 动效」，无法区分「状态」与「语义动效」——而这两者的抑制规则**恰好相反**（一个永不抑制、一个不受速率抑制），必须分开。任何新元素都能当场判定，不必等清单扩充。

> **R2b · 判据的自检机制（完备性论证）**
> **若两步口诀对某个新元素给出「矛盾答案」，那就是「第四类」出现的信号 —— 必须扩充分类，而非硬套现有三档。**
>
> 这条把「三分类够不够用」从**主观偏好**变成**客观可判**：不需要争论要不要加第四类，**判据自己会在失效时报错**。R1–R4 因此具备**可扩展的完备性论证**，而不只是当下的经验归纳。
> **来源**：`docs/VFX_SPEC_v0.1.md` §1.3（特效总监提出）。

#### R3 · 混合案例的形式化（架构约束，非美术描述）

**势力易主过渡 = ① + ② 混合**：
- **描边 alpha 终态** = 状态（不抑制）
- **扫光** = 动效（可抑制）
- 二者**共享同一 `progress`（day 空间插值），各自独立强度乘子**

> ⚠️ **这是 shader 数据契约**：**一个时间标量进，多个强度乘子出**。实现时**严禁**简化为「一个 uniform 全管」——那会丢失独立降级能力。

#### R4 · 强度档位与作用范围

- 设置项 `animation.intensity ∈ { full, reduced, off }`（三档）
- **仅 L3 受 `intensity` 控制**；**L0 / L1 / L2 不受影响**（它们已足够克制，关掉反而丢失状态可见性）
- 动效分级 L0–L3 定义见 `docs/ANIMATION_SPEC_v0.1.md` §0

## 2. 架构篇（来源：柯桥良 · 技术架构总监）

### 2.1 crate 分层与依赖方向（含 D3 修正）

```
wv-app（应用层，Bevy）
   ↓
wv-edit ─────→ wv-io
   ↓             ↓
   └──→ wv-core ←┘        wv-terrain（与 wv-core 平行，互不依赖）
```

**依赖矩阵（行依赖列）**：

| ↓依赖→ | wv-core | wv-terrain | wv-io | wv-edit | wv-app |
|---|---|---|---|---|---|
| wv-core | — | ✗ | ✗ | ✗ | ✗ |
| wv-terrain | **✗** | — | ✗ | ✗ | ✗ |
| wv-io | ✓ | ✓ | — | ✗ | ✗ |
| **wv-edit** | ✓ | **✅（D3 修正）** | ✓ | — | ✗ |
| wv-app | ✓ | ✓ | ✓ | ✓ | — |

> **D3 裁定（用户确认）**：`wv-edit × wv-terrain` 由 ✗ 改为 **✓**。
> 理由：`PaintTerrainCommand::apply` 需调用 `wv_terrain::edit::paint`。这不违反依赖方向（wv-terrain 与 wv-core 平行，`wv-edit` 依赖平行的 wv-terrain 不构成环）。
> 备选方案 B（下沉进 core）与 C（trait 注入）均被拒绝（前者使 core 变重，后者过度工程）。

**最高优先级约束**：**`wv-core` 零 Bevy 依赖、零文件系统访问。**

### 2.2 `wv-terrain` 职责重划（关键裁决）

**裁定：v0.2 的「生成」与本轮的「编辑」是两个职责，但同 crate 内部按模块划分。**

| 维度 | v0.2「生成」 | 本轮「编辑」 | 是否同一职责 |
|---|---|---|---|
| 输入 | 噪声参数 | 用户笔刷轨迹 + 当前网格 | ❌ 不同 |
| 触发 | 工程初始化 / 调参 | 鼠标交互 / 命令 | ❌ 不同 |
| 可撤销 | 重新生成即覆盖 | 必须进 `EditCommand` 栈 | ❌ 不同 |
| 输出 | 海岸线**矢量** | 高度场**栅格** | ❌ 不同 |

**分工**：
- `wv-terrain` 内部两模块：`generate`（噪声）+ `edit`（笔刷/选区/自然化），**共享 `TerrainGrid`**
- 理由：两者都操作「栅格网格」，共享数据类型与数学工具；拆两个 crate 会制造循环依赖

**笔刷算法放哪一层**：

```
用户拖拽 → wv-app 采集笔刷轨迹（世界坐标）
         → 构造 PaintTerrainCommand { map, brush, stroke }
         → wv-edit 执行 → 内部调用 wv_terrain::edit::paint(&mut grid, &stroke)
         → 命令记录 before/after 影响块的旧值（用于 revert）
```

> **`wv-terrain` 不感知 Undo/Redo，`wv-edit` 不感知像素。**

### 2.3 地形数据：栅格 + 矢量（两者都要）

| 数据 | 形态 | 存储 | 理由 |
|---|---|---|---|
| **高度场 / 地形类型** | **栅格** | `RasterRef` → `terrain.bin`（I16 高度 + U8 类型，双通道） | 连续标量场，笔刷涂抹的本质是逐格写值 |
| **道路** | **矢量** | YAML `GeometrySpan` | 折线有拓扑语义（连接哪两个 Place） |
| **势力层边界** | **矢量** | YAML `GeometrySpan` | 多边形是离散边界，且**随时间变化** |

> **关键理由**：P3 只允许**地形网格**进二进制。若把道路/国境也塞进栅格，**违反 P3**，且丧失拓扑语义。反之若只用矢量，笔刷涂抹会产生海量多边形。**两者共存是 P3 与性能的双重强制。**

### 2.4 边界自然化算法（具体建议）

| 场景 | 算法 | 实现成本 | 建议 |
|---|---|---|---|
| **矢量边界自然化** | **Chaikin 曲线细分**（2 轮，~40 行）+ **Simplex/Perlin 噪声扰动**（振幅 ∝ 段长，~60 行） | **低（≈1 天）** | ✅ **采纳** |
| **栅格海岸线平滑** | Marching Squares 提取等值线 → Chaikin 简化 → 噪声扰动 → 回写 | **中（≈2-3 天）** | 🟡 **原型延后**，原型用「笔刷软边缘（falloff）」近似 |
| **选区升降海拔** | 高斯衰减权重：`h' = h + amount * exp(-d²/2σ²)` | **低（≈0.5 天）** | ✅ **采纳，原型必做** |

**原型必需部分 ≈ 1.5 天；Marching Squares 全套额外 2-3 天，可延后。**

### 2.5 势力层模型（D2 裁定后的定稿）

#### 2.5.1 模型的三层分离

```
势力层（FactionLayer）   ← 作者命名的一个「政治划分维度」，如「国界系统」「贵族体系」「派系」
   └── 势力（Faction）      ← 层内的一个实例，如「大陈」「北境省」「镇北侯」「雅各宾派」
          └── 隶属（Membership） ← 有向、多对多、跨层、带时间
```

**关键裁定**：**「层」与「势力」是两个层级的东西**。层是「一个划分维度」（作者命名），势力是「该维度下的具体条目」。

#### 2.5.2 Rust 结构定义（定稿）

```rust
/// 势力层。用户原话「国界、省份、贵族等等，都叫做势力层。可以命名，然后绘图」。
///
/// 这是 D2 裁定的核心：层是**数据**（作者可自由增删、命名），不是 `enum`。
/// 国界 / 省份 / 贵族领 / 派系 / 教团 / 行会**全是本结构的实例**。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct FactionLayer {
    pub id: Id,
    /// 作者命名的层名，如「国界」「贵族体系」「雅各宾派系」。
    pub name: String,
    /// 本层包含的势力条目。层内可重叠。
    #[serde(default)]
    pub factions: Vec<Faction>,
    /// 本层与其他层的隶属规则（可选，描述性的层间关系，仅作编辑器默认预设）。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub default_parent_layer: Option<Id>,
}

/// 层内的一个具体势力。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Faction {
    pub id: Id,
    pub name: String,
    /// 该势力的领土几何，**多边形集合**（每块一个 span）。
    ///
    /// D5 边界（模型完整 / 工具分期）：
    /// - 模型层**保留本字段**；
    /// - 第一版**不实现绘图工具**，此字段为空 `Vec`；
    /// - 第一版「势力」退化为「名字 + 归属」，靠 `memberships` 表达关系。
    /// - 纯追加，数据结构无需迁移。
    #[serde(default)]
    pub territory: Vec<GeometrySpan>,
    /// 本势力对其他势力的隶属关系（有向、可多条、可跨层）。
    #[serde(default)]
    pub memberships: Vec<Membership>,
}

/// 隶属关系。有向边：`from`（下级）隶属 `to`（上级）。
///
/// 为什么不是 `HashMap<Id, Vec<Id>>`：隶属关系需要携带属性（效忠？加盟？主从？），
/// 且需要自己的时间区间——所以它是一个**实体**，不是一条边。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Membership {
    /// 上级势力的 ID（被隶属方）。**可为人或势力层**（使「省属于王国」可表达）。
    pub to: Id,
    /// 关系类型（自由字符串，**刻意不做枚举**）。
    /// 理由与 D2 一致：关系类型同样是开放集（效忠/加盟/主从/结盟/纳贡/名义归属…）。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub kind: Option<String>,
    /// 该隶属关系的时间区间。隶属同样随时间变化（1789 年前属A，后属B）。
    #[serde(flatten)]
    pub span: TimeSpan,
}
```

#### 2.5.3 重叠判定规则（原「层内不重叠→报错」已废除）

| 编号 | 规则 | 内容 |
|---|---|---|
| **R1′** | **一切重叠合法** | 不存在任何「重叠即冲突」判定。任意数量、任意层的势力可覆盖同一点 |
| **R2′** | **查询返回「归属集合」** | 返回 `Vec<(layer_id, faction_id)>`，可含多项（如 3 贵族 + 1 省 + 1 派系） |
| **R3′** | **绘制顺序决定视觉叠压** | 由 `z` 决定；叠压是渲染语义，**不是数据冲突** |
| **R4′** | **无归属 = 无主地** | 归属集合为空 → 灰显，**不报错** |
| **R5′** | **归属集合按时间过滤** | 每条归属带 `TimeSpan`，查询时先按 `t` 过滤 |

#### 2.5.4 归属查询拆分为三个 API（主理人拦下的关键修正）

| API | 输入 | 输出 | D5 期（无几何）行为 |
|---|---|---|---|
| `query_at_point(map, point, t)` | 地图 + 坐标 + 时刻 | 归属集合 `Vec<(layer_id, faction_id)>` | ⚠️ **返回空**（无几何无法判定） |
| `memberships_of(entity_id, t)` | 任意实体 ID + 时刻 | 该实体的隶属关系列表 | ✅ **完全可用**（纯关系数据） |
| `subordinates_of(entity_id, t)` | 任意实体 ID + 时刻 | 下级势力 ID 列表（反向） | ✅ **完全可用** |

> **为什么必须拆**：`Membership` 是**边**（图数据），`territory` 是**面**（几何数据）。前者回答「谁隶属谁」，后者回答「这块地属于谁」。**数据源不同，API 必须分开。**
> **若合并 → D5 期会把「关系查询」这个零成本功能一起砍掉**（这正是主理人拦下的错误）。

**反向索引**：

| 问题 | 裁定 |
|---|---|
| 是否需要 | ✅ **需要**（`subordinates_of` 是反向查询，`Membership` 是正向存储，不做索引需遍历全部势力） |
| 建在哪层 | **`wv-core` 的查询辅助结构**（`MembershipIndex`），**不进数据模型**（派生数据，存盘即冗余） |
| 何时构建 | **`wv-io` 加载完后调用 `MembershipIndex::build(&world)`** |
| 失效策略 | 第一版**每次查询时重建**（N 小），标注 `TODO(阶段X)`，记入 README §12 |

#### 2.5.5 单层图的表达验证（用户法国例子）

**场景 A：一个贵族控制多个省**

```yaml
id: faction_domain_zhenbei

### 2.6 图层体系（D2 后的裁定）

**核心区分**：**枚举管「怎么画」，数据管「画什么」。**

| 概念 | 是什么 | 数量 | 载体 |
|---|---|---|---|
| **`LayerKind`（图层类别）** | 「这一类图层用什么渲染管线 / 什么编辑工具」 | **固定**（Terrain/Road/**Faction**/Custom…） | **枚举**（渲染管线确实是封闭集） |
| **势力层实例** | 「作者命名的那个具体的层」（国界/贵族体系/派系） | **动态、开放** | **数据**（`FactionLayer` 实体） |

### 2.7 新增实体：事态与轨迹（D1 裁定后）

```rust
/// 事态。U1 的「链实体」（原 `Campaign`，按 D1 改名）。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Situation {
    pub id: Id,
    pub name: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub summary: Option<String>,
    /// 事态包含的事件引用（**无序**，播放顺序由事件 `span.from` 升序派生）。
    #[serde(default)]
    pub steps: Vec<SituationStep>,
    /// 事态的整体时间范围。**必须覆盖其全部节点的时间**（不变式 I5）。
    /// 播放锁定在本区间内循环（§1.8）。
    #[serde(flatten)]
    pub span: TimeSpan,
    /// 本事实涉及的**单位**（归纳容器，ADR-0004）。与 `steps` 平行。
    /// **不直接列角色**——角色只能经 `Unit.members` 间接进入，避免「两个真相」。
    #[serde(default)]
    pub units: Vec<Id>,
    /// 可选的**叙事顺序**覆盖（D1 补充）：供倒叙/插叙编排。
    /// 为空时用时间派生；有值时按此列表顺序播放。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub narrative_order: Option<Vec<Id>>,
    #[serde(default)]
    pub maps: Vec<Id>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub protagonist: Option<Id>,
}

/// 事态的一步。**不含序号**（D1：顺序派生）。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct SituationStep {
    pub event: Id,
    #[serde(default)]
    pub focus: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub pause_secs: Option<f32>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub caption: Option<String>,
    /// 本节**引用**的轨迹（ADR-0004：轨迹归单位，事态节点只**引用**，可多对多）。
    #[serde(default)]
    pub tracks: Vec<Id>,
}

/// 单位。在地图上**独立运动的主体**（ADR-0004）。对应 `units/<id>.yaml`。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Unit {
    pub id: Id,
    pub name: String,
    /// 归属主体（角色或势力）。**可无主**——如「中央红军」不隶属任何个人。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub owner: Option<Id>,
    /// 成员角色 ID 列表。复合单位的领导 / 成员；单人单位填 1 个。
    #[serde(default)]
    pub members: Vec<Id>,
}

/// 轨迹。独立实体（避免 P4 复制——同一条轨迹被两条事态引用时不重复存储）。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Track {
    pub id: Id,
    /// 运动主体：**单位**（`UnitId`），不是含糊的「角色或势力」（ADR-0004）。
    pub unit: Id,
    /// 轨迹发生的地图（决定坐标系与 LOD）。
    pub map: Id,
    /// 轨迹的时间区间（半开 `[from, to)`）。
    #[serde(flatten)]
    pub span: TimeSpan,
    /// 途经点序列。
    pub waypoints: Vec<Waypoint>,
    /// 轨迹的几何表达（用于渲染连线）。可选。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub path: Option<GeometryData>,
}

/// 轨迹上的一个途经点。
#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Waypoint {
    /// 到达该点的时间（天数计数器）。**可选**（无 = 顺序点，不参与校验）。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub day: Option<i64>,
    /// 该点在 `map` 内的局部坐标。与 `place` 二选一（place 优先）。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub pos: Option<Point>,
    /// 该点对应的地点（可选）。若有，则与 `Place` 图对齐，可用于距离校验。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub place: Option<Id>,
}
```

**排序派生规则**：

| 情况 | 播放顺序 |
|---|---|
| `narrative_order == None` | 按 `step.event` 对应 `Event.span.from` **升序** |
| `narrative_order == Some(list)` | 按 `list` 顺序；未覆盖的 step 追加其后（按时间升序） |

> **实现位置**：`wv-core` 提供纯函数 `Situation::playback_order(&self, events: &[Event]) -> Vec<Id>`（可单测）。`wv-app` 只调用它。**不在渲染层排序。**

### 2.10 多边形集合语义（定稿）

**裁定：`territory: Vec<GeometrySpan>` 已足够表达「多边形集合」，无需新增 `MultiPolygon`。**

| # | 理由 |
|---|---|
| ① | **每块可带独立 `TimeSpan`** → 「A 地块 1800 年割让、B 地块 1820 年并入」可直接表达（**比 `MultiPolygon` 更强**） |
| ② | 每块可带独立 `owner`/`map` → 跨地图领土可表达 |
| ③ | **无新增枚举变体** → 旧 YAML 兼容 |
| ④ | 渲染侧「每个 span 转成一段 Mesh」，块数 = Vec 长度，自然对应 |

**带洞多边形**：❌ **第一版不支持**，**显式记入 README §12**。
- `GeometryData::Polygon` 是**单环扁平点列**，无内环概念
- 作者第一版可用**多个无洞多边形绕过空洞**（如「回」字拆四块）
- **回退成本低**（未来给 `GeometryData` 加 `PolygonWithHoles { outer, holes }` 变体，非破坏扩展）

### 2.11 渲染架构（Bevy 侧）

| 图层类型 | 渲染手段 | 理由 |
|---|---|---|
| **栅格地形** | **`Assets<Image>` 单纹理 + `Sprite`/`Mesh` 四边形** | 1 Draw Call 画完整张地形；笔刷修改后只重传脏块 |
| **矢量图层** | **自建 Mesh**（`LineStrip`/`LineList` + `ColorMaterial`） | `GeometryData` 直接映射顶点；避免每段一个 sprite |
| **事件点 / Place 标记** | `Sprite`（billboard 图标） | 数量少 |
| **轨迹** | 复用矢量 Mesh（`LineStrip`）+ 动画着色器 | 与道路同管线 |

**栅格渲染细节**：
- 分块（256×256）上传，视口外的块不加载（LOD 基础）
- **笔刷增量更新**：`Image::data` 只 patch 脏块区域，**不要每帧重建整图**

**性能预估**（60 FPS，2D 俯视）：

| 网格尺寸 | 纹理内存 | 帧率判断 |
|---|---|---|
| 512×512 | ~0.5 MB | 轻松 60 FPS |
| 1024×1024（**原型目标**） | ~2 MB | 60 FPS 无压力 |
| 4096×4096 | ~32 MB | 60 FPS 可行 |
| 8192×8192 | ~128 MB | **必须分块** |

### 2.14 「事态播放」的渲染机制（必须走 `TimelineQuery::at`）

**AGENTS §3.2 硬约束**：禁止在渲染层做时间比较。

```
用户拖时间轴 / 点播放 → 更新 PlaybackState.current_day: i64
    ↓（拉动式刷新）
每帧：for situation in situations {
        let active_events = TimelineQuery::at(situation_event_spans, current_day);
      }
      对 tracks：插值出每个 track 在 current_day 的位置
    ↓
把结果写入 Bevy 资源（EventHighlights / TrackPositions）
    ↓
渲染 System 只读资源，不做任何时间判断
```

| 播放表现 | 实现 |
|---|---|
| **事件正在发生** | 命中 `TimelineQuery::at` 的事件点 → 高亮 sprite |
| **轨迹动画** | 每个 `Track` 在 `current_day` 用 `waypoints` 线性插值出位置 → 移动 marker sprite |
| **播放器推进** | `PlaybackState` 资源持 `current_day` + `speed`；每帧 `if playing { current_day += speed * dt }`（**UI 状态推进，不是世界数据修改**） |
| **跨图播放** | `Situation.maps` 内有城市图时，播放器自动切换当前渲染的地图 |

> **关键区分**：`current_day` 是**视图状态**（Bevy Resource），**不是世界数据**。世界数据里的时间一律是 `TimeSpan`。

### 2.15 坐标系统与变换链

| 坐标系 | 用途 | 定义 |
|---|---|---|
| **世界坐标** | 全局唯一参考系 | 一个工程一个，原点 (0,0)。`Extent` 描述各图在世界坐标中的位置 |
| **图内局部坐标** | 单张图的内部绘制 | `GeometryData` 的点列 |
| **图内归一化坐标（UV）** | 栅格采样 | `[0,1]×[0,1]` |

**`Extent` 扩展**（非破坏）：

```rust
pub struct Extent {
    pub width: f32,
    pub height: f32,
    /// 该图左上角在**父图**局部坐标中的位置。World 层 origin = (0,0)。
    #[serde(default)]
    pub origin: Point,
}
```

**变换链**：

```
数据层几何点列（图内局部坐标）
   ↓ + extent.origin + 逐层上溯到世界坐标
世界坐标
   ↓ × Camera.Transform.scale
相机视图坐标
   ↓ + Camera.Transform.translation
屏幕像素坐标
```

> **一个 `coord` 模块集中实现两个方向的变换，禁止在多个 System 里各写一遍。**

### 2.19 性能预算

| 指标 | 目标 | 测量方式 | 超阈处置 | 类型 |
|---|---|---|---|---|

### 2.21 引用完整性校验（新增）

| 项 | 内容 |
|---|---|

### 2.22 诊断分层：提示与错误在类型层面分开（2026-10-11 新增）

> 详见 `docs/adr/ADR-0005-encounter-hint.md`。本节把该 ADR 的可执行部分摘进基线。

| 项 | 内容 |
|---|---|
| **两个入口** | `Project::validate()` → **硬失败**（CI / 加载前把关）；`Project::diagnose()` → **永不失败**，返回结构化 `Diagnostics`（编辑器校验面板） |
| **`DiagLevel`** | `Hint`（提示：只列出，不阻止保存）/ `Error`（错误：数据坏了，拦保存） |
| **保存闸门** | `Diagnostics::has_errors()` 为假即可保存——**只有提示不阻断**（§7.5 V1） |
| **稳定标识** | 每条诊断带 `fingerprint`，供 UI 做「已读 / 已忽略」状态锚定 |
| **定位锚点** | 可选 `DiagAnchor { map, at, day }`——点击提示跳到地图坐标并拨动时间轴 |

#### 相遇检测（派生，不落盘）

> 用户裁定：「他们相遇，但是没有事情发生，那么就是啥事都没有。」+「后期安排再相遇……就可以提及此地」。

| 项 | 内容 |
|---|---|
| **性质** | **派生数据**（两条轨迹时空交叉），**不建实体、不落盘** |
| **判定三道门** | ① 时间重叠（同一 day 都在场）② 空间贴近（距离 ≤ 阈值）③ **未被事件覆盖** |
| **已被覆盖则静默** | 相遇处有事件（`span` 重叠 + `place` 相同）→ 不提示。**这是最扰民情形的唯一防线** |
| **跨地图跳过** | `ta.map != tb.map` → 坐标系不可比（ADR-0003 跨图靠 `PlaceId`，不靠坐标） |
| **候选日用锚点** | 候选日 = 轨迹的**带 `day` 的 waypoint**。**不逐日枚举**——`day` 是天数计数器，跨千年史实会卡死 |
| **指纹不含日期** | `{单位A}\|{单位B}\|{地点}`（单位按字典序归并）。含日期会导致停留多日则刷屏、作者微调锚点则提示「换一条」→ 无法认领 |
| **阈值** | `PROXIMITY = 1.0`（地图局部坐标单位）。**待裁**：应随缩放级别自适应（ADR-0005 §待裁 H2） |

## 3. 美术篇（来源：甄塑之 · 美术总监）

> 完整内容见 `docs/ART_STYLE_SPEC_v0.1.md`（593 行）。此处摘录关键裁定。

### 3.1 总纲：两层分离

> **地图是「画出来的世界」（JRPG，可换皮）；软件壳是「量出来的工作台」（工具型，不换皮）。两者的唯一接头是"色板令牌"与"位图契约"。**

| 层 | 是否可替换 | 内容 |
|---|---|---|
| **THEME PACK（地图风格包）** | ✅ **可整体替换** | palette / tileset / 地物符号 / 派系纹样 / 地貌笔触 / 图例装饰 |
| **LOCKED SHELL（软件壳）** | ❌ **不替换** | 面板架构 / 字体层级 / 间距刻度 / 控件状态 / 图标语言 |

**唯一接头**：① **色板令牌**（`ui_link.*` 三语义色）② **位图契约**（尺寸档位 / 命名格式 / 图集切分规则）。

**为什么必须解耦（三条硬理由）**：
1. **信息密度冲突**：JRPG 地图语言是大格子大图标；编辑器要在 1 屏呈现地图+时间轴+Inspector+校验，粗描线会吃掉信息密度
2. **寿命冲突**：地图 pack 是**内容**（会被替换）；软件壳是**外壳**（跟产品走）
3. **承包商冲突**：地图资产可外包（按契约交付）；软件壳必须主程序维护

### 3.2 风格定义

> **「十六位机晚期的日式 RPG 手绘质感 —— 高饱和水彩打底 + 硬边描线 + 斜投影俯瞰」**

| 维度 | 规格化定义 |
|---|---|
| **视角** | **斜投影俯瞰（2.5D oblique top-down）**，非等距菱形。地格为**正方形**，垂直按 `0.5×` 压缩 |
| **描线** | **外轮廓硬边描线**，线宽 = 图块边长的 **1/16**（32px → 2px）；**深色但不纯黑**（基色明度 −45% 同色相） |
| **上色** | **平涂为主 + 单层软阴影**；光源**左上偏上 45°**；阴影为**同色相压暗** |
| **饱和度** | 主调中高饱和（S **45%–75%**），明度偏高（V **60%–90%**）；大地色系单独降到 S **25%–40%** |

**明确排除**：3D 写实、像素风（Pixel Art）、低多边形、厚涂写实赛璐璐。

### 3.3 色板结构（28 色）

```
ThemePalette
├─ core        ── 10 色：地形基色（水/沙/草/林/丘/山/雪/岩/沼/路）
├─ faction     ── 8 色：派系势力色（含玩家方）
├─ ui_link     ── 3 色：地图与界面共享的语义色（可达绿/迟到黄/不可达红）
├─ line        ── 3 色：描线色（浅底/中底/深底 三档）
└─ accent      ── 4 色：强调色（选中/高亮/时间轴游标/事件标记）
   合计 28 色（低于 64 色上限，留扩容余量）
```

**色板硬约束（可自动校验）**：
1. `ui_link.*` 三色为**语义色**，色相不作替换（色相差 ≤ 8°）
2. **派系色两两之间**：CIEDE2000 ΔE ≥ 25，色相差 ≥ 30°（相邻势力 ΔE ≥ 35）
3. **任意派系色 vs 任意地形基色**：ΔE ≥ 30
4. **颜色不得是唯一信息载体**：四态校验必须叠加形状/线型；派系范围必须带边界线型或纹理填充
5. 全部色值以 sRGB 十六进制书写

| **事态** | Situation | 一段有始有终的大事，**归纳容器 / group**：收拢若干事件节点（`steps`）与相关**单位**（`units`），节点可引用轨迹。是组织层，**不是** Event 的字段 | 事件 |
| **事态节点** | SituationStep | 事态的组成单元，**引用**一个 `EventId`，可带「链视角注释」与**轨迹引用**；**不复制事件内容** | 事件 |
| **单位** | Unit | 在地图上**独立运动的主体**（ADR-0004）。可引用角色 / 势力作 `owner`，也可**无主**（如「中央红军」）；`members` 列出成员角色。与 `Character` **分离**——单人移动也建 Unit | 事件 / 距离 |
| **轨迹** | Track | 某个**单位**在某张地图上的一段运动记录（waypoint 点列，点可选带时间戳）。运动主体是 `Track.unit`；事态节点通过 ID **引用**它（**多对多**）——运动不归事态（ADR-0004 修正原「挂在事态节点上」口径） | 事件 / 距离 |
| **相遇提示** | Encounter Hint | 两个单位同时同地、而作者**未写事件**时给出的**提示**（ADR-0005）。判定三道门：时间重叠 + 空间贴近 + **未被事件覆盖**；命中已被覆盖则静默。**永不报错、不阻止保存**——留白是创作手段 | 编辑 |
| **相遇指纹** | Encounter Fingerprint | 提示的**稳定标识** `{单位A}\|{单位B}\|{地点}`（单位按字典序归并）。**刻意不含日期**——否则作者微调锚点会让提示「换一条」，永远认领不掉（ADR-0005 决策 4） | 编辑 |
| **诊断** | Diagnostic | 编辑器校验面板的一条结构化条目。`DiagLevel` 分**提示（Hint）**与**错误（Error）**：提示只列出、不阻止保存；错误才拦（ADR-0005 决策 5）。每条带 `fingerprint`（供认领）与可选 `anchor`（供点击定位） | 编辑 |
| **航点** | Waypoint | 轨迹上的一个点。二选一：引用 `PlaceId`（城市/室内推荐）或裸坐标 `(x,y)`（世界/区域荒野） | 距离 |
| **播放** | Playback | 时间轴以固定速率自动推进；**锁定在某个事态的 `span` 内**。不是独立播放器实体 | 时间 |
| **视图模式** | ViewMode | 地图基底的渲染方式 + 默认图层组合 + 可用工具集的三合一开关。四态：真实地形 / 色块地形 / 势力图 / 事件图 | 地理 |
| **色块地形** | Schematic Terrain | 一种视图模式：每种地形一种纯色，无立体感 | 地理 |
| **势力层** | Faction Layer | 一个可命名、可绘图、可重叠的区域集合；作者自定义其含义（国界/省份/贵族领/派系/教团/行会…）。**不预设角色，数量由作者定** | 地理 |
| **势力** | Faction | 势力层内的一个具体条目（如「大陈」「北境省」「镇北侯」「雅各宾派」） | 地理 |
| **势力归属** | Membership | 实体（人 **或** 势力层）与势力层之间的**多对多**归属关系，带**作者自定义的类型标签（String，非枚举）**与时间区间 | 地理 |
| **无主地** | Unclaimed | 所有势力层均未覆盖的区域，UI 灰显，**不报错** | 地理 |
| **声称 / 实控** | Claim / Control | 势力范围的两层语义：纸面声称 vs 实际管辖。**必须分开存储** | 地理 |
| **自然化** | Naturalize | 对笔刷所画区域的边界做去毛刺 + 样条平滑，保留大尺度特征、抹除小尺度锯齿 | 地理 |
| **沉浸模式** | Immersive Mode | 一键将所有浮动面板淡出至 10% 透明度，专注看地图 | 编辑 |
| **世界坐标** | World Space | 工程唯一的全局参考系，`Extent.origin` 描述各图在其父图中的位置 | 地理 |
| **图内局部坐标** | Local Space | 单张图内部的坐标，即 `GeometryData` 点列所用坐标系 | 地理 |
| **地形网格** | TerrainGrid | `wv-terrain` 的核心数据结构，承载高度场与地形类型 | 地理 |
| **衰减权重** | Falloff | 笔刷/选区按距离衰减的影响系数（高斯），用于软边缘与选区升降 | 编辑 |
| **主题包** | Theme Pack | 可整体替换的地图风格包（一个目录 + manifest + 5 类资产） | 美术 |
| **软件壳** | Locked Shell | 不替换的 UI 外壳（面板架构/字体/间距/图标语言） | 美术 |

### 5.1b Phase 2 新增术语（动画 / 特效 / 音效）

> 本节为 🔗 汇总索引；各规格内另有各自的完整术语表（供 GLOSSARY 合并）。

| 术语 | 英文 | 定义 | 来源 |
|---|---|---|---|
| **抑制三分类** | Suppression Triage | 状态 / 动效 / 语义动效 三类，决定某视觉元素是否被 `intensity` 或速率抑制。**全项目单一权威见 §1.20** | 动画 §8.4 + 特效 §1.3 |
| **抑制判别口诀** | — | 两步判定：「去掉它会少看懂什么吗？」→ 不会=动效；会 →「丢事实还是丢『正在变化』？」→ 事实=状态 / 正在变化=语义动效 | 同上 |
| **动效分级** | Motion Tier | L0 瞬变 / L1 微反馈 80–120ms / L2 状态过渡 140–200ms / L3 强调动效。**仅 L3 可关闭** | 动画 §0 |
| **强度档位** | Intensity Level | `animation.intensity ∈ { full, reduced, off }`，只作用于 L3 | 动画 §0 |
| **生长笔尖** | Growth Head | 轨迹「已生长」末端的 6px 实心圆点，指示当前走到哪。**原称「发光游标」，已统一** | 动画 §1.2 |
| **当前时刻指示色** | Current-Time Color | `accent.cursor` 的语义：呈现于**时间轴游标 + 生长笔尖**两处（同一个 `current_day` 的两个视图）。**禁止拆成两个令牌** | 动画 §7.1 |
| **推算轨迹** | — | 顺序点（无时间戳）轨迹，由**均分到事态 span** 插值决定，不参与校验 | 动画 §1.3 |
| **粗轨迹** | Coarse Track | 只两端点（T3）的轨迹。与精轨迹**同视觉待遇**，仅加空心起点 + 极淡 `≈` 标识 | 动画 §1 |
| **状态—动效判别（R1–R4）** | State vs Motion Rule | §1.20 四条规则的合称 | 动画 + 特效 |
| **滞回** | Hysteresis | LOD 切换用 **±2%** 阈值防抖，避免连续缩放时一节节闪 | 动画 §4 |
| **元素级软切换** | Per-element Soft Switch | LOD 切换以元素为单位过渡，**不做全屏淡化** | 动画 §4 |
| **性质纹理** | Nature Texture | 势力层的斜纹 / 网点 / 十字纹，用于区分多层势力的性质。**归属待裁**（§4.2） | 特效 §1 |
| **四维描边语法** | — | 势力描边的四个正交维度：**色 / 粗 / 线型 / 偏移**，用于区分 ≥3 层嵌套势力 | 特效 §1 |
| **常驻底环** | Persistent Base Ring | 事件脉冲的**不闪烁**内环（1.0R, alpha 0.25）——属**状态**，高速档保留 | 特效 §4.2 |
| **涟漪环** | Ripple Ring | 事件脉冲的外扩环（1.0R→1.6R, alpha 0.5→0, 2.4s）——属**动效**，高速档暂停 | 特效 §4.2 |
| **锚点脉冲** | Anchor Pulse | 自然化完成后 60ms 的呼吸锚点反馈 | 动画 §3 |
| **falloff 双环** | Falloff Dual Ring | 笔刷光标的内外衰减双环可视化——属**状态**，不降级 | 特效 §2 |

### 5.1c Phase 2 明确「设计上不做」项（负向清单，供 GLOSSARY 反向登记）

| 项 | 所属 | 理由（一句话） |
|---|---|---|
| BGM / 环境音 / 氛围音 | 音效 | 编辑器不是游戏 |
| UI 点击音 | 音效 | 零信息增量 |
| **笔刷与一切连续操作音效** | 音效 | 视觉反馈密度已足够 |
| 加载完成音 / 游戏化音效 / 空间音频 | 音效 | 同上 |
| 墨水扩散（笔刷涂抹延迟） | 动画 | 所见即所得不可妥协 |
| 角色拖尾 | 动画 | 与「位置唯一性校验」冲突 |
| 撤销倒放录像 | 动画 | 撤销不是回放 |
| 缩放 / 平移惯性 | 动画 | 跟手优先于顺滑 |
| 全屏 LOD 淡化 | 动画 | 连续缩放会一节节闪 |

## 7. 主理人在本轮拦下的问题（值得复用）

| # | 问题 | 拦截价值 |
|---|---|---|
| **1** | 「事态」本体的**命名与排序语义冲突**：游有方说「只能时间派生」，柯桥良说「可手动排序」 | 若采纳柯桥良，则正中游有方标的 🔴 高风险（两个真相）。**倒叙是呈现技法，不是事件顺序** |
