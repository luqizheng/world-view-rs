## 〇、一句话结论

> **不漂亮不是配色问题，是两个数字问题：近看每格只有 4 个像素，远看每格只有 1.5 个屏幕像素。**
>
> 前者让手绘细节在数据里根本不存在（描线该 2px，实有 0.25px）；后者让「构图」无处发力（色块一片、山是三角点）。
>
> **修法不是继续调色、加颗粒、加图标，而是换掉底图的生成方式**：
> 从「CPU 把每格定值烘焙成一张 4096² 位图」改成「GPU 按屏幕像素逐点求值」。
> 位图有分辨率上限，逐像素求值没有 —— 这是唯一能同时解决「放大糊」和「缩小散」的架构。

## 一、诊断：为什么现在不漂亮

### 1.1 近观：4 像素/格的物理上限

**事实链（可复算）**：

| 项 | 值 | 出处 |
|---|---|---|
| 演示图格数 | 1024 × 1024 | `examples/work-view-test` |
| 烘焙纹理边长 | 4096 px（硬上限） | `terrain_view/tile_atlas.rs:140` `tile_res_for()` = `(4096 / cells).clamp(1, 64)` |
| 每格分配像素 | **4 × 4 px** | 4096 / 1024 = 4 |
| 单格世界尺寸 | 8 世界单位 | `state.rs:1083` `GridConfig::cell_size` |
| 近观一格屏幕尺寸 | ≈ 32 px（scale ≈ 0.25） | `cell_size / scale` |
| **放大倍率** | **8×** | 32 / 4 |

**推论（这是全部问题的源头）**：

1. 规格书 §3.1 要求「描线宽 = 图块边长 1/16」。32px 图块 → 2px 线。落在 4px 的格上 = **0.25 texel**。**这条规格在当前管线里物理不可实现**——不是没画，是画不出来。
2. 规格书 §3.3 要求「海岸线 ±2px 抖动」「树冠直径 = 格边长 /4」。4px 格上分别对应 0.25px 与 1px，都低于可表达下限。
3. 于是实现只能退到「每格一个纯色 + 边界处按像素插值」。放大 8 倍后，双线性插值把 4px 的色阶拉成 32px 的糊块，格子边界成为可见阶梯 —— **`docs/codex-assets/climate-preview-mountains.png` 里海岸线的锯齿就是这个**，不是抗锯齿没开，是采样率不够。

> **一句话**：现在的地图是一张 1024×1024 的「低分辨率彩色马赛克」被放大 8 倍看，任何后处理都救不回被丢掉的 60 倍信息量。

### 1.2 远观：1.5 像素/格的构图真空

**事实链**：

| 项 | 值 |
|---|---|
| 整幅地图世界尺寸 | 1024 × 8 = 8192 世界单位 |
| 1600px 窗口 fit 时 scale | ≈ 5.12（世界单位/屏幕像素） |
| **fit 时一格屏幕尺寸** | **8 / 5.12 ≈ 1.56 px** |

**推论**：默认打开工程时（fit 全图），一格不到 2 个屏幕像素。这个尺度下：

- **细节全部消失**（1.5px 里塞不下任何纹理）；
- 玩家/作者实际读到的是**大尺度构图**：海陆比例、色块分区、山链走向、河谷、路网。

而参考图（`docs/codex-assets/ref-map.jpg`）在这个尺度下**非常好看**，它靠的恰恰不是细节，是四件事：

| 参考图的构图手段 | 当前实现 | 差距 |
|---|---|---|
| 每片地貌是一个**有边界的色块**，色块之间有淡墨线 | 单一色域平涂，无区域概念 | 缺「区域」这一层 |
| 山是**连绵山链**（3–5 段山脊 + 受光/背光两面） | 稀疏三角 primitive，间距 72px，高 1.6 格 | 缺山链语法 |
| 海岸有**三段色带**（滩 / 浅 / 深，约 1:2:6） | 单条蓝描边带，跟着格子走 | 缺色带梯度 |
| 整幅覆盖**纸纤维 + 水彩晕染**（每色域 3–4 阶明度） | 0.12α 雾 + 0.035α 屏噪点 | 缺材质层 |

### 1.3 五条现象 → 根因对表

| # | 现象（实机截图可见） | 直接原因 | 根因 | 代码位置 |
|---|---|---|---|---|
| 1 | 放大后糊 + 海岸阶梯锯齿 | 4px/格被拉伸 8× | 纹理有分辨率上限 | `tile_atlas.rs:140`、`cells.rs` 烘焙 |
| 2 | 海岸线是一条「会拐弯的色带」，不是一条线 | 边界靠逐像素改色，线宽只能 1–4px 且贴格 | 无连续距离场 | `cells.rs::write_coast_boundary_cell` |
| 3 | 山像灰色三角堆，没有体积 | primitive 三角 + 单色影面 | 无图集资产、无受光模型 | `terrain_decor.rs::site_primitives` |
| 4 | 远观一片糊，读不出「这是哪块地方」 | 仅按 biome 平涂，无区域分层 | 缺构图层 | 无（`ADR-0045` 只做了数据模型，未接渲染） |
| 5 | 整体像「地图软件的截图」，不像「画的地图」 | 只有纯色，无纸/水彩/墨三材质 | 材质层缺席 | `atmosphere.rs`（仅雾 + 噪点） |

> **诚实标注**：问题 3/4/5 在 `ADR-0042` 已经识别过一轮（「填充色退后、图标层向前」），方向对，但**被执行方式（增密三角 primitive）卡在同一个分辨率陷阱里**——三角画得再准，落在 4px 的格里也只能是灰色小块。**这才是本轮必须换架构、而不是再调参数的原因。**

## 二、决策：推翻什么、保留什么

> 「推翻」= 该路径不再作为默认观感来源，代码保留一版可切回（渐进迁移，不做大爆炸重写）。

| # | 决策 | 类型 | 依据 |
|---|---|---|---|
| **D1** | 底图默认路径：**CPU 烘焙单张整图纹理 → GPU 逐像素求值** | **推翻** | §1.1：位图有分辨率上限，逐像素没有 |
| **D2** | 边界处理：**像素级 `wobble_px` 抖动 → SDF 距离场 + 世界坐标域扭曲** | **推翻** | §1.2：抖动让阶梯更明显；距离场让岸线连续且可抗锯齿 |
| **D3** | 地物：**Mesh2d primitive 三角/圆 → 图集实例化 Sprite** | **推翻** | §1.3-3：形状语言需要画出来的资产，不是几何体 |
| **D4** | 数据模型：`TerrainData{height, surface, biome}` **三通道不动** | 保留 | AGENTS §4、P7；渲染是投影，不是事实 |
| **D5** | 色板：`PaletteColors` / `ThemePack` 令牌体系不动，改为 shader uniform | 保留 | ADR-0023 / 0043 契约不变，只换消费方式 |
| **D6** | 视图模式：`ViewMode` 七档全部保留，改为 uniform 分支 | 保留 | 基线 §1.10 四态是产品能力 |
| **D7** | 主题可换：换 pack = 换 uniform + 换图集，零代码 | 保留 | 规格书 §2.B.2 验收口径 |
| **D8** | 构图：新增「区域层」与「纸材质层」，作为独立 Z 序图层 | **新增** | §1.2：远观靠构图，不靠细节 |
| **D9** | 规格书：`ART_STYLE_SPEC` 增补 §3.8「渲染实现契约」（以屏幕像素为单位定义线宽/抖动/色带），原文不改 | **新增** | §6.3 追写不改；§3.3 的「±2px」在 4px 格上无法执行，必须给出屏幕像素口径 |

**被否决的备选（也写清为什么）**：

| 备选 | 为什么否决 |
|---|---|
| 把烘焙纹理上限提到 8192² / 16384² | 1024 格仍只有 8px/格；且 16384² = 1 GB 显存，`ADR-0020` 的分块/拣选全部白做 |
| 分块烘焙、每块每格 16px | 每块（256 格 × 16px）= 4096² = 67 MB，视口 9 块 = 600 MB。显存与 CPU 重烘时间都不可接受 |
| 上 autotile 47 块全集 | 解决的是「拼接」，不解决「放大糊」；且与规格书 §3.2.1「不做 47 块」冲突 |
| 继续调色板（再来一版 ADR-0035） | 已连调三轮（0016 → 0035 → 0042 → 0048），每次都是「截图好看一点、放大还是糊」。该换层了 |
| 全盘矢量等值线（`TERRAIN_RENDER_PLAN` D3-A） | 方向正确、成本更高（等值线提取 + 多边形三角化 + 填充），且**海面/颗粒/渐变仍需栅格求值**。本方案的 shader 路径能在同一套数据上先拿到 80% 效果，矢量路径作为 P5 之后的可选演进 |

## 三、目标架构

### 3.1 数据流

```
TerrainData (wv-core, 不变)
  height: i16  surface: u8  biome: u8        ┌── 一次性/编辑时增量 ──┐
        │                                    │                       │
        ▼                                    ▼                       │
┌──────────────────┐   ┌──────────────────────────────┐              │
│ 数据纹理打包      │   │ SDF 生成器（CPU，脏矩形）      │              │
│ height R16Unorm  │   │ distance_to_coast R16Unorm    │              │
│ attr   RGBA8     │   │ （Felzenszwalb EDT，O(N)）     │              │
└────────┬─────────┘   └──────────────┬───────────────┘              │
         │  上传 GPU（7 MB / 图）      │                              │
         ▼                            ▼                              │
┌─────────────────────────────────────────────────────────┐         │
│ TerrainFieldMaterial（Material2d + WGSL，全屏 quad / 图幅 quad）│         │
│  uniform: 色板 16 色 · 线宽 · 雾 · 海配方 · 视图模式 · 缩放     │         │
│  fragment 阶段：扭曲 → SDF → 基色 → 明暗 → 水彩 → 墨线 → 颗粒   │         │
└────────────────────────┬────────────────────────────────┘         │
                         ▼                                          │
┌───────────┐  ┌──────────────┐  ┌──────────────┐  ┌────────────┐  │
│ 纸底 Z=0  │→ │ 地形场 Z=1    │→ │ 区域/路网 Z=2 │→ │ 地物 Z=3    │  │
│ 纸色+纤维 │  │ shader 输出   │  │ 势力/道路/等深 │  │ 图集 Sprite │  │
└───────────┘  └──────────────┘  └──────────────┘  └────────────┘  │
                                                     → 标注 Z=4      │
                                                     → UI Z=5        │
```

### 3.2 为什么是「图幅 quad」而不是「chunk」

现行 `terrain_chunks.rs`（1289 行）做视口拣选 + CPU mip 链，**是为「大位图」服务的补丁**。逐像素求值后：

- 一个 quad 覆盖整个图幅即可，GPU 只对**视口内实际像素**着色（光栅化天然裁掉视口外）；
- mip 链由 shader 的 LOD 分支替代（§4.7）；
- `CHUNK_SIZE` 那套逻辑保留但降级为「编辑态脏区重绘」的登记器。

> **净效果**：`terrain_chunks.rs` 从「性能命脉」降级为「可选的批处理优化」，代码不再增长；`cells.rs`（2879 行）的烘焙主路径退役为回退路径。

## 四、关键技术细节

> 本节是施工依据。所有数值都是**可以写进代码并验收的**，不是「建议」。

### 4.1 三张数据纹理（精确格式）

| 纹理 | 格式 | 尺寸（1024² 图） | 采样方式 | 内容 |
|---|---|---|---|---|
| `height` | `R16Unorm` | 1024² × 2 B = **2 MB** | `Linear` | `h_norm = (h - H_MIN) / (H_MAX - H_MIN)`，`H_MIN = -4000`，`H_MAX = 6000`（米）。精度 10000/65535 ≈ **0.15 m** |
| `attr` | `Rgba8Unorm` | 1024² × 4 B = **4 MB** | **`Nearest`** | `R = surface`（0 水 / 1 陆）、`G = biome`（0–255）、`B = 预留（湿度）`、`A = 预留（覆盖物键）` |
| `coast_dist` | `R16Unorm` | 1024² × 2 B = **2 MB** | `Linear` | 每格到最近**异类格**（水↔陆）的距离，单位**格**，编码 `d / 32`（覆盖 0–32 格） |

**总计 8 MB**，对比现行整图纹理 4096² × 4 B = **67 MB**。另外**零 mip 链**（现行 3 级 × 16 chunk 是额外 ~100 MB 级别的分配）。

**三个必须写对的点**：

1. **`attr` 必须 `Nearest`**。biome 是 ID 不是数值，线性插值 `biome 3` 与 `biome 7` 得到 `5` 是**语义错误**（5 可能是「雪原」）。这是自研地形渲染最常见的翻车点。
2. **`height` 必须可 `Linear`**，否则硬件不帮你插值，你得在 shader 里做 9 次 `texelFetch`。
3. **`coast_dist` 用「到异类格距离」而不是「到海平面等深线距离」**。原因：`surface` 是 authoring 真值（`wv-core` 明确「不由高度推断」），海岸的权威边界是 `surface` 翻转处，不是 `height` 过零处。两者不一致时以 `surface` 为准 —— 否则作者画的水陆会被高度场「纠正」掉。

**SDF 生成器（Felzenszwalb 精确欧氏距离变换）**：

```rust
// 伪代码，落 crates/wv-render/src/terrain_view/field/coast_sdf.rs
// 输入 surface 场 → 输出每个格到最近异类格的距离（格单位，f32）
// 复杂度 O(W·H)，1024² 实测目标 < 8 ms（单线程）；脏矩形重算 < 0.2 ms
pub fn distance_to_opposite_surface(surface: &[u8], w: usize, h: usize) -> Vec<f32>;
// 双通道：水→陆 与 陆→水 各一遍，按格自身 surface 取用，避免「距离符号」歧义
```

> 为什么不用「有符号距离场（SDF）」写法：符号已经由 `surface` 通道给出，再编码进距离是冗余且易错。两遍无符号距离 + 一次 `surface` 判断，语义最干净。

### 4.2 海岸线：连续曲线，不是格子边界

shader 里海岸的三件事，全部由 `coast_dist` 驱动：

```wgsl
// 1) 亚像素平滑的水陆 mask（不再有阶梯）
let d = textureSample(coast_dist, samp_lin, warped_uv).r * 32.0;  // 格
let is_land = textureSample(attr, samp_near, warped_uv).r > 0.5;

// 2) 岸线墨线：以「距离 0」为中心，宽度为屏幕像素（§4.5）
let line_w = LINE_PX * view.scale / cell_size;   // 格单位
let ink = 1.0 - smoothstep(0.0, line_w, abs(d));

// 3) 三段色带：滩 / 浅 / 深（规格书 §1.4.5 的 water_shallow / water_deep 之间补一档）
//    带比 1 : 2 : 6（对标参考图实测比例）
let band_a = smoothstep(0.0, 1.0, d);          // 0→1 格：滩涂
let band_b = smoothstep(1.0, 3.0, d);          // 1→3 格：浅水
let band_c = smoothstep(3.0, 9.0, d);          // 3→9 格：深水
let water = mix(mix(SHOAL, SHALLOW, band_a), mix(SHALLOW, DEEP, band_c), band_b);
```

> **带比「1:2:6」的依据**：`ref-map.jpg` 逐像素量取 —— 白浪花带约 1px、浅滩青绿约 2–3px、中蓝约 6–8px（在 1 格 ≈ 10px 的参考尺度）。折算成格后即 `1 / 3 / 9`。这个比例决定了「海有没有纵深」，比色相选择更重要。

### 4.3 高度插值：双三次，否则法线出现格纹

**必须用 Catmull-Rom 双三次（16 tap），不能用双线性（4 tap）**。

原因（这是本方案最容易做错、且做错后「看起来还是丑」的地方）：

- 双线性插值的**梯度在格边界不连续**（C0 连续、C1 不连续）；
- 地形明暗（hillshade）用的是高度**梯度**；
- 于是每条格边界都会出现一条明暗折痕 —— 远看是规则的网格状纹理，近看是「塑料拼接感」。**这比模糊更致命，因为它看起来像 bug 而不是风格。**

```wgsl
fn catmull_rom(p0: f32, p1: f32, p2: f32, p3: f32, t: f32) -> f32 {
    let a = -0.5 * p0 + 1.5 * p1 - 1.5 * p2 + 0.5 * p3;
    let b = p0 - 2.5 * p1 + 2.0 * p2 - 0.5 * p3;
    let c = -0.5 * p0 + 0.5 * p2;
    return ((a * t + b) * t + c) * t + p1;
}
// h(uv) = 4×4 texelFetch 组合，成本 16 次采样（现代 GPU 可忽略）
```

**hillshade（斜投影明暗）**：

```wgsl
// 光源固定左上 45°（规格书 §1.5），与所有地物符号同向
let dx = h(uv + vec2(e, 0.0)) - h(uv - vec2(e, 0.0));   // e = 0.5 格
let dy = h(uv + vec2(0.0, e)) - h(uv - vec2(0.0, e));
let slope = normalize(vec3(-dx * Z_EXAG, -dy * Z_EXAG, 2.0 * e));
let shade = dot(slope, normalize(vec3(-0.707, 0.707, 0.707)));  // 左上 45°
let relief = mix(1.0 - RELIEF_LO, 1.0 + RELIEF_HI, shade * 0.5 + 0.5);
```

- `Z_EXAG`（高程夸张）：**0.55**（1 格 = 8 世界单位 ≈ 8 km 时，山高 2000 m 只占 0.25 格；不夸张看不出体积。0.55 让 2000 m 山对应约 1.4 格有效高度）
- `RELIEF_LO / HI`：**0.86 / 1.14**（沿用现行 `RELIEF_MIN/MAX` 0.84/1.16 的收窄版，避免陡崖压黑）

> **为什么不用法线贴图/切线空间**：规格书 §1.6 明令禁止 PBR 与法线贴图。这里的 hillshade 是**用高度场直接算的明暗乘子**，不是材质光照 —— 它只作用于已有平涂色，不引入金属度/粗糙度，符合「形状 + 色阶 + 描线」三层构成。

### 4.4 域扭曲（手绘抖动的唯一正确做法）

**规则：扭曲必须在世界坐标做，且幅度随缩放收敛。**

```wgsl
// 幅度（格）：远观允许大手绘抖动，近观收敛保证编辑精度
let amp = clamp(2.0 * view.scale, 0.05, 0.45);   // scale 大 = 远观
let w  = fbm(uv * WARP_FREQ) * amp;               // WARP_FREQ = 1/6 格 的倒数
let uv2 = uv + vec2(fbm(uv * WARP_FREQ + 17.0), fbm(uv * WARP_FREQ + 41.0)) * w;
```

三个要点：

1. **在世界坐标（格坐标）采样噪声**，不是在屏幕坐标。屏幕坐标会让海岸线在缩放时「游动」，作者会以为数据变了。
2. **`clamp(2.0 * scale, 0.05, 0.45)`**：远观（scale ≈ 5）取 0.45 格（≈ 3.6 世界单位，视觉上是明显的手绘起伏）；近观编辑（scale ≈ 0.25）取 0.05 格（≈ 0.1 屏幕像素），**保证点到哪就是哪**。这条是「好看」与「可编辑」的唯一平衡点，必须写死。
3. **`fbm` 用 3 个八度、频率 1/6 / 1/3 / 2/3 格**。低于 1/6 格会扭曲成「泡泡」，高于 1 格会变成锯齿。

> **为什么它比 `wobble_px` 好**：现在的 `wobble_px` 是「按像素随机偏移」，偏移量以 texel 为单位 —— 4px 格上等于每次跳 1/4 格，产生的是**阶梯的随机化**，不是曲线。域扭曲改的是**采样坐标**，输出始终连续。

### 4.5 墨线与边界（屏幕像素为单位）

**这是必须写进规格书的口径修正**（§6 给出增补条目）。

```wgsl
// 线宽一律以「屏幕像素」定义，再折算成格单位
let px_per_cell = cell_size / view.scale;        // 一格占多少屏幕像素
let lw = LINE_PX / px_per_cell;                  // 线宽（格单位）
```

| 线 | `LINE_PX`（屏幕像素） | 依据 |
|---|---|---|
| 海岸墨线 | **1.2** | 参考图放大 200% 量得 1.2–1.4px；<1.0 会被 AA 吃掉，>1.6 显粗 |
| biome 边界线 | **0.8** | 比海岸浅一档：地貌交界是「暗示」，不是「划线」 |
| 河流 | **1.8** | 河是线状要素，必须比边界重 |
| 道路（主干/次级） | **2.4 / 1.2** | 路网是远观构图骨架，必须比墨线重 |

**抗锯齿**：不要用 `smoothstep(0, lw, d)`（边缘宽度随缩放变，远观会糊成一片）。用**屏幕空间导数**：

```wgsl
let aa = fwidth(d);                       // d 是「到边界距离」，单位为格
let ink = 1.0 - smoothstep(lw * 0.5 - aa, lw * 0.5 + aa, abs(d));
```

**biome 边界检测**（ID 不能插值，只能比较）：

```wgsl
// 4 邻 + 中心，各取最近邻 biome；任一不等即认为在边界 1 格内
let b = textureSample(attr, samp_near, uv).g;
let bl = textureSample(attr, samp_near, uv - vec2(cell_uv, 0.0)).g;
// ... 四向
let edge = (b != bl) || (b != br) || (b != bu) || (b != bd);
```

> **已知限制（必须承认）**：这种 4 邻检测只能得到「在边界带内」的 0/1 掩码，无法得到精确距离，因此 biome 边界的线宽在斜边上会比轴对齐边略粗（最多约 1.4×）。**接受它**——它是淡墨线（0.8px、α 低），视觉上是「晕开」而非「画歪」。若要精确，需为 biome 再生成一张 SDF（+2 MB、+8 ms），列为 P4 可选项。

### 4.6 水彩颗粒与色阶（材质层）

规格书 §1.5 要求「明暗最多 4 阶」、§1.6 禁止噪声纹理。**这里的处理是「水彩晕染」，不是「噪声纹理」**，区别在于：

| 噪声纹理（禁止） | 水彩晕染（本方案） |
|---|---|
| 高频随机颗粒，逐像素跳变 | 低频连续噪声，只调制**明度**，频率 ≤ 1/2 格 |
| 破坏平涂的可读性 | 让平涂出现「纸吸水不匀」的呼吸感 |
| 缩放时变糊或闪烁 | 频率锚定世界坐标，缩放时稳定 |

```wgsl
// 三阶色阶（基色 / 亮 +8% / 暗 -15%，规格书 §1.5）+ 水彩调制
let n = fbm(uv * 0.45) - 0.5;                    // -0.5..0.5，3 octave
let wash = 1.0 + n * WASH_AMT;                   // WASH_AMT = 0.07
let c = base_color * relief * wash;
```

- `WASH_AMT = 0.07`：±7% 明度。低于 0.05 看不出，高于 0.12 会破坏「色块可辨」。
- **水面单独配方**：海不叠水彩噪声（会显脏），改用 `SeaRecipe` 的连续量（§4.8）。
- **沙漠/雪原**：`WASH_AMT` × 0.5（大地色系呼吸位，规格书 §1.4.5 补充口径已要求它们低饱和）。

### 4.7 缩放自适应（防「远观闪烁」——不做这一步会比现在更丑）

**风险**：`attr` 是 `Nearest` 采样。fit 时一格 1.56 px，最近邻会在相邻像素间剧烈跳 biome → 满屏彩色噪点、缩放时闪烁。**这是必须处理的，否则 P1 上线即翻车。**

```wgsl
let cell_px = cell_size / view.scale;            // 一格占多少屏幕像素

if (cell_px >= 3.0) {
    // 近观：单点最近邻，边界锐利，墨线全开
    color = base_at(uv);
} else if (cell_px >= 1.0) {
    // 过渡：4 tap 面积加权平均，墨线按 (cell_px-1)/2 淡出
    color = (base_at(uv + o1) + base_at(uv + o2) + base_at(uv + o3) + base_at(uv + o4)) * 0.25;
    ink *= smoothstep(1.0, 3.0, cell_px);
} else {
    // 远观：8 tap 盒式平均 + 墨线全关，只留「色域」
    color = box8(uv);
    ink = 0.0;
}
```

**阈值依据**：3 px/格 是「一格能否画出可辨边界」的下限（1.2px 线 + 两侧各 ~0.9px 填充）；1 px/格 是「最近邻开始产生不可控噪点」的上限。两档之间线性过渡，无跳变。

> 注：`box8` 用 8 次 `texelFetch` + 各取色后平均，**不是**硬件 mip（硬件 mip 对 ID 纹理无意义）。

### 4.8 海面配方迁移（`SeaRecipe` → uniform）

现行 `crates/wv-theme/src/sea.rs` 的 `SeaRecipe`（`depth_t` / `shore_band_strength` / `field_radius`）**原样搬进 uniform**，不在 shader 里重写公式：

```rust
#[derive(ShaderType, Clone)]
struct SeaUniform {
    depth_exponent: f32,     // 来自 SeaRecipe::depth_t 的指数
    depth_range_m: f32,      // 3500
    band_peak: f32,          // shore_band_strength 峰值
    band_cells: f32,         // field_radius
}
```

**依据**：ADR-0048 的实测结论（`depth_t` 平方曲线、`JRPG_SOFTEN_KEEP = 0.92`、`VEIL_MAX_ALPHA = 0.12`）是**已经用直方图对表验证过的值**，重新推导只会引入偏差。shader 只负责「在哪个像素上求值」，不负责「求什么」。

### 4.9 地物：图集实例化（替代 primitive 三角）

**图集布局（引擎中立规格，可直接交画师/生成）**：

| 项 | 规格 |
|---|---|
| 画布 | `atlas_props_2048.png`，2048×2048，RGBA8，透明底 |
| 单元格 | 128 × 128 px，规则网格，无 padding |
| 符号尺寸档 | 1× / 2× / 3× 格（在 32px 基准格下 = 32 / 64 / 96 px 显示）→ 图集内 128px 画布留 25% 安全边 |
| 锚点 | `bottom_center`（符号底部中点落格中心偏下 1/8 格） |
| 阴影 | 统一右下偏移 `+0.35 × 高`，`#000` α 0.18（**不是**黑块，是软阴影） |

**必备符号清单（按绘制优先级）**：

| 类 | 符号 | 变体数 |
|---|---|---|
| 山 | 孤峰 / 双峰 / 三峰 / 雪山 | 4（每变体含受光 + 背光两面） |
| 树 | 阔叶 / 针叶 / 棕榈 / 灌木 / 枯树 | 5 |
| 聚落 | 都城 / 城 / 镇 / 村 / 港口 / 关隘 / 驿站 | 7 |
| 地标 | 寺社 / 矿 / 桥 / 遗迹 / 战场 | 5 |

**实例化要点**：

- 用 Bevy `Sprite`（自动 batch，同图集同材质一个 draw call），**不要在 shader 里画图集符号**（会失去批处理且无法做碰撞/拾取）；
- 变体选择：`hash01(cx, cy, 0x5EED)` → 索引，**确定性**（P6/ADR-0042 D6 已确立的确定性原则）；
- 随机翻转：`flip_x = hash01(cx, cy, 0x1) > 0.5`（避免同变体镜像重复感）；
- 尺寸抖动：`scale = 0.9 + hash01(...) * 0.25`。

**资产来源与诚实标注**：图集必须**画出来**（AI 生成 + 人工精修），不能靠几何体。我会按「图标家族同源五要素」（线宽 / 透视 / 圆角 / 留白率 / 光源方向）出第一版 24 个符号的规格 + 生成图，**但每张都需要人工精修才能进正式资产**——AI 生成的手绘山形在线条收口处必然有瑕疵。

### 4.10 纸面与后处理

| 层 | 参数 | 依据 |
|---|---|---|
| 纸底 | `soften_toward` 纯色铺底（Z=0） | 让「地形没画到的地方」也是纸，不是黑 |
| 纤维噪点 | 屏幕空间 fbm 2 octave，α **0.035** | 沿用现行值（`GRAIN_ALPHA`），已验证不干扰可读性 |
| 暗角 vignette | 四角 `smoothstep` 衰减，α **0.06** | 收住画面边缘，模拟纸页受光 |
| 远景雾 | 沿用 `VEIL_MAX_ALPHA = 0.12`，改为 shader 内混色 | 省一个半透明 quad |

> **顺序**：纸底 → 地形场 → 雾 → 纤维 → 暗角。纤维与暗角必须在**所有**地图内容之上（它们模拟的是「介质」，不是「内容」）。

### 4.11 性能预算

| 项 | 现行 | 新方案 | 说明 |
|---|---|---|---|
| 显存（底图） | 67 MB + mip 链 | **8 MB** | 3 张数据纹理 |
| 全图重烘 | 31–34 ms（行带并行） | **0** | 不再烘焙 |
| 切主题 | 31 ms 重烘 | **0.1 ms**（换 uniform） | 只改 uniform buffer |
| 笔刷一格 | 重烘脏区（1–8 ms） | **< 0.05 ms**（写 1 texel + 局部 SDF） | 见 §4.12 |
| 每像素采样 | — | **≈ 20 次** | 16（bicubic）+ 5（attr）+ 2（sdf）+ 3（noise） |

**帧时间估算**：1600×900 = 1.44 M px × 20 采样 ≈ 29 M texel/帧。RTX 4060 的纹理吞吐在 **十亿 texel/s 量级**，实测预期 **< 1.5 ms**（含 ALU）。即使满屏填满画布也远低于 16.7 ms 预算。

> **保守提醒**：集显（Intel Iris Xe 级）上 20 次采样 + 3 octave fbm 可能到 4–6 ms（1600×900）。**P2 之后必须补一个「低配档」**：fbm 降到 2 octave、bicubic 降为 bilinear（接受轻微格纹）。这是可配置的 uniform 开关，不需要重复管线。

### 4.12 笔刷编辑的增量路径

```
笔刷提交（wv-edit EditCommand，不变）
  → 数据纹理：写受影响 texel（1–N 个），GPU 上传 1 次小矩形
  → coast_dist：重算脏矩形 + 2 格边距（SDF 需要邻域，边距不足会在刷子边缘出现旧距离）
  → 不需要：整图重烘、chunk 克隆、mip 重建
```

**边距必须 ≥ 2 格**：EDT 的传播半径就是它要修正的范围。刷子改 1 格水陆，影响范围是「以该格为中心、原距离值半径内」的所有格；取 2 格边距覆盖 99% 情况（超出时按整行重算该行，代价线性）。

## 六、对 `ART_STYLE_SPEC_v0.1` 的增补（不改原文）

> 按 §6.3「追写不改机制」，以下作为 **§3.8 渲染实现契约（新增一节）** 提出，不修改 §3.1–§3.7 任何条目。

| 条目 | 内容 | 为什么必须加 |
|---|---|---|
| **§3.8.1 线宽以屏幕像素定义** | 所有线（海岸 / 生物群系界 / 河流 / 道路）的宽度以**屏幕像素**为单位（1.2 / 0.8 / 1.8 / 2.4），由渲染层按当前缩放折算；`tile_size/16` 的图块内描线规格**仅适用于位图 pack**，不适用于程序化 pack | §3.3 的「±2px」在 4px/格的旧管线上物理不可执行，是「画不出来」而非「没画」 |
| **§3.8.2 连续性优先于格子精度** | 海岸 / 生物群系边界必须由**距离场**驱动，不得由「逐格改色」表达；允许视觉边界与格子事实存在 ≤ 0.45 格的偏差（域扭曲幅度），近观编辑态收敛到 ≤ 0.05 格 | 否则「手绘感」与「数据可读」无法共存 |
| **§3.8.3 三阶色阶参数化** | 亮部 +8%、暗部 −15%、描线 −45%（§1.5）改为**可配置令牌** `shade.light / shade.dark / shade.ink`，默认值不变 | 不同 pack 的明暗对比需求不同，写死在代码里等于 pack 不可换 |
| **§3.8.4 海岸三段色带比例** | 滩 : 浅 : 深 = **1 : 3 : 9 格**（或等比例折算），色带宽度随 `tile_size` 缩放 | §1.4.5 只给了颜色，没给宽度；宽度决定「海有没有纵深」 |
| **§3.8.5 符号图集画布规格** | 128px 画布 / 25% 安全边 / `bottom_center` 锚点 / 阴影 `+0.35×高, α0.18` | §3.4 给了符号清单与锚点，缺画布与阴影参数，外包无法一次画对 |
| **§3.8.6 变体选择确定性** | 变体 / 翻转 / 尺寸抖动一律由 `(cx, cy, salt)` 哈希决定，**不使用随机数** | 与 ADR-0042 D6、P6 的确定性原则同源；否则重建即抖动 |
