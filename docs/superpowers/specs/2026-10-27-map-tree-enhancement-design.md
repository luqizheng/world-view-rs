# 地图树增强设计（真数据 / 复制粘贴 / 删除 / 垃圾桶 / 新增按钮）

- 日期：2026-10-27
- 状态：设计定稿（brainstorm 会话逐条拍板），待用户批准后进入计划
- 涉及层：wv-core / wv-edit / wv-io / wv-app

## 1. 意图与动机

地图树面板目前是 4 行硬编码占位（`crates/wv-app/src/ui/layers_panel.rs:67` `panel_map_tree`，注释自述"真实层级数据对接由后续任务推进"），连点击切换都没有——切换地图只能靠场景内钻取图标和命令面板。

用户的真实工作流：**世界地图存在多个版本**（平行世界图并存），需要在版本之间搬运城市图、建筑图。为此曾提议"城市图↔世界图多对多 + Ctrl 拖拽挂关系"，**用户裁定不做**：维持严格单亲树，跨世界复用一律走**深拷贝复制粘贴**，副本独立、互不相干。

## 2. 目标

1. **地图树接真数据**：读 `World.maps`，多张世界图并列成森林（多版本场景），当前图高亮，点击切换地图，chevron 展开/折叠。
2. **右键菜单**：任意节点「复制」（标记剪贴板）、「删除」；世界图/城市图节点「粘贴」（剪贴板有货时）。
3. **复制 = 深拷贝整棵子树**：后代图（建筑图等）、地形栅格、街道、建筑、measurement、图层，以及**落在本子树各图上的全部实体**——POI（`Place`）、区域（`Region`）、海域（`Sea`）、地物/势力几何（`place_geometry` / `faction_geometry`）——全部附带；ID 全部重新生成；名字重名自动补号（青州城 → 青州城 2 → 3）。
4. **粘贴落点 = 目标图当前视野中心**，贴完可拖动摆位。
5. **删除 = 整棵子树软删进垃圾桶**，按次存放（一条 = 被删根 + 全部后代）。
6. **垃圾桶**：地图树面板底部「垃圾桶」分区，点开列出已删条目（名字 + 删除时间）；条目右键「恢复 / 彻底删除」；另有「清空垃圾桶」。真删仅发生在用户主动彻底删除/清空时。
7. **浮窗顶部 + 新增按钮**：打开现有新建地图对话框（`new_map_dialog.rs`）。

## 3. 非目标（本轮明确不做）

- **多对多关系**（D1 裁定否决；将来要做需新 ADR 推翻）。
- **拖拽改父**（reparent by drag）——复制粘贴通吃跨图搬运，拖拽本轮不做。
- 垃圾桶内预览/编辑地图（列表只读）。
- 跨工程（项目间）复制粘贴。
- 右键「改名」菜单项（未被提出，不加）。

## 4. 反目标（做了就算失败）

- 破坏 P4：深拷贝是"**新建独立子图、以 Id 挂进目标父图 children**"，绝不能把子图内容内联进父图。
- 删除不可恢复：进垃圾桶的图必须可整条还原，直到用户主动真删。
- 校验变闸门（V1）：删除/粘贴不因悬空引用被阻止，问题只提示。
- 复制产生共享可变状态：副本与原图任何数据联动（那等于变相多对多）。

## 5. 关键决策（用户逐条裁定）

| # | 决策 | 内容 |
|---|---|---|
| D1 | 关系模型 | 严格单亲树，不做多对多；跨世界复用 = 深拷贝副本（2026-10-27 用户裁定） |
| D2 | 复制深度 | 全部拷贝：整棵子树 + 全部附属数据 |

## 6. 设计者默认裁定（公示过的 builder call，用户可推翻）

- **当前打开的图被删** → 自动切回第一张世界图。
- **最后一张世界图不可删**（工程至少保留一张地图）。
- 垃圾桶条目只显示名字 / 删除时间，不能打开编辑。
- **磁盘形态**：被删**根**节点的 `maps/<id>/index.yaml` 打 `trashed: true`（+ `trashed_at` 时间戳），后代节点不打标、目录不移动；加载时"处于被删根之下"即视为垃圾桶内容。真删时才物理删除目录。
- 树点击切换复用现有 `DrillState → ViewState::current_map` 镜像链路（`ui_shell/drill_state.rs`）。
- 粘贴入口 = 目标节点右键「粘贴」；（可选）树顶工具栏粘贴钮，实现时看哪个顺手。
- 新增按钮打开 `new_map_dialog`，父图默认 = 树上选中节点（无选中 = 当前图）。
- **删除子图时，父图上指向它的 `IconSpec.drill_into` 图标一并移除；恢复时还原**（AddCityCommand 建立的图标—子图配对，删除是其逆操作）。
- **撤销与垃圾桶**：Ctrl+Z 撤销「删除」= 整条还原（与垃圾桶「恢复」是等效的两条回家路）；「彻底删除 / 清空垃圾桶」弹确认框且**不进撤销历史**——用户确认过的永久动作不应被 Ctrl+Z 复活。
- **嵌套恢复守卫**：欲恢复条目的原父图若仍在垃圾桶中，恢复置灰并提示「先恢复父图」——不产生挂在已删父图下的僵尸节点。
- **root_map 改写**：被删的若恰是 `meta.root_map`，删除命令顺带把 root_map 改写为幸存的第一张世界级图（`world.maps` 序；注意该序是加载时的 ID 字典序，不是创作序）。这是**首条改动 `meta` 的 EditCommand**，ADR 记一笔。
- **粘贴可用性**：「粘贴」只对**当前打开的图**生效（视野中心才有定义）；树上未打开节点的「粘贴」置灰，提示先切换过去。
- **层级匹配 + 世界图复制**：城市图只能贴进世界图、内部图只能贴进城市图，不匹配置灰；**世界图作源**的粘贴 = 落为新的独立根图（森林并列）——这正是"多版本世界"的生成路径之一；新根粘贴后按 new_map_dialog 既有裁定走 `settle_on` 导航。

## 7. 技术落地面（给实施者的现状地图）

### 现状锚点
- 占位 UI：`crates/wv-app/src/ui/layers_panel.rs:67`（`panel_map_tree`）+ `tree_row`（:104，`resp` 目前被丢弃）。
- 数据模型：`crates/wv-core/src/map/mod.rs` — `MapLevel`（:26，World/Region/City/Interior）、`MapNode`（:37，`parent: Option<Id>` :44、`children: Vec<Id>` :47、`outline_polygon` :154）；`Place.map: Option<Id>`（`map/distance.rs:288`）单向反查；`IconSpec.drill_into`（`map/mod.rs:253`）。
- 命令层：`crates/wv-edit/src/command/map.rs` — 已有 `AddMapCommand`（:22）/ `AddCityCommand`（:127）/ `MoveCityCommand`（:236）；**无任何删除地图命令**；wv-edit 是 trait-per-command 模式（`command.rs:148`）。
- 持久化：`crates/wv-io/src/project.rs:91` `save_maps` 每图一目录 `maps/<id>/index.yaml`；目录删除传播被 v0.1 简化掉（:92 注释自认"不主动 rm 子目录"）；`save_entities`（:27）有删除传播先例可仿。
- 浮窗：`Panel::MapTree`（`state.rs:233`）走 `float_window` 工厂；浮窗顶部带按钮有图层面板 `layer_actions` 与时间线 `ICON_PLUS` 两个先例。
- 切换链路：`drill_pick`（`wv-render/src/drill.rs:503`）+ 命令面板 `DrillUp/DrillToRoot` → `seed_drill_state`/`sync_drill_mirror`。

### 分层改动
- **wv-core**：`MapNode` 增垃圾桶字段（`trashed`/`trashed_at`，仅删除根持有）+ 反序列化兼容（老 YAML 无此字段 → 默认未删）。垃圾桶是编辑器工作台状态而非世界内事件，不区间化（P7 管的是世界内容随时间演变；若评审持异议，留 ADR 辩）。
- **wv-edit**：四个新命令——`TrashMapCommand`（软删整棵子树：根打标 + 从父 children 摘除 + 父图 drill 图标移除）、`RestoreMapCommand`（整条还原：回原父 children + 图标还原）、`PurgeMapCommand`（真删：内存移除 + 标记待物理删）、`PasteMapCommand`（深拷贝落地：ID 重生成、名字补号、视野中心锚定、raster/terrain 复制）。剪贴板状态（源图 Id）放 wv-app 侧 Resource，命令本身无状态。
- **wv-io**：`save_maps` 保存 trashed 标志（目录不移动）；purge 后的目录物理删除（补删除传播；可仿 `save_entities` keep-set 模式，maps 目录按"内存中存在（含 trashed）"保留）。
- **wv-app**：重写 `panel_map_tree`（真数据森林、右键菜单、点击切换、垃圾桶分区、新增按钮、剪贴板 Resource）；删除当前图后的自动切换；最后一张根图禁删守卫。
- **i18n**：右键菜单 / 垃圾桶全部文案走 `I18nKey`（ADR-0018 全量收口后的既有纪律）。
- **图标**：一律 Lucide（copy / paste / trash-2 / plus 等，AGENTS.md §8，落 `crates/wv-ui/assets/ui/tool_icons/`，描边烘焙 `#ffffff`）。

### 深拷贝要点（PasteMapCommand）
- 子树遍历：源根 + 全部后代各生成新 `MapNode`（新 Id、父子重接线、名字补号仅根节点需要，后代同名保留——同一父下无冲突；若粘贴目标下已有同名后代则同样补号，规则统一为"兄弟内重名则 +1"）。
- 附属数据整树复制（按 map 归属收集，Id 全量重生成）：`maps/<id>/terrain.bin`、街道/建筑/measurements、raster 引用与二进制、图层定义；POI（`world.distances.places` 中 `Place.map` 落在子树内者，含 line-POI）、区域（`Region.map`）、海域（`Sea.map`）、几何 span（`place_geometry` / `faction_geometry` 中 `map` 落在子树内者；owner 为 Place/Faction 的随其 Id 重映射）。
- 边（`PlaceEdge`）：**两端都在复制集内**的边跟随复制（端点重映射）；任一端在复制集外（如指向源世界其他 POI）的边**丢弃**——那是源世界距离图的一部分，不搬。
- 锚定：根节点按目标图视野中心重算 extent/outline 位移（参考 `MoveCityCommand` 的平移语义）；后代随根整体平移。
- 指向源子图的**外部**引用（子树之外图上的 `Place.map` / `IconSpec.drill_into`）不跟随、不重写；源图后续被删时这些引用进校验提示（V1 只提示不阻止）。

### 门禁
`cargo test --workspace` / `clippy` / `fmt` + `cargo app-test` / `app-clippy` + `bash scripts/smoke-gui.sh`（改了 Plugin 装配/Resource 时必跑）。受限环境测试用 `bash scripts/cargo-test.sh`（TEMP 指向工作区）。

## 9. 验收画面（用户视角走查）

1. 打开地图树浮窗：看到两张世界图（A / B 版）并列，当前图高亮；点 B 切到 B。
2. 在 A 的青州城上右键「复制」→ 切到 B → 在 B 根节点右键「粘贴」→ B 画面视野中心出现新青州城（名字若撞则"青州城 2"），树下 B 分支多出该子树（含其建筑图）；拖动图标摆位。
3. 对 B 的旧城市图右键「删除」→ 整个子树消失，底部垃圾桶分区出现一条（名字 + 时间）；右键「恢复」→ 原位还原（含父图 drill 图标）。
4. 「清空垃圾桶」→ 条目消失，保存后 `maps/<id>/` 目录物理删除。
5. 删除当前打开的 B → 自动切回 A；只剩一张世界图时「删除」置灰。
6. 浮窗顶部「+」→ 弹出既有新建地图对话框，父图预填选中节点。
7. 在世界图 A 根节点右键「复制」→ 粘贴 → 森林并列出现独立的「A 2」新根——多版本世界由此生成。

## 10. 追记（2026-10-27 · 计划阶段实现细化）

两条实现细化，不改变用户可见行为，动机均为**跨重启可恢复**（Undo 栈不持久，垃圾桶是 YAML 状态）：

1. **删除不再物理摘除 children / drill 图标**——垃圾桶只打 `trashed` 标志（仅被删根节点）。子图在父图 `children` 中的引用与父图上的钻取图标**原样保留在 YAML**，显隐改为**派生**：树渲染跳过被删子树、钻取图标与城市轮廓在目标图被删时隐藏、`drill_pick` 拒绝进入。§6「图标一并移除；恢复时还原」由派生显隐实现——保存/重启后恢复依然完整（若物理摘除，重启后图标就永远丢了）。彻底删除时才物理清理 children 引用与悬空图标。
2. **「彻底删除豁免撤销」的落点**——`PurgeMapCommand` 本身实现完整快照 revert（误入栈也不崩），但 wv-app 编辑包装层走「直应用」通道（apply + 脏路径，**不 commit 进 Undo 栈**）提交，语义上不可撤销。
