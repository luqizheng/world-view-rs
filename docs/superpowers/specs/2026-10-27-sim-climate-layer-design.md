## 1. 意图与为什么（intent & why）

**三项目关系（用户拍板）：**

| 项目 | 角色 |
|---|---|
| `D:\kudi-project\monster` | 最终目标——Bevy 游戏 |
| **wv（本仓库）** | 内容生产线：为 monster 低成本捏地图、排剧情 |
| sim 仓库（shadow-empire-sim） | 涌现叙事引擎，**两个宿主共享的基础设施** |

wv 是创作用的工具，不是游戏。sim 引擎引入 wv 的第一版目标**不是**让角色即兴，
而是给世界加一层「环境惯性」：**四季轮换、地理位置决定旱涝、灾害作为创作
prompt 冒出来**。作者看到灾害后是调地形还是调剧情，是创作决策，工具只负责
呈现——「不合理的、奇怪的地方让用户自己感受」。人物与剧情在 wv 中保持
作者钉死（**世界不自治**，这是与 sim 引擎全面叙事 play 的显式边界）。

sim 引擎的完整事件机器（消息路由 / 信任 / 感知 / AiDriver 决策）本版**引入
但不消费**——它为将来的涌现叙事 play 和 monster 的运行时保留；本版真正消费
的只有它的**确定性配方**与 `SimRNG`（分域随机源）。

### 为什么用 submodule（用户拍板 A 方案）

- sim 仓库是独立 git 仓库（自带 workspace），monster 与 wv 共享同一份引擎；
- monster 将来在运行时消费同一引擎，wv 侧把桥接做正，功夫不白做；
- 挂上后立刻有真实消费点（`SimRNG`），避免「挂着不用」的死依赖。

## 2. 目标 / 非目标 / 反目标

### 目标（第一版）

1. **submodule 接入**：sim 仓库以 pinned SHA 挂入本仓库；`wv-app` 以 path
   dependency 消费 `rust/sim`；构建、测试、clippy 门禁全绿。
2. **气候投影**：季节 / 天气 / 旱涝是 `(climate_seed, day, 地理)` 的**纯函数**，
   经 wv-app 侧模块求值，**零存储**（P7：不存「当前天气」字段，任何时刻的
   天气都按天求值——播放器拖到哪天算哪天，天然可回放、可并行）。
3. **地理→旱涝映射**：以图上栅格为地理输入（高度场、距水距离），叠加世界级
   宏观气候声明，输出逐格湿润度异常（干旱 / 洪涝倾向）。
4. **灾害涌现为「提议」**：旱涝异常超过阈值的地点，在播放时以**涌现标记**
   呈现在地图与时间轴上（视觉上与正式事件区分），**不**自动写入世界史。
5. **确定性**：同 `(climate_seed, day, 地理)` 必得同一天气序列；随机只走
   `SimRNG` 分域（`"world.climate"` 域），跨平台可复现。

### 非目标（第一版明确不做）

> 收窄本身有外部依据（[CLIMATE_DESIGN_RESEARCH_v1.0](../../CLIMATE_DESIGN_RESEARCH_v1.0.md) §2）：
> CK3 的反例价值——没做气候、靠地形就够用，「气候系统的投入要和它承担的
> 玩法深度匹配」。wv 是工具不是游戏，v1 只取气候层里直接服务创作 prompt
> 的最小切片。

- 角色 / 势力自治（AiDriver、决策层、消息路由、信任、感知——**引入不消费**）；
- 灾害自动落成正式事件实体（采纳之门 = EditCommand，留待下一版，见 §6 待裁②）；
- 战略级气候地理（雨影效应、纬度网格生成——sim 仓库自身也列为「明确不做」）；
- 气候**改变**地形数据（只呈现倾向，不写回 terrain.bin）。

### 反目标（出现即失败）

- 任何形态把天气 / 灾害状态持久化为「当前值」字段（违反 P6/P7）；
- sim 引擎代码沾染 wv 概念（引擎侧零反向依赖是其自身硬约束）；
- 灾害标记与正式事件在视觉上不可区分，作者误以为历史已被改写。

## 3. 约束（constraints）

- **分层（AGENTS.md §2）**：sim 是与 wv-core 平行的外部叶子；**只有 `wv-app`
  允许依赖它**（先例：wv-overture）。wv-core / wv-terrain / wv-io / wv-edit /
  wv-render / wv-ui 一律**不得**出现 `sim` 依赖。
- **分层（sim 侧）**：引擎不知道 wv 的存在；数据与规则由调用方注入
  （引擎「判定权在调用方」纪律的镜像）。
- **P3**：气候规则（各季降水概率、温度期望、灾害阈值）收在**数据表**里，
  不散落魔法数（sim 侧先例：`ClimateRules` 单文件持有气候词汇）。
- **P7**：所有「某天的天气」必须由天求值，渲染层不做时间比较；
  天气求值入口唯一（类似 `DistanceGraph::segment_days` 的唯一性纪律）。
- **确定性纪律（sim 侧移植）**：唯一随机源 `SimRNG`、分域命名
  （`"world.climate"`）、跨主体迭代显式稳定排序、不静默降级。
- **submodule 版本管理**：pinned commit SHA；升级 = 显式 bump + 全门禁
  + GUI 烟测。
- **时间粒度**：wv 时间锁定到天（`TimePoint = i64` 天计数，1-based），
  气候不引入更细粒度。日历用 `Calendar`（如 simple 360 天/年）派生季节，
  不同工程日历参数不同，**不得**假设 360。

## 5. 落到实况（已核实的 wv 现状）

| 现状 | 对气候层的意义 |
|---|---|
| `TimePoint` = i64 天数（`wv-core/src/time/mod.rs`） | 季节 = `day` 对 `Calendar.days_per_year` 取模的纯函数 |
| `Calendar { kind: simple, days_per_year, days_per_month, … }` | 季节划分按各工程自己的日历参数计算 |
| 地图栅格 `terrain.bin`（i16 高度场，如 world_main 1024²）+ `unit_per_km` | 地理输入：海拔、（配 `unit_per_km`）距水距离 |
| `world.yaml` 已有 `template.kind`（如 `cold_north`）与 `seed` / `rivers_seed` | 宏观气候基调与 `climate_seed` 的惯例落点 |
| `ViewMode`（`wv-render/src/state.rs`）+ 时间轴播放器（Browse 态） | 天气视觉层挂播放态；渲染层经 `WorldProjection` / `ViewState` 资源读应用态（现有通道；旧 `RenderInputs` trait 已不存在） |
| `EditCommand` 是唯一写路径（AGENTS §3.3） | 采纳之门（未来版）直接对接既有命令链 |

## 6. 待裁问题（本版不收敛，显式挂起）

1. **主角木偶 vs 即兴**：将来若开角色自治，作者安排的关键人物是否脱稿
   （play 模式的开关位）。本版世界不自治，不触发。
2. **灾害采纳流程**：涌现灾害何时、以何种交互升级为正式事件实体
   （候选交互：右键采纳 / 属性面板按钮）。本版只呈现。
3. **天气视觉语言**：雨 / 雪 / 旱的渲染风格（覆层 tint？粒子？色带？）——
   需要美术方向输入，实现计划阶段单独小轮。
4. **气候内核上缴**：气候纯函数模块将来是否反哺 sim 仓库 rust 侧
   （使 monster 直接复用）。影响模块落点（wv-app 内 vs 独立 crate），本版
   按 wv-app 模块实现，保留上缴可能。
5. **宏观气候的作者界面**：`climate_seed`、气候带声明的**编辑入口**（地图属性对话框已有先例）。落点已定（见 §8-1），只剩 UI 交互未裁。
6. **天气覆层是否升格为作者图层**：本版按会话开关实现（§7-3）；若将来作者要求逐图声明 / 逐子图控制，再开 ADR 动 `LayerKind`。
7. **湿度模型 v2 演进锚**：v1 的手搓公式（模板基调 + 距水加成 − 海拔罚）是有意简化。v2 候选 = Whittaker 式「温度 × 湿度」矩阵查灾害/群系倾向（同 [CLIMATE_DESIGN_RESEARCH_v1.0](../../CLIMATE_DESIGN_RESEARCH_v1.0.md) civ-atlas/Azgaar 链路）；fantasy 图无纬度，伪纬度用 template 基调 + 图 y 轴近似。三风带 + 水汽输送（雨影）是 v3 量级，明确不在路线图内除非作者提出需求。
8. **灾害两面性**：Civ6 泛洪平原「+3 食 vs 洪水毁田」式风险对赌——涌现灾害将来可带「另一面」叙事钩子（洪水 = 毁田 + 淤泥肥田来年丰产），服务采纳环节的编剧素材。v1 灾害只有单一语义，本条留给涌现叙事版。
9. **生长季派生**：温度函数落地后，「某地生长季 = 全年 temp ≥ 10°C 天数」（RimWorld 定义）是一行派生，是将来事件引擎 play 的天然事件源（农闲 / 农忙 / 饥荒预警）。v1 不做，本条挂给远期 play 模式。

## 7. 我的裁量（builder check 收口，2026-10-27）

评审员三问均按仓库既有先例收口；这些是我的判断，用户终审时可逐条推翻。

| # | 裁量 | 依据 |
|---|---|---|
| 1 | **新增 `WorldMeta.climate_seed`（u64，serde default = 由 `seed` 域分离哈希派生）**。旧工程、无模板工程零迁移自动获得确定性气候；重生成世界换 seed 时天气随之重滚（世界身份变了，天气跟着变是自洽的） | 先例：`rivers_seed` 已确立「领域独立种子并列存放」惯例；schema 未发布（用户既有裁定：先不管迁移） |
| 2 | **wv 自有气候定义，不做与 sim 的逐位对拍（parity）**。sim 侧配方（320 刻/年、窗口=8、+15% 持续性）属其游戏层且与 wv 的任意 `Calendar` 天数制互斥；wv 只借鉴其**结构纪律**（季节=纯函数、天气窗口独立分域、规则收单表），参数表 wv 自有，黄金向量手算 | sim 仓库核实：气候代码在 `games/ShadowEmpire.Bevy/src/climate.rs`（C# WarCore 为真值源），不在 `rust/sim`；D7 用户原意是「按配方做气候」，非逐位复刻 |
| 3 | **天气覆层 = `ViewState` 会话开关（先例：`isolines` / `tracks_visible`），不新增 `LayerKind`**。零 schema 改动、零 ADR 前置；升格为作者图层留 §6-6 待裁 | AGENTS §12 纪律：待决问题上选**最容易回退**的方案 |
| 4 | **改地形即时改变旱涝分布是特性不是 bug**：地理是求值输入，笔刷改地形 → 旱涝图随之移动 → 作者立刻看到「调地形」这个选项的后果——这正是 D5 创作闭环的机制化 | 用户原话「此时我是调整地形，还是调整剧情」要求两个选项都真实可感 |
| 5 | **sim 依赖随 wv-app 常规依赖（不挂 feature 门）**，submodule 落 `third_party/shadow-empire-sim/`，pin 当前 HEAD | 先例：wv-overture 即 wv-app 常规依赖；AGENTS §2 分层表需同步增列（实现时改 AGENTS + 开 ADR，见 §9） |

## 附：本版触及的设计原则自检（AGENTS §1）

| 原则 | 触及与否 | 说明 |
|---|---|---|

| P6 非破坏 | 否 | 零存储、零写回 |
| P7 时间轴驱动 | 是 | 天气 = `(seed, day, 地理)` 纯函数，播放求值，无「当前值」 |
