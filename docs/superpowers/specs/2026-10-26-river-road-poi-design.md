# 设计稿：河流与道路=线段 POI（群系退役 · 起终点算法 · 线即路网）

> 日期：2026-10-26（brainstorming 四轮收敛，用户逐项拍板）
> 状态：**已批准**（2026-10-26 用户「go」）——ADR-0070 已转「已接受」，实施计划见 `docs/superpowers/plans/2026-10-26-river-road-poi.md`
> 关联 ADR 草稿：`docs/adr/ADR-0070-rivers-roads-as-line-poi.md`（提议态；0068/0069
> 已被同日并行会话的顶栏三段化 / Schematic 退役占用，本 ADR 顺延取 0070）
> 决策者：用户（§2 各条）；§5「我的裁量」为助手代拟、已随对话复述未被否决

## 1. 意图与动机（why）

作者在使用 cell-map 涂河流/道路时体会到：**线性地物塞进面状分类的群系里，语义拧着**——
格子分辨率撑不住线状物（远看一格一格、拐弯生硬），而 edit 区画线天然顺滑、还能挂语义
（河名、级别、连通）。因此：

1. **河流(16)、道路(20) 从可涂群系集合退役**——cell-map 只管「地形 + 面状群系」；
2. **河/路 = 线段 POI**（`Place.line` 中心线 + 属性），作者在 edit 区画，不在 cell-map 涂；
3. **道路全量统一为线**：PlaceEdge 陆路路网折成 `Place.line`，行程计算从线推导（用户选 C）。

现状三个河源（涂格 16 / `river_seed` 程序派生 / 作者 `Place.line`）收敛为**一个**：
`Place.line` 实体。

## 2. 用户拍板的决定（as-decided）

| # | 决定 | 出处 |
|---|---|---|
| D1 | 群系编号 16（河）/ 20（路）退出可涂集合；河/路是 POI 的一种 | 第 1 轮 |

| D4 | 存量河编辑三景：有宽有窄、回延申、汇入另一条河（方案见 §4.3） | 第 3 轮 |
| D5 | 道路与行程计算**全量统一**（选项 C）：线即路网，PlaceEdge 陆路边不再手存，由线推导 | 第 4 轮 |

## 3. 目标 / 非目标 / 反目标

**目标**

- edit 区可钉点画河/画路，产出可选中、可改名/宽/级别、可拖顶点的 POI；
- 河流算法两模式落地，河谷下切进 History 可撤销；
- 画路即通路：线起终点吸附 Place 自动恢复连通（迁移后推导边）；
- 存量（涂格、导入路网、模板派生河）一次性迁移，全程可撤销、有诊断。

**非目标（本刀不做）**

- 手动逐段宽度编辑（锥形默认已覆盖大多数；进 backlog）；
- 汇流的显式语义（流量/通航/支流引用）；
- 道路级别→行程速度分档（v1 统一 `terrain="road"`，见 §5-8）；
- 手画路的「途经点」（mid-line 经停拆边）；
- 河/路的时间区间化（与 Place 坐标同为静态属性，暂无时变需求）。

**反目标（做了即失败）**

- cell-map 调色板仍残留河/路入口；
- 存量迁移不可撤销、或静默丢弃不诊断（违 V1：校验只提示不阻止）；
- 河回到「每帧从 seed 派生」的双供给老路。

## 4. 方案

### 4.1 数据模型（wv-core）

`Place` 增两个可选字段（serde `default + skip_serializing_if`，旧 YAML round-trip 不变——
与 `rank`/`kind` 同款纪律）：

```rust
/// 线段种类判别。`line` 存在而 `line_kind` 缺省 = River
/// （ADR-0046 的存量作者河零迁移，照常按河渲染）。
pub line_kind: Option<LineKind>,      // enum LineKind { River, Road }（snake_case serde）
/// 线基准宽度（米）。河流=河口宽；道路缺省按 rank 折算（不落盘）。
pub line_width_m: Option<f32>,
```

- 中心线复用既有 `Place.line: Option<Vec<f32>>`（图内局部 wu 扁平坐标对，与
  ADR-0046 作者河同约定）；锚点 `x/y` 缺省由折线中点派生（`anchor_from_line` 现成）。
- 河流创建模式（绕行/强制）作为创建时工具输入**不落盘**；延伸时以面板当前模式续算。
- PlaceEdge（`distances/edges.yaml`）保留，但语义收窄为：**非道路连接**（海路/抽象连接）
  与**线推导边的运行时容器**。陆路边永不直接手写（§4.5）。

### 4.2 河流/道路算法（wv-terrain 新模块 `line_path`）

输入：起终点（图内 wu）、模式、`TerrainGrid`（高度场）、cell_size、确定性种子
（由 Place id 哈希，splitmix64 房法）。

- **绕行**：高度场上 A*（8 邻域）。代价 = 步长 ×（1 + λ_up·max(0, Δh 上坡) +
  0.1·max(0, Δh 下坡)）+ 确定性蜿蜒噪声项（避免两条邻近河走出同一条折线）。
  上坡重罚 → 路径自然绕山贴谷。
- **强制改变地形**：A* 只按距离（坡度弱权重）取近乎直连路径，随后下切——
  - 河流：复用 `apply_river`（`intent.rs:895`：源头定向、河口遇水停、比两岸低
    `CUT·s`、比上游单调降 `DROP`、不低于 1m、写 `SURFACE_WATER`）；走廊半径由
    宽度换算（宽河多格下切，现单格链的推广）。
  - 道路：下切**变体**——同样压低走廊，但**不写 `SURFACE_WATER`**（山间开出通道）。
- 输出折线：途经格中心 → wu 坐标 → Chaikin 平滑两轮 → 存 `Place.line`。
- **折线即为准**：生成后作者可拖顶点微调，不自动重算；拖动/延伸后旧下切保留
  （一次性下切原则，第 2 轮已定），新增段按下切只作用于新增部分。
- 生成器统一：RegenWorld/模板的自动河改走同一算法（生成器自选起终点，噪声种子仍
  `rivers_seed`），产出直接落 `Place.line` 实体；每帧从 seed 派生的旧管线删除。

### 4.3 存量编辑（作者日常）

| 场景 | 行为 |
|---|---|
| 选中即改 | 点中河/路 → 河流和道路面板切到对应段显示名字/宽度/模式（河）或级别（路），改完走 EditCommand 写回、进 History |
| 有宽有窄 | 渲染宽度=**算法锥形**：源头≈基准宽 30% → 河口=面板宽度，按弧长插值（比例为初始值，可调）；rank 只管 LOD 显隐（ADR-0047 D5 长度折算沿用） |
| 回延申 | 拖端点续画：从新端点按当前模式续算路径，下切只作用新增段 |
| 汇入 | 拖端点靠近目标河中心线时吸附到线上最近点，端点落线即成汇流；v1 仅几何重合，不建显式引用 |

### 4.4 UI（wv-ui 面板 + wv-app 工具条）

- 地图工具条新增**线段 POI** 按钮（Lucide `route`，白描边烘焙），**仅 Edit 浏览档出现**
  （与既有编辑工具同款门控）。点击弹「道路 / 河流」二选一，选中后进入钉点模式并打开
  **河流和道路面板**。
- 面板 = 一个浮窗、两段设置（河/路各一段，随当前工具高亮），**兼任新建设置与选中
  属性编辑**（统一属性表单先例，ADR-0058）。
  - 河流段：名字 / 宽度（米）/ 模式（绕行=默认 | 强制改变地形）。
  - 道路段：名字 / 级别（rank 选择器）/ **模式（与河同款两模式，默认绕行——D3「同」
    语义，§4.2 道路下切变体即其落地）**。缺省 rank 按线长公里折算（沿用 PlaceEdge
    冻结契约，见 §4.5）。
- 钉点交互：点起点 → 点终点 → 预览折线（两模式可切看效果）→ 确认落 Place
  （+ 强制模式的下切地形命令，同一 History 条目）。
- 渲染分工不动：河走 `PassId::Rivers`（gate=MODE_TABLE ∧ terrain 图层）、路走 road
  图层（rank 三档切割，ADR-0047 D4）——两池供给源统一为 `Place.line` 后，
  `author_river_polylines` 与派生 `river_polylines` 合并为单池。

### 4.5 线即路网（D5=C 选项）

- **推导边**：加载/编辑后重建——路 `Place.line` 两端容差吸附到 Place → 生成 PlaceEdge，
  `distance_km` = 线长 ÷ `unit_per_km`（`MapNode` 现成换算），`terrain = "road"`，
  rank 继承路的级别。推导边**不落盘**（运行时结构），行程计算照旧走
  `DistanceGraph::segment_days`。
- **非道路连接**：`terrain != "road"` 的存量边（海路等）原地保留手存，无线路可画。
- **运行时容器**（评审 §1 收编）：推导边直接注入 `World.distances.edges`，带
  `#[serde(skip)]` 的 derived 标记——保存时天然不落盘（round-trip 契约不变），
  行程 / 校验消费者零改动。手写道路边（YAML 仍可写）照常加载；同端点对已有手写边
  则不再推导，避免平行重复。
- **缺省 rank 折算**（评审 §5 收编）：路 `Place` 缺省 rank 沿用 PlaceEdge 冻结契约
  按**线长公里**折算（≥100→3 / ≥30→2 / 否则 1，ADR-0047 D1），不用河流的图幅占比
  表——与存量边折算逐位一致，链式合并前后全国/区域档路网显隐零回归。
- **无 `unit_per_km` 的地图**（评审 §6 收编）：跳过推导边 + 诊断提示（V1 只提示）；
  宽度输入按 wu 解释（面板单位标注随之切换），不做隐式换算。

### 4.6 存量迁移（一次性、可撤销、有诊断）

| 存量 | 处置 |
|---|---|
| 涂格 16（河） | 转 `SURFACE_WATER`（保留水面观感）；诊断提示「建议重画为线段 POI 河」 |
| 涂格 20（路） | 转 `BIOME_NONE`（道路另有线供给）；诊断计数 |
| `edges.yaml` 中 `terrain=="road"` 的边 | **链式合并**：仅穿过 2 度顶点的边串成长折线，路口（≥3 度）与端点保留为线端点 → 落 `Place.line`（Road）——图拓扑无损（每条线两端即恢复全部边）；8.4 万边预期收敛为千量级长路 |
| 其余边 | 原地保留（非道路连接） |
| 模板派生河（rivers_seed） | 首次加载该世界时跑同款算法转 `Place.line` 实体（§4.2 生成器统一） |

迁移走单条 EditCommand（进 History 一次可撤销），校验面板列出每类计数（V1：只提示）。

**触发与幂等**（评审 §2 收编）：迁移在**加载时自动**跑——对重复导入（Overture 再进
道路边）是常设通路，不是一次性开关；链 ID 确定性派生（有序端点 place id + 链长哈希），
同一数据重导入重推导出同一批实体，不增殖。道路边转线与「从 edges 列表移除该边」在
同一 EditCommand 内（否则每次加载都重迁移）；撤销在该命令所在会话内有效，落盘随
作者正常保存。**2 度中间节点保留**（评审 §3 收编）：链式合并穿过的路口 Place
（Overture 工程主体，rank 0）不删除——保留为锚定节点，诊断计数「N 个节点已无边
引用，可稍后清理」；批量清理命令进 backlog（删除数据须显式动作，不随迁移发生）。

## 5. 我的裁量清单（助手代拟，用户复述时未见异议，批准时可一并勾销）

1. 折线即为准（生成后不自动重算、拖顶点微调；旧下切保留）。
2. 锥形宽度比例 30%→100% 为初始值，实现期可调，不写死进契约。
3. 汇流 v1 仅几何重合（YAML 坐标重合），显式引用留待流量/通航需求出现。
4. `LineKind` 缺省 = River（ADR-0046 存量作者河零迁移）。
5. 河流模式不落盘（创建/延伸时的工具态）；若实施中发现延伸需记忆模式，再升格为字段。
6. 推导边不落盘、`terrain="road"` 统一；rank→速度分档进 backlog（车辆
   `terrain_modifiers` 的键已支持，纯查表工程，晚做无损）。
7. 存量 16 转 `SURFACE_WATER`、20 转 `BIOME_NONE`（不自动骨架化成线——复杂度不值）。
8. 线段 POI 图标用 Lucide `route`。
9. 道路「强制改变地形」= 压平走廊但不写水面（`apply_river` 变体）。
10. 手画路 v1 只做端点吸附建边；中途经停拆边（途经点）进 backlog。

**评审追加（builder-check 2026-10-26，六问收编）**：

11. 推导边注入 `World.distances.edges`（serde skip 标记），不另建运行时图——
    消费者零改动、round-trip 不变。
12. 路 Place 缺省 rank 折算沿用 PlaceEdge 公里表（非河流图幅表）——显隐零回归。
13. 迁移加载时自动跑、链 ID 确定性幂等；转线与移除边同命令；2 度节点保留不删。
14. 无 `unit_per_km`：跳过推导边 + 诊断；宽度按 wu 解释并标注单位。
15. 道路面板含模式开关（对话 D3「同」已答，§4.4 已修正）。
