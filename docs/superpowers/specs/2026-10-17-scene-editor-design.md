# 场景编辑器设计 v0.1（城市 / 地下城 / 森林 / 村落）

> 2026-10-17，与作者（项目所有者）brainstorm 收敛。
> 作者委托技术裁定给助手（原话「你决定。我不懂啊」）；文中标注了每条裁定是谁拍的。

## 1. 意图与为什么

作者是世界观创作者，要往自己的世界里灌内容。他没有「画一张精确城市地图」的诉求，
他有的诉求是：**快速铺出一个像样的城市/地下城/森林/村落，然后把设定意义标上去**。

核心洞察（对话中收敛）：这不是「城市编辑器」，是一台**通用场景编辑器**——
城市、地下城、森林、村落、农田全是同一套范式，只是词表不同：

- **分区色块**：城市=贫民/富人/普通住宅/商业/工业，村落=住宅+农田，
  地下城=房间/走廊/大殿，森林=密林/空地。同一套「刷区域」工具。
- **线性要素**：城市里是河和路（几种宽度档），地下城里是通道。
- **标记点**：「这是警察局，主角上班的地方」——讲意义，不讲几何。
- **放物件**：前期一个个点放；模拟城市式建筑贴片是后期愿景。

## 2. 作者工作流（四步，用户口述）

1. **参数生成**：定配比（贫民/富人/普通居民占比，工业/商业/住宅面积比）→ 生成器铺出分区。
2. **笔刷修正**：生成结果不对的地方刷掉重画——像地形刷「地表类型」那样刷「城区类型」。
3. **放置标记**：放一个点，起名「警察局」，描述写「主角上班的地方」。文字随便录。
4. **拉线性要素**：河流拉伸成形；道路单独画，提供几种宽度档位。

## 3. 目标 / 非目标 / 反面目标

**目标（v1 整体）**

- 在非世界级地图（City / Interior 级）上刷分区色块，可撤销，渲染为色块。
- 标记点 = 名字 + 自由文字描述。
- 生成器按配比填分区（壳子来自父图，见 §5.3）。
- 城市整图级「存在时间段」，时间轴联动 + 无后继警告。

**非目标（明确不做，至少本设计周期内）**

- ❌ 逐分区的独立时间区间（作者裁定：整图一个时段就够）。
- ❌ 标记与角色/事件的结构化双向关联（作者裁定：名字+自由文字即可）。
- ❌ 模拟城市式建筑贴片（后期愿景，另起设计）。
- ❌ 精确矢量描区（笔刷网格才是本体，见反面目标）。
- ❌ 3D / 楼层竖向结构的真实建模（地下城=平铺的房间/走廊分区，作者确认「差不多」）。

**反面目标（出现即失败）**

- 把标记做成必须逐字段填写的表单——作者要的是「放一个点说一句话」。
- 为了「精确」把分区做成描多边形——笔刷的自由度是需求本身。
- 生成器生成后不能撤销、不能改参重来。

## 5. 架构与数据模型

### 5.1 分区层 = TerrainGrid 的 kind 通道（R6，助手裁定）

代码现状（调研 2026-10-17）：每图可挂一张 `TerrainGrid { width, height, cells: Vec<TerrainCell> }`，
`TerrainCell { height: i16, kind: u8 }`，存 `World.terrains: BTreeMap<Id, TerrainData>`，
二进制走 WVTR 格式 + `RasterRef` 声明（§5 二进制纪律的既合规例外）。
笔刷（`Brush`/`Stroke`/`falloff_weight`）、`PaintTerrainCommand`（before 缓存=撤销粒度）、
chunk 色块渲染、kind→颜色 ThemePack 调色板，**全链路已在**。

因此：

- **场景分区不新建任何数据结构**。城市/地下城图 = 一张普通子图 + 自己的 TerrainGrid，
  height 通道保持 0（平地），kind 通道承载分区。
- **kind 是开放 u8**，分区词表由主题包调色板承载（与地形类型同机制）。
- ⚠️ 约束：`is_water_kind(kind) = kind <= 1` 是水域判定唯一入口，笔刷跨水陆会自动压/抬高度。
  **场景分区 kind 编号必须 > 1**；场景图的基底 kind（「未分区」）也必须是陆地 kind，
  保证刷分区永远不触发高度改写。
- 建议编号分区（施工者可按现有 kind 占用情况微调）：保留 0/1 给水域；
  世界地形沿用现有编号；**场景分区类从 16 起编**（未分区基底/贫民区/富人区/普通住宅/
  商业/工业/农田/密林/空地/房间/走廊/大殿…），各主题包为场景级地图提供对应色板。

### 5.2 场景图的判定与进入

- 场景 = `MapLevel::City` 或 `MapLevel::Interior` 的 MapNode（地下城用 Interior，
  村落/森林用 City 或 Region 级皆可——判定按「图级 ≠ World」，不按语义）。
- **场景类型落数据（助手裁定，回应施工者审查 Q6）**：`MapNode` 增加可选
  `scene_type: Option<SceneType>`（Settlement / Farmland / Forest / Dungeon），
  建图时选、属性里可改。它驱动两件事：笔刷面板的分区词表瓷砖、生成器的参数集。
  不落数据的话，作者每次进图都得重选词表，违背「放进去它就该是那个东西」的直觉。
- 进入方式沿用现有双击钻入（`DrillState`），面包屑/返回零改动。
- 场景图创建：`AddCityCommand` 已能建城+父图图标。新场景图**默认不带网格**，
  首次刷色时自动引导生成一张「基底全未分区、height=0」的平坦网格（尺寸由 extent + cell_size 推，
  或给缺省 256×256——施工者定，倾向前者）。
- **新建地图对话框要改（施工者审查 Q2，助手裁定）**：对话框目前对所有层级无条件预填
  世界词表网格（海洋 kind 0 / -3500m）。「默认海洋」是作者 2026-10-16 对**世界图**的裁定，
  不是对城市/地下城的。非 World 级不再预填海洋，改为不挂网格（走上面的首次刷色引导），
  根治「首刷分区触发跨水陆高度改写」的路径。世界图行为不动。

### 5.3 生成器（第二阶段，R2）

- 形态照抄 `GenerateContinentCommand` 先例：单命令宏，一次 apply 内
  「TerrainData→TerrainGrid → 按参数填 kind → 逐格 diff 缓存 before → 写回」，种子显式传入可重骰。
- 参数面板：贫民/富人/普通居民占比 + 工业/商业/住宅面积比（其余归基底）。
- **范围（助手裁定，回应施工者审查 Q1）**：生成器只服务**配比填色型**场景
  （城市/村落/农田/森林）。**地下城不进生成器范围**——房间/走廊是连通性/拓扑问题，
  按配比随机填出来的是互不连通的噪声块；地下城靠笔刷手工画
  （这正是 R1「同一套范式」的含义——范式是刷和标，不是都有一键生成）。
  将来若要地下城生成器（房间布局算法），另起设计。
- 壳子来源：
  - 城市轮廓 = `MapNode.outline_polygon`（ADR-0022 已接受已落地）或 extent；
  - **穿城河流 = 读父图 TerrainGrid 的水域 kind/高度**（河流不是几何实体，
    是地形高度模式——ADR-0022 D3 结论，此处天然咬合）；
  - 海/山环境 = 父图地形在城址周边的 kind 分布。
- 只在场景图自己的网格上写 kind，绝不写父图（P4）。

### 5.4 标记点（第二阶段，R4）

- 现有 `IconSpec` 无名字/描述字段且语义是「钻入入口」，不硬改。
- **新实体 `SceneMarker`**（助手裁定）：每图一文件 `maps/<map_id>/markers/<id>.yaml`
  （P2+每实体一文件），字段 `{ id, name: String, description: Option<String>,
  anchor: [f32;2], shape, color: Option<Color> }`——形状/颜色沿用 IconShape 词汇。
  `anchor` 用**本图局部世界单位**（与街道/outline_polygon 同口径、与网格格对齐），
  不走 IconSpec 的 extent 归一化——免得 extent 一变标记就漂移（回应审查 Q5）。
- 配套 `AddSceneMarkerCommand` / `RemoveSceneMarkerCommand` / `UpdateSceneMarkerCommand`，
  照 Region 三命令（command.rs:1829+）现成模式。
- 渲染：小图标 + 名字标签（描述进悬浮/详情面板，不常驻），复用 Poi/PlaceLabels 通道经验，
  新增一条 PassId。
- 刻意不做：指向 Character/Event 的结构化引用（R4）。将来要加，是加可选字段，不推翻本设计。

### 5.5 道路（第三阶段）

- 【审查修正 Q4】画街道的工具 UI **已经存在**（`wv-render/src/streets.rs`：
  左键逐点连线、右键结束，面板 12 档 `RoadClass` 下拉 + 名称 + 撤销），且不限图级。
  真正缺的是两件：
  ① **场景图 road 图层供给**——新场景图 `layers` 为空，而街道工具要求图上有
  可见、未锁、带 source 的 road 图层，会在场景图上直接拒绝；建图时自动建，
  或首次画路时引导建（施工者定）。
  ② **场景宽度档位收敛**——作者原话「道路提供几种模式宽度」：场景模式给
  大道/街道/小巷等 3 档左右预设（映射到 RoadClass 子集），12 档全量仍可展开。
  档数与命名施工者定。
- 渲染宽度由街道渲染按 class 给，不新造宽度字段。
- 地下城通道=同一条 StreetSegment 路径，class 词表按主题包给场景级别名（可后议）。

### 5.6 存在时间段（第三阶段，R3）

- `MapNode.time_span` 已存在（ADR-0015 已接受），**缺写入口**：
  新增 `SetMapTimeSpanCommand`（也可清空）。
- 时间轴联动：父图上的城市图标/标签按 time_span 过滤显示
  （对齐 `label_visible_at` 的既有求值点，图标侧需要补一个对 icons 的时段过滤——施工点）。
- 同址多城各带各时段，天然由「多张子图」表达，零新概念（P4）。
- 警告：`wv-io::diagnostics` 加一条 Hint 级规则——「某图 time_span 有终点，
  同父下没有任何后继图（时段起点 ≥ 该终点）且父图时间线晚于该终点」→ 提示，不拦保存
  （照 `detect_cross_level_scale_hints` 同构先例；V1）。

## 7. 触及的设计原则自查

| 原则 | 结论 |
|---|---|
| P2 目录即工程 | 场景网格=每图目录下 raster；markers=每实体一文件 |
| P3 YAML 为主 | 无新增二进制；复用已声明的 terrain bin（§5 既有例外） |
| P4 多地图层级 | 场景就是子图；生成器只写自己图的格子；同址多城=多张子图 |
| P5 图层化 | 不动 LayerFrame/recipe 的声明模型，只按图级换调色板与词表 |
| P6/P7 | **有意识的取舍（R3，用户拍板）**：分区不逐区带时段，时代粒度=整图 time_span（字段已区间化）。存储层未引入「当前值」字段；若未来要逐区时代，kind 通道可升级为分段存储，本设计的 UI/命令面不需推翻 |
| V1/V2 | 警告只提示不拦；作者随时改，无阻力 |
