# wv 交互设计审计

## 产出物与纪律（先读）

- 报告落盘 `docs/UX_AUDIT_<日期>.md`，证据截图复制到 `docs/audit/<日期>/`（`.target` 会被清理，截图必须随文档走）。落盘前先问用户？不——审计报告属分析产物，用户说「写入文档」才落盘，否则先在对话里交付。
- **UX 编号纪律**：先找上一份报告（历史首份 = `docs/UX_AUDIT_2026-10-29.md`，UX-001..027），新编号从最大号续起（当前下一号 028）。对旧报告只允许**追加补录节**（编号不重排、不改已有条目），遵守仓库「追写不改」纪律。
- 增量审计要**对照旧报告做 diff**：已修条目标注「已修复（证据）」，未修条目不重复展开，只报新发现。
- 「待验证」不算缺陷；区分交互缺陷 / 功能缺失 / 视觉问题 / 性能风险 / 个人偏好。**不得因为功能已实现就默认它设计合理**。

## 第一步：取证（证据分级：代码 > 实机截图 > 文档）

代码是最强证据（可精确到行号），截图次之，设计文档只能当背景。**区分已实现 / 未实现 / 无法确认**——背景能力清单 ≠ 现状。

- **全量审计**：派 4 路并行 Explore agent（注意并发上限，被拒就串行重发）：
  1. 壳层与信息架构（ui_shell/ top_bar/ 命令面板 设置 布局持久化 快捷键 i18n）
  2. 导航与空间操作（camera zoom_level drill map_frame minimap 比例尺 LOD）
  3. 地形与笔刷编辑（brush_panel top_option_bar editing_bridge cell_stroke stroke 历史/撤销 选区）
  4. 图层与对象 + 数据面板（layers_panel map_tree inspector timeline validation 保存流）
  每路要求：①事实清单（每条 file:line + 关键代码摘句）②未能确认清单 ③交互陷阱。只要事实，不要评价——评价由主会话统一做。
- **增量审计**：1 路定向 Explore 或直接读目标文件即可。

## 第二步：实机截图配方（WV 探针族）

```bash
# 构建后：WV_MODE=browse|map|cellmap|faction|realterrain|event|coastline
# WV_SHOT 在第 120 帧落盘一张，不自动退出；WV_DRILL=<map_id> 开机即钻到某图
WV_MODE=cellmap WV_SHOT="D:/.../shot.png" <wv.exe> gui -m <工程> > log 2>&1 &
sleep 13; taskkill //F //IM <exe名> //T
```

坑（全部实测踩过）：

- **并行会话共用 `.target` 会互锁**：把 exe 和工程目录复制到 `.target/` 下的副本再跑，exe 改名（如 wv-audit.exe），跑完即删——既不锁构建产物也不碰用户工程。
- bash 函数里 env 前缀 `$VAR=... cmd` 会报 command not found；路径里的 `$1` 转义坑。env 赋值写在函数体内。
- **欢迎页冷加载赶不上第 120 帧**：首启截图常拍成欢迎页——想拍主界面先让工程热起来，或用 `-m` 直开工程并多等几秒。
- `--http-port` 需要 `--features http` 构建；没 http 时全靠 WV_MODE/WV_SHOT 探针。有 http 时优先 `wv-http` skill 的 screenshot（base64 管道落盘，别进上下文）。
- **探针 artifact 排除**：疑似 bug 的现象（如脏标记）要用**无探针干净启动**复测一遍再定性。

## 第三步：评审与评分

按 [references/audit-prompt.md](references/audit-prompt.md) 的完整模板执行（角色、八审计维度、评审原则、五部分输出格式、量化任务表都在里面）。要点：

- 九维评分表（信息架构 10 / 导航 10 / 地形编辑 15 / 图层对象 10 / 一致性 10 / 反馈容错 10 / 专业工作流 15 / 视觉 10 / 大地图 10），证据不足的维度标「未评分」，不得虚构。
- 缺陷条目严格用模板（编号/名称/位置/类型/严重度/证据/当前/预期/影响/根因/推荐/替代/成本/验收/验证），P0=数据损坏或关键流程阻断，P1=严重影响核心编辑，P2=明显影响效率，P3=低频细节。
- 每份报告必答**元问题**：以「地理数据编辑」还是「绘制地图」为中心？当前结论（2026-10-29）：数据中心定位正确，病灶是数据侧缺「写」（实体创建断头）+ 绘制侧缺「出」（导出未实现）。
- 先列「做得对的」（带证据），再列缺陷——审计不是找茬清单。
- 对照量化任务表逐项判定达标/不达标（绘森林≤3步、切高度工具≤2操作、撤销=1键、找图层≤3操作、缩放到位≤5秒、改笔刷不离开画布、误操作可恢复）。

## 第四步：对话交付 → 按需落盘

先在对话里给全量结论；用户说「写入文档」再落盘。落盘时文首注明「点时审计快照，非基线、非 ADR，建议均为提案」。写完把报告要点 + 编号进展记一条 memory（type: project）。

## 第二轮：反向审计（第一轮交付后触发）

按 [references/reverse-audit-prompt.md](references/reverse-audit-prompt.md) 执行。操作要点：

- **视角切换**：不再是评审员，是每天用 8 小时的专业创作者。找的是第一轮遗漏的**严重**问题与「表面合理实际伤长期效率」的模式。
- **工作流模拟（任务 1）**：从零建图全流程逐步数操作。无法实机点击的部分用代码路径推演（入口 → 面板 → 命令 → 回执），**推演出的步数要标注「推演」**，与实机验证区分。
- **挑战第一轮（任务 9）**：点名具体 UX-0XX 条目，说明证据缺口或收益存疑——第一轮报告不是免检品。修正以补录节写，不删原文。
- **减法优先**：不把加按钮/加面板当改进；「删开关、统一行为、省步骤」的方案优先。
- **输出收敛**：按 用户影响 × 出现频率 ÷（修复成本 × 实施风险） 排序，目标 10 个；证据不足就少给，**不许凑数**。
