# 第二轮反向审计模板（round 2 · 防客气 / 防笼统 / 防堆功能）

> 触发时机：第一轮审计**交付之后**。目的不是重复第一轮，而是站在**每天使用该软件 8 小时的专业地图创作者**角度，寻找第一轮遗漏的严重问题，并**挑战第一轮的结论本身**。第一轮报告（如 `docs/UX_AUDIT_2026-10-29.md`）是被审计对象之一。

## 任务（十条）

对刚才的地图编辑器评审进行第二轮反向审计。不要重复已有建议，重点完成：

1. **模拟从零创建一张大型世界地图的完整工作流**（新建工程 → 预填充 → 生成/手绘大陆 → 群系 → 水系 → 城市/道路 → 标注 → 保存导出），逐步数操作、记卡点；
2. 找出所有可能导致**重复点击、频繁切换工具、丢失上下文、误操作**的设计；
3. 识别**表面合理、实际降低长期使用效率**的交互模式；
4. 找出**新手易困惑、专家易厌烦**的功能设计（同一设计两类人都伤）；
5. 判断哪些功能**已存在但操作方式不符合用户预期**；
6. 检查**自动地形生成与人工编辑是否冲突**（覆盖、重算、撤销边界）；
7. 分析**不同地图缩放级别下，工具行为是否一致且可预测**（同一手势跨 LOD/跨图的语义漂移）；
8. 识别当前设计中**最值得重新设计的三个交互机制**（给重构级建议，不是修补）；
9. **挑战第一轮审计的结论**：点名具体条目（UX-0XX），指出其中缺乏证据或收益不明确的建议；
10. 给出**最少改动、最大收益**的优化方案。

## 每个问题的必填字段

复现路径 / 问题原因 / 实际影响 / 改进方案 / 验收标准——五项缺一不可。证据纪律与第一轮相同：能给 file:line 就给，推测标「待验证」，不得虚构。

## 输出：只挑最值得优先解决的问题

- 按四轴综合排序：**用户影响 × 出现频率 ÷（修复成本 × 实施风险）**，目标 10 个，上限不超过证据支持的数量；
- **不许凑数**：证据只支持 5 个就只输出 5 个；
- 尤其注意：**不要把「增加更多按钮、面板和功能」当作改进**。优先考虑**减少操作、统一行为、简化工作流**——一条「删掉两个开关」的方案优先于「再加一个面板」。
