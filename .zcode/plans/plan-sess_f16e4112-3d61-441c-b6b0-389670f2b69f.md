## 风险与边界

1. **`Panel::title()` 签名改动**：所有 panel 系统都得加 `current_loc: Res<CurrentLocale>`。机械但量大（~21 个 panel 系统 + `top_bar` / `inspector` / `widgets::float_window`）。每改一处调度图都重排一次，跑三套闸门确认。W2 commit 内部按"先迁移 Systems → 再迁 `float_window`"两步走更稳。
2. **CLI locale 线程局部**：写一次后所有 CLI 文件共享。`std::thread_local!` 加 `Locale` 枚举或 `RefCell<Locale>`；比 pipe 一个 Locale 参数穿过 10 个 fn 省事。比拼一个独立的 `CliLocale` 枚举小。Test 加 `cli_locale_set/get`。
3. **`format_date_with` split**：zh 表 vs en 表的 "第 N 天" 没有自然的英文等价（英文是 "Day N"），所以 Key 三件套：`TimeNoCalDayEnPrefix="Day "`、`TimeNoCalDayEnSuffix=""`（无 "Day"→"天" 后缀的英译，干脆空）、`TimeNoCalDayZhPrefix="第 "`、`TimeNoCalDayZhSuffix=" 天"`。
4. **TERRAIN_NAMES 仍未在 I18nKey 内**：W2 一并迁。Shell 模块的 `TERRAIN_NAMES: [(&str, Color32); 10]` 改成「`const TERRAIN_KEYS: [I18nKey; 10] = [...]` + 在 helper 函数里 `t_key(&loc, k)`」；这会引入 `i18n` 模块对 `state::UiShell` 的依赖（实际是反过来——`widgets::terrain_grid` 已经 `use crate::i18n`，OK）。
5. **测试 runtime cost**：ALL 数组从 85 → ~265 个 Key。`i18n::tests::every_key_resolves_*` 与 `substantive_keys_are_non_empty` 仍 O(n)；不需 `<=10ms` 优化。
