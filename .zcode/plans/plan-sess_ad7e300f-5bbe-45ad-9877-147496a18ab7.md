# 工具栏 1:1 还原（截图规格）

## 一、目标

把 `crates/wv-app/src/ui/map_controls.rs` 当前「右下一个圆角大框里塞 7 个按钮」的形态，整体替换为图片里的「左侧纵向、每钮一方块、8 个独立瓷砖」。当前 `map_controls` 的 7 个按钮（pen / line / square / eraser / + / − / 缩放到全图）变 8 个独立瓷砖：pen · line · square · pencil · separator · + · − · [ ]。**Pencil 与 pen 同义**（都切 `brush.enabled`），按用户裁定。

并在系统入口加「**无工程不可见**」早返（与 `welcome_screen` 同样的 guard 文案），让首页看不到本工具条。

## 二、需求决议（已与用户拍板）

| 维度 | 决议 |
|---|---|
| Pencil 行为 | 和 pen 联动——同 `brush.enabled` 切换（设计冗余、双图标按同钮）。 |
| 现有右下面板 | 整体替换为左列版（不留两份）。 |
| 不动的：`script`、`widgets.rs` 工作区未提交改动（panel_head 自绘） | 与本任务无关，不卷入。 |

## 三、改动清单（单文件）

### 3.1 文件：`crates/wv-app/src/ui/map_controls.rs` （重写）

**(a) 顶端 doc 注释**：从「右下角浮动工具条（v0.3 Figma …）」改成「左侧纵向工具条（图片规格 · 8 独立瓷砖）」，并写明：①每钮独立圆角方块、②活动态走 `accent` 蓝底（用户裁定的视觉）、③pen + pencil 同键联动。

**(b) 增加 system 入参** `startup_req: Res<StartupLoadRequest>`（已在 `ui_shell.rs` 注册过同名 resource 直接 import；welcome_screen 在用同一信号）。

**(c) 早返 guard**（顶部，第二段，越过 `egui::ctx_mut()` 之前）：
```rust
if !projection.has_open_project() || startup_req.0.is_some() { return; }
```
镜像 `welcome_screen.rs:96-97`。**这是「首页不见」需求的落点。**

**(d) 重写容器为 `Align2::LEFT_TOP` Area**：
- 锚点：`Align2::LEFT_TOP, egui::vec2(16.0, 58.0)`（左 16、下挪 58 = 顶栏 38 + 间距 20）。
- 把当前「一个 `Frame::NONE` 包整列」改成 **没有外层 Frame**：每钮自带 `Frame::NONE.rounded + raised_bg` 圆角方块。
- 改成用 `ui.spacing_mut().item_spacing.y = TILE_GAP` 控制钮间距，`ui.add_space()` + `ui.separator()` 画两段分隔。

**(e) 砖块尺寸与 token**：
- `TILE_SIZE = 56.0`（正方形，图片视觉比例）。
- `TILE_RADIUS = 10u8`（与现 `radius::PANEL` 同档，或新加 `radius::TOOL_TILE`）。
- 活动底：`shell.accent()`（accent = `#4C8DF6`，与图片高亮蓝一致）。
- 非活动底：`shell.raised_bg()`（`#232731`，与背景有可辨对比但留白图标）。
- 描边：无（图片无可见描边）——若色差不够，再补 1px `border_subtle`。

**(f) 8 个砖块顺序（自上而下）**（按截图逐字校对）：

| # | 图标常量 | 动作绑定 | 活动条件 |
|---|---|---|---|
| 1 | `ICON_PEN` | 切 `brush.enabled` | `brush.enabled` |
| 2 | `ICON_LINE` | `MeasureMode::Line` | `measure.mode == Line` |
| 3 | `ICON_SQUARE` | `MeasureMode::Rect` | `measure.mode == Rect` |
| 4 | `ICON_PENCIL` | **同 pen**——切 `brush.enabled` | `brush.enabled` |
| — | separator (`ui.add_space(8) + ui.separator()`) | — | — |
| 5 | `ICON_ZOOM_IN` | `set_map_scale(view/1.6)` | 始终 |
| 6 | `ICON_ZOOM_OUT` | `set_map_scale(view*1.6)` | 始终 |
| 7 | `ICON_MAXIMIZE` | `view.camera_center=frame_origin+level_map_size/2; set_map_scale(zoom.fit)` | 始终 |

> 当前实现里 pen / line / square / + / − / [ ] 的接地点直接搬过来，不重写逻辑。Pencil 用与 pen 完全等价的回调与 active 状态——按用户拍板的「联动同 pen」。

**(g) 复用现成抽象**：每砖块仍是 `ToolButton::icon(...)` 工厂（`widgets.rs:842`），仅 `.size(TILE_SIZE).active(active).tint(WHITE).active_bg(shell.accent())` 覆盖默认（图片活动态是白图标、蓝底）。复用 `set_map_scale` 私有 helper 不变。

### 3.2 其它文件

- `ui/mod.rs`、`app_bootstrap.rs`、`ui_shell.rs`、`widgets.rs`：**均不动**。
- `ICON_PENCIL` 已在 `widgets.rs:792` 与 `ui/mod.rs:97` 定义并 re-export（上一轮 v0.3 已布线），新接点直接 import 即可。
- 不动 `panel_brush.rs`（图片里没有显式笔刷面板；先按现状保留，工具栏不再引它）。

## 四、测试

| 已有 | 保留 |

| `no_project_hides_toolbar_assets_dont_render` | 重构后的 `map_controls` 在 `projection.has_open_project() == false` 时不创建任何 `egui::Area`——具体做法：把「绘制逻辑」抽成 helper `render_toolbar_tiles(ctx, …)`，单测里构建 `WorldProjection` 默认态 + `StartupLoadRequest::default()` 传入，调 helper 后断言 **0 个 `area_created`**（egui 没有 area 计数的直接 API；改用「helper 必经 `Area::new().show(...)` 的 call site 数」配 ctx 全局 `egui::Context::all_areas()` 是否非空）。若 API 限制测不动，则改为「断言函数在 guard 命中时只走一行 `return;`，不申请任何 GPU/字体资源」——行级覆盖。|

> 若单测行级覆盖在 egui 0.36 0.42 下拿不到可信信号（`Area::show` 必然走 GPU 准备），改为 **assert 后续 eprintln / 函数签名 schema**：helper 函数 `pub(crate) fn render_toolbar_tiles(...)` 独立编译通过 + 现有 zoom 测不变为底线，渲染正确性继续吃 `scripts/smoke-gui.sh`。
