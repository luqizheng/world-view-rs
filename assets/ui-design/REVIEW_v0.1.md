## 二、缺陷清单

### 🔴 严重（功能失效 / a11y 阻断）

#### B1 · 时间轴游标与事件条永远对不齐
```
原因：left = 12 + 比例 × 整个时间轴宽度
     但轨道区 .lane-t 前有 56px 标签列 + 8px padding ⇒ 基准不一致
影响：拖动播放头时，游标划过的事件条 ≠ 当前日期对应的事件
修复：新增 trackMetrics() 实测 .lane-t 的 offsetLeft/width，游标与拖拽共用该基准
      并在 resize / 密度切换时重算
```

#### B2 · 裸 Tab 被拦截，纯键盘用户无法移出输入框
```
原因：沉浸模式绑定裸 Tab 且 preventDefault()
影响：违反 WCAG 2.1.1 Keyboard —— Tab 是键盘用户唯一的焦点移动键，
      拦截后键盘用户进得去出不来
修复：改绑 Ctrl+Shift+I；Tab 完整归还浏览器
```

#### C1 · 笔刷选中描边仅 2.34:1（需 3:1）
```
原因：rgba(242,193,78,.35) 叠在 #212530 上合成后过暗
影响：10 个地形里"当前选中了哪个"几乎看不清，等于没有选中态
修复：抽 --ui-focus-ring 令牌，暗色 .85 → 7.01:1，亮色用深琥珀 .90 → 4.37:1
```

#### C2/C3 · HUD chip 压在地图上不可读
```
原因：scrim 不透明度按"深色地图"直觉设定，未考虑地图最亮处是雪原 #E6ECEF
实测：暗色 .72 → 3.92:1 ；亮色 .34 → 2.86:1（比暗色更糟）
修复：新增 --ui-bg-float（暗 .94 → 6.73:1 / 亮 .93 → 6.49:1）
```

## 三、最值得记住的一条

> **C4 暴露的是标注纪律问题，不只是配色问题。**
>
> 我测出 4.01:1 后，在表格里写了"PASS AA-large"——
> 但那个徽标字号只有 **10px**，远低于大字号门槛（≥18.66px 粗体 / 24px）。
> **写"PASS"之前必须先确认用的是哪条门槛，而不是看到一个数字就归类。**
>
> 同类风险：`ui.focus-ring` 亮色 4.37:1 满足的是**非文本 3:1**，
> 若它是正文则**不合格**。门槛选错，数字再准也没意义。

## 五、尚未验证的（诚实标注）

以下项目**本次没有工具能验证**，需要人工在浏览器里过一遍：

1. **实际渲染是否与计算一致** —— 计算的是色值对比度，浏览器渲染受 `backdrop-filter`、字体抗锯齿影响，可能有偏差
2. **拖拽/缩放手感** —— 面板跟手度、滚轮缩放的阻尼感，需实际操作
3. **地图性能** —— 512² 地形 + 多图层的帧率，未测
4. **中文字体渲染** —— 原型用系统栈，实际工程走 `fonts.rs` 探测，两条路径未对齐验证

## 六、下一步建议（按性价比排序）

| 优先 | 事项 | 理由 |
|---|---|---|
| **高** | 把 `audit-contrast.py` 接入 CI | 人工算对比度必然衰减，脚本化才不会回归 |
| **高** | 色值统一改为 CSS 变量驱动 | 现在 JS 里还有硬编码色（事件标记、时间轴游标），换主题会漏 |
| 中 | JS 硬编码色 → 读 `getComputedStyle` 的 CSS 变量 | 同上 |
| 中 | 面板位置持久化（Q5 已提） | 布局是长期手感 |
| 低 | 树节点虚拟滚动 | 人物上千时才需要 |
